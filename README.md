全站共用一个聊天入口，登录后的每轮提问固定由后端 DeepSeek Harness 子进程处理；即使项目生成任务选择 `AI_PROVIDER=http`，聊天也不会切换供应商。聊天框显示服务名称、已发送的问题与等待状态，支持备赛、分工、计划、GitHub 和技术问题。DSH 缺失或失败时明确报错，不生成替代答案。初次网站介绍可跳过、重放，是公开说明，不触发模型收费。

聊天发送最近十条消息和当前页面；项目页另附项目 ID，后端只读取当前有权限的项目名称、阶段和目标，并在返回前复核账号、会话和成员权限。用户消息最多 2000 字符、AI 回复及其历史最多 6000 字符，历史总量超过 32 KiB 时移除最旧的完整消息。对话按本人账号及当前空间保存，重新打开时可恢复本人历史；明确清空只影响对应本人对话。模型没有读取项目完整规则/代码或执行安装、提交的权限。

在项目的“比赛要求”页，可以搜索并引用自动发现的赛事，预览完整分析与来源，填写队伍备赛备注，保存、编辑、替换或清除赛事线索草案。草案保留保存时的分析快照及版本，刷新后可恢复；来源更新时提示核对，不自动覆盖队伍记录。管理员编辑、成员阅读、归档只读；版本冲突会保留输入并要求重新读取。它不会自动发布赛事、确认正式规则或修改项目截止。

比赛页用桌面三列、平板两列、手机一列展示；不足 24 条时明确标示等待位置，手机多余空位折叠。当前真实条数单独显示，预留位置不表示已发现对应数量的比赛。

GitHub 页用主分支、独立工作分支、拉取基版本、commit 和 PR 合并图解释协作关系；“拉取”先读取远端基线或恢复本站草稿，不会静默覆盖工作区。遇到冲突按“保留草稿 → 重新拉取 → 对比修复 → 预览差异”处理。本站不接收 GitHub 密码、验证码或 PAT，也不会把 commit 保存成功当成赛事提交成功。

报名入口只能来自本次实际读取的可见 HTML 链接，或真实搜索引用中明确出现的报名地址，并保留证据供 DSH 选择。没有可靠候选时显示查看原文，不按赛事名称猜测链接。参赛建议有“值得了解”“先核对再决定”“信息不足，暂无法判断”三类，说明条件与依据，不给匹配百分比或保证用户符合资格。旧卡片缺少新字段时保留原分析并提示信息不完整；后续重分析不清除未知付费结果标记。

持续发现有三种入口：`dsh_native` 通过本机 DSH 账号调用官方原生联网工具；`official_sources` 定期检查 ETHGlobal/lablab.ai 等固定官方列表；`brave` 使用独立 Brave key。它们复用常驻调度、公开网页获取和 DSH JSON 分析。原生搜索只采用官方工具返回的结构化 URL、标题及真实 `cited_text`，不把生成回答当来源。搜索与分析都计入发现预算，未知付费结果持久阻断自动重发。卡片保留出处、依据类型和未知项，不自动成为已审核赛事。公开索引、robots、登录及平台访问限制会影响覆盖，微信小程序内部数据没有接入。详见 [后端 DSH 与自动发现](docs/规划/11-后端DSH与自动发现.md)。

技能安装目前有 Codex、Claude Code、Cursor、GitHub Copilot、Gemini CLI、OpenCode、Windsurf、Cline 八种客户端目录适配。目录和格式适配声明不等于已在八种真实客户端验证加载与样例任务。文件写入、客户端加载和任务效果分别记录；复制命令或确认预览不能显示为安装成功。

## 本地命令

需要 Node 24。由主会话统一安装依赖。

```text
npm ci
npm run dev
npm run typecheck
npm run build
npm test
npm run test:integration
npm run test:e2e
npm test -- auth
npm run config:check
```

打开 `http://localhost:3000`。`npm run dev/start` 在服务启动时初始化应用，本地模式自动执行根迁移并启动后台任务，无需先访问网页。数据与登录密钥保存在被忽略的 `.runtime/`。只有未配置邮件服务且 Origin 为可信 loopback 时才提供开发邮箱预览；配置 SMTP/Resend 后使用真实发送接口。公开代理须使用实际公网 Origin、安全 Cookie 与可信 HTTPS，不能暴露开发邮箱。

`npm test -- auth` 按模块运行 Node 行为测试，可将 auth 换成实际模块目录名。端到端测试要求 loopback 页面服务已启动，并使用本机已安装的 Microsoft Edge。登录与协作使用独立内存 PostgreSQL、真实迁移和 HTTP handlers，所有 API 拦截到测试库并阻断外网；不访问运行数据库、真实开发邮箱或收费服务，不保留试验账号到生产库。

生产构建在本机体验时需显式指定本地模式：

```powershell
$env:APP_MODE = 'local'
npm run start
```

关闭服务器后再执行本地数据库维护，避免两个进程同时打开嵌入式数据库。实际迁移位于根 `migrations/`；修改已应用文件会因校验和不一致被拒绝，使用新增迁移调整结构。

## 运营初始化

让实际运营人员先完成邮箱登录，再在可信服务器终端赋予角色。没有“注册即管理员”或公开赋权接口。下面的邮箱是说明占位符，需换成已验证账号：

```text
npm run admin:grant -- operator@example.com admin
npm run admin:grant -- reviewer@example.com reviewer
```

本机使用前需停止网站进程，再执行赋权并重启。命令复用 `.env.local` 配置，角色变更与审计同事务写入。访问 `/admin` 录入真实规则/资源，逐项核验后明确确认发布；默认仍要避免创建者自行审核自己的内容。正文录入使用结构化 JSON，格式见模块 domain 与规划，不将粘贴内容视为已审核。

## 连接模式

复制 `.env.example` 为 `.env.local`，设置 `APP_MODE=connected`、HTTPS `AUTH_ORIGIN`、`DATABASE_URL`、至少 32 字节的 `AUTH_CODE_PEPPER`。登录邮件可用 Resend（密钥和已验证域名的发件地址）或 QQ SMTP（发件邮箱和授权码）；配置见 [QQ邮箱验证码配置](docs/部署/QQ邮箱验证码配置.md)。2026-10-09 本机 QQ SMTP 的真实验证码发送已被服务器受理，收件箱到达和用户输入验证码仍待确认。

```text
npm run db:migrate
npm run build
npm run start
```

命令只迁移配置的数据库，不自动采购或部署服务。数据库连接模式使用真实 pg 连接池；跨模块多连接竞争仍需在目标 PostgreSQL 验证。本机 PGlite 测试证明 SQL 行为、原子回滚与持久化，不证明远程部署的并发性能。

连接模式默认采用全站 15 分钟预算，默认发送 200 次、验证 500 次，可用 `AUTH_GLOBAL_SEND_LIMIT` / `AUTH_GLOBAL_VERIFICATION_LIMIT` 调整；每邮箱限额与重发冷却仍有效。可信代理签名入口已实现，启用需按部署环境配置 `AUTH_PROXY_SIGNERS_JSON` 并清除外部伪造头；未配置时不把普通请求头当每 IP 身份。

## 后台服务配置

依赖由 `package-lock.json` 锁定，应用采用 Next.js App Router＋React＋TypeScript，连接模式使用 PostgreSQL。不同服务分别配置：

- 项目 AI：设置 `AI_PROVIDER=dsh`，规则建议、评分、分工、计划和复盘共用下面的 DSH；如需独立 HTTP 服务，设置 `AI_PROVIDER=http` 及 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`。调用数、费用与租约在数据库记录。
- DSH：本机使用 `DSH_DESKTOP_DIRECTORY=D:\dddsss`、`DSH_MODEL` 和输入/输出 USD 费率，运行实际 Desktop `0.2.0-rc.2`。Linux/容器可改用 `DSH_API_KEY` 与后端固定的官方 `@deepseek-ai/dsh@0.2.1-alpha.1`。两种方式均使用独立子进程、无工具、有限输入和输出；Desktop 模式只在子进程读取官方账号 grant，不读取个人技能或插件，不修改个人授权。
- 发现入口：官方来源方式使用 `DISCOVERY_PROVIDER=official_sources`、可选 `DISCOVERY_SOURCE_IDS_JSON` 和 `DISCOVERY_*` 限额。Brave 方式使用 `BRAVE_SEARCH_API_KEY`、搜索费率和查询；Brave 与 DeepSeek 模型分别计费。两种方式都需要配置 DSH，官方来源方式未调用付费搜索 API。
- 灵感分析：配置有效 DSH 后设置 `INSPIRATION_ENABLED=true`，由同一后台任务组按固定官网范围获取与分析。`INSPIRATION_*` 单独控制调度、重抓、模型调用与 USD 预算，不从公开网页发起模型任务。
- GitHub：GitHub App ID、slug、客户端凭据和服务端 token 加密 keyring。网站登录、本人 GitHub 授权、App 安装范围和仓库写入权限分别核对。

采用 API key 运行时，先运行 `npm run dsh:install`，再用 `npm run dsh:install -- --check` 核验固定版本。Desktop 模式直接使用已安装目录，无需重复安装。安装核验本身不表示完成在线推理。`npm run dev/start` 在 Next 的服务启动钩子初始化一次后台任务；构建没有服务标志，不会启动数据库或付费搜索。需要独立 PostgreSQL worker 的连接部署设置 `FIELD_GUIDE_EMBEDDED_WORKERS=0`，再运行 `npm run worker`；Compose 已采用此方式。不要另开一个进程同时使用本机 PGlite 目录。

本机自动发现最短周期已配置为 5 分钟，后台每 10 秒检查到期、暂停和预算；单轮尚未结束时不会并发启动另一轮。比赛页每 3 秒读取共享缓存的公开元数据，只有发现版本变化时才读取卡片，隐藏页面停止检查，恢复时立即同步。浏览历史页时提示有更新，保留当前位置。读取页面不发起模型调用。公开状态区分进行中、等待、暂停、额度限制、需检查和离线；达到已有每日上限后不会继续收费，下一配额日恢复检查，未知请求仍需要人工核对。

赛事详情的最短重抓间隔为 5 分钟，正文哈希不变时不重复付费分析；报名与参赛建议的分析结构升级会使旧成功结果进入新分析，未知结果 hold 仍然有效。每轮也回访最多一个已保存赛事，避免它不再出现在搜索结果后永远停留在旧分析。灵感后台每 10 秒检查调度，最短每分钟处理一个到期官网，同站成功后默认 24 小时重抓，已知获取失败可在 5 分钟后重试；内容与提示版本未变时不重复模型调用。当前本机灵感独立上限为 24 次模型调用、0.10 USD / UTC 日；预留、网络与未知结果也可能让可用次数更少。迁移 `020_inspiration_catalog.sql` 保存灵感卡片、不可变版本及独立 worker 心跳类型。

灵感页可见时每 10 秒读取 `GET /api/v1/inspiration` 已保存快照，隐藏时停止请求。赛事元数据和卡片、灵感快照读取都有有界超时；断线保留已读取内容并重试只读请求。管理员通过 `/api/v1/admin/inspiration/status` 查看独立账本，以预期 revision 调用 `/api/v1/admin/inspiration/paused` 暂停或恢复，当前权限复核及审计沿用后台规则。

目前 144 次搜索/UTC 日、每轮一个原生查询词，最多约 144 轮；5 分钟是最短间隔，不能据此承诺全天每 5 分钟收费搜索。默认查询有十六组轮换，覆盖全网、公众号、小红书、微博、B 站、即刻、知乎、抖音及国际官方/社区来源；轮次由持久化搜索计数决定，月份与年份随时间滚动，自定义查询保持原样。原生搜索还轮流读取 ETHGlobal/lablab.ai 的公开官方目录，单次最多 20 秒、五个单场链接，与搜索结果共用每轮最多三页的 DSH 分析名额。目录失败不会阻塞其他来源，也不产生额外模型搜索调用。`npm run build` 的 postbuild 会检查并清除 NFT 中本机运行数据和环境文件的引用；若构建目录已有私有副本则拒绝通过，不删除源数据。`npm run build:verify` 可独立验证。

完整环境变量、容器、回调、预算、后台心跳与失败恢复以 [.env.example](.env.example) 和 [后端部署](docs/部署/后端部署.md) 为准。真实邮件发送、模型/搜索调用、GitHub 写入、客户端技能加载和容器运行，需要各自保留验收证据。
