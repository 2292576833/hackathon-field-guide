# 主办方填写与管理员测试

主办方表单的字段旁说明用途、填写格式和示例；示例只帮助理解，请替换为真实比赛信息。日期预填可用于建草稿，发布前需要逐项核对。参赛新手、普通选手和主办方共用账号，具体权限随机构和比赛分配。

## 主办方测试顺序

1. 主办方账号从 `/organizers` 提交机构申请；名称、联系人、联系方式和证明需与真实机构对应。
2. 平台管理员从 `/admin/organizers` 核查申请。测试时使用另一个主办方账号，不能自己审核自己的申请。
3. 入驻通过后，从 `/organizers/workspace` 建一场测试比赛，按字段提示设置规则、时间、报名和组队。
4. 先配置报名表，再预览发布比赛，复制本场报名链接；用另一个选手账号报名，返回主办方页面审核。
5. 编辑入选通知、预览实际收件内容，再确认发送；站内发布、邮件排队、邮件服务接受、用户实际收到分别核对。
6. 按需测试行程、住宿、餐券与人工评审。使用虚构测试选手资料时，明确标注测试，不给真实选手发送测试通知。

更详细的闭环见 `docs/协作/主办方工作台试用步骤.md`。

## 管理员测试凭证

此入口只兑换已有验证码挑战，不能给普通账号增加权限。签发工具只运行在可信部署主机，限定已有活跃、邮箱已验证的管理员。没有公共签发接口，不创建永久通用管理员密码。

- 登录入口：`/login?test=1&returnTo=%2Fadmin%2Forganizers`。
- 在受限的 `.runtime/admin-test-access/` 文件里复制整段 `挑战编号.8位数字`，粘贴到“管理员测试凭证”，点击登录。
- 凭证默认有效 10 分钟，使用一次后失效；失败次数、速率限制和审计沿用原验证码机制。此方式没有发送真实邮件。
- 兑换后的登录会话沿用网站原策略（当前 7 天），可在账号菜单退出，或在账号设置撤销会话。不要把 10 分钟凭证有效期理解成 10 分钟会话。
- 本机文件含登录凭证，不放公开仓库、网站资源目录、截图或交付压缩包。这里只记录用法，不记录真实凭证。

重新签发：先停止本机网站，确保嵌入式数据库没有其他进程占用，再运行 `npm run admin:test-code -- --email 已验证管理员邮箱 --output .runtime/admin-test-access/新的文件名.json`；关闭签发进程的数据库后重新启动网站。输出目录必须提前创建并限制为本机用户可读；文件名只能用英文、数字、点、下划线和连字符，不能覆盖已有文件。真实凭证以新文件的到期时间为准，重发会使同邮箱旧验证码失效。

正常停机使用 `npm run server:stop` 或 `scripts/serve-service.ps1 stop`，等待实例确认关闭数据库并退出，再检查无自动重启或其它数据库拥有者；不要用强制结束任务代替。签发沿用同邮箱每15分钟最多三次、至少间隔一分钟的保护，达到限制等待自然重置，不删除账本来重发。

本机测试启用 `AUTH_LOCAL_TEST_ORIGIN=http://localhost:3000`，仅允许 `APP_MODE=local` 使用这个固定地址；它复用同一网站和数据库。请用 localhost，不能换成局域网 IP 或 127.0.0.1。浏览器 Host 与写操作 Origin 必须匹配这个固定地址，不信任转发头来切换认证。公网 `AUTH_ORIGIN` 和 HTTPS 安全 Cookie 保持原配置；本机登录使用单独的 Cookie，账号操作复用原身份服务。这是额外允许的浏览器来源，不是独立隔离的测试服务器，也不改变账号权限。

域名处理已按用户要求暂停。本机测试优先使用 `http://localhost:3000`；公网访问问题不影响本机主办方业务验收，但仍需以后单独验证。
