## 已确认的体验问题与建议

以下结合实际隔离浏览器交互、截图与源码定位，不等于已完成真实萌新试用。实际缺陷与改善建议分别记录。

### 本轮已有明确修复方向，新增测试防止回退

1. **选好比赛后创建团队空间容易丢失上下文。** 原来卡片进入私人计划，去“我的参赛”后要重新找赛事。根会话本轮新增私人准备到团队空间的 event 链接及 discovery 候选带入。贯通测试验证完整回跳与保存动作，仍保留“线索不是正式规则”的解释。
2. **邀请链接入口与主要操作不明显。** T01 已把邀请放在各空间页面顶部，生成后突出复制，并解释关闭、刷新与恢复边界。测试验证默认人数、操作可见与焦点返回，详细满额/撤销/二维码场景由专用邀请测试覆盖。
3. **新空间先看到空筛选与管理操作。** 本轮工作台改为开始动作、阶段指南和可单人继续；复杂管理折叠。贯通测试验证新空间没有空的“全队任务”筛选。
4. **任务“完成”与队友检查容易混淆。** 本轮清楚区分“提交成果，请队友检查”与“检查通过”。测试验证等待关系、并行准备与检查后的释放，不把未检查成果当完成。
5. **首次登录缺少网站操作介绍。** 新增账号级六步指引，测试要求完成后继续所选比赛，不跳丢上下文。邀请接受优先由首次指引专用测试覆盖。
6. **计划确认无故报版本冲突。** 实际浏览器发现 `versionsEqual` 对成员意愿引用直接 JSON.stringify，JSONB 回读只改变对象键序就令相同业务值比较失败。创建响应对 GET/lock 比较为真，持久快照对同一输入为假；计划 revision 0、任务基线 0、当前计划 null 均匹配。根已按固定字段投影修复，并增加真实持久化回归。本测试的持久快照/GET/锁版本一致和实际确认已通过。
7. **确认计划后“开始执行”立即令计划过期。** 保存 active 本来要求已有计划，阶段保存又增加整个 Project revision，导致刚确认的计划不能开始，等待时也无并行建议。根已加入仅服务器提供的规划项目事实版本，阶段本身不影响调度事实；旧草案/适配仍保守校验 revision，规则、分工、时间、意愿及成员身份仍校验，归档写入仍拦截。恢复正常用户顺序后已通过 `inputVersionsChanged=false` 与实际任务开始/并行推荐。
8. **阶段保存提示被藏在另一个折叠表单。** 实际 stage POST 成功，但“阶段已更新”在通常关闭的目标编辑折叠区。根已在阶段表单内提供独立 stageNotice。该 UI 修复尚需最新构建验证；本测试目前以真实响应与可见顶部阶段标签验证保存，不把隐藏提示当保存失败。
9. **规则确认成功后同页赛道仍停在“还没有规则”。** 本代理在临时授权内修复：成功 POST 后发送带当前 projectId 的 `hackathon:project-input-changed`，官方赛道面板仅为当前项目/兼容既有本页无作用域事件重新 GET 赛道视图与规则依据，拒绝其他项目的有作用域事件。首次空白且未编辑的表单可采用第一份已确认规则，立即出现下一步；已有规则基线、选择、说明和确认状态不会自动被新版替换，沿用“载入最新版本”及替换确认。保存赛道也改发同项目作用域事件，不会自动保存统一赛道或代替用户确认。TypeScript 已通过，隔离浏览器回归待最终构建。

### 建议继续优化

| 优先级 | 萌新会遇到什么 | 当前证据与建议 |
| --- | --- | --- |
| P1 | 赛事页有比赛，空间却说没有“已发布赛事”，到提交时找不到可选入口 | DSH 自动线索与 M03 经审核规则是两个合法状态，但用户容易理解成比赛“消失了”。在无正式规则时提供明确说明与下一步：当前已保存什么、尚缺哪些官方要求、谁负责核对。缺正式入口时保留明确阻塞，不能编造或把线索当已审核。 |
| P1 | 我只是想排一天任务，要填写大量工时、缓冲、必交要求引用 | 手动计划每个任务需要负责人、交付物、检查条件、三种工时与依据等；真实业务校验有价值，但初次填写负担高。建议先以少量字段形成可编辑草案，再在确认前集中补齐负责人、依据与风险；估算必须标明来源，不能自动当作成员承诺。 |
| P1 | 我选了“准备路演”，为什么还没有我的任务 | 职责意愿与正式分工、计划是不同事实。保存意愿后应明确显示“已让队友看到意愿；现在请管理员确认任务”，管理员侧提供直达分工/任务安排的入口。独立人工任务仍允许，无需强迫测评。 |
| P1 | 顶部阶段标签与五个阶段按钮看起来像两种进度 | Project.stage 保存参赛阶段，工作台五段是浏览指南。建议视觉上分别写“当前团队记录”和“查看阶段指南”；浏览阶段不得产生写请求或假进度。根随后改为树状动作路线，需要最新页面再验收。 |
| P1 | GitHub 未配置时看到 App 安装 ID、仓库 ID 等，误以为每个人都得懂这些 | 当前高级绑定内容已折叠，但未配置页仍有多组受限操作。优先展示可用路径：读图形指南→到 GitHub 操作→回本站记录运行/提交；技术参数留高级操作。不能把用户执行外部操作说成已由本站完成。 |
| P2 | 任务已经全部打钩，为什么还需要记录运行与正式提交 | 任务完成只是团队成果检查，GitHub 版本、运行、赛事提交各自有记录。工作台和任务全完成时继续提供“下一步检查代码/运行/正式提交”，不写整场比赛完成百分比。 |
| P2 | 我有路演和 PPT，却不知道怎样让队友看见 | 当前生成结果私人，主动导出分享或加入空间资料才可共享。建议在导出操作附近提供对应团队共享入口并说明其用途，仍不自动公开私人稿件。 |
| P2 | 复盘以后又多出“经验卡”，列表出现 draft/confirmed 等英文 | `experience-client.tsx` 列表直接渲染 item.status。建议翻译为草稿/已确认/已过期/已归档，并解释“复盘记录本次经历，经验卡只提炼以后可复用的一条做法”，允许用户只做复盘。 |

## 未接入与实际边界

- 邮件验证码来自隔离开发邮箱，没有发送到真实 QQ/SMTP 或 Resend。
- 赛事卡片和已发布规则是明确的作者夹具，没有触发搜索或 DSH 分析；不证明来源覆盖或事实核验质量。
- 人工计划建立通过真实 API，但没有在此条测试重复全部手动编辑器输入；现有 workflow 套件覆盖编辑、保存、校验、载入、修改和确认。
- 演示成果、运行依据、提交回执均明确写成隔离练习；不证明真实作品可运行或已在主办方平台提交。
- 路演/PPT 只验证选择资料、预览、本人确认、表单带入、返回上下文与模板工具入口；没有模型产出质量验收。
- GitHub 不调用真实账号或仓库，实体手机、公网证书、外部平台和 QQ 笔记本部署均不在此次验收内。
- 375px 自动化不等于真实萌新“5 秒找到邀请、10 秒说清下一步”。这些仍需少量真实队伍试用观察。
