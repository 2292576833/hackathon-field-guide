# 确认式执行 · 接口对照（核实结果）

> 2026-10-18 晚。**只核实、未改代码**。目的：确认三种动作各自写到哪个既有接口，避免凭记忆接。

## plan_task → 计划草稿（版本化）

核实到的真实路由（`src/server/router.ts`）：

| 方法与路径 | 处理器 | 作用 |
| --- | --- | --- |
| `POST /projects/:id/plan-versions` | `planning.createDraft` | 建一版计划草稿 |
| `PATCH /projects/:id/plan-versions/:planId` | `planning.editDraft` | 改草稿（加/改任务） |
| `POST /projects/:id/plan-versions/:planId/apply` | `planning.apply` | 草稿转正 |
| `GET /projects/:id/plans/current` | `planning.getCurrent` | 读当前计划 |

**关键发现**：计划本身就是「草稿 → 应用」两段式，**已经内建人工确认**。
所以确认式执行不需要发明新机制：

```
AI 提议 → 用户点确认 → 创建计划草稿（含这条任务）
→ 用户在计划页看 diff → 点应用才生效
```

这比直接写任务更安全：AI 永远只能产生草稿，正式计划仍由人应用。
