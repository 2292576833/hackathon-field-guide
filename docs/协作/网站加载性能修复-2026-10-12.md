# 网站加载性能修复

依据：用户要求“网站加载缓慢修复”，继续使用现有域名；由主会话集成，侧栏独立会话分别处理空间分区、赛事刷新和穿透测量。

## 实测问题

- 旧版 `/events` 首屏重复读取整份赛事列表，两次各 117345 字节正文，未压缩；同一页另有四次 `/me` 和两次 `/system/status`。
- 首页空闲导航员提前读介绍，登录后还提前读取私人对话、项目列表。首页可见链接自动预取多个尚未进入的页面。
- 空间首屏即使设置折叠也挂载设置表单；画布先挂默认组件再切换本人保存布局，造成无用读取。
- 旧版比赛页模拟手机、150ms 网络延迟、1.5Mbps 下载、四倍 CPU 降速，三次首卡可见耗时为 4470、4481、4118ms。仅为受控浏览器模拟，不能替代实体手机和移动网络验收。
- 公网节点严格 TLS 页面约 72–95ms，本地页面约 1–2ms；普通 hib 域名三次连接约八秒超时。正常委派/A 记录与本机普通查询返回不符，不能把固定节点成功当成普通域名已恢复。

## 修复范围

1. 合并同时发生的精确只读接口请求，不持久缓存账号或空间资料；写请求之前清空共享在途请求组。请求过期、切换页面时取消本组件的读取；一个订阅者取消不影响另一个。
2. 导航员首次打开后才读取其资料，首次账号指引照常读取。首页和站点导航取消自动预取其它页面。
3. 公开赛事、灵感目录 GET 支持 gzip 协商，保留 no-store；私人接口、写操作、错误响应和带 Cookie 的响应不压缩。
4. 赛事列表新增与卡片同一 SQL 快照的 `version`，与 live 聚合算法一致，避免用分开读取的版本掩盖并发更新。客户端按版本读取，保留隐藏暂停、失败恢复和历史页位置。
5. 空间编辑分区按需加载，设置首次展开后才挂载、关闭保留输入。自由画布确认保存布局后才挂组件。
6. 用户追加样式：从用户提供的色样中心读取 RGB(255,253,248)，统一使用 `#FFFDF8` 暖白色作为待办、团队进度、队友状态、协作提醒、空间 AI 入口、倒计时和范围调整的底色；文档白底和参赛流程保持原样。不新增外层大框。
7. 用户追加交互：修复左键按住空白拖框圈选；圈选的组件可整体拖动和缩放。未圈选时滚轮正常滚动，只有圈选组可以缩放，流程内部行动节点遵守同一规则。
