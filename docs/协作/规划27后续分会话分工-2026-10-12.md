## 0. 总规则（所有会话必须遵守）

1. **只改自己名下的文件**（见第 2 节清单）。清单外的文件一律不碰，需要改动就在交付文档里写 `NEEDS_ROOT`。
2. **不运行构建、不重启服务、不执行真实迁移、不安装依赖**——这些由主会话做。
3. **不新增第二套完成状态/百分比**（宪法原则 X）。"完成"只由真实记录判定。
4. 测试用 `node:test`；**不 mock 内部实现**，纯函数优先，依赖注入隔离外部服务。
5. 交付物：`index.ts` 公共导出（如需）、README 或交付说明、关键行为测试。
6. 交付说明必须**区分**：已完成 / 已验证 / 模拟测试 / 未接入 / `NEEDS_ROOT` / 需要的环境变量名（不含值）。
7. 自己的测试日志放 `.runtime/<slug>-*.log`，不要污染他人文件。

## 2. 分会话任务与文件清单

### S1 · 范围调整（第 4.3 项「做不完怎么砍」）

**动机**：新人在黑客松最常见的处境是"做不完"。全站现在**没有任何地方**教他如何砍范围保交付。本项目已有"最小成果"（`minimumDeliverable`）概念，正好是这件事的支点。

| 项 | 内容 |
| --- | --- |
| 新目录（独占） | `src/modules/scope-cut/` |
| 交付物 | `model.ts`（类型）、`advice.ts`（**纯函数**：输入当前目标/最小成果/剩余时间/任务进度 → 输出可执行建议）、`advice.test.ts`、`README.md` |
| 输入契约 | 只用**只读事实**：`goal`、`minimumDeliverable`、剩余毫秒、任务统计（总数/已完成/阻塞数）、`stage`。不得读取或写入任何模块私有存储 |
| 输出契约 | `{ verdict: "on_track" \| "at_risk" \| "must_cut"; keep: string[]; cut: string[]; sayToTeam: string; notice: string }`。**不产生完成状态、不产生百分比、不替团队做决定** |
| 硬约束 | 建议必须基于传入事实；事实不足时返回 `verdict: "unknown"` 并说明缺什么，**不得编造进度** |
| 不做 | 不改 `HostedEvent`、不改计划与任务、不写库、不做 UI（UI 由主会话装配） |
| 交付说明 | `docs/协作/交付/scope-cut.md` |

### S2 · 倒计时与资源（第 4.2 项）

**动机**：空间的线从"写目标"开始，**没有"还剩多少天/多少钱/多少假"**。选手最需要的是时间压力可见。

| 项 | 内容 |
| --- | --- |
| 新目录（独占） | `src/modules/space-resource/` |
| 交付物 | `model.ts`、`compute.ts`（**纯函数**：由报名截止/开赛/提交截止与"今天"计算倒计时与阶段）、`compute.test.ts`、`README.md` |
| 输入契约 | 截止时间数组（每个含 `instantUtc`、`sourceText`、`verified`）、当前时刻、可选预算与已用额度。**不得读取赛事或报名存储** |
| 输出契约 | `{ next?: { label, at, remainingMs, verified }, overdue: [], phase: "before" \| "during" \| "after", budget?: { total, used, remaining, over } }` |
| 硬约束 | 时区与"最早/最晚"边界按传入的 UTC 时刻计算；**未核实的截止必须带 `verified: false`**，界面文案不得把它说成官方确认；缺数据返回 `null` 而不是 0 |
| 不做 | 不读库、不做 UI、不改既有赛事模块 |
| 交付说明 | `docs/协作/交付/space-resource.md` |

### 6.3 主会话同期修掉的真缺陷

| 缺陷 | 根因 | 修法 |
| --- | --- | --- |
| `dsh-model.test.ts` 4 项稳定失败 | Windows `TEMP` 被规范化成大写（`C:\WINDOWS\TEMP` vs `C:\Windows\Temp`），测试用 `deepEqual` 比原样路径。**同一类问题早前在 `deepseek-harness.test.ts` 修过一次，这个文件漏了** | 按平台归一化后比较（`pathsEqual` 同款做法） |
| `graceful-stop.test.ts` 并发下 2 项失败 + 误导报错 | `waitForFile` 只有 3s 固定预算，而发布前要串行拉起约 10 个 `powershell.exe`（空闲 3.3s、并发 16–18s）；两个游离 Promise 无 handler，测试提前结束后报成"测试结束后仍有异步活动" | 改用真实截止时间（90s）；对 `stopped` 与 `rejection` 先挂空 handler |
| 三个交互"无反应"（用户报告） | **不是代码缺陷**：真实浏览器实测三个交互全部正常（无控制台错误、无未捕获异常）。用户看到的是**缓存的旧页面** | 给页面 HTML 加 `Cache-Control: private, no-store, must-revalidate`，从根上消除这类假故障 |

**验证口径**：真实浏览器（Playwright + 系统 Edge，无需下载）实测——浮动条命中探测 `isAnchorOrChild: true`、`pointerEvents: auto`、`zIndex: 60`；组件箱点击后画布组件 1→2；`Alt`+滚轮后 `transform` 由 `matrix(1,0,0,1,280,24)` 变为 `matrix(1.05,0,0,1.05,280,24)`；`pageerror` 与 `console error` 均为空。
