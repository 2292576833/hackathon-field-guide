## 3. 横切结论

1. **外部环境验收是最大的「仅文档」类缺口**：真实 GitHub 写入、真实邮件到达、可信公网 TLS/DNS、实体手机登录、远程 PostgreSQL 并发、DSH 八客户端真机加载、21 条灵感官网正文——这些都只有登记，没有本次可复跑的证据。它们不影响代码正确性，但**不能当作已验收**。
2. **浏览器层当前没有在执行**：50 个 Playwright spec 与 Playwright 都在，但相关 spec 要求 `ORGANIZER_READY=1` 与 3101 端口隔离服务，本地跑为整组 skipped。
3. **新人「下一步」链路仍断**：规划 27 第 2 期主页主路径未做 + 模块 01 项目级权限端点缺失 + 规划 26/27 阶段不随记录推进，三件事叠加，正好是「新人不知道现在该做什么、也看不到自己缺什么授权」。
4. **两处文档与代码不一致（我已修正其中一处）**：`docs/协作/交付/plan34-root-wiring.md` 原先在 §1 写「通知 Port 未接」、§3 写「只列 2 个助手」，均与代码矛盾，已改为「通知已接」「全部 7 个」；`AGENTS.md` 里 `GUANCHA_LOGIN_ENABLED=false` 与 `.env.local` 实际 `true` 不符（本机已启用）。审阅规划时应以代码为准。
5. **禁止项未被违反**：全仓未发现「匹配度/适配分/推荐分」的真实打分实现，也未发现自动扣分/自动晋级代码；相关命中都在**禁止性注释与校验**里（如 `gap.ts`、`fairness.ts`、`role-help-model.ts` 的正则拒绝）。
