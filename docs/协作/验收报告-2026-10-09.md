# 赛事持续发现、报名建议与独立灵感页验收

记录日期：2026-10-09，北京时间。本机项目：`F:\黑客松情报局`。

## 当前结果

赛事页不再只依赖同一组搜索词。服务启动后即调度 DSH 原生搜索，轮换公开全网、公众号、小红书、微博、B 站、即刻、知乎、抖音和海外社区查询，同时实际读取六个公开目录或主办方入口。新线索仍须经过单场页面获取、DSH 分析、证据校验和持久化才会显示为卡片。

本轮移除公开列表的日期与报名状态门禁：比赛页展示 DSH 已保存的全部赛事分析，卡片单独显示报名未知、已结束、截止时间和开赛时间。生产 API 已实测返回 6 张赛事卡片，`/events` 可直接读取并渲染；预留位置仍不计入真实赛事。DSH 达到每日预算时会暂停新轮次，页面显示最近完成时间与预计下一 UTC 统计日（北京时间 08:00）恢复时间。

历史账本里仍保留严格门禁时期的搜索/获取尝试记录；这些记录不会覆盖当前“保存即展示”的规则。部分来源不可访问或模型结果需要复核时，DSH 仍不会把不确定内容伪造成卡片，后续会在配额和来源访问允许时继续重试。

这是有限覆盖的自动发现，不是已搜遍全网。登录后内容、未被索引的帖子、微信小程序内部数据、验证码及平台访问限制仍会影响结果。

## 来源与排序修复

| 入口 | 实际获取及处理 |
| --- | --- |
| HackerTrip 当月目录 | 实际读取，返回最多 5 个单场 UUID 详情链接；明确为第三方目录，月份随 UTC 日历滚动 |
| 腾讯云黑客松 | 实际读取首页服务端数据，采用已存在的 banner.link、可见名称和未结束日期，不由数字 ID 猜测详情 URL |
| 校园 VC 当前报名区 | 实际读取当前报名区域中的外部单场链接，月清单本身不作为比赛 |
| 新竹政策黑客松 | 实际读取主办方公开页，固定身份仅是线索，不是人工撰写的分析卡片 |
| ETHGlobal、lablab.ai | 继续读取现有公开目录；个别详情访问失败时保留错误并继续其他来源 |

六个入口每轮只读取一个，最多 20 秒、2 MiB、5 个链接；robots、公开 DNS、固定目标 IP、TLS、路径范围和取消检查保持有效。原生结果与补充线索共享每轮最多 3 次详情尝试，不增加额外无界模型调用。

默认八组查询的批次与排名按同组访问次数轮换，修复第 0、8、16 轮总优先同一排名的问题。目录与原生结果交替优先；旧卡最多优先回访一条。hold 和未到重抓时间的 URL 不占详情槽，robots/HTTP 失败及获取后正文未变仍占槽，防止无界抓取。

## 报名、分析与页面体验

- 报名地址只能由本次可见 HTML 或真实原生引用中的明确链接提取，DSH 精确选择完整候选；支持简体、繁体与英文报名文字。缺少可靠链接时保留原文入口。
- 参赛建议分为值得了解、先核对再决定、信息不足，说明适合人群、限制、准备项和未知项，不保证资格或生成匹配百分比。
- 卡片保留真实出处及未人工核验状态。旧 AMD 卡片存在未解决模型标记，继续保留旧分析及字段缺失提示，未清除标记或自动重发。
- 比赛页每 3 秒可见读取只读元数据，只有保存版本变化才读取卡片；后台搜索不依赖浏览器打开。预留位置明确标示等待，数量不计入真实赛事。
- 灵感页补齐全站导航、统一容器、初次导航说明和聊天入口；正常组件演示中的密码字段不会直接当成实际登录墙。
- 灵感正在运行时优先显示分析状态，不因当前调用已预留额度而误报剩余额度不足。页面每 10 秒可见读取已保存快照，隐藏时停止轮询。

## DSH 与灵感真实记录

Desktop 与 API 适配共同接受一个完整 JSON 对象或唯一完整外层 JSON 围栏。混杂文字、多个对象、截断、token 上限、中断和无有效用量继续拒绝；不补造或截取模型答案。最新消息必须具有自己的完成状态，不能借用前一条消息的完成标志。

实际失败原文未被读取或保存，因此不能认定旧失败必然由围栏造成。格式错误仅附固定分类与原文 UTF-8 字节数，既有未知付费标记不被重启、提示升级、轮换或跨日清除。

03:25 的公开快照显示灵感已保存 9 个实际 DSH 分析、12 个等待条目，共 21 个官网身份。已分析站点包括 21st.dev、Aceternity UI、Ant Design、Awwwards、daisyUI、Httpster、Magic UI、Material UI、Radix UI。等待条目仅显示名称、分类和真实官网链接，编辑 seed 正文不充当 DSH 结果。

服务器仍运行时数量可以继续变化。未读取成功的官网不冒充已分析；拒绝访问、内容不足和已知获取错误按调度处理，未知模型调用继续 hold。

## SakuraFrp 部署

生产服务以 `0.0.0.0:3000` 监听，SakuraFrp 隧道 `hackathon_guide` 已启动并转发到本机 3000。HTTPS 入口已实测返回 200：<https://frp-off.com:44353/events>；同一公网入口的赛事 API 实测返回 6 张卡片，带公网 Origin 的登录挑战返回 200。该节点使用自动 HTTPS 生成自签证书，首次访问可能显示浏览器证书提示；确认继续后即可使用。明文 HTTP 会被节点合规策略拦截为 501，因此对外只公布 HTTPS 地址。

当前 `.env.local` 仍是 local 预览模式，验证码只写入部署主机的开发邮箱，公网 `/api/v1/dev/mailbox` 保持 404，避免把验证码公开给任何访客。手机要完成真实邮箱登录，还需切换 connected 模式并配置 PostgreSQL、已验证发件人和 Resend；登录页已明确提示这一点。

集成测试跳过的是需要实际外部环境的远程 PostgreSQL 并发与 Desktop 兼容检查；浏览器跳过的是可选真实 AI 测试。测试夹具不代表这些外部环境已验收。`/github` 页面在桌面与手机宽度完成主分支、工作分支、拉取、提交、PR、冲突恢复图解检查，手机无横向滚动；官方注册、Clone、Pull Request 链接均在新窗口打开。

本轮没有使用额外外部托管服务，不采购服务、不提高原有费用上限、不输出凭据、不绕过访问验证；网站已按用户要求通过 SakuraFrp 隧道上线。真实操作期间先停止网站、确认 3000 无监听，再单独打开 PGlite；操作结束关闭数据库后重启网站，未并发打开同一嵌入式目录。

## 运行方式

`npm run dev` / `npm run start` 由服务 wrapper 和 Node instrumentation 初始化单例后台任务。发现与灵感任务每 10 秒检查各自账本；赛事最短 5 分钟一轮，灵感最短每分钟一站，成功灵感内容每 24 小时重抓。连接部署可用独立 PostgreSQL worker，并设置 `FIELD_GUIDE_EMBEDDED_WORKERS=0`。

本机事件上限仍为每日 48 次搜索、搜索与分析合计 120 次模型及 1 USD；灵感独立上限为每日 24 次模型及 0.10 USD。账本按 UTC 配额日处理。达到次数或费用预留条件会等待下一配额日，不能承诺全天每五分钟都成功搜索或每次都新增赛事。
