## 3. 同期修掉的真实产品缺陷：护航面板失败提示会被吞掉

**现象**：`src/modules/team-supervision/ui.test.ts` 稳定失败（`getByRole("alert")` 超时）。

**根因（经插桩取证，非推断）**：组件里写的是

```ts
if (reason instanceof SupervisionApiError && [401,403,404].includes(reason.status))
```

`SupervisionApiError` 来自**被注入的模块**。该测试夹具把 `./client.ts` 整个替换成桩，只导出了 `createSupervisionApiClient`，**没有导出 `SupervisionApiError`**，于是执行 `reason instanceof undefined` 抛
`Right side of 'instanceof' is not an object`（页面错误实测捕获到），**catch 在 `setError` 之前中断**——失败提示永远不会出现。

这既是**测试夹具的缺口**（漏导出真实错误类），也是**产品代码的脆弱点**（`instanceof` 依赖注入模块的导出，对方一变就静默吞掉错误提示）。

**修法（两侧都修）**：
1. 组件：先断言类可用再比较 —— `const status = typeof SupervisionApiError === "function" && reason instanceof SupervisionApiError ? reason.status : 0;`
2. 夹具：桩里补上真实的 `SupervisionApiError` 类。

**防回归**：新增 `src/modules/team-supervision/panel-failure.test.ts`，真浏览器锁定两条语义——
普通错误**必须**显示 `role="alert"`；`401/403/404` **必须**清空面板（保留原有"权限变化即重置"语义，不被防御性改写破坏）。三项状态均 `pageerrors=[]`。

## 4. 过程中我自己犯的错误（记录以免再犯）

| 错误 | 说明 |
| --- | --- |
| 编造了不存在的接口路径 | 用 `/api/v1/auth/guancha/start` 测试，真实路径是 `begin`；404 是我测错，不是功能缺失 |
| 给 POST 传了错误 Origin | 本站是**单源**校验（非 GET 必须 `Origin === AUTH_ORIGIN`），传 loopback 得到 403 `ORIGIN_FORBIDDEN`；改用公网 Origin 才拿到真正的 503 业务响应 |
| 用服务端 HTML 判断客户端渲染内容 | 登录页入口由客户端取状态后渲染，`/login` 的 HTML 里本来就没有「观猹」；应看公开接口或真实浏览器 |
| 最初的根因假设是错的 | 我先把缺陷归因于 effect 依赖里的 `client` 对象每次重建，改完仍然失败；插桩后才拿到真因（`instanceof`） |
| 新增测试里连犯三个夹具错误 | 路径层数写错（`../../../node_modules/react-dom/…`）、`new exports.SupervisionApiError` 在顶层作用域（`exports` 不存在）、模板字符串里写了反引号把模板提前终止 |
