## 一、一句话定位

**陪第一次参赛的人，把一场黑客松走完。**

备选：
- 从第一次参赛，到第一次交付。
- 不是替你参赛，是让你知道下一步该做什么。
- 黑客松新人的参赛手册：找比赛、分任务、留时间、交作品。

---

## 二、初衷（为什么做这个）

**顺口版**

AI 让做原型变简单了，可第一次参赛的人，卡住的地方往往不是写代码：

不知道什么比赛适合自己，看不懂规则里到底要交什么，
不知道该负责哪一块，也不确定队友在做什么、还剩多少时间，
最后好不容易做出来，却不知道该怎么交出去。

我们见过太多次，作品其实做出来了，只是没交成。
所以我们做了这个网站——**不是再生成一堆 AI 文字，而是把"我不知道接下来做什么"，变成一件可以动手做的事。**

**完整版**

起因是一个很具体的观察：随着 AI 工具让制作原型变得容易，一批技术基础薄弱、没有协作经验的新人开始参赛。他们能借助 AI 做出部分内容，却卡在三件事上——**不知道自己该承担什么，不知道怎么和队友配合，也不知道怎么把作品整理并提交出去。**

我们想解决的不是"想法不够多"，而是流程不清楚。所以这个产品从第一天起就有一个明确的自我约束：

> 核心价值不是产生更多 AI 文本，而是把"我不知道接下来做什么"变成可执行的动作：知道必交什么、由谁负责、何时完成、卡住时怎样删减，以及最后是否真的提交成功。

品牌叫"情报局"，取自"有人把复杂的东西替你整理清楚"这件事。视觉上是一本**可以操作的参赛手册**：暖白＋橙红，编辑部式排版。三个关键词——**清楚、踏实、有活力**。

一条我们刻意守住的分寸：**面向新人不等于把界面做成儿童游戏**。不做战力分，不做闪烁警报，不做倒计时制造焦虑。

## 三、受众群体（我们说给谁听）

首批**不限定人群**——不限定高校、不限定成年、不限定技术基础，覆盖所有黑客松新人。
并写明一条：**年龄不用于推断能力。**

| 说给谁 | 他现在的处境 | 我们能帮上的 |
| --- | --- | --- |
| **第一次参赛的个人** | 不会读规则，不知道作品做到什么程度算够 | 看清必交材料，从一个能演示的最小作品开始排 |
| **二至五人的新人小队** | 不清楚彼此擅长什么，时间还互相撞 | 各自选职责，写清谁做什么、什么时候交 |
| **非技术成员** | 不知道自己能贡献什么，常被"技术岗"漏掉 | 需求、视觉、测试、文档、路演都是明确交付物 |
| **有经验的队长** | 反复讲 GitHub，反复追问进度 | 一个项目里看得到状态、版本和提交记录 |
| **还没找到队友的人** | 想参赛但组不起队 | 公开名片按想做什么、能投入多少时间找人 |
| **正在准备下一场的人** | 上次的经验没沉淀，又要从头来 | 作品和经验都留下，下一场接着用 |

**先说给谁听（对外主推的两个场景）**
1. 第一次参赛、还没决定做什么的人 → 入口：找比赛 + 参赛路线图
2. 已经组了队、正在赶进度的人 → 入口：我的参赛（团队空间）

## 四、定位（我们是什么，不是什么）

**我们是什么**

一个带登录的参赛网站。**一个参赛项目 = 一个团队空间**，把这一场比赛的要求、成员、任务、交付记录放在一起。公开部分不用登录就能看。

**我们不是什么**（写下来是为了不自我膨胀）

| 不是 | 因为 |
| --- | --- |
| 不是赛事导航站或链接合集 | 只堆链接很容易被替代，价值来自"选完能接着用" |
| 不是通用 AI 问答 | 单次生成一份分析、分工或时间表，任何 AI 工具都能做 |
| 不是在线 IDE | 本地环境故障、复杂调试、复杂 Git 冲突，网页不保证能解决 |
| 不是招募平台 | 组队只解决"已经想参赛的人怎么找到彼此" |
| 不是能力测评机构 | 我们不给真实能力百分比，不做排名 |

**我们的差异在哪**

价值来自**持续保存上下文、跟踪执行、验证交付**，而不是一次生成。
围绕同一场比赛保留要求、分工、进度与交付记录，才可能形成复用价值。

## 五、解决办法（我们怎么帮）

四个核心能力，共享同一个参赛项目——**不是四个孤立的工具**：

```
找比赛 → 理解要求 → 创建参赛项目 → 邀请队友（或找队友）
→ 自选职责或用 AI 建议分工 → 确认时间与依赖
→ 执行、交接、检查 → 保存成果并核对正式提交 → 复盘沉淀
```

**1｜先找一场合适的比赛**
看 AI 整理的分析、必交材料、资格与各轮截止，关键条件都附来源与核验时间，再打开主办方原文核对。
（写着"还没读到全文"的线索，就是还没读到，不会假装已经确认。）

**2｜约好谁做什么、什么时候完成**
邀请队友进同一个空间，每人选自己愿意负责的部分和能投入的时间；不确定就用"我不确定，请 AI 帮我判断"。分工确认后才进入排期，之后谁都能看到最新进度。

**3｜把时间排到真的做得完**
从截止时间倒排，算进学习、排错、休息、集成、测试和提交缓冲。任务分"必须完成"和"有时间再做"。
**如果容量不够，我们会直说"这样排不完"，并建议砍掉哪些**——而不是给一张看起来完整、实际做不到的表。

**4｜把作品交出去，并且知道交没交成**
保存代码、确认作品能否演示、记录向主办方的正式提交——**这三件事我们分开显示，绝不混在一起。**

**贯穿全程的一条路线图**
`/journey` 把赛前、赛中、赛后拆成一棵树：每个行动说明**什么时候做、怎么做、怎么核对、下一步去哪**。不用登录就能看。

**顺手能用的资料**
工具、找灵感、AI 技能（按你在用的 AI 工具分类）、新手教程、GitHub 教程、路演与 PPT——都在对应任务旁边，**收藏后能接回项目继续用**，不只是逛一逛。

## 六、我们不会做什么（信任条款）

这一段建议在首页或介绍页保留。它是我们敢让新人用的理由。

**① 事实、建议、未知，永远分开。**
规则里写明的、我们建议的、还没确认的，分区显示。

- 「AI 使用规则未说明」不会改写成「允许 AI」
- 不会输出无法解释的可靠性总分
- 不会说某场比赛「内定」或「奖金不会兑现」

**② 不制造虚假成功。**
已登录 ≠ 已授权仓库；保存成功 ≠ 代码能跑；命令已复制 ≠ 技能装好了；仓库链接 ≠ 平台已接收提交。

**③ 外部服务出问题，你还能继续。**
模型、邮箱、GitHub 任一环节不可用，已保存的项目、任务和草稿都还在，手动路径继续走。**比赛有截止时间，不能因为服务故障让你丢掉进度。**

**④ 你的私人内容默认是你自己的。**
原始测评、私人笔记、个人收藏默认仅本人可见；团队身份不会放大仓库权限；网站账号不等于仓库权限。

**⑤ 决定权在你。**
AI 只做建议，计划、分工、提交都要人来确认才生效。

## 七、可直接使用的版面文案

### 7.1 首页 Hero（替换建议）

- 眉标：`HACKATHON FIELD GUIDE / 试用版`
- 主标题：**第一次参加黑客松，也能一步步完成作品。**
- 副标题：看懂比赛、分好任务、留出时间。让每个人都知道下一步该做什么。
- 主动作：**先找一场比赛** → `/events`
- 次动作：**看完整参赛路线图** → `/journey`
- 一句话说明：面向所有黑客松新人 · 从一个可完成的最小作品开始

### 7.2 三个入口卡片

| 编号 | 标题 | 说明 |
| --- | --- | --- |
| 01 / 找比赛 | 了解比赛，再决定参加 | 看 AI 整理的分析、报名入口和注意事项，关键条件以主办方说明为准 |
| 02 / 我的参赛 | 开始准备，和队友一起做 | 创建项目、邀请队友，确定分工与任务时间 |
| 03 / 工具与资料 | 找工具、灵感和入门教程 | 从开发工具、设计案例到 AI 技能，按当前需要找，收藏后继续用 |

### 7.3 结尾区

> **作品留下来，经验也留下来。**
> 保存代码，检查作品能否演示，再记录向主办方的提交结果。赛后留下做得好的和需要改进的地方——下一次，从上次停下的地方开始。

### 7.4 邀请队友页

> **先了解对方想做什么、能投入多少时间，再申请加入团队空间。每份名片由本人确认公开。**

### 7.5 页脚

> 陪你从第一次参赛到完成作品。比赛要求请以主办方最新说明为准，AI 建议由你和队友确认后使用。

| 不要写 | 因为 |

## 十、尚在验证中的事（对外沟通要诚实）

如果对方追问"好不好用""有没有人用"，按实际回答：

- 第一版目标是**少量真实参赛队伍完整试用**，覆盖所有新人。
- 本机已可访问，公开页面（找比赛、路线图、工具与资料）不用登录即可看。
- **公网 HTTPS 目前使用自签证书，浏览器会提示不受信任**，正式对外前需换成受信任证书。
- GitHub 真实授权与写入**暂未验收**（按用户要求暂缓），当前提供官方手动路径指引。
- 真实新人队伍的完整试用、实体手机登录、客户端技能加载效果，均**尚待目标环境验证**。

即：**不把"代码写完了"说成"验证通过了"。**
