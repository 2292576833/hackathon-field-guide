# 后端 DSH、自动发现与新人导航

版本：实施说明 v1.3 · 2026-10-09。对应宪法：v1.3.2 草案。
本文记录已经组合的代码路径、产品边界和目标环境验证要求。本机 `.env.local` 已选择 Desktop DSH，项目 AI 与导航员真实调用已验证；用户没有 Brave key，现启用官方 DSH 原生搜索；官方列表仍可单独配置。实际抓取、模型与卡片验证分别记录，配置不等于联网成功。操作步骤以 [后端部署](../部署/后端部署.md) 为准，当前报名筛选验证见 [验收报告](../协作/验收报告-2026-10-09.md)。

## 1. 用户会看到什么

| 入口 | 用途 | 来源与状态 |

| `/library` 新人资料馆 | 认识黑客松、网站、GitHub 分支协作及交付步骤 | 本站原创中文说明；外部链接只作参考，不复制第三方完整文章 |

网页刷新只读取已保存的数据。发现流定时刷新不代表每次访问都会向搜索或模型供应商发起付费调用。

用户已明确公开网站只显示赛事分析与跳转链接：比赛页以分析卡片为主，官网按钮在新窗口打开；依据默认折叠。采集配置和运行控制留在管理员后台，公开页面不要求用户操作搜索、审核或模型任务。卡片有游标分页，二十四张以上仍可继续查看。

## 2. DSH 在后端怎样工作

本机直接使用 `D:\dddsss` 中 Desktop `0.2.0-rc.2` 的 SDK，独立子进程只取得官方 DeepSeek 账号 grant。API key/容器方式固定官方 `@deepseek-ai/dsh@0.2.1-alpha.1`，由 `scripts/install-dsh.mts` 安装和核验运行包；使用精确版本、官方 registry 来源、tarball integrity 与运行 receipt，不用浮动 `latest`。这是服务器运行依赖，不是参赛者需要自己安装的插件。

分析由 `deepseek-harness.ts` 启动独立子进程，每次使用新的工作目录、受控 HOME 和无工具 JSON profile；原生搜索由 `src/server/dsh-search-runtime.ts` 单独组合本机官方 Web/account/credentials 运行包，只准一次固定官方端点的原生搜索请求。两种子进程均不继承应用数据库、Brave、代理、邮件、GitHub、个人插件或 `NODE_OPTIONS`。原生搜索不是允许分析模型自行执行网页脚本或任意命令。

父进程限制输入/输出、实际模型用量与调用时限；超时或取消时结束这次子进程。进程隔离有明确凭据和配置边界，不能等同于虚拟机级沙箱。`--check` 核验安装身份，不代表已经调用真实模型。

## 3. 持续搜索与分析流程

```text
常驻 worker 检查周期、暂停、租约与每日预算
  → 按配置调用 DSH 原生搜索、限定官方列表或 Brave
  → URL 规范化、去重、排除登录/凭据链接
  → robots + 公开 DNS/IP + HTTPS/重定向/体积/时限检查
  → 获取有限正文，不执行脚本
  → 全文不可得时，仅在原生工具提供真实 cited_text 时采用标明来源类型的公开摘录
  → 内容哈希与重抓间隔检查
  → 固定版本 DSH 判断是否为具体赛事并生成 JSON 分析
  → 校验结构与原文摘录，复核调度租约和暂停状态
  → 保存未核验卡片及版本，用户仍需核对主办方规则
```

`DISCOVERY_PROVIDER=official_sources` 检查服务端固定 catalogue 中的 ETHGlobal 与 lablab.ai；从近期区域和赛事状态提取单场链接，排除历史比赛、会议、登录和任意外链。此模式无需 Brave key、没有搜索 API 费用；DSH 模型仍按用量估算并限额。名单仅覆盖这些官网，结构发生变化时留下错误供人工修正规则。

`DISCOVERY_PROVIDER=brave` 使用独立搜索服务，有单独账号、API key 和费用。DSH 负责判断与分析有限来源文字，搜索、网页获取和调度由可信父进程控制。未配置有效发现入口与 DSH 时，不产生虚构结果。

`DISCOVERY_PROVIDER=dsh_native` 是本机当前入口。通过 `D:\dddsss` 安装的 `0.2.0-rc.2` 官方 `deepseek-official` provider 调用 DeepSeek 原生联网搜索，使用隔离的现有 DeepSeek 账号授权，无需 Brave key。搜索模型独立设为官方 `deepseek-v4-flash` 别名，`maxTokens=2048`、`maxUses=1`，一次固定 `https://api.deepseek.com/anthropic/v1/messages` 请求；只采纳官方工具的结构化 URL/title 和真实引用，不从生成回答中抽取链接或编造摘要。[官方原生搜索说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-search-deepseek/README.md)。

默认两组查询涵盖当前及未来两个月的公众号/小程序公开公告、微博、小红书、即刻和 B 站线索，交错选择两组结果。公开索引不等于直接登录平台，也没有读取微信小程序内部数据。登录墙、robots 禁止或无法读取全文时，只有官方结构化结果确实含 `cited_text` 才能分析摘录，保存 `sourceKind=indexed_excerpt` 并固定添加完整规则未读取的未知项。搜索没有给出引用时不会拿标题或生成回答代替正文。本轮宽泛探针和正式周期均未证明小红书/微信内部数据可读。

未自定义 `DISCOVERY_QUERIES_JSON` 时，原生搜索在每轮读取当前及后两个月的时间窗口，服务跨月无需重启。手工配置的查询不自动改写。此调整不清除原查询的未知请求标记，也不重置全站预算。

目前每轮按查询获取有限结果，抓取与模型次数有上限；没有遍历 Brave 所有搜索结果页的保证。卡片列表 API `GET /api/v1/event-discoveries` 支持 `limit`、`query`、`cursor` 游标分页，返回 `{items,nextCursor}`；这也不代表搜索覆盖完整。

代码默认发现间隔和赛事详情重抓间隔均为 5 分钟；本机原生模式每轮最多分析三场，每天搜索上限 144 次、搜索与分析共同的模型调用上限 360 次、费用上限保持 1 USD。正文哈希不变时不重复模型调用；报名与参赛建议的结构版本升级会重分析旧成功结果，未知请求 hold 不因此清除。原生搜索按完整上下文窗口及 maxUses 保守预留，返回合法 token 用量后按已配置 peak Flash 单价结算估算；usage 缺失但结果有效时保留完整预留，不能按免费处理。预算是最高限额，并不保证达到所有次数。每轮一个查询词，因此 144 次搜索至多约 144 轮；最短间隔不意味着全天每 5 分钟收费搜索。暂停、忙碌、未到期或达到限额均可跳过，常驻运行不保证全网完整、永不中断或所有比赛实时更新。

搜索索引、地区/语言和查询词、robots、登录墙、网络、网页格式、限额与比赛更新都影响覆盖。自动发现摘要可能遗漏资格、费用、时区或材料，应以原始官方来源和人工确认版本为准。

## 4. 发现线索与正规审核分别处理

`src/server/discovery.ts` 管理发现卡片、原始来源摘要、内容哈希和版本；发布给用户的卡片仍保持 `verificationStatus: 'unverified'`。DSH 必须返回来自本次正文的摘录；结构无效、摘录无法匹配、页面无内容或不是具体赛事时，不能生成合格卡片。

公开发现会把 DSH 已保存的赛事分析全部放入比赛页，报名状态、报名截止和开赛日期作为独立字段展示。`registrationWindow` 保存 `status/closesAt/closesOn/evidence/checkedAt`，仅接受本场真实报名或参赛申请的截止与状态证据；赛事开始/结束及作品提交截止不能代替报名截止。`eventWindow` 保存本场开赛日期和来源证据，但不再参与公开列表过滤。日期仍按服务器时钟规范化，未知、已结束或时区不明的状态必须在卡片中明确标注，历史与项目快照保留。

公开 list、get 与 live 元数据共用活动状态谓词，但不再按截止或开赛时间移出卡片；到期、未知和关闭状态由卡片标签提示。可信 DSH 复查读到状态变化时，只更新已有卡片的窗口与证据版本，不伪造报名入口；提交受原有账本租约保护。旧版本与项目已保存快照保留，未知请求 hold 不变。没有结果时说明后台尚未保存分析，不能用预留位置冒充赛事。

报名链接不由模型猜测。可信父进程从实际可见 HTML，或真实引用文字中明确写出的报名地址，提取有限候选与证据；排除账号登录、跳转、短链及敏感参数。DSH 只允许完整选择某一候选的 `url/sourceUrl/evidence`。没有有效候选时保存 `registration:null`，卡片提示从原文确认入口；有入口也不代表本站已确认报名仍开放或用户符合资格。

`participation` 保存 `consider`、`caution`、`insufficient_info` 三种条件性建议及理由、适合条件和需谨慎的情况，页面分别显示“值得了解”“先核对再决定”“信息不足，暂无法判断”。建议来自当前公开证据，不掌握访问者全部技能、位置与资格，不能给匹配百分比或保证参赛。旧卡片没有这些字段时保留已有 DSH 分析并提示信息不完整；不能在前端补造一个判断。分析结构版本 `discovery-registration-participation-v2` 纳入内容身份，后续合格周期可重新分析旧成功结果。

M08 来源配置是另一条受管理员控制的流程：批准来源范围 → 排队采集/分析 → 校验并保存 M03 候选 → 人工审核 → 明确发布。模型没有发布权限。发现卡片不会直接写成已核验 M03 规则，不把网页标题中的“官方”当作本站人工核验。

参赛项目确认规则、使用截止时间和必交要求时，沿用 M03 规则版本与证据流程；任务和正式提交仍需按团队确认结果执行。

项目“比赛要求”页新增赛事线索草案：从自动发现列表搜索、分页、选择并预览完整分析，记录队伍备赛备注，再明确保存。`GET/POST/DELETE /api/v1/projects/:projectId/discovery-draft` 由 root 组合服务管理，真实卡片内容只由服务器读取；客户端只提交发现 ID、分析 revision、草案预期 revision 与备注。保存快照保留未核验状态、来源和版本，更新与清除留不可变历史；清除保留 revision 墓碑，阻止旧页面覆盖。只有当前项目管理员可写，成员可读、归档只读；账号、请求会话和项目成员在同一事务受保护。来源更新或不可用时，重新读取草案会提示核对，不能静默覆盖原内容。此路径不会生成已发布赛事、M03 正式规则确认或自动修改项目截止。

公开比赛页最新页至少 24 个位置，桌面三列、平板两列、手机一列；不足部分明确显示“等待新赛事分析”，手机多余空位折叠，每页最多 60 条真实卡片并可继续分页。分析结果数量单独显示，24 个位置不能描述成 24 场已发现赛事。卡片展示数量不改变现有搜索周期、单轮分析上限、费用或未知请求 hold。

## 5. AI、导航与预算

| 能力 | 实际模型路径 | 预算与确认 |
| --- | --- | --- |
| 规则建议、测评、分工、计划、复盘 | `AI_PROVIDER=dsh` 的后端 DSH，或通用 `AI_*` JSON 适配与队列 | 项目调用/费用与中央执行租约；建议保存为草案，由用户核对采用 |
| 全站自由聊天 | `createDshWebsiteChat` 固定调用后端官方 DSH 子进程，独立于项目任务供应商设置 | 当前项目或本人导航 scope 的独立调用/费用范围；登录与项目权限前后复核 |
| 已批准来源的提取/分析 | DSH + 来源 worker + `source-budget.ts` | 每来源独立预算；当前管理员、来源配置、run attempt/token 和租约前后复核 |
| 全站自动发现 | DSH 原生搜索、官方来源或 Brave + DSH + 发现 worker | 全站发现调度和独立来源检查/搜索、模型、费用预留，保存前再核对当前租约 |
| 灵感官网说明 | 固定官网候选 + 有界公开获取 + DSH + 灵感 worker | 独立 `inspiration-catalog` 账本、UTC 日调用与 USD 预算，保持未人工核验 |

原生搜索也属于全站发现账本。迁移 `018_native_discovery_search.sql` 保存每个真实请求标识的预发送标记和明确首次激活审计。标识不包含返回结果条数；请求未知时，跨日、重启或调整结果数量都不能自动再次发出同一请求。只有明确 `not_sent` 才退调用/费用预留。结构结果已收到但 usage 缺失，按完整费用预留结算，下一已到期周期可正常进行。模型对具体页面仍保留独立的未知结果 hold。

`AI_PROVIDER=dsh` 将项目服务和中央队列显式选择为 DSH，不需要伪造通用 API key。本机已采用此路径。真实模型 token 用量与配置的 USD 费率用于估算费用，预算预留不等同于供应商最终账单；不得把未知价格写成免费。

当前来源预算默认每来源每天 20 次、2 USD，可在实际计费依据下调整。每个来源 run 的同一次 attempt 只能进入一次模型执行；此前付费请求仍在运行、结果未知或存在未结算预留时，reclaim 增加 attempt 不能授权再次派发。未知结果保守结算；确需重新收费由管理员明确创建新的 run，并保留记录。

初次导航介绍可跳过、重放，版本化“已看过”偏好仅保存在浏览器本地，公开说明不发起模型调用。所有自由聊天由全站一个入口处理，固定返回 `provider:dsh`，可讨论备赛、协作、计划、GitHub、技术调试与网站操作；不强制把每个问题转成导航建议。DSH 未配置、运行失败或返回无效内容时显示错误，没有其他模型或静态答案降级。

真实提问需登录，发送消息、最近对话、页面路径和可选项目 ID；服务端只读取当前有权限的项目名称、阶段、目标摘要，并在交付回复前复核会话、账号和权限。不能声称读取未提供的完整规则、代码、测评、任务或复盘。导航没有仓库、安装或审核执行权。用户消息最多 2000 字符，AI 回复及历史最多 6000 字符；发送最近十条，历史总量最多 32 KiB，超出时从最旧的完整消息开始移除。当前对话存在页面内存，尚无跨刷新保存。

聊天框显式显示 DeepSeek Harness 来源、发送后的用户气泡与等待状态；成功后清空输入，失败保留问题供用户处理。前端拒绝非 `dsh` 的回复来源。每次输出最多 1500 token 或更小的 DSH 配置值，无自动重复付费请求。

## 6. 独立灵感页与 DSH 官网分析

用户已确认赛事和灵感卡片都由 DSH 更新。导航、首页和工具库分别提供 `/inspiration` 入口；`/resources` 继续承载 M09 审核资源、个人收藏和项目共享，页面拆分不会删除已审核资料。灵感页按视觉参考、网页案例、组件代码、动效四类组织，支持 `q/category` URL 筛选、刷新后恢复、空结果清除及官网新窗口跳转。

`inspiration-catalog.ts` 的 21 个已核查官网仅固定站点身份、分类、原始链接和获取依据。生产正文 `description/useWhen/usageNote` 必须由 DSH 分析本次真实取得的官网文本生成；编辑 seed 的手写说明不能当作完成的 DSH 结果。正文尚未生成时，公开卡片只展示真实名称、官网链接和“等待 DSH 分析”。候选数不等于完成分析数，不宣称已取得素材、字体或代码复用许可。

可信父进程按固定官网范围校验公开 DNS/IP、TLS、robots、重定向、体积与超时，读取有限正文，不执行网页脚本。DSH 使用无工具子进程，只生成说明与本次正文中的准确摘录；服务器校验摘录、固定身份、保存实际 `checkedAt` 分析时间及取得内容的官网依据地址。不可访问或证据无效时保持等待/失败状态，不用标题、搜索生成回答或旧编辑说明补成成功。

迁移 `020_inspiration_catalog.sql` 新增持久化卡片与不可变版本，并支持 `inspiration` worker 心跳。`src/server/inspiration-worker.ts` 复用发现账本机制，以独立 `inspiration-catalog` 调度 ID 在同一后台任务组运行：每 10 秒检查，最短每分钟处理一个到期官网，同站默认 24 小时重抓。内容与提示版本未变时不重复模型调用；已发送请求结果未知时持久 hold，重启、跨日和刷新不能绕过。当前本机独立上限为 24 次模型调用及 0.10 USD / UTC 日，实际可用次数仍受费用预留、网络、暂停与未知结果限制。这不是全网灵感搜索，也不保证一分钟产生一张有效说明。

`INSPIRATION_ENABLED=true` 需要有效的 DSH、模型与费率；其余配置使用 `INSPIRATION_MINIMUM_INTERVAL_MS`、`INSPIRATION_RECRAWL_AFTER_MS`、`INSPIRATION_DAILY_MODEL_CALL_LIMIT`、`INSPIRATION_DAILY_BUDGET_MICRO_USD` 等独立字段。不会使用赛事剩余额度代替灵感额度，也不会从公开 GET 发起付费模型任务。

`GET /api/v1/inspiration` 返回已保存 `items`、未完成的 `pendingItems` 与安全状态说明，合并并缓存一秒。网页可见时每 10 秒只读刷新，隐藏停止请求；读取有 10 秒超时，断线保留已读取内容。管理员通过 `/api/v1/admin/inspiration/status` 读取独立调度账本，以 `expectedRevision` 和 `paused` 调用 `/api/v1/admin/inspiration/paused`；写入复核当前管理员身份并保留审计。暂停、费用不足和获取失败不能显示为分析成功。

上述是本次实现的契约与运行策略。最终集成、真实官网读取/DSH 调用及管理员可视化验收仍由主会话完成并补充证据；本文不宣称 21 个候选均已分析。

## 8. 配置、运行和真实验收

环境变量名及完整命令见 [.env.example](../../.env.example) 与 [后端部署](../部署/后端部署.md)，不得将密钥放入前端或 `NEXT_PUBLIC_*`。本机开发使用持久化 PGlite 和邮件预览；独立 `npm run worker` 要求实际 `DATABASE_URL`，不能与网站进程同时打开嵌入式目录。连接模式由迁移、网站与常驻 worker 共享真实 PostgreSQL。

`GET /api/v1/system/status` 区分通用模型、GitHub、DSH 和发现服务配置。管理员可以读取 `/api/v1/admin/workers` 心跳和 `/api/v1/admin/discovery/status`、`/api/v1/admin/inspiration/status` 的独立频率/预算/错误，通过各自带预期 revision 的暂停入口控制。已配置只说明必要配置存在，不保证密钥有效、worker 健康或供应商可达。

网站启动时通过 Node instrumentation 初始化后台任务，不再依赖首次 API 调用。`npm run dev/start` 自动设置仅服务进程使用的标志；构建不会启动后台任务。后台发现每 10 秒检查一次持久化调度，本机最短搜索间隔为 5 分钟；长轮次串行运行，不叠加搜索。既有调用和费用上限、暂停及未知请求 hold 均保留。达到每日额度时停止收费，到下一配额日继续检查；未知请求不会因跨日自动重发。

公开只读 `GET /api/v1/event-discoveries/live` 返回卡片版本标记、数量、脱敏运行状态、间隔与时间。服务端把并发读取合并并缓存一秒，读取此接口不创建调度、不改账本、不调用搜索或模型。版本包含有效卡片 ID、revision 与分析时间，新增、更新和撤回均可检测。比赛页可见时每 3 秒检查，变化后自动加载；隐藏停止，恢复立即同步。历史分页保留位置并提示新结果。状态不能把“等待到期”写成“正在搜索”，也不能把上轮结束时间写成成功分析时间。

目标环境应验证：固定 DSH 包身份与真实模型返回、Brave 搜索及可访问来源、robots/超时/费用与暂停行为、后台持续运行、真实邮件、GitHub 授权/仓库写入及未知结果核对、每种实际客户端的技能加载与样例输出，以及容器健康、数据库备份恢复。代码、隔离服务测试、本机网页验证、真实第三方和容器验收分别记录，不能互相替代。

## 10. 避免发现结果长期重复

默认 DSH 原生搜索按持久化搜索计数轮换八组、每组两条查询：全网公开赛事与国际报名；公众号；小红书/微博；B 站/即刻；知乎/抖音；ETHGlobal/lablab.ai；Devpost/中文开发者；X/LinkedIn/Reddit/Luma。日期随年份、月份滚动，不把所有平台塞进同一个查询；自定义查询不自动替换。轮换、重启和改数量不能清除旧未知请求标记，原有每日次数和费用上限保持。

默认八组查询的结果排序按“同组第几次访问”轮换，避免第 0、8、16 轮总取同一排名；自定义固定查询保持逐轮排序。目录和原生结果交替优先，使剩余槽位双方都有机会。robots、获取拒绝及已获取但正文未变仍占本轮详情尝试，最多三次；hold 和未到重抓时间的链接在获取前跳过，不占尝试槽位。

原生搜索每轮另外轮流读取六个已成功获取的公开入口：HackerTrip 当月目录、腾讯云黑客松、校园 VC 的当前报名区、新竹政策黑客松主办方页、ETHGlobal、lablab.ai。最多 20 秒、2 MiB、五个单场链接；目录仅提供真实 URL/标题提示和获取记录，必须重新获取单场证据并由 DSH 分析。第三方目录明确保留身份，不能冒充官方公告，合集页不作为赛事卡片。最多一个最旧的已保存赛事优先回访，其余原生结果和目录线索交错，共用原来最多三页/轮的抓取与模型预算，不能增加无界模型尝试。相同 URL 去重，旧卡片摘要不冒充新证据；真实原生引用可补充同 URL 的搜索依据。访问失败的目录返回空补充，其余发现继续。

灵感目录中的正常组件示例不应因为含密码输入框而被当作登录墙；明确登录要求、验证码与拒绝访问仍停止。已知获取失败在五分钟后可以再次检查，成功内容仍按一天重抓；未知模型调用始终需要人工恢复，不能通过来源重试间隔绕过。

DSH 结构化结果必须来自已完成的最新消息。仅兼容一个完整 JSON 对象或它的完整外层 JSON 代码围栏；截断、混杂说明、多个对象、token 上限、中断及无有效用量继续拒绝，不截取括号或补造输出。格式失败的诊断只保留固定分类和原文 UTF-8 字节数，不能记录模型正文或凭据。报名候选支持简体、繁体及英文的实际可见报名文字。灵感正在分析时优先显示运行状态，不能因当前调用已预留额度而误报下一轮额度不足。
