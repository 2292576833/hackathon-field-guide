## 用户流程

1. 在 `/register` 填写姓名、邮箱，接收验证码后创建账号；已有邮箱验证后继续使用原账号，注册不会覆盖原昵称。`/login` 使用同一邮箱验证码机制。
2. 在账号页填写首次参赛、开发经验、技能、所在城市、每天可用时间和路演背景。字段可暂空，生成个人计划前补全必需项。
3. 比赛卡片点击「制定我的参赛计划」。资料齐全时，明确点击的一次性标记允许生成一轮；单纯 GET、打开链接或刷新不触发模型收费。缺资料会引导补全。
4. 计划保存本人使用的赛事/画像/天气快照、任务与工时、出行建议、风险备选、报名核实和路演准备。可查看历史、打印和下载 Markdown。
5. `/roadshow` 先阅读原创虚构事例与注意事项，再输入项目想法和真实进展，生成计时讲稿、演示备选与评委问答。讲稿只属于当前账号。
6. 从讲稿进入 `/ppt`，服务器复核记录所有者，继承项目输入。模板、逐页写作指引和制作工具可直接查看；DSH 大纲仅登录后明确生成。提供 Markdown 大纲与可打印预览，不能称其为 `.pptx`。

## 账号 DSH 会话

`personal_dsh_sessions` 为每个账号保存一个稳定的网站工作台会话 ID。聊天历史、计划、讲稿和大纲绑定账号及此 ID；聊天的项目上下文进一步按项目隔离，读取前后复核现时权限。客户端提供的聊天历史不作为服务器可信历史。

此会话是网站自有的持久上下文。原生 DSH 每次调用仍使用隔离的受限子进程，不共享用户桌面的私人聊天或工作目录；不会把数据库、邮件、GitHub 密钥交给模型。每个账号同一时间处理一个请求，恢复崩溃锁时保留未知请求及预算预留，不退款、不自动重放。

## 事实和建议

赛事卡片的时间、报名链接和来源以已保存字段为准。缺比赛城市、确切时刻或线下方式时，可由用户补充并显式标为用户自述；不会从标题猜成官方事实。报名、开赛、结束和作品提交截止分别记录。

城市和开赛时刻都明确且落在范围内，才通过 Open-Meteo 查询比赛城市当地日期的天气；同名城市要求补充省份/国家。远期、接口失败、缺日期或线上赛均有明确提示。AI 只生成准备建议，不生成天气数值、实时车票价格或虚构预订。

讲稿与 PPT 只整理用户提供的事实、已完成能力与设想，不编造获奖、用户数量、测试结果、市场数据或演示成功。所有结果是可审核修改的建议草案，不直接替队伍修改正式任务计划。

## 邮箱验证码

用户确认没有自有域名，本机选择 QQ 邮箱 SMTP：`AUTH_EMAIL_PROVIDER=smtp`，服务器 `smtp.qq.com`、465 加密端口，`SMTP_USER` 为发件邮箱，`SMTP_PASSWORD` 为该邮箱授权码。2026-10-09 已配置并重启，真实登录验证码发送得到 SMTP 受理；实际进入收件箱及用户输入验证码仍待确认。配置步骤见 [QQ邮箱验证码配置](../部署/QQ邮箱验证码配置.md)。一次配置供本站用户使用；用户只填写收件邮箱，不需要自己配置邮件服务。

Resend 接口继续保留，后续可验证可管理 DNS 的发件域名，再改为 `AUTH_EMAIL_PROVIDER=resend` 并填写 `RESEND_API_KEY`、`AUTH_EMAIL_FROM`。网站不会在 SMTP 失败时自动切换到其他发件账号或重复发送。

支持本地数据库加 SakuraFrp HTTPS 预览时真实发送。缺真实配置的公网实例返回发送不可用，不把开发预览当作已发送。开发邮箱仅限 loopback 配置与访问，不公开验证码。邮件 API 接受请求与用户邮箱实际收到邮件是两个验收步骤。
