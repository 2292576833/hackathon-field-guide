2026-10-09 补充：用户已明确要求独立公开树状路线图，而非仅团队空间概览。找比赛、赛前/赛中/赛后、注意事项、团队空间与工具资料按 [参赛树状路线图规划](15-参赛树状路线图.md) 连接，宪法升级为 v1.6.0；下文保留 U01–U04 原实施依据与已验收边界。

## 1. 要解决的问题

用户不应先理解我们的模块编号，才能完成一次参赛。网站要帮助他回答：我现在能做什么、谁在负责、什么时候完成、卡住后怎么办。

当前顶部有 12 个固定功能入口，项目内原有 8 个标签。个人准备与团队计划都叫计划，分工与排期分两轮填写和确认，项目想法在个人计划、讲稿与 PPT 多处重复输入。工具、视觉站点和 GitHub 教程有重复介绍。手机版虽然换行，却仍要面对所有入口。

本轮合并页面入口和连续操作流程，保留实际业务边界、旧网址、来源证据和已有记录。新增职责选择和进度协作直接增强现有项目任务板。

## 2. 页面结构

一级导航固定为：**找比赛 / 我的参赛 / 工具与资料**。网站首页从品牌进入；账号资料、固定队伍和有权限的后台放账号菜单。登录、注册在访客状态保留明显入口。

| 一级入口 | 用户要做的事 | 二级组织 |
| --- | --- | --- |
| 找比赛 | 看比赛分析、要求、报名入口，决定是否准备 | 分析卡片、原文、报名链接、制定我的计划 |
| 我的参赛 | 准备个人行程，打开项目和团队任务 | 我的准备 / 我的参赛项目 |
| 工具与资料 | 找到适合当前任务的工具和教程 | 工具 / 找灵感 / AI 技能 / 新手教程 / GitHub 教程 |

项目主导航为：**概览 / 比赛要求 / 分工与进度 / 代码与提交 / 复盘**。项目资料保留就地辅助入口。路演、PPT 在准备材料时展示，不再占两个一级入口。独立灵感页和 GitHub 页仍可直接访问。

分工与进度包含三个相连步骤：邀请队友与时间 → 确定分工 → 安排与查看任务。用户可直接访问已有步骤；首次设置清楚指出缺少的输入，不要求反复回到项目列表。

## 3. 用户刚讨论的协作想法

### 3.0 团队空间与邀请

用户进一步确认每次参赛项目就是一个团队空间，通过邀请链接或二维码加入，创建者可选择该链接最多邀请几人。空间集中职责、任务、资料和提交记录，底层继续使用 Project 的成员权限。默认普通成员，登录/注册后明确接受邀请；有效期、撤销、邮箱限定保留，多人名额在服务端事务内计数，旧单次邀请默认 1 人。详见 [团队空间与邀请加入](14-团队空间与邀请加入.md)。

### 3.1 先确认比赛与主办方赛道

- 项目引用实际规则版本与来源证据。官方赛道由主办方决定，AI 不自行创造比赛赛道。
- 主办方没有细分赛道时，显示“主办方未细分赛道”。资料不足时显示“赛道待核对”，允许团队先做通用准备。
- 游戏、影视、AI Agent 等技能包分类只是资源分类，不能自动写成该比赛的官方赛道。
- 赛道变更保留旧版本与选择历史，受影响分工/计划标记需要复核，不自动替换团队已确认安排。

### 3.2 每个人先选择愿意负责什么

- 让成员选择本次愿意承担的任务、已有经验、能投入的时间；可多选，允许调整。
- 已有经验从本人画像提供初始参考；本次选择是项目内独立记录，不能覆盖私人画像或历史测评。
- 根据当前赛道和必交内容给出职责建议，职责用具体产物解释，如“做能玩的核心流程”“准备评委能看懂的讲稿”。
- 角色并非互斥岗位。一个人可承担多类任务，同一交付物仍有明确主负责人。

### 3.3 不知道负责什么时请 AI 帮助

- 入口写“我不确定，请 AI 帮我判断”，问少量与任务相关的问题；不要求所有人先完成正式评分题组。
- DSH 根据官方要求、成员主动提供/共享的摘要、意愿与可用时间提出建议。
- AI 说明为什么这样分、哪些信息不足、团队还缺什么；不给真实能力百分比或年龄推断。
- 团队可以手动修改；管理员确认后的分工才作为排期输入。AI 建议不能直接创建权限或发布正式安排。

### 3.4 刚开始就规划任务和时间

每项任务至少说明：要做什么、谁负责、预计工时、开始与完成安排、依赖什么、完成后交什么、怎样检查。时间包含环境准备、学习、休息、集成、测试、演示和正式提交缓冲。

任务分为“必须完成”和“有时间再做”。容量不足时先缩小作品范围，不给出明知不可行却看起来完整的时间表。

用户举出的 demo → UI → 视频是一种具体依赖，不作为全项目固定顺序。配色、页面草图、组件选择、讲稿框架、录制脚本等可以提前并行；最终视频依赖可演示版本，真实交互与截图依赖相应成果。团队可编辑依赖，服务器拒绝循环。

### 3.5 等待时知道可以先做什么

任务板显示“我现在能做 / 等待队友 / 正在做 / 待检查 / 已完成”。这是对现有任务状态与依赖的易懂展示，不新增相互矛盾的完成事实。

- 能开始的任务：本人负责、依赖已满足、计划有效。
- 等待的任务：说明在等哪项成果、负责人是谁，提供可先做的其他任务。
- 卡住的任务：本人填写遇到的问题、希望谁协助、预计还需多久。
- 无法判断时显示缺少的信息，不把成员未更新状态推断为偷懒或已经完成。

### 3.6 完成勾选与队友可见

- 用户点“我已完成”后补充成果链接或说明，依现有规则进入待检查；检查通过才显示已完成。
- 单人项目同样提供自检说明。保存代码、可以运行、主办方正式提交仍是三个独立事实。
- 误勾可请求更正，保留谁在何时修改及原因；不得直接删除已验收记录或静默回退。
- 队友可看到同项目任务和最后更新时间。首次实现可用页面可见时只读刷新，离开页面停止；不要求新建聊天或通知平台。
- 自动读取不覆盖正在填写的输入；新版本有明显提示，并发写入按 revision 拒绝旧版本覆盖。

## 4. 资源与展示材料整合

资源中心按使用场景提供少量明确入口。同一网站的名称、主链接和基础身份一致；经人工审核的工具、DSH 的官网分析、本站原创教程保留各自发布与证据状态。不得为了合并卡片把等待分析的内容补成模型结论。

GitHub 教程集中在独立 GitHub 页，其他教程提供摘要及跳转。实际仓库操作留在当前项目，并显示当前仓库、分支、授权和结果，不要求先理解整套 Git 命令。

路演与 PPT 组成准备展示材料的连续流程。项目事实可作为初始输入；用户选择使用并确认后生成自己的材料。已有路演 → PPT 继承保留。私人行程、画像和讲稿不自动分享给团队。生成时保存输入快照，后续编辑项目不改写历史稿。

## 5. 状态基线与本轮范围

| 内容 | 2026-10-09 记录时状态 | 本轮要求 |
| --- | --- | --- |
| 三主入口、资源分类、项目导航分组 | 首轮源码已调整；生产构建/浏览器验收未完成 | 主会话验证、修复并整合 |
| 分工、排期、依赖、任务进度、权限 | 既有服务和页面已实现 | 复用现有数据，不建立第二份任务状态 |
| 自选项目职责 | 尚无完整独立记录与界面 | 新增版本化意愿记录、权限和流程 |
| 官方赛道结构与项目选择 | 现有规则有事实/阶段/要求，未形成完整专用流程 | 保留证据和版本，完成接入 |
| 任务简单完成操作、队内自动读取 | 现有待验收→已验收规则；页面未自动更新 | 简化操作、保留检查事实，增加只读更新 |
| 路演继承到 PPT | 已实现本人讲稿继承 | 延续事实复用，减少重复填写 |
| 项目事实带入私人材料 | 目前不能假称已经带入 | 做本人明确选择、权限复核与输入快照 |

首版不增加社交平台、能力排行榜、新一套即时聊天、强制测评或自动修改用户仓库。复杂推送与跨团队排程留待真实试用证明需要后再做。

## 6. 并行模块与实施顺序

| 编号 | 范围 | 责任与交付 |
| --- | --- | --- |
| U01 | 导航、首页、引导与根集成 | 主会话负责；统一壳、文案、共享接口、迁移、API、构建、贯通验收 |
| U02 | 官方赛道、自选/AI 分工、任务进度 | 独立会话；增强现有 M02–M05 与任务界面，提出根接口/迁移需求 |
| U03 | 路演/PPT/GitHub 连贯使用 | 独立会话；减少重复输入，保留私人材料边界与三种交付状态 |
| U04 | 资源中心、教程、技能入口 | 独立会话；按场景清晰导航，处理重复内容和跳转，保留来源状态 |

阶段 A：宪法与本规划先写入，明确文件所有权后启动三个会话。U03/U04 可独立推进；U02 的根迁移和新公共接口由主会话审核接入，依赖未到时继续完成不依赖部分。

阶段 B：各会话交付组件、模块规则、必要测试、SQL 建议及 NEEDS_INTERFACE。主会话确认停止编辑后再改其文件，不在同时改动同一区域。

阶段 C：主会话组装接口与迁移，验证真实页面流程；区分实现完成、模拟测试、真实外部调用、手机实际使用。构建通过后再替换运行中的版本，保留现有数据库和发现记录。

不预估“并行就能几小时做完”。排期按实际任务与接入情况更新。进度以协作登记和交付报告为准。

## 7. 验收脚本

1. 新人从首页解释三个入口，能找到比赛、开始准备及入门资料。
2. 从真实比赛卡片进入个人计划，登录后仍保留该比赛；未登录不触发模型。
3. 创建项目、邀请队友；单人可直接使用，不强制先建固定队伍。
4. 核对主办方赛道；未知或无细分状态清楚，不能看到虚构赛道。
5. 两名成员分别选职责，其中一人使用 AI 帮助；管理员能修改并确认，私人回答不泄露。
6. 排一个有依赖又有并行工作的计划；缺少容量、循环、未知截止均有可执行提示。
7. 一名成员提交完成，另一名成员看到待检查和最新版本；依赖满足后能找到下一项可做任务。
8. 两人同时更新产生冲突时，不丢输入、不覆盖新记录；已验收误勾有更正记录。
9. 从当前项目准备讲稿、PPT，内容来源可解释，私人材料不自动共享；继续到代码与提交不丢项目位置。
10. 手机 375px 与桌面 1280px 检查菜单、长中文、错误、空状态、键盘操作；真实手机登录需另行记录，不以窄窗口替代。

体验观察记录实际人数、找到入口和完成动作的时间、回退次数、卡住点。建议目标是新人不用讲解也能完成主要步骤，但未测量前不宣称已达成。
