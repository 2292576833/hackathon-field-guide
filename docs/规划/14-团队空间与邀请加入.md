# 团队空间与邀请加入

2026-10-09 本轮界面以 [全流程工作台](16-团队空间全流程工作台.md) 和 [T01](团队空间/T01-邀请与加入.md) 为准：常驻弹窗、复制优先。下文邀请业务约束有效，旧U02授权结束，本轮以T01–T03登记为准。

日期：2026-10-09。用户已确认本方案，作为 [体验优先改版](13-体验优先与协作整合.md) 的补充，由 U02 实现业务/页面、主会话负责二维码基础、根接口与验收。

## 1. 一个参赛项目就是一个空间

用户在“我的参赛”创建团队空间。每次参赛对应一个空间，集中比赛要求、职责、任务、共享资料和提交记录。一个人也可以使用；下次比赛建立新空间，保留上次任务和复盘。

底层继续使用 Project 和 ProjectMembership，不新建另一份 Workspace、成员表或第二份完成状态。长期固定队伍是可选设置，加入固定队伍不自动获得所有空间权限。

空间首页优先展示：我现在能做什么、我正在等谁、等待期间还能做什么、下一项截止。资料、成员作为就地入口，避免继续增加一级模块。

## 2. 邀请流程

1. 创建者打开“邀请队友”，选择最多邀请几人后生成链接；默认 1 人，提供 1 / 3 / 5 人和自定义。
2. 复制到微信/QQ，或展示本网站本地生成的二维码供现场扫码。二维码编码同一链接，不调用第三方二维码服务。
3. 持链接者看到最小邀请说明，核对空间、比赛（有真实数据时）和邀请人。尚未提供公开预览接口时清楚说明登录后核对，不能编造这些字段。
4. 登录或注册后回到同一邀请页面；打开只读页面不能建立成员关系。
5. 队友明确点击“加入团队空间”，服务端再核对有效期、状态、限定邮箱、空间是否可加入和当前成员身份。
6. 成功后明确“进入团队空间”，引导选择职责与填写时间。任务协作沿用 U02。

用户最新明确要求可选择链接邀请人数，覆盖之前只做单人一次性链接的安排。新链接按最大名额供多人使用，达到名额后失效；旧链接与缺少新参数的调用仍默认 1 人。

首版自定义名额建议为 1–50 的正整数，创建时固定；这表示“最多通过此链接新加入的人数”，不是团队总人数。已活跃成员进入空间不占名额，同一账号成功接受只计一次。原来通过此链接加入后退出或被移除的人不能靠原链接自动恢复；名额不因离开返还，需要负责人发新邀请。限定邮箱仍适合指定一位队友，界面解释该限制不会因名额增大放宽。

链接列表与有效预览显示已用/剩余名额和到期时间，不公开使用者身份。第一次成功建立新成员关系才消耗名额；失败、事务回滚、刷新和重复点击都不计入。

## 3. 成员与权限

- 新邀请默认普通成员；提升管理员在空间内单独明确设置，不借邀请静默提升已有成员。
- 邀请支持最大加入名额、有效期、撤销和限定邮箱（选填）。有效期默认沿用现有 72 小时，允许未来 30 天内设置；页面解释真实行为。
- 原始 token 只在生成时返回，数据库只持久 hash；失去原链接后重新创建，不能从列表拼回 token。
- 加入仅获得目标空间共享内容。私人画像、测评、行程、讲稿以及其他空间仍维持原可见范围。
- 私人资料共享必须本人选择，不因创建或接受邀请自动发生。

## 4. 预览的边界

已认证的邀请预览继续执行限定邮箱与当前身份检查。登录前预览如果提供，必须是独立、持 token 的最小 DTO，仅给有效邀请的空间名称、实际可用比赛名称、公开邀请者显示名、普通角色/到期状态和剩余名额。

不返回成员清单、私人邮箱、项目目标、测评、资料、token hash；对无效、撤销、归档或已使用邀请不给私人对象信息。返回 no-store，不将邀请 token 写进普通日志/分析或发给外站。匿名预览不能赋予加入权限，实际接受仍需当前已验证账号。

## 5. 易懂状态

| 情况 | 提示与下一步 |
| --- | --- |
| 未登录 | 登录或注册后继续，同一邀请保留 |
| 可以加入 | 核对邀请说明，点击加入 |
| 已是成员 | 直接进入空间，不要求重复接受或升级角色 |
| 邮箱不匹配 | 使用收到邀请的邮箱登录，或请邀请人重新发链接 |
| 已过期/撤销/名额已满 | 联系邀请人索取新链接 |
| 空间归档/暂不可加入 | 说明当前不能加入，可联系空间负责人 |
| 网络失败 | 保留页面上下文，可重新核对结果，不假称已加入 |

## 6. 持久化、并发与历史兼容

- 创建参数增加 maxUses，服务端整数/范围校验；默认 1，不能由前端计算剩余名额决定准入。
- 持久记录最大名额、实际使用次数/接受记录。接受记录至少关联 invitationId、userId、membershipId、加入时刻，invitationId + userId 唯一。
- 邀请/空间状态、邮箱身份、额度、成员写入、接受记录与审计在同一事务。最后一个名额并发接受只有一名新成员成功，其他请求收到名额已满并保留上下文。
- 幂等返回不能重新消耗额度或恢复被移除成员；重复点击先读取已存在的接受事实。
- 旧单次邀请迁移 maxUses=1；已接受邀请保留已消耗名额及原始接受事实，不重开已使用、过期或撤销邀请。acceptedBy/acceptedAt 旧字段如何兼容由 M02 报告，不能丢旧记录。
- 事务中途失败整体回滚，不出现占名额却没加入、加入却不计数的半状态。
- 实际根迁移由主会话递增执行，不原地改已应用文件；模块提供 SQL 建议及 NEEDS_INTERFACE。
