# 参赛树状路线图规划

日期：2026-10-09。依据：宪法 v1.6.0、用户要求“独立新页面、树状图，把找比赛、赛前/赛中/赛后、注意事项、团队空间、工具与资源串起来并说明清楚”。本规划覆盖此前“仅在团队空间概览展示”的初步设想。

## 目标与边界

新增公开 `/journey`，名称“参赛路线图”。新人不用登录就能看懂一场黑客松如何从选比赛走到留下经验。用清楚的树根、阶段枝、行动节点和资源子枝连接实际功能，不新增独立任务管理系统。首页、比赛页、我的参赛、资源中心和导航员提供入口；主导航仍使用三个已确认入口。

首版提供真实可点击的通用指南、场景资源说明、阶段注意事项和空间入口。公开页不读取私人资料、不显示个人完成率、不自动创建空间或调用模型。团队任务进度继续在现有空间显示，点击链接不会被当作完成。显式选择空间后展示事实投影可作为后续增强，首版不为此增加接口、数据表或第二套打钩记录。

## 树状结构

```text
参赛路线图：从找比赛到留下经验
├─ 赛前：选比赛、定目标、做好准备
│  ├─ 找比赛并核对资格、报名、日期、主办方赛道
│  │  └─ 比赛分析 / 黑客松入门 / 主办方原文
│  ├─ 确定一个最小能演示的作品
│  │  └─ 创建或打开团队空间 / 新手操作说明
│  ├─ 个人备赛、出行和环境准备
│  │  └─ 个人参赛计划 / 经验与城市资料 / GitHub 教程
│  ├─ 邀请队友，填时间，选择职责
│  │  └─ 团队空间 / 邀请链接与二维码 / 可选 AI 帮助
│  └─ 排任务、依赖与提交缓冲
│     └─ 任务计划 / 开发工具 / AI 技能与适配说明
├─ 赛中：做出作品、协作检查、展示提交
│  ├─ 做通核心 Demo
│  │  └─ 任务进度 / 开发工具 / GitHub 分支协作
│  ├─ UI、素材和视觉参考（可提前并行）
│  │  └─ 设计灵感 / 组件资源 / 许可与适用说明
│  ├─ 集成、测试，记录实际运行结果
│  │  └─ 代码与提交 / 交付检查清单
│  ├─ 讲稿、PPT 与路演练习（大纲可提前）
│  │  └─ 路演页 / PPT 页的模板与制作工具
│  ├─ 准备演示视频（成片需可演示流程）
│  │  └─ 演示与录制工具 / 必交内容检查
│  └─ 保存代码并向主办方正式提交
│     └─ GitHub 教程 / 代码与提交 / 主办方提交入口
└─ 赛后：复盘、保留成果、用于下一次
   ├─ 复盘合作、技术与时间问题
   │  └─ 空间复盘 / 确认经验卡
   ├─ 保存成果并按需归档
   │  └─ 团队空间历史 / 仓库 / 共享资料
   └─ 选择性复用经验和资源
      └─ 经验卡 / 个人收藏 / 下一次参赛空间
```

节点顺序描述准备路径，不能成为不可更改的任务依赖。找比赛是赛前的起点，不增加一条平行而断开的流程。每阶段显示“注意事项”，每个行动下显示对应辅助资源的名字、用途和前往入口。

## 节点与资源映射

| 行动 | 用户需要知道 | 首版真实入口 |
| --- | --- | --- |
| 找比赛、报名核对 | DSH 卡片是线索；资格、费用、报名截止和 AI 规则需核对原文 | `/events`、`/library/hackathon-introduction` |
| 目标与空间 | 单人也可创建；队友通过邀请进入同一参赛空间 | `/app`、`/library/start-here` |
| 个人准备与出行 | 经验、城市、天气和交通建议是本人资料；远期天气不能保证准确 | `/participation`、`/app/account` |
| 成员职责与时间 | 自选多项职责或可选 AI；主办方赛道优先；管理员确认正式分工 | 已有空间的 team/assessment 页，无空间先到 `/app` |
| 时间与依赖 | 算入学习、排错、休息、集成、展示与提交；等待时先做无依赖的工作 | 已有空间 plan 页；`/resources`、`/skills` |
| 核心实现与协作 | 先做能演示的最小流程，代码保存、运行和提交分别说明 | plan/delivery 页、`/github`、`/resources` |
| UI 与素材 | 草图、配色和组件可并行；参考不等于获得素材许可 | `/inspiration`、`/resources` |
| 讲稿、PPT、视频 | 大纲可提前，成片依赖可运行成果；按实际比赛要求准备 | `/roadshow`、`/ppt`、`/resources`、`/library/delivery-checklist` |
| 正式提交 | GitHub 保存不是提交主办方；核对格式、链接权限和最终截止 | delivery 页、`/github`、交付检查清单 |
| 复盘与复用 | 确认的经验选择性带入下次；旧截止、资格和授权需重新核对 | retrospective 页、`/app`、`/resources` |

无空间时不得生成虚假的 projectId 或不可用深链。相关行动明确写“先创建或打开一个团队空间”。打开私人保存功能需要登录，注册/登录保留目的地。资源说明引用本站真实栏目，不新增未经核验的外站地址、评分或许可结论。

## 视觉与交互

- 树根有一句起点说明与“先找比赛 / 打开我的团队空间”动作。
- 桌面沿横向分出三条阶段枝，阶段下纵向排列行动，再以缩进和短连接线引出辅助资源；三阶段不是无关系卡片网格。
- 手机使用纵向主干与阶段分枝，资源继续缩进。文本按容器换行，不要求横向拖拽或缩放才能使用。
- 用“赛前 / 赛中 / 赛后”锚点快速定位；可并行、建议核对、可选资源用文字区分，颜色不是唯一依据。
- 使用原生 section/nav/ol/li 与链接，不使用需要复杂键盘模型的 ARIA tree。连接线装饰不进入屏幕阅读器。
- 暖白、炭黑、橙红延续已有设计；主要动作至少 44px，焦点可见，减少动效模式可用。必要说明贴近节点，长注意事项可按需展开。

## 技术与状态

内容模型位于 `src/modules/journey/`，只维护流程指南、用途说明及本站链接。纯数据公共导出与 UI 公共导出分离，避免 Node 测试加载 TSX。首版不增加依赖、数据库迁移、收费调用或新的后台任务。

`JourneyGuide` 包含 root、phases；phase 包含 id/title/description/cautions/nodes；node 包含 id/title/description/actionLabel/href/parallel/resources；resource 包含 title/description/href。字段以 `model.ts` 为单一类型来源，节点和阶段 ID 唯一，内部链接只允许本轮确认的已存在入口。

准备指南不需要 status、checked 或 progress 字段。后续若引入空间上下文，读取事实必须经过既有权限接口，并校验计划与空间匹配；项目阶段只能定位阶段，不能推断任务完成。M05 的 done/review/cancelled 分别是完成/待检查/不纳入有效任务完成统计；M06 保存、运行验证、正式提交事实保持分离。不得按任务标题关键词自动给流程节点打钩。

## 验收标准

1. 游客打开 `/journey` 无须登录；识别树根、三阶段、行动与资源子枝，并读到注意事项。
2. 直接从找比赛开始，也能进入团队空间、个人准备、工具与资料、灵感、技能、GitHub、路演/PPT和复盘路径。
3. 每项辅助资源说明什么时候用、帮助什么；没有“看过即完成”、虚构百分比、统一强制 UI 等 Demo 的依赖或假官方赛道。
4. 375px 与 1280px 真浏览器视口没有水平溢出；键盘操作到达行动与资源链接；主导航仍保留三项。
5. 浏览指南不新建空间、不查他人项目、不发验证码、不触发模型收费或修改仓库；登录返回路线图。
6. 所有内部目的地实际存在且项目功能无虚假 ID；页面加载和公开接口只读。
7. 类型检查、必要 Node 回归、针对性 E2E 和生产构建通过；不会清除真实数据、账本或未知请求 hold。
8. 公网受信任证书和真实手机登录继续按已有验收报告独立记录，桌面窄窗口不替代该项。

## Constitution Check

| 原则 | 判断与措施 |
| --- | --- |
| I、X 新人流程与体验 | 独立公开树图连接已有动作及场景资源；三主入口保留；手机与语义层级验收 |
| II 来源与事实 | 通用指南标为本站说明；不替主办方确认资格/赛道，不冒充 DSH 分析或审核资源 |
| III、IV 分工与时间 | 自选/可选 AI 与真实依赖保持；可并行工作明确；不强制装技能或创建固定队伍 |
| V、VIII 交付与验证 | 保存/运行/提交不混用；浏览器模拟、真实公网、手机与外部服务分别记录 |
| VI、VII 私人与安全 | 指南只维护公共数据；私有操作沿既有权限/确认；无新增数据库或安装权限 |
| IX 外部失败与成本 | 路线图无需 DSH 可用；无隐式收费，既有服务失败不阻止读取指南 |

成本测量：路线图自身模型、邮件、仓库调用次数应为 0；E2E 记录所有 API 与外网请求并断言无生成/写入。性能记录实际浏览器读取与构建结果，不先承诺固定响应时间。后续空间状态投影是另一个需权限验收的增强，不塞进首版公共指南。
