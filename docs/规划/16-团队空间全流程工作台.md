# 团队空间全流程工作台

日期：2026-10-09。对应宪法 v1.7.0。用户要求整理想法、宪法、规划并分会话执行。本规划为本轮实施依据，复用既有模块与公开路线图。

## 1. 想法整理

一个参赛项目就是一场比赛的执行中心。用户要看懂当前阶段、自己下一步、团队缺口与最近截止。公开 `/journey` 解释通用流程；团队空间保存本场比赛目标、官方要求、队友、依赖任务和交付记录。单人也可继续，固定队伍不是前置。

| 阶段 | 要解决的事 | 就地辅助 |
| --- | --- | --- |
| 组队与选方向 | 找比赛、核对官方赛道、邀请队友、明确目标 | 赛事分析、指南、自选职责与可选AI建议 |
| 赛前准备 | 要求、时间、环境、仓库、备赛安排 | GitHub、工具/技能、本人出行与天气计划入口 |
| 比赛进行中 | 执行任务、检查成果、等待交接、调整范围 | 本人任务、真实依赖、团队进度、相关资料 |
| 演示与提交 | Demo、PPT、视频、讲稿和必交材料 | 运行/提交核对、路演/PPT工具、官方入口 |
| 赛后复盘 | 留存成果、发现问题、复用经验 | 复盘、经验、任务与资料历史 |

并行工作由真实依赖决定。UI草图、技术验证、讲稿结构可以并行；真实演示录制需要可展示成果。不硬编码“Demo完成才能设计UI”。赛道以主办方规定为准，技能包分类不是官方赛道。

## 2. 当前问题

邀请藏在“分工与进度”子步，手机简称省掉邀请；先看到管理交接，再看到生成链接。生成后“再生成”比复制突出，离开后无法找回原链接却未解释。无计划空间先展示空任务筛选；概览卡片名称与落地页不符。规则、资料、代码、讲稿和复盘需要用户自己拼接。

## 3. 五入口与旧路由

| 主入口 | 主地址（空间内） | 保留子入口 |
| --- | --- | --- |
| 工作台 | 空间首页 | 阶段、下一步、本人任务、空间设置 |
| 队友与分工 | `/team` | 队友与时间；`/assessment`选择职责与确认分工 |
| 任务进度 | `/plan` | 当前任务优先，安排/草案/历史按需展开 |
| 比赛与资料 | `/rules` | 官方要求；`/resources`团队共享资料 |
| 提交与复盘 | `/delivery` | 保存/运行/正式提交；`/retrospective`复盘经验 |

旧地址全部保留，每次只有一个当前主入口。子导航不编号成强制顺序，手机保留易懂名称。标题区常驻“邀请队友”打开弹窗；普通成员说明由管理员邀请，归档只读。旧 `/team#space-invitation` 保持可用。

## 4. 工作台与事实

顶部显示空间名称、阶段、身份、邀请。阶段线允许浏览五段准备路径，不修改Project.stage。清单说明行动、下一步、对应资源用途；初始按保存阶段选择，归档提示只读。

目标、当前计划与输入变化引用已有事实；报名、环境、出行、天气、讲稿和PPT没有合法共享事实时，只显示待核对/私人入口。代码保存、当前版本运行、正式提交分别说明。提交记录注明成员自报，多阶段/历史不得由任意一条reported概括全部成功。读取失败不得当作空记录或未完成。

无生效计划先展示开始入口，隐藏空任务筛选；有计划突出本人任务。等待项说明谁负责什么、是否已检查，直达对应任务；并行项只来自合法ready任务。最近截止区分已核对比赛要求与团队安排；计划输入失效时提示重新核对。

不新增清单表、不存localStorage完成勾选、不造整体完成百分比。M05仍管任务，M06仍管提交。首页GET不触发模型、费用或仓库写入。

## 5. 邀请体验

默认1人，1/3/5快选，自定义1–50按需展开；邮箱限定放更多设置。生成后复制为主操作，提供复制失败手动恢复、本地同链接QR、72小时有效说明与真实名额。

原token只返回一次，数据库仅存hash。关闭弹窗再打开可保留本次链接；离开页面不承诺恢复，清楚提示复制和丢失后的新建/撤销。不得在持久本地存储、日志或截图保存真实token。撤销某旧邀请只清除对应当前链接，不能误清另一条新邀请。

加入页按登录状态减少重复，保留returnTo和明确接受。成功后提供进入空间、填写时间、选择职责。权限/满额/限定邮箱/未知结果恢复沿用既有规则。

## 6. 任务、工具与隐私

默认卡片只显示任务名、负责人、时间、状态、成果摘要和主要动作；工时范围、检查、历史、纠错按需展开。“提交成果，请队友检查”与“检查通过”分别操作，自检按现有权限与证据执行。

阻塞说明用真实前置名称/负责人/状态，定位时处理当前过滤。就地资料入口按任务类型说明用途，复用GitHub、资料、灵感、技能、路演、PPT；不镜像资源、不自动安装。个人行程、画像、讲稿/PPT仍私人，团队时间来自本人确认可用时间，资料共享仍主动操作。

## 8. Constitution Check

| 原则 | 处理 |
| --- | --- |
| I/X 流程体验 | 少入口、常驻邀请、阶段下一步、手机主动作 |
| II 证据 | 未读/未知分开，官方与团队时间分开，成员自报清楚 |
| III/IV 分工时间 | 官方赛道、现有确认流程、真实依赖、检查交接 |
| V/VI 授权隔离 | 无新仓库写入；邀请/令牌与私人资料边界保留 |
| VII 简单 | 旧路由API状态复用，无新迁移供应商 |
| VIII 验证 | 纯模型测试与隔离桌面/手机贯通 |
| IX 成本失败 | GET不收费，失败可恢复，不假报完成 |

## 9. 验收

新空间先看到开始动作、单人继续与邀请；有计划先看本人任务。管理员各页可邀请、普通成员/归档不能越权；375px无水平溢出，弹窗关闭回焦点。默认/自定义/复制失败/QR/旧邀请撤销/关闭重开/旧锚点可用。五入口及旧详情地址可达且不双重选中。浏览阶段无写请求，读取失败显示未知。未检查前置不能开始；纠错与冲突保留输入。提交前能找到要求、运行、路演/PPT、官方入口及记录动作；链接缺失说明待核对。

类型检查、必要单元/集成、生产构建、隔离浏览器完成后记录结果。模拟与真实服务分别注明。新人5秒找到邀请、10秒说清下一步是后续试用目标，不以开发测试冒充达成。公网证书、实体手机、笔记本与云部署另验，不推定完成。
