# 萌新全流程验收与首次登录指引

日期2026-10-09，对应宪法v1.8.0。用户在团队空间执行期间追加两项：模拟第一次参加AI黑客松跑完整流程，首次登录自动带着认识网站。继续实施规划16，新增下列闭环，不回退原有状态与权限。

## 1. 验收角色与范围

新人没有Git经验、第一次参赛，使用手机375px和桌面。先看公开路线图与赛事卡片，注册/登录、认识网站、选择比赛、创建空间、邀请/自选职责/时间、确认计划、执行检查交接、GitHub指南与手动替代、路演/PPT、运行与提交、复盘。采用隔离账号和数据库，真实页面与业务接口；邮件/模型/GitHub按测试夹具或未配置状态验证，不能当真实第三方通过。

## 2. 首次登录指引

六个短步骤：欢迎与下一步、找比赛和事实核对、个人准备与资料、团队空间邀请分工、任务进度与就地工具、作品展示提交复盘。每步清楚说明用途、下一步与操作结果，显示步骤数、上一步/下一步，最后“了解了，继续刚才的操作”。不强制实际创建空间、报名、模型生成或仓库操作。

按账号保存版本、stepIndex、completedAt、revision。GET只读，POST仅当前账号并检查版本/会话；首次未开始自动显示，完成后不自动重弹，手动重看可用。访客看过公开导航不等于账号看过指引；退出与换账号清除私有状态。

原生dialog键盘与手机可用，关闭保留步骤。可“稍后继续”；邀请页支持先处理邀请，进入空间后继续，保留登录returnTo。避免与公开导航员双弹窗；有模型故障时静态指引仍可用。完成导览只表示用户明确点了结束，不能证明已经完成参赛或掌握技能。

新增表user_onboarding，不重写既有迁移。根迁移027由主会话备份后执行；模块先交SQL建议与端口。新API `/me/onboarding` 只访问本人，fresh会话与更新事务复核按根组合处理。

## 3. 走查优先问题与处理

| 问题 | 处理 |
| --- | --- |
| 资源筛选或GitHub上下文登录后回/app | 精确安全回跳字段，不放开任意next/外部URL |
| 选公开比赛后无法直接进入团队空间 | 卡片/个人计划提供“在团队空间继续”，保留公开discovery ID并由本人明确保存线索 |
| DSH线索无法等同正式规则 | 尽早解释未人工核验，保留原文/备注；提交要求未确认不能假造官方入口或成功 |
| 补个人画像后丢比赛 | 保留安全event上下文，保存后可返回原计划，不自动模型生成 |
| 路演/PPT丢空间 | 传递projectId仅导航，本人仍确认采用，主动分享成果 |
| GitHub未配置看似全流程阻塞 | 就近官方手动路径与返回运行/提交检查，不假报授权 |
| 复盘高级JSON/英文状态 | 中文状态与具体内容，保留确认和权限 |

## 4. 分工

原T01–T03继续本轮授权。主会话负责公共文档、根接口/迁移/组合、赛事到空间、画像返回与最终验收。内部代理first_login_guide仅新onboarding模块、first-login-guide.tsx/CSS、独立e2e和交付；auth_return_context仅auth/service.ts、return-to.test.ts、交付；novice_flow_acceptance仅独立萌新e2e与交付。不沿用旧授权，不build/重启或生产DB，交付停止后交还。

## 5. Constitution Check与验收

I/X：自动短指引、原上下文、通俗场景。II/IV：清单和交接只引用真实记录。V/VI：本人导览隔离，read不收费、明确动作才写，防开放重定向。VII：小模块持久状态，复用已有业务。VIII：账号隔离/并发/重登/邀请/手机及完整萌新贯通。IX：保存失败保留步骤、重试先核对，静态指引无需DSH。

验收：首次账号自动出现、另一个账号独立出现；完成后刷新/另设备不自动出现；稍后可恢复与重看；邀请登录原去向和加入清晰；首登只有指引自身状态写入，无模型/仓库/私人共享；安全回跳和完整流程通过。真实新人理解时间、实体手机、公网证书与外部服务另行记录，不由模拟推定。
