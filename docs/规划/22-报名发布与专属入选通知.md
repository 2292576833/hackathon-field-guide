# 报名发布、专属入选通知与主办方规划收尾

日期：2026-10-11。依据用户最新授权、规划21及宪法v1.13.0。本文件记录实施范围；写好文档不代表已经上线。

## 1. 用户要完成的事情

主办方入驻通过后，创建比赛，配置并发布报名表，再预览发布正式赛事。在工作台复制本站完整报名链接，自行发到微信、公众号、小红书等社交平台。选手打开链接看公开说明，注册/登录后返回原比赛，填写并提交；主办方在本站的待审核名单逐条处理。

审核通过以后，工作人员可以编辑本场入选通知，预览收件人、标题、正文及样式，明确点击发布给对应选手。选手在自己的比赛中看通知与下一步，真实配置邮件服务时同时进入邮件队列。草稿不等于报名，已收到不等于审核通过，通知站内发布不等于邮件已到邮箱。

## 2. 简单性与界面

- 主办方主路径：保存比赛 → 设置报名表 → 预览发布 → 复制报名链接 → 查看报名与审核 → 为已通过者发布入选通知。
- 报名分享区显示正式版本、真实报名窗口及审核模式；未设置表单、未开始、截止、满额、结束或运营暂停有明确说明。
- 报名管理默认待审核，批准/拒绝后刷新本场名单；切到已通过名单可发送通知。无需复制选手邮箱到别的网站。
- 通知模板提供标题、正文、简洁/信函两种样式及少量强调色；白名单变量如姓名、比赛、主办方由服务端替换。无需写HTML或配置JSON。
- 发布前展示实际收件人和样式预览；只有本站站内通知时直接说明“站内已发布，邮件未配置”。重发需明确操作，不能由改模板、刷新网页或后台重启触发。
- 本人报名页提供刷新审核结果，未开启组队的比赛引导官方安排，不把每个通过者都送到组队页。

## 3. 数据、权限与状态

模板按eventId版本化，revision CAS；已发布通知保存模板、替换后内容、样式、报名ID/版本和发布者的不可变快照。本人读取只取当前账号的本场通知。工作人员仅registration_manage可查看/编辑模板与为本场通过者发送；公开链接、其他主办方、评委不因此获得权限。

发布时在同一事务复核当前账号/会话、Origin、组织/赛事权限、目标账号活跃且邮箱已验证、本场Registration approved与expectedRevision；失败回滚站内通知和队列。幂等键绑定完整输入，重放不能向另一个人发送。

邮件采用持久outbox，后台按有限批次领取。发送前持久记录sending，重新核对权限事实及对应公告/入选通知版本。SMTP/Resend明确接受只记accepted；超时、进程中断或未知结果保留unknown_hold，不自动重发。未配置邮箱的已排队通知持久延后60秒，优先处理尚未延期的新队列项，不让一家机构挡住其他机构；这只表示未开始发送，不制造unknown。变量替换后标题最多998字符，发布前即拒绝过长标题。无真实配置不使用开发邮箱冒充投递。邮件HTML由代码转义和固定样式生成，不执行输入HTML/CSS；不记录邮箱、正文、密钥到日志。

## 9. 主办方自己的发信账号

用户追加：主办方可以配置发信账号邮箱，不必须使用网站邮箱。机构工作台提供可折叠的“发信邮箱”设置，只向当前已批准机构的组织管理员开放。首版支持QQ、163、126和Gmail固定SMTP配置，填写自己的完整邮箱和SMTP授权码/应用密码；网站代填主机、TLS和端口，不让主办方配置任意网络地址。

保存动作先复核权限和版本并登记限频尝试，再做一次真实SMTP认证验证，不向选手发送测试信；验证成功后重新复核当前权限与CAS才保存。失败保留原可用设置，超时明确结果未知并禁止后台自动验证重试。60秒一次、UTC日每机构最多10次，重启不清账。

完整邮箱和授权码按机构AES-GCM加密，使用后端独立用途密钥；GET只给脱敏邮箱、当前配置版本/启停状态与验证时间。不得在浏览器存储、DSH上下文、日志、导出或其他机构响应中保留凭据。密钥备份和更换遵循部署文档，不能把密文损坏静默解释为改用网站邮箱。

本机构官方公告/入选通知优先使用当前已验证专用账号，未配置或用户明确停用后使用已有网站邮箱。发送前再次校验机构状态和邮箱配置版本；账号修改/停用期间已经发起且结果未知的请求仍保留hold，不能换号重复发送。登录验证码始终属于网站身份系统，与当前选择的赛事及主办方发信账号无关。
