### 13.2 过程中发现并修掉的真实缺陷

1. **默认排布必然重叠**：6 个方框 × 212px = 1272px > 画布 1040px。单测直接抓到（"相邻方框不应重叠"失败），改为折行网格。

3. **`42P18 无法推断参数类型`**：给文档加共享字段时把 `author_id` 从 UPDATE 的 WHERE 去掉，`$3` 不再出现在语句里。改为显式声明类型。
4. **成员表主键列名写错**：待办与文档服务里写成 `id`，真实为 `membership_id`，会导致"列不存在"。
5. **验证夹具违反 deferred 约束**：`projects_project_manager_check` 在提交时要求存在活跃 manager，必须先成员后项目、且同一事务；删除同理需要 `SET CONSTRAINTS ALL DEFERRED`。

### 13.9 整宽画布：两侧空白变成可用区域（用户指出）

用户指出截图里左右两侧的空白"也是可以活动的区域"。根因已定位：

> 站点外壳 `.shell{max-width:1200px;margin:0 auto}` 把内容限制在 1200px 居中，宽屏上两侧就是**用不到的死区**。

**修法**（显式、影响面最小）：`SiteShell` 新增 `wide` 属性，加 `shellWide` 类放宽 `max-width`；**只有空间页**传 `wide`，其它页面保持 1200px 居中不变。

- 期间我先试过在画布样式里用 `:global(.shell):has(.root)` 覆盖，但构建产物显示规则落成了 `.xxx_root{max-width:none}`——**没作用到外壳上**，属于无效 hack，已撤掉，改为显式属性。
- 验证：构建产物中 `.zF3XJG_shellWide{max-width:none;padding-left:16px;padding-right:16px}` 正确生成。

1. 先用 `:global(.shell):has(.root)` 覆盖外壳宽度，构建后规则落成 `.xxx_root{max-width:none}`——**没生效**，已改为显式 `wide` 属性。

### 13.12 去掉内容容器 + 长按拖动 + 滚轮改大小 + 点不了修复（用户追加）

| 要求 | 结果 |
| --- | --- |
| **修好"点不了"** | 两处叠加原因：① 拖动处理器在 `pointerdown` 里无条件 `preventDefault()`，连链接/按钮的点击一起吃掉；② 助手浮动入口是 `position:fixed; top:16px; left:50%` 且 `z-index:40`，**压在浮动条（z-index:30）上面**。修法：拖动只从**拖动把手**开始（`isInteractive()` 放过 `a/button/input/select/textarea/summary/details`，并把把手标成 `data-drag-handle` 使其仍可拖）；助手入口移到**右上角**、层级降到 25 |
| **去掉组件底部限制内容的容器** | 删除卡片的 `max-height:560px` 与 `cardBody{overflow:auto}`。构建产物核对：`cardBody{min-width:0}`，**不含 `overflow:auto`**。组件内容直接铺在画布上，不再被裁切或内滚 |
| **长按拖拽位置** | 改为**长按 300ms 后**才开始拖动；在此之前位移超过 4px 即取消本次拖动（视为滚动/点别处）。拖动把手是整条操作栏，默认半透明、悬停显形 |
| **滚轮改变大小** | 画布上滚轮即调整该卡片宽高（`Shift` 加速）。尺寸写进摆放数据（`width`/`height`），限位 `280–900 × 160–1400`，**只改尺寸、不改位置、不动业务数据**；用非被动监听 `preventDefault` 避免缩放时页面跟着滚 |

**验证**：画布模型单测 **18/18**（新增：滚轮改尺寸不动位置、尺寸限位、非法尺寸容错、尺寸参与容器范围、拖动与缩放互不干扰）；模块测试 **2395 通过、0 失败**；构建 `failures: 0`；站点 200、stderr **0 字节**。

| 指引树（六阶段）**已实现**且质量高：含"建议先做"、每节点带事实状态 | `space-guide-tree.tsx`、`buildSpaceGuideTree` |
| 但指引树**埋在深层**：空间页共 **13 个折叠层**（lifecycle 8 + workbench 2 + project-client 3） | 实测计数 |

| 首页是**纯静态**，无任何状态读取 | `src/app/page.tsx` 无 `useApi`/`useState` |
| 首页已有 **10 个链接**；SiteShell 导航 **18 个链接** | 实测计数 |
| 空间页已有 5 个页签导航，与拟新增的线**指向同一批内容** | `project-workflow.tsx:8-11` |
| 工作台内部折叠只有 2 个（做得比 lifecycle 克制） | 实测计数 |
| 各组件都已存在，多数在 `project-client.tsx` 内直接渲染 | 见第 4 节映射 |

**结论**：本规划主要是**搬迁、重构组合与新增聚合**，不是从零开发。最大风险是"又加一套导航"。

## 5. 待办清单的数据模型（本次唯一新增聚合）

四类来源与结束条件：

| 类别 | 数据来源（已有） | 结束条件 |
| --- | --- | --- |
| **要我填** | 目标为空、时间未确认、职责未选、赛道未选、规则未确认 | 对应记录已保存 |
| **要我确认** | 任务 `status=review` 且本人是检查人/管理员 | 检查记录已通过 |
| **要我做** | 本人负责且状态 `todo`/`in_progress`/`blocked` 的任务 | 留下检查记录 |
| **要我读** | 队友共享资料未读、可转待办的动态条目 | 本人确认已读 |

**规则**：

- 只放**有结束条件**的事项；"关注一下"类不进列表
- 系统未读取时**不显示待办**，而是显示"读取中/读取失败 + 重新读取"（宪法新增第 4 条）
- 排序：真阻塞（有人等我）→ 期限临近 → 其余按创建时间
- **不落库新状态**：待办是**派生视图**，完成与否由既有事实（记录、检查）判定，不新增勾选表

> **这条最重要**：待办清单必须是**纯派生**，否则会变成第二套完成状态，违反既有原则。

## 6. 主路径线的形态与红色阈值

**形态**：竖向单列（手机优先），六节点等高标题条；展开时就地插入组件；已完成节点收成一行并打勾样式。

**节点三态**：

| 状态 | 判定 | 视觉 |
| --- | --- | --- |
| 已完成 | 该节点对应事实已有记录 | 收成一行 + 完成标记 |
| **该我了** | 当前推荐节点（复用 `buildMissionWorkbench` / `buildSpaceGuideTree` 已有的 next 计算） | **展开 + 高亮** |
| 还没轮到 | 其余 | 一行标题条 + 中性点 |

**红色只用于**：① 有人等本人确认；② 本人负责的期限临近；③ 队友标记阻塞求助。
其余一律中性灰点。**避免常亮导致麻木。**

## 7. 主页主路径（第二部分）

**现状**：首页纯静态，已有 10 个链接 + 3 步清单 + 4 个功能入口。

**做法**：
1. 把首页改为**可读状态**（引入 `useApi<Me>` 与本人空间列表，同 `discovery-client.tsx` 的既有做法）
2. 主路五段：**找比赛 → 组队 → 执行 → 交付 → 复盘**
3. 按状态给"下一步"：

```
未登录／首次到访   → 讲整条路（保留现有 3 步清单的意图，但由线承载）
已登录、无空间      → 指向"去看比赛 / 建一个空间"
有空间、目标未填    → 指向"回去把目标写清楚"
有空间、计划在跑    → 指向"你有 N 件待办，先看最急的"
比赛结束           → 指向"看结果、写复盘"
```

4. **收敛**：明确 `/journey`（树）与首页线的关系——建议 **`/journey` 留作"完整教程"**，首页线只做"你的下一步"；首页下方那 4 个功能入口与 3 步清单**去重**，不得与线重复表达同一件事

**边界**：主页线是**路标**（点了往前走），不是操作台（不能就地填）；因为新人还没有空间可填。这与空间线**必须不同**，硬套会出怪事。

## 9. 验收口径

1. **就地完成**：抽查主线六节点，每个都能在空间页内完成，无需跳页往返
2. **首屏干净**：默认展开的组件 ≤ 2；其余为一行的可见标题条（非隐藏）
3. **待办可执行**：每条都有明确结束条件；能独立完成并消失
4. **无内部状态**：待办清单不出现"尚未读取/未知/需要复核"
5. **红点不麻木**：红色仅出现在真阻塞场景
6. **层次清楚**：任意时刻站内只有一条主路 + 一条空间细步，无第五条
7. **两处交互不同**：空间线可就地展开；主页线只作路标
8. **位置固定**：主线、节点、待办不可移动；仅助手与浮动弹窗可移动
9. **无障碍**：折叠/展开可用键盘完成；手机单列可完整操作
10. **不新增完成状态**：待办与线均为派生视图；完成仍由真实记录判定
