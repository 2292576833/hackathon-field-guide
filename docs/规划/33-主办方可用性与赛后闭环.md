## 1. 我们的产品定位（不是把战略文档搬进来）

### 1.1 用我们自己的话说

我们做的是**一个带登录的黑客松参赛与办赛网站**：公开区域帮助找比赛、认工具；登录后围绕一个参赛项目完成规则确认、分工、计划和交付；同时为主办方提供可配置的报名、沟通、运营、正式收件与人工评审。

核心价值放在两句话上：

- **把"我不知道接下来做什么"变成可执行的动作**——知道必交什么、谁负责、何时完成、卡住怎么删减、最后是否真的提交成功。
- **把主办方每一场赛事里已经产生的事实留下来**，让下一场不必从零开始。

### 1.2 我们真正的"护城河"是什么（改写后的表述）

原战略文档的护城河是"专有数据 × 网络效应 × 工作流嵌入 × 生态绑定 × 品牌信任"，并配了一条数据飞轮：**用户行为洞察 → 动作验证 → 更多数据 → 更准的模型**。这条飞轮要求把选手行为数据归平台所有并用于训练算法，**与我们宪法 II/VI 直接冲突，本期不做**（见第 7 节 G2）。

在**不改变任何数据归属、不新增第二套事实**的前提下，我们能够真实积累、也已经有一部分的东西是另外四样：

| 我们真实的积累 | 已存在的载体 | 与"专有数据"的区别 |
| --- | --- | --- |
| **可核验的赛事事实与规则版本** | M03 来源证据与规则快照、`organizer_event_publications` 不可变发布版本（`PublishedEventRevision`，迁移 042） | 是**主办方自己发布、可公开复核**的事实，不是我们抓来的选手行为数据 |
| **跨本场赛事的纵向记录** | 同一主办方的多场赛事（规划 21「同主办方其他赛事只读互链」已实现） | 是**主办方自己的运营资产**，他授权我们保存，不是我们据为己有 |
| **不可改写的交付与评审链路** | M06 交付记录、`event-judging` 收件回执快照、开轮冻结、撤回/重开/重新公布版本、申诉表 | 是**可追溯的事实链**，正是竞品给不出的东西（拆解报告多家"宣传≠实现"） |
| **公开、可被机器读取的赛事信息** | `events/public-structured-data.ts`（JSON-LD 与 `.ics`，已实现） | 是**公开信息的可发现性**，不涉及任何私人数据 |

**结论（写进纪律）**：我们的复利来自**"事实可比对、可追溯、可复用"**，不来自**囤积用户数据训练模型**。原战略文档里所有依赖后者才能成立的部分（专有模型、评分校准模型、成果预测、开放写入型 API），本期一律不做。

## 2. 目标（以我们的真实摩擦点为准）

用户 2026-10-16 要求：**根据实现目标完善内容，写成独立规划，规划以项目实际内容去写。**

因此本规划的顺序是"**我们真实的卡点 → 既有能力核对 → 吸收闸门三问 → 只做不冲突的部分**"，每一项候选都要过第 4 节的闸门，并写清落在**哪个既有模块、哪条既有路径**。

**判断标准**：做完这些之后，一个主办方**在既有路径上少一次从零重来**（每场重新配一遍、看不到评审卡在哪、数据导不出来、选手找不到自己该领的东西、赛后成果散掉），而不是"我们的功能列表更长了"。

> **三处值得注意的结论**（影响实施成本）：
> 1. **N2 与 N3 都不需要新的读取路径**——`event-judging` 的 `workspace()` 已返回判定进度所需的全部集合，`OrganizerWorkspace`/`EventReadiness` 已有真实计数。缺口在**聚合与呈现**，不在数据。
> 2. **N4 不是"从零做导出"**，而是**加一种导出口径**（已公布投影）并复用既有 CSV 生成与防公式注入，成本远低于新建导出框架。
> 3. 因此本规划的**风险集中在 N1 与 N6**（前者动创建路径，后者涉及对外表达），这是第 5 节把它们放在第 1 期与最后一期的原因。

**已排除的"缺口"（核对后确认其实已有）**：活动创建向导（`OrganizerWorkspace` 已按 基本信息 → 赛道 → 报名 → 评审 → 品牌 → 发布 分步）；品牌配置；邮件模板；自定义发件人；导师/评委管理；操作日志；批量审核；消息中心。**这些不得作为新功能重复建设。**

## 4. 吸收闸门与冲突审查（先过这一关）

沿用规划 32 第 4.0 节与宪法 XII 的三个必答问题。本次删去了原战略文档中"解决我们哪个真实问题"答不出的全部候选。

| 候选 | ① 解决我们哪个真实问题 | ② 会碰到的既有能力 | ③ 冲突风险与处理决定 |
| --- | --- | --- | --- |
| **N1 复制上一场活动** | 主办方**每场都要从零重配**基本信息、赛道、报名表单、评审规则、品牌；模板只能给默认值，不能带走上一场实际改过的配置 | `organizer` 的模板、`createEvent`、`PublishedEventRevision`、模块开关 | **风险**：如果复制的是**已发布版本**，等于把上一场的正式规则静默变成新赛事的规则，与"发布是不可变版本"冲突。<br>**决定**：只复制为**新草稿**，走既有 `createEvent` 写路径；**不复制**报名答卷、队伍、通知已读、评审分数、申诉、审计；不新增状态表、不新增第二套创建入口，按钮放既有创建向导第一步。 |
| **N2 评审进度追踪** | 主办方**看不到卡在哪件作品、哪位评委没交**，只能逐个作品点开 | `event-judging` 轮次/指派/评分/冻结名单 | **风险**：容易做成第二套评审状态或"完成百分比"。<br>**决定**：**纯派生只读**视图，不新增状态列；每件作品给出"已有 N 位有效评委提交 / 本轮最少 M 位"与"未提交的评委（按指派）"，缺口只提示不催办；催办仍走既有通知写路径（若本期做，必须复用 `EventNotificationPort`，不得另写发送逻辑）。 |
| **N3 数据看板下钻** | 现有计数**停在总览**，主办方拿不到"哪个赛道提交少""哪位评委进度慢""哪个队材料不全" | 报名、队伍、收件、评审、行程全部既有事实 | **风险**：容易变成"成果预测/影响力评分/ROI 看板"，撞宪法 II 与 XII。<br>**决定**：只做**既有事实的筛选与下钻**；`MUST NOT` 出现预测、成功率、"影响力分"、跨赛事优劣排名；每个数字都带**统计口径与数据时间**；空值写"未提供"不补零。 |
| **N4 已公布结果导出** | 赛后要留档、要交给赞助方/学校，**已公布结果只能一页页看**（既有 `exportScores` 是内部对账用的指派级分数表，不是作品级结果） | `event-judging` 已公布版本投影、`exportScores` 既有 CSV 口径 | **风险**：导出可能带出联系人、评委真名、私人求助等不该外流的字段。<br>**决定**：**只导出主办方明确发布过的投影字段**（作品、队伍标识、总分、名次、已批准反馈）；`MUST NOT` 导出评委账号或真名到对外留档件；CSV 沿用既有防公式注入；导出动作写既有审计。 |
| **N5 选手侧资源入口** | 选手**不知道自己在当前赛事里"能领什么、要做什么"**，行程/住宿/餐券/公告/求助分散 | `event-communication`（公告/行程/住宿/餐券/求助）、`event-registration`（本人报名与队伍） | **风险**：容易建第二份"发放记录"或第二个"我的赛事"页。<br>**决定**：**只读汇总**既有记录，每一项**指回原记录**；不新增发放事实、不新增领取状态；算力 Token 见第 7 节 G5，**本期不承诺发放**。 |
| **N6 赛后闭环** | 赛后**成果沉在空间里**，优秀项目没有正式的"往下走"路径，下一届又要重搭 | M07 复盘、`organizer` 发布版本、`event-judging` 已批准反馈、既有通知模板 | **风险**：容易变成"投资对接/招聘/孵化"新模块，与宪法 II（不保证结果）与最小权限冲突。<br>**决定**：只做**只读的赛后清单 + 主办方人工确认的下一步记录**；`MUST NOT` 撮合交易、`MUST NOT` 承诺投资或录用、`MUST NOT` 把队伍成绩当作能力评价；复用既有 `retrospectives` 与人工审批写路径。 |

**已按闸门判定"不做"的候选**：专有模型训练、评分校准模型、成果预测、开放写入型 API、对外数据授权条款、支付分账与渠道费、子域名/白标/私有化、拖拽建站、国际化、赞助商与场地自动对接、场馆与现场三件套、奖金支付。

## 5. 分期执行

排序原则：**先做不新增写路径、不新增状态、能直接减少主办方重复劳动的**；越接近结果、越涉及对外承诺的越往后。

### 第 1 期 · 复制上一场活动（N1）

| 项 | 要求 |
| --- | --- |
| 入口 | 既有创建向导**第一步**内的一个动作；不新增独立页面或导航 |
| 行为 | 选定同一机构下的一场既有赛事 → 生成**新草稿**，名称默认"<原名>（副本）"并允许改，时区沿用来源赛事，时间字段**不沿用**（避免把上一届的截止直接变成这一届） |
| 复用 | 只复用 `organizer` 内部读草稿/发布版本 + 既有 `createEvent` 写路径；不新增表 |
| 不复制 | 报名与答卷、正式队伍、通知与已读、评审轮次/指派/评分、申诉、审计、已发布版本号 |
| 版本语义 | 新赛事从 `revision` 起点开始；来源是**草稿**时复制草稿，来源是**已发布**时复制**当前草稿**而非发布快照（发布快照只读，不可作为新赛事起点） |
| 验收 | 复制后新赛事可独立编辑、发布、归档，来源赛事**逐字段不变**；不产生第二条创建路径 |

### 第 2 期 · 评审进度派生视图（N2）

| 项 | 要求 |
| --- | --- |
| 形态 | 既有评审轮次页内的折叠面板（与 `calibration`、`integrity` 并列），**不新增导航、不新增状态列** |
| 数据来源 | **只用 `service.workspace()` 已返回的 `rounds / submissions / assignments / scores`**，不新增读路径、不加表、不加查询 |
| 内容 | 每件冻结作品：已提交有效评分数 / 本轮最少评委数；本轮每位被指派评委：已提交数 / 应评数（`recused`、`revoked` 排除并标注）；轮次层面：尚未收齐的作品清单 |
| 口径 | 与 `aggregate()` / `calibration()` **同一套**"有效指派 + 已提交"判定，不得另写一套；未提交≠不负责，措辞只报"已有 / 还差" |
| 禁止 | `MUST NOT` 出百分比、进度条或"完成度" |
| 催办 | 若本期做催办，`MUST` 复用 `EventNotificationPort` 既有写路径与投递状态记录；`MUST NOT` 另写发送逻辑或前端直接发 |
| 验收 | 读取前后 `workspace` 的评分、指派、汇总、公布哈希**完全一致**；无指派时不得凭空造出评委行；与既有 `calibration` 视图对同一评委的"已提交数"**必须相等** |

### 第 3 期 · 数据看板下钻（N3）

## 6. 验收口径

每个分期 `MUST` 区分：**模块测试、根接入、隔离浏览器走查、真实外部验收**。此外新增三条本规划专属的必查项：

1. **不新增第二套事实（闸门可复核）**：每期交付说明 `MUST` 写明第 4 节三个问题的答案，并给出"没有新增第二套入口 / 第二份状态 / 第二套写路径"的证据（路由与入口清单对照、相关表的列变更说明、复用既有写路径的调用点）。任何一项只能靠"新加一个页面"实现时，视为**未通过闸门**，退回改造既有流程。
2. **数字必须可比对**：凡新增的数字（评审进度、看板、导出计数），`MUST` 与既有模块各自读到的数字逐一相等；`undefined`（未读取）`MUST NOT` 显示为 0；空值写"未提供"。
3. **对外表述不得超出证据**：全站搜索"预测/成功率/影响力/ROI/最佳/排名"类文案，`MUST` 不出现能力或成果预测；对照原战略文档的许诺给出我们的替代表达。

**原文档"衡量主办方端是否完善"五问，作为第 3–6 期的联合验收**：

| 原文档五问 | 我们的对应与现状 |
| --- | --- |
| 主办方能否把活动办起来，不用再靠人力推 | 已有（模板 + 向导 + 发布门槛清单）；第 1 期再加"复制上一场" |
| 选手报名后能否一键发确认邮件、拉群、发算力 | **拆分对待**：确认邮件**已有**（通知队列，状态分别记录）；"拉群"**不做**（不替主办方在第三方平台发消息，宪法 II）；"发算力"**待观猹接口确认**，见第 7 节 G5 |
| 评审截止前能否自动催办未评分评委 | 第 2 期给**可见的进度**；催办若做，复用既有通知写路径 |
| 活动结束后能否一键导出完整数据报告 | **部分已有**（报名导出、评审分数导出）；第 4 期补**已公布结果**口径，第 3 期补看板下钻。仍**不做**"一键生成报告文档"（避免第二份事实来源） |
| 主办方能否自定义活动页、邮件发件人、品牌 | **多数已有**（品牌配置、邮件模板、自定义发件人）；"自定义活动页（拖拽建站）"**不做**，见第 7 节 G8 |

## 7. 本期不做（附理由与依据）

| # | 不做项 | 理由 |
| --- | --- | --- |
| **G1** | 用户行为数据授权、把选手行为/技能/完赛率/评审偏差/赛后转化数据用于算法 | **宪法 v1.22.0 已直接禁止**（XII「用户数据与算法」）；且不存在已确认的合作条款 |
| **G2** | 专项模型训练：团队匹配算法、AI 评分校准模型、成果预测模型 | **宪法 v1.22.0 已直接禁止**（XII「用户数据与算法」）；另见 XII（不出适配分与跨人排名）、XI（不由 AI 判分或晋级）；成果预测需要的赛后融资/收入数据**我们没有任何来源**；已实现的校准是只读派生视图，不训练 |
| **G3** | 算法著作权登记 | 与我们做不做产品无关，属于法务动作，不在工程范围 |
| **G4** | 对外数据共享协议、独家接口、联合白皮书与"行业标准制定" | 我们不自称标准制定者，也不发布行业报告；对外表述须限于已取得证据（宪法 XII） |
| **G5** | 算力 Token 发放、TokenDance 渠道费与补贴置换 | **观猹官方是否开放该接口未确认**，不能据战略文档的转述当作已有条件；不承诺未确认资源 |
| **G6** | 爱猹收支付接入、交易分账、主办方收款 | 宪法 II 明确平台不负责收款/退款/开票；商业模式属待用户确定的未决项 |
| **G7** | 对外写入型 API / MCP | 规划 32 已按闸门判定不做：写入型接口会与既有权限、CSRF、revision 校验并行出一套新边界 |
| **G8** | 子域名、拖拽建站、白标、私有化部署、国际化 | 需要 DNS/CNAME、低代码引擎与数据本地化，成本与风险远高于收益；且当前**公网 TLS 仍是未解决边界**（旧入口证书 UntrustedRoot），先做这些不合理 |
| **G9** | 赞助商与场地自动对接（含语音 AI 询价） | 涉及对外商业谈判与第三方通讯，超出范围且无法核验 |
| **G10** | 场馆导航、现场日程、现场聊天、酒店预订、餐饮支付 | 线下三件套与我们的线上主路径不是同一场景，规划 32 已判不做；现场服务只做已实现的行李程/住宿分配/餐券核销 |
| **G11** | 奖金支付与结算自动化 | 同 G6；且需要资金通道与合规审查 |
| **G12** | 战略目标定义辅助、法律合规条款自动生成（IP/NDA/GDPR） | 我们不是咨询或法务服务；条款应由主办方自行制定并在规则中声明，我们不代写 |
| **G13** | 不新建：第二份成员/职责/成果事实、第二套完成状态、第二套写路径、第二个同类入口 | 宪法 X「效率工具」与 XII「冲突时保留既有单一事实来源」 |

## 8. 需要用户确认的决策点

1. **第 1 期是否立即开始**：复制上一场活动不新增表、不新增状态、复用既有 `createEvent` 写路径，风险最低，且直接消除"每场从零重配"。是否开始？
2. **复制粒度**：建议复制**基本信息、赛道、报名表单字段、评审规则与权重、品牌配置、模块开关**；**不复制时间字段**（避免上一届截止变成这一届）。是否同意？
3. **催办是否在本期做**：建议**先只做可见进度**（第 2 期），催办单独作为一步再定——因为它会真实发邮件，需要先确认"催办话术、频率上限、是否可关闭"。是否同意先不做催办？
4. **看板范围（第 3 期，P07）**：建议只做**报名/队伍/收件/评审/后勤**五块既有事实的下钻，**不做**任何预测、成功率或影响力评分。是否同意？
5. **赛后闭环的"联系意愿"（第 6 期，P09）**：建议由**队伍本人明确选择**是否愿意被联系，默认不公开；主办方只能看到已选择公开的队伍。是否同意？
6. **是否同步修订宪法**：本规划未改变任何原则，建议**不修宪**（v1.21.0 继续适用）。若你希望把"不把用户行为数据用于算法训练"写成显式条款，可另起一次 MINOR 修订。
