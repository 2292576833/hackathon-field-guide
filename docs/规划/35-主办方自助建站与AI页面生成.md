# 主办方自助建站与 AI 页面生成

日期：2026-10-18 ｜ 依据：用户本轮口述需求 ＋ 宪法 **v1.24.0**（本轮新增原则 **XIV「内容归属与许可」**，见 §14；XIII 的自治与审计边界继续适用）
状态：**可实施规划**。本轮只写规划、宪法与协议，**不改任何代码**。
分期实施时每期 MUST 过 `tsc`、模块测试、根路由验收与 `next build`。

## 0. 吸收闸门三问

**① 解决哪个真实问题？** 公开赛事页只有一种版式（`competitions/[eventId]/page.tsx` 直接渲染 `CompetitionWorkspace`），
不同比赛想强调的内容差异很大，主办方只能塞进公告纯文本，或在外站另做一页（于是产生第二份事实与两套链接）。

**② 与哪些既有能力冲突？** 不能成为第二份赛事事实；不能执行任意代码；不能绕过宪法 XIII 的自治与审计边界；
不能替代或破坏平台默认页（那是兜底）。

**③ 如何避免重复入口／第二份事实／第二套写路径？** 不新建一级导航；不新建第二个公开赛事事实；
专属页的全部动作**跳转**到平台功能页，服务与写入只有平台这一套；页面只读既有只读投影。

## 1. 定位：两条并行表面

| 表面 | 地址 | 作用 | 可变性 |
| --- | --- | --- | --- |
| **平台默认（权威与兜底）** | `/organizers/workspace/:eventId`、`/competitions/:eventId`、报名/提交/结果/申诉页 | 功能永远可达、事实唯一 | 主办方**不能**改 |
| **专属页（表达与自由）** | `/s/<短码>` | 主办方自己的赛事门面 | **完全自由** |

专属页**不替换**平台默认页。删空专属页也不影响报名、提交与结果——这是「完全自由」成立的前提。

## 2. 专属链接

| 项 | 规则 |
| --- | --- |
| 地址 | `/s/<短码>`，短码为**不透明随机串**（不可由赛事 id 推导） |
| 重置 | 主办方可一键重置短码，**旧链接立即失效**；重置写审计 |
| 可见性 | 默认**公开**（拿到链接即可看）；可切「仅本场参赛者」（需登录且报名已通过） |
| 索引 | 默认 **`noindex`**（专属链接不进搜索引擎）；仓库当前**没有任何 `robots`/`generateMetadata`**，需新增该能力 |
| 有效期 | 默认跟随赛事（结束后仍可访问，作为留档）；可设截止日期 |
| 登录 | **只允许**平台邮箱验证码或观猹 OAuth（见 §9） |

## 3. 页面规格模型：两层

```
PageSpec
├─ 语义层（AI 的主要工作）
│   ├─ blocks[]     区块序列：leaf（文案/数据绑定）或 container（见 §21）
│   ├─ aiBlock      AI 组件：容器式，manages = 它框住的 blockIds（§21）
│   ├─ priority     每块 1–5 重要度（AI 给，用于手机重排与折叠）
│   └─ collapse     手机是否折叠为「展开更多」（AI 建议，受规则约束）
└─ 布局层（引擎生成，AI 不碰）
    ├─ desktop      栅格列位（由 priority + variant 推出）
    └─ mobile       单列顺序、折叠分组、图片比例（由规则推出）
```

**`priority` 不是位置**：AI 决定「什么重要」，引擎决定「放在哪、折不折叠」。
规格是**封闭枚举**：区块只能从注册表里选，文案只能填纯文本，绑定只能指向既有只读投影。
因此「AI 生成了一个删掉报名入口的页面」在结构上不可能变成第二个报名系统——动作一律跳转（§8）。

**容器**：AI 组件是唯一允许嵌套的区块类型；**一块只能属于一个 AI 容器**（结构上禁止重叠，见 §21）。

## 4. 区块库（首批 8 个内容区块 ＋ 动作跳板 ＋ AI 容器）

| 类别 | 区块 | 数据来源 |
| --- | --- | --- |
| 内容 | 倒计时 | 既有赛程时间（不新增字段） |
| 内容 | 要点卡片 | 主办方文案 |
| 内容 | 赞助商／合作方墙 | 上传图片（走既有上传校验） |
| 内容 | 时间线 | 既有赛程节点 |
| 内容 | 评委／导师／嘉宾墙 | 主办方文案 + 图片 |
| 内容 | FAQ | 既有公开 FAQ 投影或主办方文案 |
| 内容 | 图片横幅 | 上传图片 |
| 内容 | 富文本段落 | 主办方文案（纯文本渲染，不执行 HTML） |
| 动作（跳板，非内容） | 报名 / 提交 / 结果 / 申诉 | 跳转到平台功能页（§8） |
| **容器** | **AI 组件**（框住若干区块并只管理它们） | 见 §21 |

区块数量上限（防止页面过重）：内容区块 ≤ 20，图片区块 ≤ 8，单页规格序列化后 ≤ 128KB。

## 5. 完全自由与默认值

> 编辑器的交互规范见 **§19**（快捷／方便／高效／简单／易懂），P1 即按该规范实施。

1. **默认全在**：新建专属页时默认包含「赛事信息、报名、提交、赛程、公告、FAQ、结果、页脚」；
2. **删除只建议**：删除任一模块时给**一次**三段式确认（影响／仍可到达／一键恢复），**不阻止删除**；
3. **允许完全空白**：只剩赛事名与平台页脚也合法；
4. **可一键恢复默认模块集**；
5. **草稿有版本历史**，可回退到上一版。

## 6. AI 的四个交互

> 编辑器内的**生成助手**（提示／提醒／辅助编辑）见 **§20**；可放置的 **AI 组件**见 **§21**。

### 6.1 一键生成（P2）
输入结构化意图（比赛类型、目标人群、想强调什么、语气），或一段简介 → 产出**整页规格草案**（含手机语义安排）。
**只出草案**：必须主办方点「采用」才写入草稿，发布仍需走发布门槛。失败时退回默认模板，不给半成品页面。

### 6.2 打标生成（P3）
在画布上打点 → 写一条**结构化意图**：`位置` + `想要什么` + `文案`；AI 把意图映射到区块枚举并给出插入位置候选，人可选。
约束：批注是意图不是代码；每条批注可**单独采纳/忽略**；采纳前后可对比；做不到时给最接近的可做项（例如「客服脚本」→「外链卡片」）。
批注可标记为**只影响手机**（例如「手机上把评委墙折叠」）。

### 6.3 实时预览与修改（P4）
左侧画布即时预览（不发布），右侧对话/批注面板；每次 AI 改动产出**新版本草稿**，可回退。
预览固定三档：**375 / 768 / 1440**，与仓库既有 620／760 断点对齐。

### 6.4 多模态（P5，有硬限制）
当前模型传输是**纯文本**（`JsonModelRequest` 只有 `systemPrompt` + `input`），因此「看图直接生成界面」**今天做不到**。三条路：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A 换视觉模型 | 接入支持图像输入的端点 | 需新凭据与费用口径；`AI_PROVIDER=dsh` 是否支持图像**未验证** |
| B 两段式 | 图片→视觉模型抽结构→文本模型产规格 | 多一次付费调用，抽取质量不可控 |
| **C（本期采用）** | 对话生成为主，图片只作**参考附件存档、不解析** | 成本最低，但不是「看图生成」 |

A/B 需先验证模型能力与费用，属外部依赖，**不得先承诺**。

### 6.5 实时生成预览：真流式（C），且**只在可视化编辑时使用**

**裁定**：采用 **C 真流式**。流式**仅用于可视化编辑器的生成**（一键生成、批注生成、对话修改）；
模块助手、测评、评分、灵感等既有 AI **继续走非流式 `completeJSON`**，不受影响。

收紧范围的理由：流式会占用长连接、改变账本结算方式、增加取消与重连复杂度。限制在编辑器里，影响面可控。

#### 传输与事件格式

- `POST /api/v1/organizer/events/:eventId/page/generate` 创建生成任务，返回 `jobId`（写请求走既有 `authorizeMutation`）；
- `GET /api/v1/organizer/events/:eventId/page/generate/:jobId/stream`（SSE，`text/event-stream`）订阅增量；
- 事件类型：`block`（一个**完整**区块对象）、`meta`（priority 与手机语义）、`done`、`error`、`settled`；
- **渲染边界 = 事件边界**：token 只进解析器，**只有完整区块才进画布**，半截 JSON 永不渲染。

#### 账本与取消

- 开始按既有 `reserve` 预留，结束按**最终 usage** `settle`；
- 中途取消或断连：按已确认 usage 结算；拿不到 usage 时按上限**保守结算**（与既有「未知请求不自动重放」一致），**不退款、不重放**；
- 每次生成落一条 `ai_execution_jobs`（新增 kind `page_builder`），可在既有账本核对；
- 预算沿用既有每日预算，另加**单次上限**：时长、字节数、区块数。

#### 需要新增的能力（实施项，属 P4）

1. `streamJSON` 传输：`stream: true` + SSE 解析 + 增量 JSON 容错；
2. 新的 `PageBuilderModelPort`：只有它支持流式，其他端口与调用方不变；
3. 账本结算路径扩展：按最终 usage 结算；取消时保守结算；
4. 前端增量渲染器：收到完整区块即插入，未通过校验的块灰显。

#### 与方案无关、但必须守住的四条

1. 未通过校验的块**灰显占位**，不伪装成已完成；
2. 可**取消**，保留已到达的块并标注「未完成」；
3. 结束后跑一遍 §7 的手机硬规则校验；
4. 半截 JSON 永不进画布。

**外部依赖**：在提供方确认支持 `stream: true` 与增量 usage 之前，**不承诺上线**；若确认不支持，回落为「骨架＋一次性替换」并在界面写明。

#### 开关与降级

| 项 | 规则 |
| --- | --- |
| 开关位置 | 编辑器顶部 `实时生成` 开关 ＋ 本场设置内的同名选项 |
| 默认 | **关闭**（与宪法 XIII「默认保守」一致） |
| 开启 | 走 SSE 增量路径，**边生成边预览** |
| 关闭 | 走一次性 `completeJSON`，生成完成后整体显示；**1 次调用**、更省更稳 |
| 产出 | 两条路径产出**同一份 `PageSpec`**，只是呈现方式不同；切换不影响已保存内容 |
| 自动降级 | 提供方不支持／流式中断／超时 → 自动回落一次性生成，并**明确提示「已降级为一次性生成」**，不静默 |
| 并发 | 同一赛事**同时只允许一个生成任务**，避免重复计费 |
| 不可用态 | 提供方不支持流式时，开关**置灰并说明原因**，不做成坏掉的开关 |

编辑过程中的**本地即时预览**始终开启（不依赖 AI、不花钱），与这个开关无关。

## 7. 手机布局：AI 排优先级，引擎排几何

AI 在**同一次生成**里给出桌面与手机的**语义安排**（顺序、变体、折叠）；几何由引擎保证。
理由：断点不可穷举、触控与字号有下限、任意坐标在手机上必崩。

手机端硬规则（引擎保证，**不限制主办方的内容选择**）：

1. 单列、不横向滚动；
2. 触控目标 ≥ 44×44，正文字号 ≥ 14px；
3. 图片有确定宽高比、宽度不超容器；
4. **不自造断点**（只允许仓库既有档位）；
5. 折叠只允许**一层**，且折叠后仍可展开；
6. 区块高度上限；
7. **极简页/空白页不硬塞模块**：标题 + 正文的单列是合法结果。

主办方调顺序导致报名按钮落到第二屏时，给**替代方案**（横幅变体、缩小高度、折叠），而不是拒绝保存。

## 8. 动作必须跳转，服务走我们后端

专属页上的「报名／提交／结果／申诉」都是**跳转**到平台功能页；不在专属页内自建表单，不接主办方系统或第三方。

降低摩擦的五个手段：

| # | 手段 | 效果 |
| --- | --- | --- |
| 1 | **同域跳转** | 不像离开主办方 |
| 2 | 带**赛事上下文** | 报名页直接锁定这一场 |
| 3 | **`returnTo` 免重登** | 已登录直入；未登录登录后回原功能页（全站成熟模式，175 处用法） |
| 4 | **回跳条** | 平台页顶部 `← 返回 <赛事名>` |
| 5 | **成功后回专属页**（默认 A 方案） | 报完名/交完在专属页看到紧凑回执 |

成绩与结果：专属页读平台投影，不另算。

## 9. 登录：只允许平台或观猹

- **平台**：邮箱验证码（`/login?returnTo=...`）；
- **观猹**：复用 `GuanchaLoginButton({ returnTo })`（`src/components/guancha-login.tsx`）与 5 条 OAuth 路由；
- **观猹按 `/auth/guancha/status` 自适应**：未配置就**不显示**，绝不出现点了没反应；**邮箱登录永远可用**，观猹不得成为报名堵点；
- 观猹账号仍须落地平台账号（既有 `/app/account/guancha` 关联页）；
- **不接受主办方自建账号或任何第三方登录**。

外部边界如实记录：`GUANCHA_LOGIN_ENABLED=true`（本机已开），但**精确 callback 登记与可信公网 TLS 尚未验收**。

## 10. 持久化与复用

| 事实 | 作用 | 关键约束 |
| --- | --- | --- |
| `organizer_page_specs` | 赛事级：`draft` + `published` 两态、`revision`、`spec jsonb`、`short_code`、`status` | 一赛事一条；发布=不可变快照；草稿与线上分离 |
| `organizer_page_templates` | 机构级可复用模板（只存规格快照） | 套用=复制，**不做跨赛事联动** |

复用路径：新建赛事从模板套用；`复制赛事`（既有 P05 能力）可一并带上页面规格；**重置短码**用于链接外泄。
页面规格属于「可复制配置」，复制赛事时**不复制任何业务数据**（报名、队伍、收件照旧不复制）。

## 11. 两处落点与状态机

| 落点 | 位置 | 职责 |
| --- | --- | --- |
| 主办方工作台 | 本场赛事工作台新增「专属页」页签；机构级另有「我的专属页」总览 | 建、改、预览、发布、复制链接/二维码、重置短码、存模板、停用 |
| 管理后台 | 新增 `/admin/hosted-sites`（与 `/admin`、`/admin/organizers`、`/admin/services` 同级） | **只读清点 + 停用/恢复/回收短码**；不能替主办方编辑 |

```
草稿 ──发布──> 已发布 ──停用(主办方)──> 已停用
  ↑              │                        │
  └──继续编辑────┘                        └──恢复──> 已发布
                 └──停用(平台管理员)──> 已停用（标注「平台停用」，主办方不能自行恢复）
```

**停用不删除数据**；短码保留可恢复；「回收短码」才是让旧链接失效。两个入口操作**同一份状态**。

## 12. 治理：先发后审 ＋ 可即时停用

默认**先发后审**（否则「一键生成即上线」的体验会被砍掉）：

- 任何页面可被平台管理员**立即停用**，且不影响平台默认页与报名／提交／结果；
- 创建、发布、停用、恢复、回收短码均写既有主办方／平台审计；
- 若改为「先审后发」，一键生成退化为「一键提交审核」——这是待确认项（§18）。

## 13. 安全与宪法边界

1. **不执行任意代码**：无 eval／`new Function`／用户 React 组件／外部脚本；区块是编译期枚举；
2. **AI 只出草稿**，人工「采用」后进草稿，发布走既有门槛；
3. **不新增赛事事实**：页面只是投影；事实类文案**只能绑定**，不能手写（防止「报名截止」两处不一致）；
4. **文案按纯文本渲染**，有长度上限；图片走既有上传校验；
5. **用户内容不进训练**（宪法 XII 与本轮 XIV）；
6. AI 生成计入既有 AI 账本（可核对、有花费、可失败降级）。

## 14. 内容归属与许可（对应宪法 XIV）

| 东西 | 归属 | 平台拿到的权利 |
| --- | --- | --- |
| 主办方上传素材（Logo、照片、赞助商物料） | 主办方及其许可方 | 托管、展示、缓存、备份、必要公开传播的**非独占许可**（不含训练） |
| 页面文案 | 主办方 | 同上 |
| 本次页面的**具体编排** | 主办方（选择与编排） | 同上 |
| **模板、区块组件、渲染器、设计系统、默认模板** | **平台** | 主办方只有**使用权**，不可转售/再分发 |
| 选手提交的作品 | **队伍/选手本人**（既有口径） | 平台按赛事需要展示；主办方仅在本场范围内使用 |

一句话口径：**能力归平台、表达归主办方、作品归选手**。
记忆点：**主办方明天搬到别家，能带走文案与素材（提供导出），带不走模板与组件。**
AI 生成内容**不承诺**必然受著作权保护或具备新颖性/唯一性，只做归属与许可约定。

## 15. 最小埋点与成功指标

现在**没有任何埋点**（`analytics`／`telemetry`／`pageview` 全站 0 命中），需新增最小四数：

1. 专属页访问 → 点击功能入口的转化率；
2. 到达平台功能页 → 完成报名／提交的转化率；
3. **报名后 7 日内是否访问 `/me/competitions` 或 `/app`（回流率，核心指标）**；
4. 通过专属链接进入的选手，人均使用的平台服务数。

若回流率长期很低，说明这套东西只是「给主办方做了个报名页」，战略价值需重估。

## 16. 分期与验收门槛

| 期 | 内容 | 验收 |
| --- | --- | --- |
| **P1** | 规格模型（含 priority、mobile 层与 **AI 容器结构**）＋ 区块注册表 ＋ 渲染器 ＋ 存储与发布冻结 ＋ 默认模块集与删除建议 ＋ 短码与 `noindex` ＋ **规则提醒（不调模型）** | tsc／模块测试／根路由验收／build；三档预览无横向滚动；规则提醒 0 成本 |
| **P2** | 一键生成（结构化意图 → 整页草案，含手机语义安排）＋ **生成助手的 AI 建议（按需）与辅助编辑（应用才生效）** | 生成失败退回默认模板；草案可采纳/丢弃；建议永不自动改 |
| **P3** | 打标生成（批注 → 定点插入/改写，支持只影响手机）＋ **AI 组件的编辑模式**（只改它框住的块，含可保存的职责指令） | 每条批注可单独采纳/忽略，可对比；AI 组件不能碰框外内容 |
| **P4** | **流式传输**（`stream`＋SSE＋增量解析＋账本结算扩展）＋ 编辑器增量渲染 ＋ 版本回退 ＋ 对话修改 | 五条：可取消、半截 JSON 不渲染、未校验块灰显、按最终 usage 结算、三档同屏可切 |
| **P5** | 多模态（按 §6.4，本期方案 C；A/B 待验证后另立） | 图片仅存档，不解析 |
| **P6** | 机构模板库 ＋ 跨赛事复用 ＋ 复制赛事带上页面规格 ＋ 管理后台清点与停用 | 模板套用不建立跨赛事联动 |

## 17. 明确不做

- 不执行用户代码、不允许自定义 CSS/JS、不做白标与子域名（与规划 32 既有判定一致）；
- 不让 AI 修改报名规则、赛程时间、评审维度或结果；
- 不做多语言与多站点；
- 不把页面规格另存为一份「公开赛事目录」事实；
- 不在页面里嵌入第三方脚本（统计、客服、地图 SDK 均需单独评估）；
- 不做「模板市场」式的全局公共模板（需内容审核，另立）；
- 不把主办方文案、素材或编排据为平台所有；
- **AI 组件的问答模式（选手侧由 AI 回答）本期不做**——它会让主办方的 AI 对选手说话，须先解决事实绑定、标注、限流与责任，单独立项。

## 18. 待确认项（实施中可先按默认执行）

| # | 事项 | 默认 |
| --- | --- | --- |
| 1 | 报名/提交成功后自动回专属页（A）还是停在平台成功页（B） | **A** |
| 2 | 先发后审 还是 先审后发 | **先发后审 + 即时停用** |
| 3 | 平台署名强度：页脚一行（可弱化、不可删） | 页脚一行 |
| 4 | 机构级「我的专属页」总览是否本期就做 | 做（P6） |

## 19. 可视化编辑器交互规范（快捷／方便／高效／简单／易懂）

编辑器**不是设计工具**，是「填空 ＋ 拖动 ＋ 说话」。凡是需要读文档才会用的功能，一律不做。

### 19.1 三条铁律

1. **就地编辑**：所有修改在画布上直接完成，**不弹窗套弹窗**；
2. **一屏看全**：左侧画布、右侧检查器；手机上退化为「画布 ＋ 底部抽屉」；
3. **随时撤销**：所有操作可撤销，**不弹确认框**（唯一例外：删除核心模块，按 §5 给一次建议）。

### 19.2 五个动作，每个 ≤ 2 次点击

| 动作 | 交互 |
| --- | --- |
| **加区块** | 点「＋ 添加」→ **带预览的缩略图列表**（不是文字菜单）→ 点一下即插入到当前块下方 |
| **调顺序** | 拖动（显示插入线）＋ **上下箭头按钮**（键盘可达） |
| **改文案** | **双击就地编辑**，回车换行、Esc 退出；不做富文本 |
| **换样式** | 右侧只给 **2–3 个变体缩略图**，不做属性面板树 |
| **删区块** | hover 出现 ×；删除后顶部「已删除 · 撤销」提示条 |

### 19.3 快捷键（高效）

| 键 | 动作 |
| --- | --- |
| `/` | 呼出添加区块 |
| `Ctrl/Cmd + Z` / `Shift + Ctrl/Cmd + Z` | 撤销 / 重做 |
| `Ctrl/Cmd + S` | 立即保存 |
| `↑` / `↓` | 在选中区块上移动 |
| `Ctrl/Cmd + Enter` | 发布 |
| `Esc` | 取消选择 |

### 19.4 默认即可用（通俗易懂的关键）

- 新建页面**不是空白**：默认模块已就位（§5），主办方看到的是「已经能用的一页」，只需改文案；
- 每个区块 hover 显示**一句人话**（例如「这块是倒计时，时间来自你的赛程」）；
- AI 入口只有一个输入框：**「你想让这页看起来像什么？」** ＋ 3 个示例问题；不做参数表单；
- 手机端不合规时**就地标红 ＋ 一句话 ＋ 一键修复**（例如「改成横幅」），不弹错误汇总。

### 19.5 保存与发布

- **自动保存草稿**（输入停止即存），顶部只显示「已保存 · 12:04」；
- 发布是唯一主按钮，点击前显示「与线上差异 N 处」；
- 版本历史收进「历史」，不占主流程。

### 19.6 性能即体验

- 区块级更新，**不整页重渲染**；
- 图片上传即压缩并提示尺寸；
- 画布首屏可交互目标 **< 1 秒**（本地）。

### 19.7 「简单」是可以量的

| 指标 | 目标 |
| --- | --- |
| 改一次文案 | ≤ 2 次点击 |
| 加一个区块 | ≤ 2 次点击 |
| 发布一次 | ≤ 3 次点击 |
| 新用户到首次发布 | **≤ 60 秒**（可用任务测试验证） |

### 19.8 明确不做的交互

- 多层弹窗、属性面板树、自由坐标（C 档只作预览）、富文本、代码视图；
- 「必须点保存」；
- 强制分步向导（一次性填完才让发布）；
- 需要读文档才能理解的图标与术语。

### 19.9 与分期的关系

这条规范从 **P1** 就生效（P1 的编辑器就是最终形态的骨架），P2–P4 只在此基础上加 AI 能力，**不重构交互**。

## 20. 生成 AI 助手（提示／提醒／辅助编辑）

编辑器里的副驾。它有**三个不同机制**，成本与可靠度不同，不能混成一个「AI 按钮」。

### 20.1 三个机制

| 机制 | 谁来做 | 例子 | 成本 | 会不会错 |
| --- | --- | --- | --- | --- |
| **提醒（检查项）** | **规则引擎，不调模型** | 手机横向滚动、文案超长、图片过大、首屏无报名入口、手写截止与平台不一致、空区块 | **0**（本地即时） | 不会错 |
| **提示（建议项）** | 模型，按需或节流 | 两块内容重复、赞助商区建议用 Logo 墙、建议加倒计时 | 计费 | **可能错**，只作建议 |
| **辅助编辑** | 模型产出 → 点「应用」才生效 | 改写、压缩到 N 字、统一语气、调整顺序建议 | 计费 | 可撤销 |

**能用规则算出来的，绝不调用模型。**

### 20.2 呈现（不打断）

- 不弹窗、不堆红色横幅；右侧检查器一个折叠的「建议条」显示条数；
- 点开是清单：一句话 ＋ **一键修复**（改成横幅／压到 80 字／补上报名入口）；
- 修完自动消失；可整组忽略；
- 编辑中只报最严重的 1–2 条，**发布前**做一次完整体检。

### 20.3 触发与频率

| 时机 | 行为 |
| --- | --- |
| 编辑中 | 规则提醒实时（0 成本）；AI 建议**不逐键调用**，同一页面同一分钟最多一次 |
| 点 ✨ | 一次给 3 条建议，可采纳/忽略 |
| 发布前 | 规则体检 ＋ 一次 AI 复核，出统一结论 |
| 开关 | 规则提醒**默认开**；AI 建议可整体关闭 |

### 20.4 边界

1. **永不自动改**、永不自动发布（与宪法 XIII「只出草稿」一致）；
2. 只读**本场**页面规格与平台事实，不读其他赛事、不读选手数据；
3. **不碰事实**：只能提示「这里与平台不一致」，不能改截止／资格／结果；
4. 每次调用计入既有 AI 账本；应用后可撤销。

## 21. AI 组件（容器式）

把 AI 当组件：可拖入、框住若干区块、只管理它们、可删除、可随模板复用。

### 21.1 结构与上限

| 项 | 规则 |
| --- | --- |
| 形态 | **容器**：拖入后是空框，把要它管的块拖进去（或勾选） |
| 作用域 | `manages = [blockIds]`，**结构性隔离**，不是提示词自律 |
| 独占 | **一块只能属于一个 AI 容器**（结构上禁止重叠） |
| 上限 | 一页**最多 3 个** AI 组件 |
| 可删 | 与其他组件一样可删；删后其产出作为静态内容保留 |

### 21.2 它能管什么

| 能管 | 怎么管 |
| --- | --- |
| 它框住的区块**文案** | 编辑时改写／压缩／统一语气（出草稿，应用才生效） |
| 它框住的区块**变体与顺序建议** | 给 2–3 个建议，人选择 |
| **它自己的职责描述** | 一行话，可保存、随模板复用 |

| 不能管 | 原因 |
| --- | --- |
| 报名规则、赛程时间、评审维度、结果 | 宪法 XIII/XIV：AI 不改事实 |
| 框外的任何区块 | 作用域必须结构性隔离 |
| 平台页脚、署名、合规入口 | 平台层不归主办方配置 |
| 选手数据、报名名单 | 不是页面内容 |

**一句话：它能管「怎么说」，不能管「是什么」。**

### 21.3 两种模式

| 模式 | 谁用 | 默认 | 本期 |
| --- | --- | --- | --- |
| 编辑模式 | 只有主办方 | **开** | **做（P3）** |
| 问答模式 | 选手 | **关** | **不做**（单独立项，见 §17） |

### 21.4 交互

1. 组件箱里「AI 组件」→ 拖入成空框；
2. 把块拖进框（或勾选）；
3. 一行输入职责：「这块你只管…」＋ 2–3 个示例；
4. 框上 ✨ → 建议 → 并排对比 → 应用／再来一版；
5. 应用后显示「已应用 · 撤销」。

**空职责不报错**：显示默认职责与提示「先告诉我它管什么」，且不产生任何调用。

### 21.5 成本与审计

- 每次调用计入既有 AI 账本（kind `page_builder`）；
- 按**组件 ＋ 赛事**限额；
- 记录：谁、何时、对哪个组件、改了哪些块、用了哪个模型；
- 问答模式若将来开启，必须单独计费与限流。

### 21.6 一个例子

> 拖入 AI 组件 → 框住 [FAQ] 与 [材料要求] → 职责：「只回答报名条件与材料要求；不确定就引导到规则原文」。
> 编辑时说「把这两块统一成更正式的语气」→ 只改这两块，并排对比后应用。
> 随模板保存 → 下次办赛套模板时，职责与框内块一起带过去。
