# 规划 38 · 主线不跑偏与团队沉淀

> 日期：2026-10-18 ｜ 依据：用户「任务会偏离轨道，能不能在一开始把框架定好，之后用 skill 防止跑偏；和自己的智能体对话的关键内容可以上传团队空间，由团队空间的智能体总结」＋「选手进团队后，选手之间的 AI 工作台可以相互交流」。
> 宪法：XIII（助手只读、只出草稿）、XIV（AI 生成须人工确认）、XV（模型中立与插件只读）。

## 1. 框架卡（Charter）

立项时把主线钉死，AI 只起草，**本人确认后才锁定**。

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| `goal` | 一句话目标 | 必填，≤400 字 |
| `deliverables` | 交付物 | ≤12 条，每条 ≤200 字 |
| `acceptance` | 验收标准 | ≤600 字 |
| `nonGoals` | 明确不做 | ≤12 条 |
| `timebox` | 时间盒 | ≤60 字 |
| `locked` | 是否锁定 | 锁定后改动须带版本号 |
| `version` | 版本 | 每次保存 +1 |

**已落地**：迁移 `086_project_charter.sql`、`src/server/project-charter.ts`、`GET/PUT /api/v1/projects/:id/charter`。**待接**：工作台里的编辑界面。

## 2. 防跑偏（不靠提示词自觉）

- **注入**：每轮把框架卡摘要作为约束送进上下文，要求回答末尾声明「本轮是否服务于目标」；
- **检测**：规则比对（是否提到非交付物主题、是否在扩范围），命中就在消息上标「可能偏离主线」；
- **不拦截**：只让偏离可见，用户可一键标为「主线之外」。

## 3. 沉淀到团队空间

- **只本人主动**勾选若干轮 → AI 压缩成摘要 → **发布前可编辑** → 写入团队空间；
- 团队空间助手读这些条目做四块总结：**进展 / 决策 / 待办 / 风险**；
- 边界：不自动上传、不带密钥、不带他人私有内容；只总结不打分。

## 4. 选手之间的 AI：用共享事实，不做 AI 直连

**决定：不做 AI 与 AI 直接互调。** 理由：任何一方被提示注入，都可能绕过人的确认去驱动另一方执行动作。

替代设计（效果接近，风险可控）：

1. 队员 A 的 AI 生成「交接摘要」（进展、卡点、需要谁配合）；
2. **A 点确认**后写入团队空间；
3. 队员 B 的 AI **只读**这条摘要，并把回应生成为新草稿；
4. **B 点确认**后才发布。

规则：
- AI 之间**没有**直接通道；一切经过团队空间这个共享事实层；
- 每条摘要都记作者与时间；不得代他人发言、不得评价队友；
- 摘要只读，不能作为执行指令（提示注入防线：它只是引用材料）。

## 5. 分期

| 期 | 内容 | 验收 |
| --- | --- | --- |
| P1 | 框架卡界面（起草/编辑/锁定/版本冲突） | 锁定后 AI 能看到 |
| P2 | 防跑偏注入 + 规则标记 | 故意跑题被标出 |
| P3 | 勾选 → 摘要 → 发布到团队空间 | 条目出现在团队空间 |
| P4 | 团队 AI 四块总结 | 只含事实，不含评价 |
| P5 | 交接摘要（A 确认 → B 的 AI 只读回应 → B 确认） | 全流程有人工节点 |
