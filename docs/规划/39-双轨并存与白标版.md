# 规划 39 · 双轨并存：公共站 + 白标版

> 2026-10-18。用户确定「并存」：公共 C 端继续作为获客与个人选手入口；白标版面向企业/学校/政府办赛，**数据不出机构、选手不进公共池**。

## 1. 两条产品线

| | 公共版（现状） | 白标版（新增） |
| --- | --- | --- |
| 面向 | 个人选手 | 机构办赛 |
| 赛事目录 | 公开可搜 | **不存在**（只有本机构赛事） |
| 组队大厅 | 跨机构可见 | **仅本场、本机构** |
| 参赛名片 | 公开 | **不公开**，仅在主办方开的范围内 |
| 品牌 | 平台品牌 | **客户品牌**，无平台痕迹 |
| 数据 | 平台托管，用户可导出 | 客户主权，可全量导出 + Webhook |
| 部署 | 平台 SaaS | SaaS 分租 / 私有化 |

## 2. 隔离模型（一个开关，不是两套代码）

机构级配置 `deploymentMode: "public" | "white_label"`，默认 `public`。

`white_label` 时**强制生效**：
- 关闭公共赛事目录、灵感库、跨机构招募；
- 组队大厅只在本场范围内可见（已有三门槛，再加机构边界）；
- 参赛名片不进入任何公共检索；
- 页脚、登录页、错误页、邮件模板换成客户品牌；
- 导出与 Webhook 默认开启。

**代码上不新增第二套页面**：既有页面按 mode 隐藏/替换，路由与权限只有一套。

## 3. 数据主权（客户要能验证，不是口头承诺）

| 能力 | 现状 | 要做 |
| --- | --- | --- |
| 全量导出（报名/结果） | 部分有 | 补全：团队、提交、评审、日志 |
| Webhook 推送 | 无 | 新增：签名、重试、幂等、**只增不改** |
| 删除 | 无 | 机构级删除与保留期说明 |
| 数据用途 | 宪法 XII 已禁训练 | 在白皮书里写明 |

Webhook 纪律：**单向投影**，绝不反向写回平台；失败重试有上限；不推送他人私有内容。

## 4. 品牌与域名

| 阶段 | 内容 |
| --- | --- |
| P2 | 品牌整体替换（logo/名称/主色/页脚/邮件） |
| P3 | 客户自有域名 + 通配符证书自动签发 |
| P4 | 私有化部署包（数据库/迁移/密钥/升级路径） |

域名与 TLS 是我们至今未解决的公网边界，**先解决自己的，再谈客户的**。

## 5. 宪法影响

建议新增原则 **XVI「数据主权与白标边界」**：
- 机构数据 MUST 可全量导出、可删除；
- MUST NOT 跨机构聚合或用于训练；
- 白标模式 MUST NOT 让选手进入任何公共池；
- 平台品牌 MUST 可在白标模式整体移除；
- Webhook MUST 为单向投影，不得成为第二写入路径。

## 6. 分期

| 期 | 内容 | 验收 |
| --- | --- | --- |
| P1 | `deploymentMode` 配置 + 隔离生效 | 白标模式下公共目录/大厅 404 或空 |
| P2 | 品牌替换（含页脚/邮件） | 页面上找不到平台品牌 |
| P3 | 全量导出 + Webhook | 客户库能收到并去重 |
| P4 | 客户域名 + 证书 | 自有域名可访问 |
| P5 | 私有化部署包 | 空机上能跑起来 |

## 7. 话术（对外）

> 我们不做选手社区，我们给每个主办方一套专属的 AI 办赛平台：页面是你的、域名是你的、数据在你库里。我们只提供两样东西——让选手不卡在流程上的 AI，和让组委会少干重复活的 AI。你的选手不会出现在任何公共池子里。

**不说「提高完赛率」**（无可验证度量），说「不卡在流程上」（报名向导、提交检查、缺件提示都能演示）。
