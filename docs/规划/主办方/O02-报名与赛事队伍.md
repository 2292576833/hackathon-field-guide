# O02 报名与赛事队伍

日期2026-10-11；规划21、宪法v1.11.0。独占新 src/modules/event-registration/ 与 docs/协作/交付/event-registration.md。其他文件由根统一，禁止build/重启/实际迁移。

## 目标与简单流程

赛事页带入正确比赛→展示简短表单→本人提交→收到真实报名结果/审核状态→组队或进入已有队伍。加入队伍需要本人同意；同账号可多赛事，但一赛事只一活跃正式队伍。

主办方发布报名表后，在工作台复制本站报名链接，自行分享到微信、公众号、小红书等平台。所有渠道收集的报名集中到本场“查看报名与审核”，默认待审核，按实际审核开关显示待审核或服务器确认的已通过结果。公开链接不附带审核/答卷权限；报名记录仅本人和有当前本场报名管理权限的工作人员查看。

## 实施任务

1. 定义版本化Form/Field，常用字段text/textarea/number/choice/multichoice/url，白名单长度/选项/必填/允许值。原始HTML/任意规则表达式不执行，字段说明纯文本。邮箱来自真实账号无需再填，同步资料需本人确认。
2. 持久服务配置form、保存draft、提交、withdraw、review、listown/liststaff、分页/CSV导出。免费报名；关闭审核才直接approved。容量/最后名额/幂等同事务，锁event统一顺序，退出/拒绝处理名额显式规则且保留历史。
3. 队伍create/list公开最小招募投影/requestjoin/accept/reject/leave/rosterlock，队长不能代替成员注册/通过/接受。人数上下限、参加资格、赛道、状态校验，mixed模式提供人工建议/确认入口，不自动强制加入。
4. EventParticipationPort实现：getRegistration/getTeam；按event限定，不泄漏答卷/邮箱。名单确认版本保存；成员退出/报名失效影响参赛资格但不删除私人M02记录。
5. 已有私人项目关联通过root ProjectLinkPort显式确认当前manager、赛事与队伍；不直接写M02表。初版可以无私有Project仍正式组队，关联入口清楚。
6. 前端 RegistrationPanel、RosterTeamsPanel、RegistrationManager、MyCompetitions 导出ui.ts；注册保留returnTo；加入/错误/拒绝说明下一步，不要求懂租户/JSON。
7. SQL建议、postgres适配、index/README、API/Port/节点测试/交付。

## 共同规则

报名表发布形成版本，答卷持原schema与revision，不用新字段重写旧答案。报名在服务器时间窗口内执行，日期时区由O01EventScope。模块关闭不能假装清除既有报名；只读历史保留，未报名不能被当合格队员。first draft不是submitted。Staff仅registration_manage可看答卷/导出，teams_manage只能队伍运营必要字段。

私有草稿仅本人。参加定位/目的可选，不强制年龄/MBTI或借其推断能力。报名与现有auth账号注册分别命名。导出CSV转义公式、当前权限复核，不公开暴露邮箱名单。

## HTTP建议

GET/PUT /organizer/events/:eventId/registration-form；
GET /competitions/:eventId/registration-form；
GET/PATCH /competitions/:eventId/my-registration；POST submit/withdraw。
GET /organizer/events/:eventId/registrations；POST registrations/:id/review；GET export。
GET/POST /competitions/:eventId/teams；POST teams/:id/join-requests、requests/:id/respond、leave、lock、project-link。
GET /me/competitions。精确API在交付登记，根组合最终路径。

## 验收

两赛同用户/一赛唯一注册；草稿/审核/批准状态；动态字段旧版保护；并发最后名额；重复提交/撤回；报名关闭；跨赛队伍/猜ID；非队长操作；队长无法代全员接受；私人Project不因关联被主办读取；CSV/公开投影不漏资料。
