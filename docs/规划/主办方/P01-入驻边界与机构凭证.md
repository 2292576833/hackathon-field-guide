# P01 入驻边界与机构凭证

日期：2026-10-11。遵循 [规划25](../25-主办方入驻完善-认领赛事与补充未知.md)、规划21、宪法 v1.15.0。

**依赖**：无。可独立先做，是 P02 的文案前提。

## 目标

主办方第一次进入 `/organizers` 时，**先看懂我们要什么、能做什么、不做什么**，再决定是否入驻；提交申请时按机构类型看到具体凭证提示，减少来回驳回。

## 实施任务

1. **边界与"不做"清单**（文案，落在 `/organizers`）
   - 我们做：正式规则与报名表、报名审核、队伍名单、通知与问答、行程与现场服务、材料收件、人工评审与结果公布。
   - 我们不做：收款/退款/开票、短信账号与短信通知、接管选手私人备赛空间与私人 AI 对话、自动决定录取/晋级/获奖、在第三方平台替主办方发消息。
   - 明确：入驻**不等于**自动招生；平台只确认归属，不替主办方背书赛事质量。
2. **机构类型与凭证清单化**
   - 类型保持 `school` / `company` / `community`，新增 `platform`（平台型，如 ETHGlobal、lablab：报名在其平台完成，本站只做信息与准备辅助）。
   - 每类型给出**推荐凭证提示**（见规划25 第13节表格），并说明社团代办需注明授权关系。
   - 表单保持"受控文字说明 + HTTPS 依据链接"，不抓取任意内网 URL（沿用 O01 既有边界）。
3. **状态说明**
   - `pending` / `approved` / `rejected` / `suspended` 各自显示**下一步动作与等待说明**；驳回给可执行的补充方向，不空留错误。
4. **不新增数据表**；本节只改文案、类型枚举与表单提示，凭证仍走既有申请字段。

## 验收

- 不用编辑 JSON 即可提交入驻申请；
- 未登录可看全部边界说明；登录后保留原目的地返回；
- 四种类型都给出对应凭证提示；`platform` 类型明确"报名在第三方平台"；
- 手机端主要按钮无需横向滚动，长文案可展开；
- 不出现"保证招生""自动晋级"等表述。

## 范围

仅主办方入驻入口文案与表单提示；不改 O02–O04，不改评审与报名逻辑。实施时按协作登记授权文件范围。
