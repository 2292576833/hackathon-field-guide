# P02 认领已发现赛事

日期：2026-10-11。遵循 [规划25](../25-主办方入驻完善-认领赛事与补充未知.md)、规划21、宪法 v1.15.0。

**依赖**：P01 的边界文案（可并行，但发布顺序建议 P01 先）。可在 `src/modules/organizer/` 内扩展，另加根侧只读候选 Port。

## 目标

解决"同一场比赛存在两份事实"：主办方入驻后可以**认领**我们已发现的赛事，把抓取到的信息作为预填草稿，避免从头录第二遍。

**核心约束**：候选匹配**不产生任何权限**；未通过归属核实前，**不得改写任何公开内容**。

## 数据

新增两项事实，均由 O01 organizer 拥有（详见规划25 第9节）：

- `OrganizerClaimRequest`：`id`、`organizationId`、`discoveryId`、`requestedBy`、`verification`（`official_domain_mailbox` / `official_statement` / `authorized_document` / `platform_source_page` / `other`）、`evidenceText`、`evidenceUrls[]`、`status`（`pending`/`approved`/`rejected`/`withdrawn`）、`reviewedBy`、`reviewedAt`、`note`、`revision`、时间戳。
- `HostedEvent.claimedDiscoveryId`：可空、**唯一**；同一 discovery 只能被一个 HostedEvent 认领。

**不复制发现卡片数据**：批准时把预填值写入 HostedEvent 草稿字段，之后走既有"草稿 → 预览 → 发布版本"。

## 接口

- 只读候选（根提供，读自动发现存储）：`list(sql, organizationId)` 返回 `{discoveryId, title, sourceUrl, sourceHost, analyzedAt, matchReason}`；`matchReason` ∈ `source_host` / `name_conflict` / `manual_pick`。
- `assertClaimable(sql, discoveryId)`：确认仍 `active` 且未被认领。
- 认领申请：`POST /organizer/claims`（body：`discoveryId`、`verification`、`evidenceText`、`evidenceUrls`）；`GET /organizer/claims`（本人机构）；`POST /organizer/claims/:id/withdraw`。
- 平台审核：`GET /admin/organizer/claims`；`POST /admin/organizer/claims/:id/review`（`{decision, note, expectedRevision}`）。
- 路径与工厂方法由根最终统一，提交时精确登记。

## 规则

- **仅平台当前 admin 可批准**；机构负责人不能自审，`reviewer` 身份不自动获得批准权。
- 候选只作提示；来源域名相同或名称相似**不构成授权**。
- 同一 discovery 已被认领时，后续申请明确拒绝并说明现有归属。
- 批准必须**同事务**复核：账号与请求会话、机构状态、`event_manage` 能力、discovery 仍可认领、`expectedRevision`。
- 批准后该 discovery 与 HostedEvent 建立唯一关联；公开页以 HostedEvent 发布版本为准，原发现记录保留不可变。
- 撤回认领：不删除已发布赛事与历史；**不自动回退成抓取版本**，按现状展示并提示归属待确认。
- 认领失败/无匹配：明确引导用模板新建，新建后可填官方规则页链接以对齐抓取。

## 安全与失败

- 直接猜 `discoveryId`、`claimId`、跨机构 ID 均返回拒绝，不泄露他人赛事的私密字段。
- 认领流程**不依赖 AI**：匹配依据是可核对的来源域名与名称；模型不得判定"这就是你的比赛"。
- 邮件核实失败、超时、重放：保留申请与失败原因，允许重新发起；**不因重试产生第二份批准事实**。

## 验收

1. 认领候选可见但不产生权限；非管理员无法批准。
2. 未批准的认领**不能改动任何公开卡片**（含直接调 API）。
3. 同一 discovery 只能被认领一次；重复认领被拒并说明归属。
4. 批准后公开页显示主办方版本；抓取版本仍可追溯。
5. 撤回后不自动回退成抓取版本。
6. 跨机构、过期会话、撤权、缓存、猜测 ID 均不越权。
7. 手机端可完成"看候选 → 提交认领 → 看结果"。

## 范围

`src/modules/organizer/`（认领实体与服务）、根侧只读候选 Port、`src/server/organizer-*` 组合、实际迁移与页面由主会话接入。模块不直接读自动发现存储，通过注入 Port。
