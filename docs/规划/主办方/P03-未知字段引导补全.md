# P03 未知字段引导补全

日期：2026-10-11。遵循 [规划25](../25-主办方入驻完善-认领赛事与补充未知.md)、规划21、宪法 v1.15.0。

**依赖**：可独立做；认领（P02）完成后体验更连贯。

## 目标

把主办方的填报从"从头填一张表"变成"**我们只确认了这些，剩下的请你补**"。

当前真实数据是这件事的依据：运行库 15 场赛事里**只有 3 场**有时间窗口证据，其余为空；有证据的 3 场里 2 场仍标 `unknown`。**"报名截止时间未知"是常态，而只有主办方能给权威答案。**

## 数据与接口

**不新增完成状态、不落勾选表、不落完成百分比。** 清单是**派生视图**。

`OrganizerEventReadinessPort.list(sql, eventId)` 返回（详见规划25 第10节）：

```
{ field, state, sourceEvidence[], sourceUrl, checkedAt, priority }
field: registrationClosesAt | registrationOpensAt | startsAt | endsAt | timezone
     | tracks | requiredMaterials | submissionMethod | judgingRounds | resultsAt
     | fee | eligibility | aiPolicy
state: known_from_organizer | known_from_source | missing | conflicting
priority: 1（影响报名决策）| 2 | 3
```

数值来源：
- `sourceEvidence` / `sourceUrl` / `checkedAt`：读自动发现卡片中已保存的证据与核验时间（根提供只读 Port）；
- `known_from_organizer`：来自 HostedEvent 草稿/发布版本的对应字段；
- `conflicting`：两侧都有值且不一致。

## 规则

- 只读清单**不写任何业务数据**；浏览不等于确认（沿用规划16/18）。
- 补全写入 HostedEvent 草稿，带 `expectedRevision`，冲突不覆盖；发布后成为新版本。
- 时间字段必须带**时区**；多阶段截止分别记录（沿用规划21/22）。
- `known_from_source` 与 `known_from_organizer` 在界面上**必须可区分**；只有后者可标注"主办方已确认"。
- `conflicting` 必须**显式展示两侧依据**，由人决定，**不自动取新值覆盖**。
- 不允许把抓取值或模型摘要直接标成主办方确认。

## 页面

`/organizers/workspace/events/:eventId/readiness`（挂在主办方工作台内，**不新增一级导航**）：

- 默认按 `priority` 排序，**报名截止排第一**；
- 每项显示：字段名、当前状态、我们的依据（含原文片段与链接）、核验时间、可编辑输入、保存动作；
- 保存成功/失败分别说明；失败保留本页输入；
- 手机端主要动作可独立完成，长证据可折叠。

## 验收

1. 清单为派生数据：只读访问不产生任何写入、不产生完成度；
2. 补全"报名截止"后，选手在该场看到有出处的权威时间，而非空白；
3. `known_from_source` 与 `known_from_organizer` 可区分，且只有后者标注为主办方确认；
4. `conflicting` 展示两侧依据，不自动覆盖；
5. 并发保存按 revision 拒绝旧版本，不静默覆盖；
6. 非本赛事工作人员无法读取或写入该清单；
7. 不依赖 AI：DSH 不可用时清单与保存仍可用。

## 范围

`src/modules/organizer/`（readiness 服务与组件）、根侧只读证据 Port、`/organizers/workspace/**` 页面与组合由主会话接入。不修改 O02–O04 的报名与评审逻辑。
