# P05 · 复制上一场活动与配置复用

> 总纲：[规划 33 · 主办方可用性与赛后闭环](../33-主办方可用性与赛后闭环.md) 第 5 节第 1 期
> 对应缺口：**N1**
> 宪法依据：v1.21.0 原则 VII（简单可维护）、X（不新增第二套入口）、XI（多赛事与不可变发布版本）、XII（吸收闸门）
> 状态：**尚未实施代码**，待总纲第 8 节决策点 1、2 确认

## 1. 要解决的真实问题

主办方每办一场赛事，都要把**同一套配置**重填一遍：基本信息、赛道、报名表单字段、评审维度与权重、品牌配置、模块开关。现有能力只能提供**模板默认值**（`online` / `onsite` / `practice` 三个固定 `version: 1` 模板），**带不走上一场实际改过的内容**。

已核对事实（不得重复建设）：

| 事实 | 证据 |
| --- | --- |
| 全仓**没有**任何复制/克隆赛事实现 | `grep -r "copyEvent\|duplicateEvent\|cloneEvent\|复制上一场"` 无匹配 |
| 创建走 `createEvent(principal, organizationId, CreateEventInput)`，模板只提供默认字段 | `src/modules/organizer/service.ts`、`model.ts` L102–108 |
| 事件创建需并发校验 `expectedOrganizationRevision` | `CreateEventInput`（`model.ts` L108） |
| 报名表每场一份、按 `revision` 递增 | `event-registration/service.ts` `getForm` / `saveForm`、`RegistrationForm`（`model.ts` L9–12） |
| 已发布版本是不可变快照 | `PublishedEventRevision`（`model.ts` L88–91）、不可变触发器 |

## 2. 闸门三问（宪法 XII）

**① 解决我们哪个真实问题**
主办方每场从零重配，且模板无法携带上一场实际改过的配置（赛道、表单字段、评审权重）。这是可复现的重复劳动，不是"竞品有所以我们要有"。

**② 会碰到的既有能力**
`organizer` 的模板、`createEvent`（含 `expectedOrganizationRevision` 并发校验）、`PublishedEventRevision` 不可变快照、`EventModuleFlags`；`event-registration` 的 `getForm` / `saveForm`（含 `SaveFormInput` 的 `expectedRevision`）。

**③ 冲突风险与处理决定**
- **风险 A**：若复制的是**已发布版本**并直接成为新赛事的正式规则，等于把上一场的正式声明静默变成这一场的规则 —— 与"发布是不可变版本、每次发布需 `changeSummary`"冲突。
  → **决定**：只读**当前草稿**（`getManagedEvent`）作为来源；来源是已发布赛事时也复制其**当前草稿**，**不读发布快照**。新赛事一律从 `status=draft` 开始，必须重新 `previewEvent` + `publishEvent` + 填 `changeSummary`。
- **风险 B**：容易做成第二个创建入口或第二套写路径。
  → **决定**：动作放在**既有创建向导第一步**内，走既有 `createEvent` 与 `saveForm`，**不新增表、不新增仓库方法、不新增路由族**。

## 3. 复制范围（决策点 2）

| 项 | 复制 | 说明 |
| --- | --- | --- |
| `title` | ✅ 加后缀 | 默认 `<原名>（副本）`，允许当场改 |
| `timezone` | ✅ | 沿用，避免跨时区误算 |
| `startsAt` / `endsAt` | ⚠️ **平移，不照抄** | 见第 2.1 节：保留来源的**时间结构**，整体平移到当前时刻；**绝不沿用上一届的绝对日期** |
| `registrationOpensAt` / `registrationClosesAt` / `submissionClosesAt` | ⚠️ **平移** | 同上；相对开赛的位置保持不变，绝对值全部重算 |

### 2.1 时间字段的落地修正（2026-10-16，实施中发现）

原定案写的是"时间字段**不复制**、必须重填"。实施时发现这与共享契约冲突：

- `HostedEvent.startsAt` / `endsAt` 在 `src/shared/organizer-contracts.ts` 里是**非空 `string`**（只有 `registrationOpensAt` / `registrationClosesAt` / `submissionClosesAt` 是 `string | null`）；
- `createEvent` 也要求这两个时刻有效。

若复制出的草稿带上空时刻，会造出一个**类型上不可达、且 `publishEvent` 会拿无效日期做比较**的赛事——这比"沿用时间"更糟。

**落地做法（`shiftedOccurrenceTimes`）**：保留来源的**时间结构与各截止的相对位置**，把整段排期**平移到当前时刻**。

- 不沿用上一届的绝对日期（`2026-10-20` → `今天 + 相同跨度`），这正是"不继承时间"真正要避免的事；
- 报名窗口、作品截止、队伍锁定**相对开赛**的位置保持不变；
- 新赛事可立即编辑与发布，主办方在**发布前仍需逐项确认**每个时刻（发布快照会锁定它们）。

**这是对原定案的修正，不是静默偏离**：原定案的目的（"避免上一届截止变成这一届"）由平移达成，且不引入类型上不可达的状态。界面上的"将复制 / 不复制"对照 `MUST` 如实描述为"时间必须重新确认"，`MUST NOT` 写成"时间已保留"。若用户更希望**留空强制重填**，则需同时改共享契约里 `startsAt`/`endsAt` 的可空性——属独立决策，另行提出。
| `registration.reviewRequired` / `capacity` | ✅ | 审核开关与名额 |
| `teams.mode` / `minSize` / `maxSize` | ✅ | `locksAt` ❌ 不沿用 |
| `modules`（`EventModuleFlags`） | ✅ | 模块开关 |
| `summary` / `rules` / `location` / `format` / `templateKey` | ✅ | `summary`/`rules` 内容照抄但**状态是草稿**，发布前需重新确认 |
| 报名表单 `title` / `description` / `fields[]` | ✅ | 经 `saveForm` 写成**新赛事自己的** `revision=1` 表单 |
| 报名表单 `id`（字段 id） | ⚠️ 保留字段 id | 字段 `id` 是表单内标识，随表单走；**不复制答卷** |
| 评审维度与权重（`JudgingConfig`） | ✅ | 经 `saveConfig` 写成新赛事的 `setup` 轮次（`revision=1`） |
| 品牌配置（Logo/主题色/Banner） | ✅ | 机构级，新赛事读取即可 |
| `linkedEventId`（M03 关联） | ❌ | 必须显式重设，不得继承（宪法 II：不能因名称相同合并） |
| 报名与答卷、正式队伍、通知与已读、评审轮次/指派/评分、申诉、审计、`publishedRevision` | ❌ | **一律不复制** |

**来源赛事状态限制**：只接受 `draft` / `published` / `ended`；`archived` 可作为来源（只读），但其配置可能已过时，界面需提示。

## 5. 明确不做

- ❌ 复制**发布快照**作为新赛事起点（发布快照不可作为草稿来源）
- ❌ 复制报名答卷、正式队伍、通知与已读、评审轮次/指派/评分、申诉、审计
- ❌ 继承 `linkedEventId` 或任何 M03 关联
- ❌ 新增第二个创建入口、第二套写路径、新表或新状态
- ❌ "从上一场导入选中部分"的字段级勾选器（第一期不做，避免复杂度；若真实需要另起一期）
- ❌ 跨机构复用（不得绕过组织隔离）

## 6. 验收

| 项 | 口径 |
| --- | --- |
| 独立可编辑 | 复制出的新赛事可独立改、`previewEvent`、`publishEvent`、`end`、`archive` |
| 来源不受影响 | 复制前后，来源赛事的 `revision`、草稿字段、`publishedRevision`、发布历史**逐字段不变** |
| 无半成品 | 任一步失败（如表单字段非法）后，机构下**不新增**赛事；断言事务回滚 |
| 单一路径 | 新赛事的创建只经由既有 `createEvent`；断言**没有**第二处写 `organizer_hosted_events` 的调用点 |
| 时间不照抄 | 新赛事的时间**不等于**来源赛事的绝对时间；相对开赛的跨度保持一致（断言两者都不成立即失败） |
| 跨机构拒绝 | 来源赛事属于另一机构时 403（或 404），且不产生副本 |
| 并发 | 过期的 `expectedOrganizationRevision` 返回既有版本冲突错误，保留输入 |
| 发行为草稿 | 新赛事 `status=draft`、`publishedRevision=null`；未经 `publishEvent` 不出现在 `/competitions` |
