## 1. N2 · 评审进度追踪

### 1.1 要解决的真实问题

`service.workspace()` **已经返回** `rounds / submissions / assignments / scores`（`event-judging/service.ts` L314–322），但**没有任何地方把它聚合成**"哪件作品还差几位评委、哪位评委还没交"。主办方只能逐个作品点开数。

**关键结论：缺口在聚合与呈现，不在数据。** 因此本项 `MUST NOT` 新增读路径、表或查询。

### 1.2 闸门三问

**① 真实问题**：`workspace()` 已有全部集合，但主办方拿不到"卡在哪"。
**② 既有能力**：`workspace()`、`aggregate()`、`calibration()` 的有效指派判定、`checkedIn()`（`service.ts` L141）、`JudgingPanels.tsx` 既有面板。
**③ 冲突风险与决定**：
- 风险：做成第二套评审状态或"完成百分比"。
- **决定**：**纯派生只读**视图，**不新增状态列、不落库、不加表**；判定复用与 `aggregate()`/`calibration()` **同一套**"有效指派 + 已提交"口径，不得另写一套；措辞只报"已有 / 还差"。

### 1.3 内容设计

| 层级 | 内容 | 口径 |
| --- | --- | --- |
| 作品 | 每件本轮冻结作品：已提交有效评分数 / `round.config.minJudges`；还差几位 | 与 `calibration()` 的有效性判定一致 |
| 评委 | 本轮每位被指派评委：已提交数 / 应评数 | `recused`、`revoked` 排除并**标注原因**，不混入分母 |
| 轮次 | 尚未收齐的作品清单（按缺口数降序，同数按作品标识稳定排序） | 不排名评委 |

**措辞纪律**：
- `MUST NOT` 出百分比、进度条、完成度、"落后"。
- `MUST NOT` 把"未提交"写成"不负责"或推断态度；只陈述事实。
- 无指派时为**空态**，`MUST NOT` 凭空造出评委行。

## 2. N4 · 已公布结果导出

### 2.1 要解决的真实问题

赛后要把结果交给赞助方、学校或留档。现状：

- `service.exportScores`（`service.ts` L674–682）导出的是**指派对账用的内部分数表**：指派编号、评审轮、作品快照、**评委账号**、指派状态、评分状态、维度 JSON、评语。
- **没有**"作品 → 队伍标识 → 总分 → 名次 → 已批准反馈"这种**面向留档**的口径。

**关键结论：这不是从零做导出**，而是**加一种导出口径**并复用既有 CSV 生成与防公式注入（`csvCell`）。

### 2.2 闸门三问

**① 真实问题**：已公布结果无法一次性留档，只能一页页看。
**② 既有能力**：`exportScores` 与 `csvCell` 防注入、`projection()`（`service.ts` L195）已公布投影、`staff()` 权限、`audit()`。
**③ 冲突风险与决定**：
- 风险：导出带出评委真名、联系人、答卷、私人求助；或做出"公开榜"。
- **决定**：**只导出主办方已发布过的投影字段**；对外留档件 `MUST NOT` 含评委账号或真名；不新增公开页面。

### 2.3 两种导出的关系（不得互相覆盖）

| 导出 | 用途 | 含评委账号 | 文件名单 |
| --- | --- | --- | --- |
| `exportScores`（**已有，保留**） | 内部对账、核查谁没评 | ✅ 含 | `judging-scores.csv` |
| `exportResults`（**新增**） | 留档、交给赞助方/学校、发布附件 | ❌ 不含 | `judging-results.csv` |

界面 `MUST` 用一句话说明两者区别，避免主办方拿错（宪法 X：多入口须说明分工）。

### 2.4 内容设计

| 列 | 来源 |
| --- | --- |
| 作品名称 | 冻结快照材料标题 |
| 队伍标识 | 快照 `teamId`（**不导出成员姓名与联系方式**） |
| 总分 | `projection()` 的已公布总分 |
| 名次 | 已公布名次（并列共享） |
| 人工批准反馈 | 该作品**已批准**的公开反馈 |
| —— | 文件头注释行：赛事、轮次、**公布版本号**、生成时间 |

**状态处理**：`needs_review` 时 `MUST NOT` 输出分数与名次，只输出状态与版本；`waiting_publication` 时拒绝导出并说明原因。

## 3. 两项共同的前置与风险

| 项 | 说明 |
| --- | --- |
| 前置 | 无。两者都不需要新迁移；N2 只读、N4 只加一种 CSV 口径 |
| 风险：口径漂移 | 若 `aggregate()` 或 `calibration()` 的"有效指派"判定将来变化，`progress` 必须同步；用"三处计数必须相等"的测试固定 |

| 风险：面板堆积 | `JudgingPanels` 下已有 `calibration` / `integrity` / `duplicates` / `fairness` 四个折叠面板；再加一个 `progress` 时 `MUST` 检查首屏不遮挡关键期限与正式操作 |
