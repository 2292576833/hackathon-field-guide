# P07 · 数据看板下钻

> 总纲：[规划 33 · 主办方可用性与赛后闭环](../33-主办方可用性与赛后闭环.md) 第 5 节第 3 期
> 对应缺口：**N3**
> 宪法依据：v1.21.0 原则 II（事实可追溯、不编造）、X（不新增入口、`undefined`≠`0`）、XII（不做不透明评分与预测）
> 状态：**尚未实施代码**，待总纲第 8 节决策点 4 确认

## 1. 要解决的真实问题

工作台与各 section 页已有**真实计数**（`EventReadiness.tsx`、`registrationCounts()` 等），但停在**总览**。主办方拿不到这样的问题答案：

- 哪个赛道的提交少？
- 哪些队伍还没收件？
- 哪位评委进度慢？（与 P06 共用口径）
- 报名的时间趋势如何？
- 后勤还有多少人没分配住宿/餐券？

**关键结论**：这些问题的原始读数**都已在既有模块里**，缺的是**筛选视图**。因此本项 `MUST` 以"复用既有读取、不另算一套"为硬约束。

## 2. 闸门三问（宪法 XII）

**① 真实问题**：计数只有总数，无法按赛道/队伍/评委/时间筛。
**② 既有能力**：`organizer` 的 `EventReadiness` 与机构/赛事授权；`event-registration` 的报名分页与 `registrationCounts()`（`GROUP BY status`）；`event-judging` 的 `workspace()` 与 P06 的 `progress()`；`event-communication` 的行程与后勤分配。
**③ 冲突风险与决定**：
- 风险最大的两条：**变成"影响力/ROI 看板"** 与 **另算一套数字**。
- **决定**：`MUST` 只做既有事实的筛选与下钻；`MUST NOT` 出预测、成功率、影响力分、跨赛事优劣排名；每个数字 `MUST` 与既有模块各自读到的数字**逐一相等**；`undefined`（未读取）`MUST NOT` 显示为 0，空值写"未提供"。

## 3. 面板范围（决策点 4）

| 面板 | 下钻维度 | 数据来源（既有） |
| --- | --- | --- |
| 报名 | 状态、赛道、时间区间 | `event-registration` 报名分页与计数 |
| 队伍 | 人数分布、材料齐全度、关联空间状态 | `event-registration` 正式队伍、`event-judging` 收件 |
| 收件 | 已交 / 未交 / 已交但材料过薄 | `event-judging` 收件回执 |
| 评审 | 轮次进度、已公布状态 | `event-judging` `progress()`（P06）与 `workspace()` |
| 后勤 | 住宿已分配/未分配、餐券已发/已核销、行程覆盖 | `event-communication` `logistics` / `schedule` |

**每个数字必须带**：统计范围（本场/本轮）、数据时间（读取时刻）、口径说明（计的是什么）。

## 5. 明确不做

- ❌ 预测、成功率、"影响力分"、"ROI"、成果转化预估
- ❌ 跨赛事优劣排名、给队伍或评委打综合分
- ❌ 为看板新建宽表、物化视图或第二份计数事实
- ❌ 新增一级导航或第二个工作台
- ❌ 把看板数字做成可对外公开的页面（公开面仍只走既有 `/competitions` 投影）
- ❌ 用模型生成"分析结论"（宪法 XI：AI 只做格式、规则核对、去重提示和摘要）

## 6. 验收

| 项 | 口径 |
| --- | --- |
| 数字一致 | 同一筛选条件下，看板每个数字与对应模块各自读到的数字**逐一相等**（断言，不是目测） |
| 未读取≠0 | 未读取的维度返回 `undefined` 并显示"未读取 / 未提供"，`MUST NOT` 显示 0 |
| 空值不补 | 无数据时不补占位、不补零、不编造趋势 |
| 无预测文案 | 全量搜索看板相关文案，`MUST` 不出现"预测/成功率/影响力/ROI/最佳/排名" |
| 权限 | 本场 `staff` 且具备相应 capability 才可见对应面板；跨机构 403/404；匿名 401 |
| 只读 | GET 不触发采集、模型、通知或任何写入（沿用既有公开 GET 纪律） |
| 首屏 | 新增面板不遮挡关键期限、正式操作与错误信息（宪法 X） |

## 7. 风险与前置

| 风险 | 应对 |
| --- | --- |
| 口径漂移 | 每块面板的测试都断言"与来源模块相等"，而不是断言固定数字 |
| 数据量大 | 首批试用规模小；分页复用既有 `Page<T>` 游标，不做全表聚合 |
| 诱导做排名 | 面板内 `MUST NOT` 按分数排序队伍或评委；排序只允许按计数、时间或标识 |
| 与 `organizer-action-center` 重复 | 该组件负责"唯一下一步 + 发布门槛"；看板负责"看数据"。两者 `MUST NOT` 表达同一件事，接入时逐项核对 |
