# P08 · 选手侧资源与下一步汇总

> 总纲：[规划 33 · 主办方可用性与赛后闭环](../33-主办方可用性与赛后闭环.md) 第 5 节第 5 期
> 对应缺口：**N5**
> 宪法依据：v1.21.0 原则 II（不编造、不承诺未确认资源）、VI（最小权限）、X（不新增入口、不新增状态）
> 状态：**尚未实现代码**，无决策点阻塞（可直接实施）

## 1. 要解决的真实问题

选手进入一场赛事后，自己"能领什么、要做什么"分散在四处：

| 现状位置 | 内容 |
| --- | --- |
| `/competitions/[eventId]` | 规则、报名状态、最新官方通知 |
| `/competitions/[eventId]/schedule` | 行程 |
| `/competitions/[eventId]/services` | 本人的住宿、餐券、破冰活动 |
| `/competitions/[eventId]/help` | 公开问答与本人求助 |

选手需要自己拼。**这些读数都已存在**（`event-communication` 的公告/已读、行程、住宿、餐券、求助；`event-registration` 的本人报名与队伍），缺的是**一处只读汇总**。

**关键结论：缺口在汇总呈现，不在数据。** 因此本项 `MUST NOT` 新增发放事实、领取状态或核销状态。

## 2. 闸门三问（宪法 XII）

**① 真实问题**：选手要跳三四个页面才能知道自己当前能领什么、还差什么。
**② 既有能力**：`event-communication`（`Announcement`/`ReadReceipt`、`ScheduleRevision`、`AccommodationAssignment`、`MealVoucher`/`Redemption`、`HelpTicket`/`Reply`）、`event-registration`（`MyRegistrationView`、本人队伍）、`event-judging`（`my-checklists`）。
**③ 冲突风险与决定**：
- 风险：建第二份"发放记录"、第二个"我的赛事"入口，或承诺算力 Token。
- **决定**：**只读汇总既有记录**，每一项**指回原记录并保留原入口**；不新增发放/领取/核销状态；算力 Token **本期不承诺**（官方接口未确认，见总纲第 7 节 G5）。

## 3. 内容设计

| 区块 | 内容 | 指回原记录 |
| --- | --- | --- |
| 我的报名 | 状态（草稿/待审/已通过/未通过/已撤回）、审核说明（若有） | `/competitions/[eventId]/register` |
| 我的队伍 | 队伍名、我在队内的身份、成员数（受既有可见性约束） | `/competitions/[eventId]/teams` |
| 重要期限 | 报名截止、作品截止（**有值才显示**） | 赛事已发布规则版本 |
| 官方通知 | 已发布公告标题与**本人已读/未读** | 原公告 |
| 我的行程 | 本人可见行程条目 | `/competitions/[eventId]/schedule` |
| 我的后勤 | 住宿安排、餐券（**仅本人**） | `/competitions/[eventId]/services` |
| 我的求助 | 本人 ticket 状态与处理进度 | `/competitions/[eventId]/help` |
| 我的提交与自检 | 复用既有 `my-checklists`（7 项只读核对） | 既有提交面板 |

**位置**：既有赛事页内的只读汇总区。`MUST NOT` 新增第二个"我的赛事"入口；`MUST NOT` 放进 `participation` 模块（该模块职责是个人参赛计划与 AI 生成，与此无关）。

## 5. 明确不做

- ❌ 新增发放事实、领取状态、核销状态或第二份后勤记录
- ❌ 新增第二个"我的赛事"入口或一级导航
- ❌ 把本汇总放进 `participation` 模块
- ❌ 承诺算力 Token、云资源或任何未确认资源（G5）
- ❌ 站内报名支付、票券售卖、酒店供应商预订（G6/G10）
- ❌ 向选手展示其他成员的住宿、餐券、求助或联系方式
- ❌ 新增模型生成内容（本页只列事实，不生成建议）

## 6. 验收

| 项 | 口径 |
| --- | --- |
| 每项可回溯 | 汇总里每一条都能点回原记录；断言 href 指向既有路由 |
| 无值不补 | 无公告/无住宿/无餐券时写"未提供"或空态，`MUST NOT` 补占位、`MUST NOT` 编造截止时间 |
| 期限真实 | 重要期限只来自赛事已发布规则版本；无值不显示（沿用既有纪律） |
| 本人隔离 | 断言队长看不到其他成员的住宿与餐券；选手 A 看不到选手 B 的求助 |
| 未登录 | 401，且不返回任何个人字段 |
| 非参与者 | 403 |
| 不改事实 | 读取前后，公告已读数、住宿分配、餐券核销、求助状态**完全一致** |
| 不遮挡 | 汇总区不遮挡既有报名按钮、期限、错误信息（宪法 X） |

## 7. 风险与前置

| 风险 | 应对 |
| --- | --- |
| 变成第二份后勤台账 | 汇总 `MUST` 全部由既有记录投影而来；测试断言"没有新增后勤表" |
| 与既有赛事页重复 | 接入时逐项比对现有区块，重复内容**只合并不并列**（宪法 X：同义入口不得两套并行） |
| 诱导承诺资源 | 算力/云资源一律不出现；若未来官方接口确认，另起一期并过闸门 |
| 隐私 | 复用既有可见性规则，不因"汇总方便"而放宽任何字段 |
