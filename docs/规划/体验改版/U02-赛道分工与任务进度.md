# U02 赛道分工与任务进度

日期：2026-10-09。独立会话实施，主会话接根接口和实际迁移。依据：[总体改版规划](../13-体验优先与协作整合.md)。

## 用户流程

用户最新确认的团队空间与邀请链接/二维码按 [补充规划](../14-团队空间与邀请加入.md) 实施：每个参赛项目为一个空间，复用现有权限；默认成员、有效期/撤销/邮箱限定，加入前登录并明确接受。创建者可选择最多邀请几人，新增多人额度与接受记录，满额失效；旧单次邀请默认 1 人，名额必须真实持久化并发校验，不能只加人数下拉。

核对主办方赛道 → 邀请队友并填写时间 → 自选职责或让 AI 辅助 → 核对任务和时间 → 看自己现在能做的事 → 提交完成 → 队友检查并继续。

## 必须完成

1. 官方赛道使用稳定标识、名称、来源/证据、规则版本与状态。没有细分、未知、冲突分别显示；不从资源技能分类补造赛道。
2. 项目引用赛道版本；新规则提示复核，不静默改分工。历史规则兼容，没有新字段的旧版本明确保持未知。
3. 项目成员职责意愿独立版本化，本人可改、归档只读；共享字段由成员明确选择。不能写进私人测评结果充当意愿记录。
4. 自选路径不要求评分。AI 路径问少量任务相关问题，现有已授权画像只作本人初始参考，私密回答不自动传给队伍。
5. 通过注入 Port 把官方要求、共享意愿、时间输入现有分工/排期。模型返回必须在服务端核对成员、依赖、时间与权限，用户确认后应用。
6. 同一组流程展示成员、分工、任务安排，不建立第二套任务数据；既有分工/计划版本和校验仍保留。
7. 任务板易懂展示“我现在能做、等待队友、正在做、待检查、已完成”，等待项指明前置任务；不限制全部任务都等 demo 完成。
8. “我已完成”是清楚的成果提交交互，进入待检查；验收后才释放依赖。误勾更正保留记录，不绕过已验收不可普通撤回的规则。
9. 页面可见时只读刷新当前共享任务，离开停止；只刷新已保存数据，不派发 AI。正在编辑的表单不被新数据覆盖。
