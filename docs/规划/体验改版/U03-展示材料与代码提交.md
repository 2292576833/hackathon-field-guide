# U03 展示材料与代码提交

日期：2026-10-09。独立会话实施，主会话接共享事实/API。依据：[总体改版规划](../13-体验优先与协作整合.md)。

## 用户流程

在当前项目确定已完成内容 → 准备讲稿 → 带入 PPT 大纲 → 挑选制作工具 → 检查代码和演示 → 按主办方要求提交。

## 必须完成

1. 路演与 PPT 用连贯的“准备展示材料”入口，原路由保留。现有本人讲稿继承到 PPT 继续可用；独立填写也保留。
2. 引用项目时由用户主动选择，复核活跃成员与当前会话。默认带入当前项目目标、范围与明确的成果事实；计划内容不能标成已完成能力。
3. 路演/PPT 材料仍是本人记录，先说明哪些项目信息将被用于生成。私人资料不因导航整合而自动分享给团队。
4. 生成保留输入快照、来源项目/版本。修改项目后不静默覆盖旧讲稿、大纲。已保存旧稿不强制重新生成。
5. 不能声称已读完整代码、真实演示或完整规则。需要共享事实接口时定义 NEEDS_INTERFACE，根接口接入前展示真实未接入状态，不能静态伪造成功。
6. GitHub 图形教程集中在独立页；从当前项目进入操作时保留该项目位置。登录、账号绑定、仓库授权分别显示，仓库操作复用现有实现。
7. 合并重复的仓库摘要，保存、运行检查与正式提交仍各自清楚。待配置、未知结果、失败均可理解，文件变更预览不跳过。
8. PPT 制作工具推荐说明用途，链接有明确去向；相同资源不维护两份矛盾说明。Markdown/打印能力不冒充生成 PPTX。

## 验收

- 从选定项目到讲稿/PPT/代码操作有清楚去向和返回入口。
- 同一确认项目介绍能够复用，补充输入只问本次材料需要的信息。
- 他人项目、退出成员、归档修改和会话失效不会泄露事实或保存旧结果。
- 旧稿和私人材料保持原范围；来源不可解释时不冒充来自项目。
- 手机可用，长输入失败后保留；不进行真实邮件、模型或 GitHub 写入。

提供组件、模块测试及共享上下文接口需求。使用模拟适配验证权限与输入快照，真实外部效果留主会话有边界验收。交付停止编辑，不重启或发布网站。
