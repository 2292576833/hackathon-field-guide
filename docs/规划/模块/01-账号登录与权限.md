# M01 账号登录与权限：详细模块规划

日期：2026-10-08  
状态：设计建议，供需求规格和实施使用；不是已实现功能。  
依据：[产品想法与问题分析](../../../草根黑客松情报局-产品想法与问题分析.md)、[项目宪法 v1.1.0 草案](../../../.specify/memory/constitution.md)。宪法首次批准日期仍待确认，本规划不改变其状态。

配套：[总体规划](../00-总体规划.md)、[数据与接口协作约定](../10-数据与接口协作约定.md)、[工具与灵感库](09-工具与灵感库.md)。

## 1. 目标与决策状态

本模块让用户登录网站、保存参赛记录、加入正确的团队，并确保不同账号只能访问被授权的项目和数据。网站登录与 GitHub 授权必须分开：能进入项目不代表能修改项目仓库。

| 项目 | 状态 | 本规划的处理 |
| --- | --- | --- |
| 网站需要登录系统 | 已明确 | 登录后使用私人项目、邀请、任务和个人记录 |
| 私人数据要有明确权限边界 | 已明确，宪法 VI | 服务端执行对象级权限检查 |
| 工具与灵感库、暖白＋橙红视觉 | 已明确，宪法 v1.1.0 | 个人收藏按本人权限，项目收藏显式共享；登录与设置页沿用统一视觉 |
| 采用邮箱验证码或验证链接登录 | 建议默认 | 首版选择一种成熟认证方案，避免自行设计认证协议 |
| 使用 GitHub 作为网站登录方式 | 待确认 | 可后续添加；不以登录成功代替仓库授权 |
| 面向用户年龄范围、数据保留期、部署地区 | 待确认 | 发布前确定；不推断所有年轻用户都可使用第三方服务 |

**MVP 范围：** 注册或登录、邮箱验证、会话、退出、登录恢复、个人设置、项目与团队权限、中止会话、撤销 GitHub 绑定入口、个人数据导出和删除申请入口、管理员操作审计。

**MVP 不包含：** 企业单点登录、公开个人主页、陌生人社交、复杂自定义角色编辑器、账号买卖或共享账号、身份年龄推断、自动替用户注册 GitHub。首版不采集身份证、学校证明等与使用无直接关系的资料。

## 2. 用户故事与最短可用流程

| 用户故事 | 可观察结果 |
| --- | --- |
| 作为新人，我希望登录后找回上一次的参赛项目 | 同一账号再次登录看到已保存的项目和进度 |
| 作为受邀队员，我希望先看邀请对象再决定加入 | 登录后显示团队或项目名称、邀请人、角色，用户主动接受 |
| 作为成员，我希望队长不能看到我的所有测评原始回答 | 原始回答默认本人可见；授权的摘要按项目范围共享 |
| 作为项目管理员，我希望撤销成员后立即停止其访问 | 服务端后续请求失去权限，既有页面不能继续保存 |
| 作为用户，我希望退出并处理误绑定的 GitHub | 退出终止会话；撤销绑定不删除网站账号 |

正常流程：游客浏览 → 点击需要保存的操作 → 登录 → 邮箱验证成功 → 返回允许的站内路径 → 完成操作。邀请登录流程使用一次性待处理邀请标识，登录成功后再次检查邀请状态，不能把“登录”直接等同于“接受邀请”。

## 3. 页面与状态

| 页面/入口 | 核心内容 | 必须覆盖的状态 |
| --- | --- | --- |
| `/login` | 邮箱输入、发送验证、返回首页 | 初始、已发送、发送失败、冷却、限流 |
| `/auth/verify` | 验证码或链接验证 | 验证中、成功、过期、已使用、无效 |
| `/settings/profile` | 昵称、默认时区、本人邮箱状态 | 读取、编辑、保存冲突、邮箱重新验证 |
| `/settings/security` | 当前会话、退出全部设备、登录恢复 | 活跃、撤销、再次认证要求 |
| `/settings/connections` | GitHub 身份/应用授权/仓库范围状态 | 未连接、连接、范围不足、已撤销、过期 |
| `/settings/data` | 导出、删除申请、共享说明 | 申请中、处理中、失败、完成 |
| 无权限页面 | 当前对象与恢复路径 | 未登录、已登录但无权、成员被移除、资源不存在 |

账户状态建议：`pending_verification → active → deletion_pending → deleted`。暂停账户为单独管理状态 `suspended`，需要原因与审计。认证提供方有自己的状态时，以适配层映射，不重复发明状态含义。

页面不能暴露账户是否存在等不必要信息；验证码发送返回统一提示。会话过期时保留尚未提交的非敏感表单草稿，完成重新登录后再让用户确认保存。登录回跳只允许预设站内路径，避免任意外部回跳。

## 4. 权限模型与业务规则

### 4.1 权限分域

- 网站管理角色、团队角色、项目角色、GitHub 操作权限分别记录。
- 团队建议只有 `captain`（队长）与 `member`（成员）；项目建议只有 `manager`（管理员）与 `member`（成员）。这些名称为候选。
- 团队成员身份不自动公开其所有个人项目，项目访问依据 `ProjectMembership`。
- 项目管理员可以安排任务和管理成员；不能因此读取其他人的原始测评或扩大 GitHub 仓库权限。
- `Project.createdBy` 只记录创建者，不产生额外权限或不可撤销身份；项目管理员完全依据当前有效的 `ProjectMembership.role = manager`。
- GitHub 写操作须同时满足：网站项目权限、有效 GitHub 应用授权、仓库范围及所需操作人权限。任一条件不满足即停止写入。
- 站点管理员处理赛事审核、故障与账号问题；不得把“管理员”当作日常自由浏览私人仓库和原始测评的入口。必要支持访问必须有明确目的、受控范围和审计。

### 4.2 建议权限矩阵

| 操作 | 游客 | 已登录非成员 | 项目成员 | 项目管理员 |
| --- | --- | --- | --- | --- |
| 浏览公开赛事 | 允许 | 允许 | 允许 | 允许 |
| 创建本人项目 | 登录后 | 允许 | 允许 | 允许 |
| 查看私人项目 | 不允许 | 不允许 | 允许 | 允许 |
| 更新本人负责的任务 | 不允许 | 不允许 | 允许 | 允许 |
| 调整他人的负责人/核心期限 | 不允许 | 不允许 | 提出建议 | 确认后允许并记录 |
| 邀请、移除项目成员 | 不允许 | 不允许 | 不允许 | 允许；最后管理员不能被移除 |
| 查看他人原始测评 | 不允许 | 不允许 | 默认不允许 | 默认不允许 |
| 查看已共享分工摘要 | 不允许 | 不允许 | 允许 | 允许 |
| 更改公开分享设置 | 不允许 | 不允许 | 不允许 | 主动设置后允许 |
| 写入 GitHub | 不允许 | 不允许 | 额外核验仓库授权 | 额外核验仓库授权 |

自有数据查看、导出和删除的权限始终按数据主体处理，不能因为退队而失去处理本人资料的路径。平台账务与法定保留要求如存在，必须在具体方案中说明，不能先承诺所有记录即时物理删除。

### 4.3 关键规则

1. 用户唯一 ID 稳定；邮箱更换需要验证，不以邮箱字符串直接关联全部项目。
2. 不把相同邮箱或相似 GitHub 名称自动当成同一身份；合并账号须由已认证用户证明两边身份。
3. 每次读写对象检查当前成员状态，不仅在首次打开页面检查。路由 ID、上传 ID、任务 ID 都要核对所属项目。
4. 邀请令牌随机生成，服务端只保存安全摘要；具备有效期、撤销与接受状态。登录后再次检查角色和容量。
5. 原始测评默认本人可见；共享字段清楚列出，例如“适合任务、可投入时间、需要的帮助”。撤回共享影响后续访问，已发布的分工依据保留必要版本说明。
6. 用户退出、账号暂停、删除进入处理状态时，撤销适用会话；令牌和验证码不得进入普通日志。
7. 状态变更保留操作人、时间、对象、动作和结果。失败审计不记录验证码、原始试题回答或仓库正文。

## 5. 实体与接口建议

以下是实施设计建议，并非现成 API。技术候选为 Next.js + TypeScript + PostgreSQL；也可以用开发者熟悉的栈实现相同行为。

| 实体 | 建议关键字段 | 说明 |
| --- | --- | --- |
| `User` | `id, displayName, emailVerifiedAt, timezone, status, createdAt` | 只收集必要资料 |
| `AuthIdentity` | `userId, provider, providerSubject, verifiedAt` | 第三方身份使用稳定 subject，不用展示名当主键 |
| `Session` | `userId, expiresAt, revokedAt, lastSeenAt` | 具体存储由认证方案决定 |
| `TeamMembership` | `teamId, userId, role, status` | 团队权限见 M02 |
| `ProjectMembership` | `projectId, userId, role, status` | 项目对象级权限依据 |
| `Invitation` | `scopeType, scopeId, tokenHash, role, expiresAt, revokedAt, acceptedBy` | 邀请归属 M02，此处承担认证验证 |
| `ConsentRecord` | `userId, projectId, category, fields, version, revokedAt` | 可表达共享范围，不收集无用泛化同意 |
| `AuditEvent` | `actorId, action, objectType, objectId, result, occurredAt` | 必要权限与安全操作记录 |

建议接口：

| 接口 | 行为与校验 |
| --- | --- |
| `POST /api/v1/auth/login-challenges` | 发送验证；统一响应、限流、有效期 |
| `POST /api/v1/auth/login-challenges/verify` | 单次消费验证；创建会话；拒绝过期与重复使用 |
| `POST /api/v1/auth/logout` | 撤销当前会话 |
| `POST /api/v1/auth/logout-all` | 重新认证后撤销本人全部会话 |
| `GET /api/v1/me` | 返回当前用户与必要权限摘要 |
| `PATCH /api/v1/me` | 修改允许字段；邮箱变更单独验证 |
| `GET /api/v1/projects/{id}/my-permissions` | 返回网站能力和缺失授权原因；不返回令牌 |
| `POST /api/v1/me/data-exports` | 创建异步导出请求 |
| `POST /api/v1/me/deletion-requests` | 展示影响后申请删除；不擅自删除队友成果 |

写操作采用当前用户会话和服务端防跨站伪造机制，认证 cookie 建议限制脚本读取，并配置安全传输与适用站点策略。具体参数以所选认证方案和部署环境验证为准。

权限失败示例：

```json
{
  "error": {
    "code": "PROJECT_PERMISSION_REQUIRED",
    "message": "你已退出该项目，无法保存此修改。",
    "requestId": "req_example"
  }
}
```

未登录使用 `401`；已登录但无权使用适当的 `403` 或统一资源不可见响应。不能通过错误差异向非成员泄露私人项目存在性。

## 6. 异常、删除与降级

| 情况 | 必须提供的处理 |
| --- | --- |
| 邮件供应商不可用 | 显示发送失败、允许合理重试；保留已有有效会话，不谎称已发送 |
| 验证码过期或多次失败 | 说明重新获取，限制尝试；不让用户无限重试旧码 |
| 邀请在登录期间被撤销 | 登录仍有效，加入操作拒绝并显示可联系邀请人的说明 |
| 成员打开页面后被移除 | 服务端拒绝保存；说明原因并保留本地未提交草稿 |
| GitHub 被撤销 | 网站仍可使用任务与复盘；仓库写操作禁用，显示重新授权入口 |
| 删除本人账号但仍有共享项目 | 先转交最后管理员身份或选择归档；必要共享记录去标识化，私有原始资料按规则处理 |
| 数据导出任务失败 | 保留请求状态与错误编号，允许重试；下载链接短期有效 |

账户删除至少区分网站账号、本人原始测评、共享项目记录、GitHub 授权和第三方仓库。网站无权把账户删除自动变成删除 GitHub 仓库；队友交付与审计记录的处理规则要在发布前说明。

## 7. 依赖与事件

- M02 使用身份与权限服务创建成员、邀请、转交与移除；见 [参赛项目与团队](02-参赛项目与团队.md)。
- M04 调用权限服务保护原始测评，并把已授权摘要交给分工；见 [测评与分工](04-AI提问测评与团队分工.md)。
- M05 写任务时检查项目权限和负责人关系。
- M06 独立验证 GitHub 授权；不能只信页面传来的“有权限”。
- M07 使用个人数据权限导出与删除复盘；见 [交付复盘与经验沉淀](07-交付复盘与经验沉淀.md)。
- M09 的 `ResourceBookmark` 为个人收藏，默认仅本人访问；M02 的 `ProjectResourceBookmark` 为项目收藏，只有显式加入项目后才共享。收藏不赋予资源外部账号、素材或组件的使用许可。

建议事件：`UserCreated`、`UserSessionRevoked`、`ProjectMembershipRevoked`、`ConsentChanged`、`AccountDeletionRequested`、`AccountDeleted`。事件内容只携带 ID、版本和必要状态，不广播验证码、测评正文或凭据。后端提交成功后发出事件；需要可靠异步通知时再引入事务外盒等机制，不默认拆成微服务。

## 8. 开发任务与完成顺序

| 任务 | 交付与验证 |
| --- | --- |
| M01-T01 决定认证方案 | 确定邮箱方式、供应商、会话恢复；记录候选选择依据和成本 |
| M01-T02 建立用户与会话 | 数据迁移、身份唯一约束、登录/退出/过期验证 |
| M01-T03 建立权限服务 | 团队/项目权限规则集中实现；对象越权与撤销即时生效测试 |
| M01-T04 完成登录与个人设置 | 登录回跳、加载失败、过期提示、邮箱修改验证 |
| M01-T05 接入邀请与测评隐私 | 与 M02/M04 贯通，验证成员不能看原始测评 |
| M01-T06 账户与授权退出 | 会话撤销、GitHub 断开入口、数据导出/删除影响说明 |
| M01-T07 审计与发布检查 | 验证日志脱敏、限流、恢复；区分模拟邮件与真实邮件验证 |

估算应在认证方案选定后给出，不把供应商接入、数据删除和权限验证按“一个登录页”计入。

## 9. Given / When / Then 验收

1. **Given** 用户已有私人项目；**When** 同一账号退出后重新登录；**Then** 原项目与任务仍存在，过期会话不能再使用。
2. **Given** A、B 属于不同项目；**When** A 通过直接接口访问 B 的任务或测评 ID；**Then** 服务端拒绝，响应不包含 B 的私人资料。
3. **Given** 队长仅拥有项目管理权限；**When** 请求队员原始测评；**Then** 默认拒绝，已授权摘要可以单独读取。
4. **Given** 邀请未过期；**When** 登录后邀请被撤销再点击接受；**Then** 加入失败，不创建成员记录。
5. **Given** 成员的 GitHub 授权失效；**When** 继续登录网站并查看任务；**Then** 任务正常可见，仓库写入拒绝且原因明确。
6. **Given** 用户申请删除且是项目最后管理员；**When** 执行删除检查；**Then** 先给出转交/归档路径，不能静默丢弃队友成果。
7. **Given** 同一验证码已成功消费；**When** 再次提交；**Then** 拒绝复用，不创建新的有效会话。

## 10. Constitution Check

| 原则 | 本模块落实与检查 |
| --- | --- |
| I 新人可执行 | 登录后回到当前任务；邀请明确展示对象和角色；资源收藏与完成任务分开 |
| II 事实可追溯 | 不负责赛事或资源内容审核；提供个人时区，资源原始来源/费用/许可由 M09/M08 管理，收藏不改写这些事实 |
| III 测评为分工 | 原始测评本人默认可见，摘要共享可控 |
| IV 时间可交付 | 会话失效保留草稿，避免临近提交丢失输入 |
| V GitHub 授权 | 网站登录不代表仓库权限，M06 再次验证 |
| VI 最小权限 | 服务端对象权限、邀请有效期、数据处理与会话撤销；个人与项目收藏分域 |
| VII 可维护 | 权限规则集中、认证适配边界清楚；Resource 内容和两类收藏不混为一个实体 |
| VIII 验证行为 | 自动验证跨项目越权、失效会话与成员撤销 |
| IX 降级 | 认证外部服务失败不抹掉项目；GitHub 失效仍可查看任务 |

## 11. 风险、待确认与测量

主要风险是“看似简单的角色”遗漏对象级权限、邀请泄露私人信息、账号合并造成误归属，以及删除承诺与共享记录处理冲突。实施前确定首批年龄范围、认证方式、账户恢复方式、管理员支持访问政策、保留与删除期限。候选默认允许先开发测试账号和权限原型，不能据此宣布生产登录已可用。

建议测量登录成功率、验证邮件延迟、恢复流程完成率、邀请加入成功率、权限拒绝与授权错误次数；失败码须可定位但不记录验证码或邮箱明文等无必要内容。生产日志的具体脱敏与保留策略另写实施配置。
