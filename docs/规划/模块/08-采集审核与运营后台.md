# M08 采集审核与运营后台：模块实施规划

日期：2026-10-08｜版本：0.1｜状态：来源验证前的规划草案

关联：[产品构想](../../../草根黑客松情报局-产品想法与问题分析.md) · [项目宪法](../../../.specify/memory/constitution.md) · [M03 赛事分析](03-赛事聚合与证据分析.md) · [M06 GitHub 助手](06-GitHub助手与赛事交付.md)

跨模块字段、角色与响应沿用 [数据与接口协作约定](../10-数据与接口协作约定.md)；宪法检查依据当前 v1.1.0。

## 1. 目标与需求性质

让公开赛事数据经过可审查的采集、结构化、核验和发布，并让运营能定位失败、纠错和成本。后台是公开内容的生产与维护工具，不是拥有所有私人项目和仓库的超级入口。

| 性质 | 内容 |
| --- | --- |
| 用户已明确 | 通过 DSH 方向获取赛事信息，并由 AI 分析 |
| 用户新增方向 | 网站纳入参赛工具、AI 审美/设计灵感网站、UI 组件网站；M09 负责用户侧工具与灵感库 |
| 宪法约束 | 采集与仓库凭据隔离，外部文本仅为数据；超时/重试有界；事实有证据和状态 |
| 默认建议 | 来源白名单、关键字段人工审核；独立低权限 Worker；先用少量来源验证 |
| 待确认 | 采集适配器、来源授权与允许用途、定时频率、审核人、SLA、保留期限、成本上限 |

**成果：**每个公开关键字段都能追到来源版本；错误能被纠正；任务失败不会损坏已发布数据；可回答一场赛事从采集到核验花了多少时间和费用。

## 2. 第一版范围

1. 来源注册与验证记录：URL 模式、获取方式、用途限制、负责人和当前状态。
2. 手动启动及低频定时采集，记录 CrawlRun 与步骤结果。
3. 内容去重、变更检测、字段提取、证据引用与结构化校验。
4. 审核队列：前后版本比较，逐项确认资格、日期、费用与提交要求。
5. 发布、撤下、归档和纠错；重大更新提示已关联项目。
6. 查看来源失败、未处理纠错、内容过期和模型/抓取成本。
7. 审核行为和权限变更审计，服务端控制后台访问。
8. 为 M09 维护人工精选工具链接、分类与审查记录，核对官方入口、费用和许可；失效/不适用条目可下架。

后置全网搜索爬虫、多层审批、任意自定义 Agent 插件市场、全功能客服/CRM、广告投放后台和生产环境自动执行任意脚本。第一版可以由一名授权运营审核，同一人录入再审核必须记录，不虚构双人复核流程。

## 3. 工作流与页面

`注册并验证来源 → 排队采集 → 安全获取 → 归一化/去重 → AI 提取 → 结构校验 → 关键字段审核 → 发布版本 → 更新监控与纠错`

| 页面 | 建议路由 | 核心内容 |
| --- | --- | --- |
| 运营概览 | `/admin` | 待审核、失败、过期、纠错与预算摘要 |
| 来源管理 | `/admin/sources` | 允许域名/路径、获取方式、验证记录、启停 |
| 工具资源管理 | `/admin/resources` | 人工精选条目、用途/阶段/技术栈/门槛、官方链接、费用/许可与核验时间 |
| 采集任务 | `/admin/crawl-runs` | 状态、步骤、耗时、错误、重试和取消 |
| 审核队列 | `/admin/events/review` | 候选与发布版本 diff、证据、缺失/冲突 |
| 赛事编辑 | `/admin/events/:id` | 手动修正、核验、发布/撤回与原因 |
| 纠错处理 | `/admin/corrections` | 用户提交、处理状态、关联版本 |
| 运行与成本 | `/admin/operations` | 来源成功率、模型用量、队列时延与告警 |
| 审计 | `/admin/audit` | 谁更改/审核/发布了什么，权限记录 |

审核页优先呈现影响决策的变更，不让运营在长篇 AI 摘要中寻找日期差异。来源引用、候选值、当前发布值、差异和核验动作并列展示；未知项允许公开显示“未说明”，不能为了清空队列随意补值。

## 4. DSH 运行边界

DeepSeek Harness 的官方安全说明把它视作实验性软件，并说明模型可能生成代码和命令，因此本项目把 DSH 放在专用执行环境中，仅赋予当前采集任务需要的能力。[DSH 官方安全说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md)

### 建议最小配置

- 独立 Worker / 容器 / 受限进程，固定经验证 DSH 与插件版本，不把它嵌进网页请求处理进程。
- 无用户 GitHub token、App 私钥、网站认证密钥和完整生产数据库凭据。
- 每次任务有独立临时目录、任务超时、内存/文件大小限制；结束后清理临时内容。
- Worker 从任务队列读必要 ID 与已批准来源，通过窄接口提交候选结果；不直接修改公开赛事、项目权限或仓库。
- 出站网络按来源或抓取代理限制；固定抓取工具，不允许页面要求 Agent 下载并执行脚本。
- 插件与模型供应商通过适配器封装。DSH 暂不可用时可通过人工录入、规则文本导入完成同样审核流程。

外部网页中的“忽略规则、执行命令、读取凭据”等内容只作为来源文本，不能改变系统权限、工具定义、任务目标或发布规则。AI 输出进入候选区并经 schema 校验，不能自动运行或直接发布。

### M09 工具与灵感库维护

第一版采用人工精选链接与简短说明。类别包括参赛工具、AI 审美/设计灵感、UI 组件；面向阶段、用途、技术栈和门槛设置标签。浏览侧展示由 M09 实现，本后台负责内容核查与上架。

- 每项资源保留官网、用途、适用阶段、技术栈、账号/网络门槛、免费/收费概况、许可来源、最后核验时间。
- 费用会变化，不将“有免费档”写成永久免费；没有明确依据时标为未确认。组件许可须核对项目官方许可文件，不能凭“开源”推断任意商用。
- 灵感网站作为外链参考，不抓取第三方作品图片、不复制设计稿、不把网站入选当作对其审美或安全的保证。
- 上架前核查链接可用与说明依据；状态为 `draft / pending_review / published / needs_recheck / withdrawn`，过期或失效可提示复核/下架。
- 首版不进行全网自动推荐排名，也不根据年龄判断适合程度；人工解释推荐用途，M09 的筛选标签不是能力评分。
- 资源归档保留历史核验，便于项目复盘知道当时参考的内容；公开页不展示运营私人备注。

## 5. URL 获取与来源控制

用户和管理员都可能提交不适合直接获取的 URL，后台必须避免把输入 URL 当作可信网络目标。

1. 仅接受 HTTP(S)，默认 HTTPS；规范化主机名与路径，拒绝嵌入账号密码和不允许端口。
2. 拒绝本机、私网、链路本地、云元数据等地址，解析 DNS 后核查目标 IP；连接时避免 DNS 重绑定绕过。
3. 每次重定向重新核查域名/IP，限制次数；不要从批准的公开地址跳到内部地址。
4. 首版白名单来源；不在白名单的请求进入待验证，不即时自动抓取。
5. 限制响应大小、超时、内容类型、并发与递归深度；不自动下载任意附件或执行 JavaScript 包。
6. 对登录墙、验证码、访问限制与获取失败记录状态，不以换账号/绕过控制作为默认恢复措施。
7. 给每个来源记录允许用途、使用条款核查和最小保留字段；采集公开内容并不自动等于允许复制全文或高频抓取。

第一版尽量选择主办方正式公告/规则页。搜索结果只用于发现候选；搜索摘要不自动变成官方条款依据。支持来源优先级，但冲突时仍需人工处理，不能只因“更晚抓到”就选为事实。

## 6. 状态机、版本和重试

### 来源状态

`proposed → verifying → enabled / rejected`，后续可 `paused / degraded`。管理员开启来源前记录获取方式和验证结果；普通审核员不能随意扩大出站白名单。

### 采集状态

`queued → fetching → normalizing → extracting → validating → review_ready / failed / cancelled`

采集成功意味着生成合格候选，不代表公开发布成功。超时、抓取拒绝、解析错误、模型错误分别编码。只对明确可重试错误按退避重试，默认总尝试上限 3 次可配置；不可重试的输入错误直接停止。管理员手动重跑生成新 run，引用原 run，不改写旧日志。

### 审核状态

`pending → changes_requested / approved / rejected → published`

发布时间另行记录。发布操作校验候选版本未变更；若其他审核员已改内容，则要求重新查看。公开内容每次发布新版本，旧版本可回查。撤下只改变可见性，不清空已关联项目的规则快照。

### 纠错状态

`received → triaging → confirmed / needs_more_info / dismissed → resolved`

所有拒绝、撤下和修正记录理由；无需向用户公开内部日志，但应提供其纠错的处理结果与相关版本。对外回复渠道第一版为站内状态，未授权时不发送邮件或外部消息。

## 7. 核心数据与接口

### 数据

| 实体 | 关键字段 |
| --- | --- |
| `SourceConfig` | M08 所有；来源域/路径白名单、类型、获取方式、频率、凭据策略（无凭据或获准服务凭据引用）、允许用途核查、网络规则版本、状态、最近成功/失败；不存单次抓取内容或用户 GitHub 凭据 |
| `EventSource` | 单次来源快照/证据记录，模型契约归 M03；M08 采集创建，引用 `sourceConfigId?`、`crawlRunId?`、`eventId`、实际 URL、获取时间、内容哈希、内容/证据引用与候选版本；不是来源白名单配置 |
| `CrawlRun` | `sourceConfigId`、任务 ID、输出的 `eventSourceIds`、触发方式、DSH/适配器版本、状态与步骤、时长、重试、错误类别、候选内容引用、请求 ID |
| `AnalysisRun` | 来源候选、schema/模型/提示版本、输入哈希、输出引用、校验错误、token/费用估计、超时状态 |
| `Resource` | 资源 ID、名称、类别/标签、官网、用途说明、适用阶段/栈/门槛、费用概况/来源、许可概况/来源、最后核验时间、版本与发布/下架状态；契约与 M09 统一 |
| `ResourceCategory` | 分类 ID、名称、说明、显示顺序、启用状态；技术栈和门槛可先作为受控标签 |
| `ResourceReview` | 资源/版本 ID、核验人/时间、链接核查、费用/许可来源、结论、下架/修正原因 |
| `Event` | 发布版本、质量标记、核验时间；内容模型由 M03 定义 |
| `RuleEvidence` | 字段依据与核验记录，由 M03 读取 |
| `AuditEvent` | 操作者、动作、实体版本、理由、时间、关联 run；日志脱敏 |

来源配置与抓取快照是不同实体：一条 `SourceConfig` 可以产生多个 `CrawlRun` 和 `EventSource`。M08 管配置/任务，M03 定义可被规则引用的快照/证据契约，不允许双方用 `EventSource` 各自存一套配置。人工导入来源可无 `sourceConfigId`，仍须带真实来源、提供方式和核验状态。候选文本、文件引用、错误日志都有保留期限，不能无限保存抓取全文。

### API 草案

统一前缀 `/api/v1`，后台权限在服务端逐资源检查。

| 方法与路径 | 操作 |
| --- | --- |
| `GET /admin/sources` | SourceConfig 来源配置和健康状态；不返回或编辑 EventSource 快照 |
| `GET /admin/resources` | 工具资源列表、待核验和下架状态 |
| `POST /admin/resources` | 新建人工精选候选条目 |
| `PATCH /admin/resources/:id` | 版本化编辑用途、标签、官网、费用/许可信息 |
| `POST /admin/resources/:id/reviews` | 记录核验结果；发布前检查必填来源与核验时间 |
| `POST /admin/resources/:id/publish` | 发布已核验版本 |
| `POST /admin/resources/:id/withdraw` | 下架并记录原因，保留审查历史 |
| `POST /admin/sources` | 管理员登记待验证 SourceConfig |
| `PATCH /admin/sources/:id` | 更改 SourceConfig 状态/频率/规则/凭据策略，携带版本和理由 |
| `POST /admin/sources/:id/crawl-runs` | 手动触发受限采集，幂等键防重复 |
| `GET /admin/crawl-runs/:id` | 任务与脱敏错误信息 |
| `POST /admin/crawl-runs/:id/cancel` | 请求取消，正在外部请求的任务按超时结束 |
| `GET /admin/events/review` | 待审核与关键变更 |
| `PATCH /admin/events/:id/candidates/:version` | 手动修正候选、附证据与原因 |
| `POST /admin/events/:id/candidates/:version/approve` | 核验关键字段并审批 |
| `POST /admin/events/:id/candidates/:version/publish` | 有权限者发布未变更的获批版本 |
| `POST /admin/events/:id/unpublish` | 撤下内容并记录原因 |
| `PATCH /admin/corrections/:id` | 处理纠错，不改写原提交 |
| `GET /admin/operations` | 用量、队列和来源聚合状态 |

Worker 接口使用独立服务身份，仅允许领取批准任务、更新自身 run、上传候选结果。管理员接口不向 Worker 开放；Worker 不能调用 `publish`。

## 8. 后台权限

| 身份 | 允许行为 | 不自动获得的能力 |
| --- | --- | --- |
| 普通用户 | 提交来源候选/纠错并查看自身请求状态 | 后台、公开发布、私人项目访问 |
| 运营审核员 | 核验、修正、处理公开内容与纠错 | 扩大来源网络权限、读私人测评、写用户仓库 |
| 网站管理员 | 来源配置、运营角色、预算/任务控制，必要时发布 | 代表用户授权 GitHub、静默修改其项目 |
| 采集 Worker | 执行获批来源任务、提交候选与 run 状态 | 用户 token、管理员接口、公开发布 |

第一版可以由管理员兼运营审核员，但权限能力分别定义，审计记录仍保留。涉及后台支持访问私人项目时，后续须有单独、明确、可审计的授权机制；不能因“管理员”自动加载全站私人报告。

## 9. 异常与恢复

| 情况 | 恢复与用户影响 |
| --- | --- |
| 来源页面结构改变 | 标记来源 degraded，保留上次已发布版本；人工核验并修适配器 |
| DSH/模型不可用 | 有限重试；允许手工录入；既有项目仍可使用 |
| 内容无变化 | 记录核查成功，不重复分析相同哈希；保留最后核查时间 |
| 候选包含错误日期/证据 | 进入修正队列，不能自动发布 |
| 出现提示注入或脚本内容 | 当作来源数据，不执行；任务缺少有效规则时失败或人工核验 |
| 运行超时/进程异常 | 看门狗将 run 置失败/可恢复，清理临时文件，不永久占用执行槽 |
| 预算达到阈值 | 暂停新批量分析并保留人工路径，当前项目查询不受影响 |
| 错误版本已发布 | 撤下/发布纠正版本，保存差异；提醒关联项目，保持原快照可回查 |

## 10. 依赖与事件

依赖 M01 管理员认证与角色、M03 赛事 schema/证据模型；面向 M02 关联项目发送变更信号。M09 定义工具资源的用户侧页面、分类和读取契约，M08 管理同一批 Resource 数据与审查记录。与 M06 GitHub 凭据无共享。

事件建议：`CrawlRunFailed`、`EventCandidateReady`、`EventPublished`、`EventRulesChanged`、`EventUnpublished`、`CorrectionResolved`、`SourceDegraded`、`ResourcePublished`、`ResourceWithdrawn`。消费者以事件 ID 和版本幂等处理；关键变更提醒在站内显示，不自动替用户更改任务。

候选技术方案：Next.js + TypeScript + PostgreSQL 的模块化单体管理公开数据和后台；独立 DSH Worker 执行长任务。先用数据库任务表和 outbox，任务执行与 API 进程分开。若实测队列容量/吞吐有瓶颈，再评估专用队列，不因“有 Agent”提前引入复杂服务体系。

## 11. 监控与验证指标

这些是需测量的指标，不是已达到的承诺：

- 每来源成功率、连续失败次数、最近成功时间、队列等待与 run 执行耗时。
- 关键字段抽取正确率、审核修改率、字段冲突数、超期未核验数。
- 每场赛事模型 token/抓取用量、估算费用、人工核验分钟数；每队实际使用成本由总体规划汇总。
- 纠错收到与解决时间、错误发布数、受影响项目数、撤下恢复时间。
- 权限拒绝与服务身份调用异常；记录类别和请求 ID，避免收集内容全文。

建议先由来源验证建立基线，再制定刷新与错误告警阈值。连续失败或关键日期临近时提高关注，不能把“定时任务跑过”当作信息可信。

## 12. 可实施任务

| 任务 | 交付与检查 |
| --- | --- |
| O-T01 来源验证 | 获取方式、允许用途、样例、变化频率与失败模式；与 E-T01 共用结果 |
| O-T02 Worker 隔离 | 任务身份、临时目录、网络规则、超时与资源限制，确认无 GitHub 用户凭据 |
| O-T03 采集适配器 | 固定版本、哈希去重、最小文本提取与来源快照 |
| O-T04 结构校验 | M03 schema、证据引用、阶段日期、输出权限隔离 |
| O-T05 审核发布 | diff、关键字段确认、版本控制、撤下与审计 |
| O-T06 任务控制 | 有界重试、取消、超时回收、状态查询与手动恢复 |
| O-T07 纠错变更 | 处理队列、站内结果、关联项目规则变化提示 |
| O-T08 成本监控 | 用量汇总、预算阈值、来源健康与脱敏日志 |
| O-T09 验证记录 | URL 获取、权限、注入文本、过期/冲突、失败降级与真实来源样例 |
| O-T10 工具资源维护 | 与 M09 共用资源模型，人工录入/核验/发布/下架、费用许可依据、失效状态；不采集第三方图片 |

## 13. Given / When / Then 验收

1. **Given** 提交 URL 指向本机/私网，**When** 创建采集任务，**Then** 抓取前拒绝，网络请求不进入内部地址。
2. **Given** 批准来源重定向到不允许目标，**When** Worker 获取页面，**Then** 再次校验并停止，不继承首跳信任。
3. **Given** 页面写有要求读取用户 token 的文本，**When** AI 处理规则，**Then** 不执行该指令，Worker 本身也无该凭据。
4. **Given** 候选包含提交日期但证据缺失，**When** 发布，**Then** 关键字段门禁阻止发布或明确保留未知，不伪造核验。
5. **Given** 内容哈希未变化，**When** 定时核查，**Then** 更新核查记录而不重复消耗完整模型分析。
6. **Given** Worker 崩溃，**When** 超时回收，**Then** run 进入失败/恢复状态，旧公开数据与项目继续可用。
7. **Given** 两名审核员同时修改同一候选，**When** 后一人提交旧版本审批，**Then** 要求重新加载差异，不覆盖前一人的核验。
8. **Given** 运营有赛事审核角色但无某私人项目访问权，**When** 请求其测评或仓库凭据，**Then** 服务端拒绝。
9. **Given** 发布版本修正提交日期，**When** 关联项目打开，**Then** 显示变更并等待确认，不静默重排计划。
10. **Given** 工具价格或组件许可缺少依据，**When** 编辑资源，**Then** 明确显示待确认，不发布“永久免费/任意商用”等无依据结论。
11. **Given** 灵感资源已下架，**When** 用户浏览 M09，**Then** 不在正常推荐列表出现；历史项目引用保留失效提示，不抓取替代图片。

## 14. Constitution Check

| 原则 | 本模块门禁 |
| --- | --- |
| I 新人流程 | 维护用户真正依赖的资格、日期、材料，避免只追求采集量 |
| II 可追溯 | 赛事字段证据、核验、冲突和版本审核；资源官方/原始链接、费用许可证据、可用状态及最后核验时间，未知可发布为未知 |
| III 测评 | 不触碰测评评分与个人画像；后台权限不扩大私人报告访问 |
| IV 时间 | 多阶段日期准确传给 M03；规则变化需团队确认 |
| V GitHub | 不保存 GitHub 用户凭据，不执行仓库写入 |
| VI 隔离 | Worker 最小身份、URL 防越界、工具固定、外部内容仅数据 |
| VII 可维护 | 采集/提取/审核/发布分离，适配器可替换；资源库人工精选与链接管理，无需求证据不扩展自动排序 |
| VIII 验证 | 权限、抓取限制、候选发布和真实来源样例验证 |
| IX 恢复 | 有限重试、故障回收、手工维护、旧数据可读 |

## 15. 风险与待决策

- **采集成功率不等于规则准确率。** 必须统计审核修改与错误字段，不能只看 run 成功。
- **人工审核可能成为扩张瓶颈。** 首批测出每场用时，再确定来源量和更新频率；可以先扩大结构化来源而非扩张全网覆盖。
- **DSH 与适配器仍可能变化。** 固定验证版本、记录升级影响、准备人工替代，不能把未验证插件能力列为现成功能。
- **来源合法用途与全文保留需要核查。** 默认最小字段和证据摘要；如要复制规则全文，单独核验许可与必要性。
- **待决定：**来源负责人、关键字段复核清单、发布时间目标、保留期限、管理员认证强度、成本阈值、可用抓取服务与部署环境。

本规划仅制定运行和审核方案，没有实际抓取、安装依赖、创建定时任务或修改任何外部平台。
