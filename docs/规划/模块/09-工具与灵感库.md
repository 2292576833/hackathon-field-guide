# M09 · 工具与灵感库独立规划

日期：2026-10-08 · 规划草案 v0.1  
依据：用户新增要求、[宪法 v1.1.0](../../../.specify/memory/constitution.md)、[总体规划](../00-总体规划.md)。

## 1. 为什么值得加入

新人经常知道要做页面，却不知道在哪找参考、选组件、画原型或准备演示。
资源库把搜索过程接到参赛任务上：选一个目标→看到少量合适资源→了解怎么用与限制→保存到项目→在实际交付中使用。

它可以成为网站的轻入口，也能服务设计、测试、文档和路演成员。
价值来自清楚的适用说明和项目关联，不能单纯靠链接数量。

| 确定性 | 内容 |
| --- | --- |
| 用户已要求 | 加入参赛工具、AI 审美/设计参考网站、UI 组件网站，方便找灵感 |
| 推荐首版 | 人工精选、分类筛选、费用/栈/门槛说明、个人收藏与项目共享 |
| 待决定 | 第一批具体条目、维护频率、长期收藏数据保留、是否接受公众建议 |

## 2. 范围

### 首版包含

- 公开浏览和资源详情，无需登录才能了解用途。
- 按参赛阶段、资源类型、技术栈、门槛与费用类型筛选，关键词搜索名称/简介/标签。
- 每条资源有原始链接、具体能帮助做什么、适合什么人、使用前要确认什么、最后核验时间。
- 登录后个人收藏；显式选择项目后共享到项目资料页。
- 项目任务可引用资源。AI 只推荐已审核条目，默认最多给二至三个选择，说明与当前任务的关系。
- 简单报告失效/信息错误，运营在 M08 处理。

### 后置

社区投稿与评论、社交关注、自动全网抓取、图片/代码镜像、大规模个性化推荐、交易、付费推广排序、组件在线运行、自动安装工具。
首版不让访问第三方资源成为完成参赛流程的必需条件。

### 新增 M10 的衔接（2026-10-08）

用户已新增按主流 AI 工具分类的技能库、教程、赛道技能包与一键安装方向，详见 [M10 独立规划](10-技能库与赛道技能包.md)。M09 的“后置自动安装工具”仍指本模块；技能版本、兼容测试与安装事实由 M10 单独设计。
M09 可提供“技能与赛道包”入口，保持现有资源类型、收藏和发布契约稳定；不把 skill 安装状态混入 Resource，也不承担本机命令执行。当前实现按 [宪法 v1.2.0](../../../.specify/memory/constitution.md) 复核，旧版本标记保留初始规格历史。

## 3. 分类要按任务理解

### 3.1 一级资源类型

| 类型 | 典型资源 | 页面解释 |
| --- | --- | --- |
| 设计灵感 | 整站案例、界面参考、布局与动效案例 | 帮你决定怎么呈现，不能据此取得素材使用权 |
| AI 设计辅助 | AI 页面原型、界面草稿与视觉方向工具 | 帮你做草稿，生成结果仍需检查 |
| UI 与视觉资源 | 组件体系、独立 UI 元素、图标 | 帮你实现界面，先检查栈、依赖和许可 |
| 参赛实用工具 | 原型、协作白板、开发环境、部署/演示辅助 | 帮你推进工作，先检查账号、成本与环境 |

“AI 审美”拆成可理解的用途：找风格、做布局草案、生成界面、检视一致性。
不做“某工具能客观打出你的审美分数”的宣传。

### 3.2 筛选字段

- 阶段：备赛 / 需求与设计 / 开发与集成 / 测试与交付 / 复盘。
- 技术栈：与栈无关、HTML/CSS、React、Vue 等受控标签；未核实为“待确认”。
- 门槛：直接浏览、需要注册、需要基础代码、需要环境配置；可以多选。
- 费用：免费方案、免费＋付费、按量计费、自部署成本、未知。费用筛选不能把“有免费方案”显示为所有功能免费。
- 用途：找首页布局、做工作台、搭表单、画流程、选图标、准备演示等。

首版只开放有足够条目的筛选维度，避免空分类。复杂搜索引擎后置；数据库文本检索足够作为候选。

## 4. 用户故事与页面

### R1 找设计方向

作为负责视觉的新人成员，我选择“需求与设计→设计灵感”，看到参考站的用途说明，知道该观察布局、字体或交互。
我可以记下“参考卡片信息层级”，而不是直接复制整个网站。

### R2 找可接入组件

作为使用 React 的开发成员，我筛选适用组件，先看依赖与维护成本，再保存一个基础体系。
网站提示“优先统一一套体系”；动效元素只能补充，不能因为多个组件好看就混合三套表单系统。

### R3 从任务直接找到资源

在“完成报名表单”任务旁，查看已审核表单组件参考；页面显示推荐理由与门槛。
没有合适资源时显示空状态，任务仍可执行。

### R4 保存与共享

个人收藏默认私有。点击“加入项目资料”必须选择本人有权限的项目，并显示分享的标题、链接与备注。
复制共享引用，不把个人全部收藏自动公开。离开项目后按 M02 收敛权限。

### 页面结构

1. `/resources`：标题“少搜一点，多做一点。”＋用途搜索＋类型栏目＋筛选＋资源列表。
2. `/resources/:resourceId`：用途、适合/不适合、开始步骤、门槛/费用/许可来源、核验时间、官方访问、收藏/共享、报告错误。
3. `/account/bookmarks`：个人收藏；这条路由可合并进账号页标签，首版不必增加导航。
4. `/app/projects/:projectId/resources`：共享资料、使用目的、关联任务、保存者；由 M02 提供容器与权限。
5. `/admin/resources`：运营编辑、核验、发布、下架；由 M08 实现。

### 状态

加载保留布局；无结果提供清除筛选；未登录收藏引导登录并保留返回位置。
链接失效、费用未知、版本过期要在详情可见。资源下架后已收藏引用显示原因，不悄悄消失。
收藏失败保留备注；离线不提示“保存成功”。新窗口访问外站使用清楚的外链标识。

## 5. 条目质量规则

每条资源必须回答：

1. 可以用它完成什么具体任务？
2. 谁适合使用，技术栈和账号门槛是什么？
3. 从哪里开始，最短步骤是什么？
4. 费用与许可信息依据哪个官方页面，哪些仍不清楚？
5. 最后核验是什么时间，能否正常访问？

费用与许可使用自己的短说明加官方链接，不复制大量原文，也不替第三方作许可承诺。
某资源有开放源码不等于其云服务永久免费；某网站供设计参考不等于其截图、商标、图片与代码均可使用。
赛事是否允许 AI 或预制组件，仍以该赛事已核实的规则为准。

公开资源首选官方入口或原作者页面。运营要能记录变更历史、停用原因；首版发布不要求每项费用都已精确核实，但必须把未知明确标记，不能进入“已确认免费”筛选。
不从用户分享的 URL 自动执行、下载或触发服务器抓取；用户输入的标题与备注按文本处理。

## 6. 首批候选清单

下面是 2026-10-08 查阅的候选入口，用于说明分类和维护方式。
本次查阅主页/官方文档不等于完整核验所有套餐、许可、地区可用性，也不代表条目已经在本站发布。
正式入库时，补足 ResourceReview，并按当时官方信息写费用与许可。

| 阶段/类型 | 候选 | 可以帮助什么 | 入库时核查什么 |
| --- | --- | --- | --- |
| 设计灵感 | [Awwwards](https://www.awwwards.com/) | 从整站案例、栏目与分类寻找布局参考 | 部分入口/收藏是否需账号；案例素材使用权另核验 |
| 设计协作 | [Figma](https://www.figma.com/) | 设计协作、界面原型候选 | 账号与套餐、比赛期可用功能、AI 数据设置 |
| 设计协作 | [Penpot](https://penpot.app/features) | 原型和设计交接候选 | 云端/自部署差异、配置成本与当前许可 |
| AI 设计辅助 | [v0 官方文档](https://v0.app/docs) | 根据描述形成界面/应用草稿 | 使用额度、框架依赖、导出和生成代码的验证 |
| UI 体系 | [shadcn/ui](https://ui.shadcn.com/docs) | 获取可修改的组件代码并建立自己的体系 | 选中组件的栈、依赖、升级与许可；不是安装后就完成设计 |
| UI 基础 | [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction) | 无预设样式的交互基础组件 | 需要样式与代码经验；整页可访问性仍要验证 |
| UI 体系 | [Ant Design](https://ant.design/docs/react/introduce/) | React 工具型界面组件候选 | 技术栈、包体、主题统一、适用版本与许可 |
| UI 元素 | [Uiverse](https://uiverse.io/) | 查找独立 UI 元素与代码示例 | 单个条目的栈/许可/可访问性，不混为完整组件体系 |
| 图标 | [Lucide](https://lucide.dev/) | 统一界面图标风格 | 选用版本、许可、图标语义与文字标签 |
| 开发环境 | [GitHub Codespaces 官方介绍](https://docs.github.com/en/codespaces/about-codespaces/what-are-codespaces) | 为代码项目配置云开发环境的候选 | 账号、额度/计费、仓库配置、网络；陌生环境需要预演 |

这一批是候选示例。首版可先维护约 12–20 条，每个常见任务给一至三个选择；数量是运营建议，不是质量验收替代。
交付工具、流程白板与路演工具在来源核验后补齐，不靠编造费用信息填满分类。

## 7. 数据模型与所有权

| 实体 | 字段建议 | 负责模块 |
| --- | --- | --- |
| `Resource` | `id, name, officialUrl, type, stageTags, useTags, stackTags, prerequisites, summary, quickStart, costType, costNote, costSourceUrl, licenseNote, licenseSourceUrl, verifiedAt, linkStatus, publicationStatus, version` | M09 定义内容；M08 管理发布 |
| `ResourceCategory` | `id, name, kind, description, displayOrder, enabled` | M09/M08 共用受控分类 |
| `ResourceReview` | `id, resourceId, resourceVersion, reviewerId, checkedAt, sourceLinks, result, notes` | M08 |
| `ResourceBookmark` | `id, userId, resourceId, purposeNote, createdAt, revision` | M09，个人私有 |
| `ProjectResourceBookmark` | `id, projectId, resourceId?, url?, title, purposeNote, savedBy, savedAt, status` | M02；复用同一共享资料，不重复建表 |
| `Task.resourceRefs` | 已审核资源 ID，生成时记录引用的版本摘要 | M05 |

`publicationStatus` 建议 `draft / in_review / published / withdrawn`；`linkStatus` 建议 `unknown / available / unreachable`。
核验“过期”由 verifiedAt 和可配置复核期限派生，不能因为一条旧链接还打开就假定价格没变。
ResourceReview 的核验与发布时间分开；资源可访问不等于许可与费用均已确认。

个人收藏对 `userId + resourceId` 唯一；项目共享相同资源可幂等合并，不重复插入。
项目保存自定义 URL 时，标明“成员添加，未由情报局审核”。只接收有效 HTTP(S) 链接，不执行内联脚本；服务器不主动抓取用户 URL。
下架条目保留引用历史。严重链接风险时不再提供可点击外链，其余可显示带状态的资料摘要，由运营记录原因。

## 8. API 与跨模块契约

前缀 `/api/v1`，以下为设计草案，并非已实现接口。

| 接口 | 行为 |
| --- | --- |
| `GET /resources` | 查询已发布资源；分页、受控筛选、排序不伪造“最受欢迎” |
| `GET /resources/{id}` | 详情与公开核验摘要；下架时返回清楚的状态摘要 |
| `GET /resource-categories` | 分类及有效标签 |
| `GET /me/resource-bookmarks` | 仅本人收藏 |
| `POST /me/resource-bookmarks` | 收藏已发布资源，幂等；服务端 userId 来源于会话 |
| `PATCH /me/resource-bookmarks/{id}` | 本人修改备注，携带预期 revision |
| `DELETE /me/resource-bookmarks/{id}` | 本人移除个人收藏，不影响项目共享 |
| `POST /resource-corrections` | 提交资源 ID、错误类型与文本；限制频率，接入 M08 审核 |
| `POST /projects/{id}/resources` | 复用 M02 共享入口，验证项目权限与资源状态 |

运营编辑与发布接口复用 M08，不在 M09 再建第二套后台。
AI 推荐接口首版不单独存在；在 M05 任务草案生成中查询少量已审核候选，并验证输出引用。
资源变化通知可以采用 `ResourcePublished / ResourceWithdrawn / ResourceUpdated`。只携带 ID、版本与状态，更新收藏页面提示；不自动改变计划、执行安装或购买服务。

## 9. 失败与降级

| 情况 | 行为 |
| --- | --- |
| 外站访问失败 | 保留资料摘要和核验时间，提供报告错误与其他资源 |
| 收费/许可尚未核实 | 明示未知，不列入确认免费/确认许可筛选 |
| 收藏请求重复 | 返回已有引用，不产生重复收藏 |
| 分享时项目成员资格已失效 | 拒绝共享，保留个人备注与收藏 |
| 资源已下架 | 展示状态与原因，不能把收藏悄悄删除 |
| AI 推荐不存在/未审核 ID | 删除该候选并显示缺项，不补造链接 |
| 资源服务不可用 | 项目任务继续可看可改，计划可生成不带资源引用的草稿 |
| 用户 URL 看似恶意或不合法 | 拒绝存储不支持的协议，不执行抓取与脚本 |

## 10. 开发任务

| 顺序 | 交付物 |
| --- | --- |
| M09-T01 | 内容字段、受控分类、状态与唯一约束迁移；与 M08/M02 契约统一 |
| M09-T02 | 少量真实候选审核，补用途/门槛/费用与许可来源；未知也要明确 |
| M09-T03 | 公开列表、筛选、详情与状态；移动端可用 |
| M09-T04 | 本人收藏、登录返回、备注与失败保留 |
| M09-T05 | 复用项目资料共享接口，显示成员添加与审核资源的区别 |
| M09-T06 | 任务 resourceRefs 验证，版本记录、下架处理与无资源降级 |
| M09-T07 | 纠错接入与运营复核列表；无假热度排序 |
| M09-T08 | 验证个人隔离、项目越权、重复收藏、下架/生成异常 |

资源详情文案与样式使用人工检查；权限与引用约束用必要自动化验证。维护工作量独立计入运营，不用“自动 AI 收集”掩盖审核成本。

## 11. Given / When / Then 验收

| Given | When | Then |
| --- | --- | --- |
| 未登录访客 | 筛选 UI 组件 | 可以阅读用途、门槛和原始链接，不被强制登录挡住 |
| 资源费用未知 | 选择“确认有免费方案”筛选 | 不把未知资源混入已确认结果 |
| 登录用户已有收藏 | 重复发送收藏请求 | 只保留一个收藏并返回真实结果 |
| 本人私人收藏 | 队友查询项目资料 | 看不到未显式共享的私人收藏 |
| 非项目成员 | 用合法资源 ID 请求共享到该项目 | 服务端拒绝，无资料变更 |
| 项目已有资源引用 | 运营下架资源 | 引用保留且显示下架，不重新推荐为可用条目 |
| 模型输出不存在的资源 ID | 校验计划草案 | 候选被拒绝，计划核心任务不受影响 |
| 自定义链接含不支持协议 | 保存资料 | 拒绝并保留用户可编辑备注，不触发抓取 |
| 需要付费工具的推荐 | 用户查看详情 | 费用与替代路径可见，不表现为必须购买 |

## 12. Constitution Check

| 原则 | 落实 |
| --- | --- |
| I 任务流程 | 按用途找资源，关联项目与任务，不把浏览等同完成 |
| II 证据 | 原始链接、费用/许可来源、核验与未知状态 |
| III 分工 | 工具选择不推断能力，资源也不取代试做证据 |
| IV 时间 | 陌生工具的学习/接入工时进入计划，不强迫切换工具 |
| V GitHub | 收藏/推荐不触发仓库写入，工具授权单独处理 |
| VI 权限 | 私人收藏隔离，项目共享显式进行，URL 输入仅为数据 |
| VII 简单实现 | 人工精选、受控分类、共用资料容器，无首版推荐引擎 |
| VIII 验证 | 收藏隔离、引用合法性、下架和生成异常可观察验收 |
| IX 失败继续 | 外站/资源服务失败不阻塞任务与草稿 |

## 13. 主要风险与运营要求

容易出现的失误：所有卡片都写“好用”；把 AI 生成界面当可运行作品；免费额度过期；混用组件体系；未经许可复制素材；收藏太多挤占比赛时间。
应对方式是用途说明、少量推荐、明确门槛与证据、失效复核，以及把参考目的写进项目备注。

维护建议：费用与高变动 AI 工具优先复核；常见开发库跟随重要版本变动复核；频率由首轮维护数据决定。
若暂时没有维护人手，缩减条目并显示核验时间，不用大量未审核链接维持虚假的丰富度。
