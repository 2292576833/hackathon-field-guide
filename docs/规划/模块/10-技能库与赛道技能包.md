# M10 · 技能库与赛道技能包独立规划

日期：2026-10-08 · 规划草案 v0.1  
依据：用户新增 skill 分类、讲解、精选、赛道套餐及一键安装的想法；用户进一步明确“按 AI 工具分类，主流的都有支持”。关联：[宪法 v1.2.0](../../../.specify/memory/constitution.md)、[总体规划](../00-总体规划.md)、[M09 工具与灵感库](09-工具与灵感库.md)。

本文是新增功能规格方向，尚未实现目录、安装器或真实兼容验证；没有安装第三方 skill，也没有发布外部套餐。

## 1. 定位与机会

把“到处找 skill”变成“选择正在用的 AI 工具和比赛任务，拿到少量适合的技能、入门教程和可核验的安装方案”。
skill 是提供给 AI agent 的任务说明与配套文件，可能包含脚本、参考资料和素材；不是一种保证能完成作品的软件。标准格式不保证所有客户端的工具调用、依赖与行为一致。[Agent Skills 官方规范](https://agentskills.io/specification)

已有平台提供目录、榜单和一条命令安装多个技能的 Packs，因此单纯做链接聚合或套餐没有足够差异。本站围绕黑客松提供中文讲解、最小交付任务、少量实测精选、赛道组合与项目经验复用。[skills.sh Packs 文档](https://www.skills.sh/docs/packs)

先验证三个假设：用户能挑到合适的技能；安装与示例使用比自己搜索更顺畅；团队实际任务获得帮助。页面访问、复制命令和安装数量均不能单独证明作品质量提升。

## 2. 用户已确认与实施分层

| 类型 | 内容 |
| --- | --- |
| 已确认方向 | 分类收录开源 skill，讲清用途，精选好用条目，按游戏/影视/AI Agent 等赛道组成技能包，目标支持一键安装 |
| 已确认工具范围 | 按 AI 工具分类，覆盖主流工具；不锁定为只支持 Codex 或 Claude Code |
| 推荐第一层 | 公开目录、中文教程、主流工具筛选、兼容证据、版本化套餐、复制经过验证的安装命令 |
| 推荐第二层 | 本地安装桥接、多工具适配、实际安装回执、冲突处理与恢复；具备实测证据后开放“一键安装” |
| 尚需验证 | 每个客户端版本/操作系统的发现路径、加载方式、脚本运行条件；候选许可证；维护成本；安装桥接交付形式 |

第一层与现有参赛流程并行推进；第二层按工具分批验证。覆盖目标包含主流工具，但首页不得把尚未测试的组合标为“全部兼容”。不要求每个 skill 在每个 AI 工具上都可用。

## 3. 分类与发现流程

四个维度分别维护，组合筛选而非混成一棵很深的目录：

1. **AI 工具**：Codex、Claude Code、Cursor、GitHub Copilot、Gemini CLI、OpenCode、Windsurf、Cline 等。工具注册表可扩展，以官方文档与实际测试持续维护。
2. **任务用途**：需求/规划、设计/UI、编码/调试、游戏原型、脚本/分镜、Agent/工具调用、测试/评估、GitHub/文档/路演。
3. **赛道**：通用、游戏、影视、AI Agent；后续有真实需求再增加。
4. **使用条件**：技术栈、操作系统、所需运行时、账号/API、费用、学习门槛、已验证状态。

默认流程：选择正在使用的工具 → 选择赛道或当前任务 → 查看少量推荐 → 阅读示例与前置条件 → 选择技能或套餐 → 查看安装方案 → 安装后试做一个小任务。
支持反向发现：先看赛道包，再选择自己的工具；切换工具必须重新计算可用条目与缺项，不能只更换安装按钮上的名字。

普通聊天网页、编码 IDE 和命令行 agent 的接入能力分别处理。没有可验证本地技能接入能力的产品提供教程与手动使用说明，不生成虚假的本地安装按钮。AI 工具拥有技能能力也不等于其所有版本、所有账号或所有操作系统表现相同。

## 4. 主流工具兼容方案

采用 `AgentAdapter` 注册表，记录工具 ID、显示名、官方说明、版本范围、平台、安装目标解析、加载条件、安装方法和验证方法。路径由适配器计算与校验，不能由网页文本任意指定。

现成 `skills` CLI 列出多种 agent，并可选择具体 agent、具体技能、项目或用户范围。它可作为安装适配候选，不能代替本站的行为验证。[官方 CLI 仓库](https://github.com/vercel-labs/skills)

| 工具组 | 本站支持目标 | 本站目前状态 |
| --- | --- | --- |
| Codex、Claude Code | 分类、目录、教程、安装适配、示例任务验证 | 规划中，未完成真实兼容测试 |
| Cursor、GitHub Copilot、Windsurf、Cline | 同上；按 IDE/扩展版本核查发现与加载条件 | 规划中，未完成真实兼容测试 |
| Gemini CLI、OpenCode | 同上；核查运行时与工具调用差异 | 规划中，未完成真实兼容测试 |
| 其他主流工具 | 纳入注册表后提供明确的支持级别 | 待核查，不展示为已兼容 |

每条兼容记录 `SkillCompatibility` 至少包含：skillVersionId、agentId、agentVersion、OS、方法、所需依赖、验证日期、证据、限制。
分开记录四件事：官方/安装器声明支持；本站命令验证通过；文件安装验证通过；示例任务验证通过。推荐列表优先显示对应环境已有实测的条目；未实测条目明确标记，不能仅靠目录存在就显示绿色“可用”。

首轮覆盖清单为上表八个具名工具，每个工具至少在一个明确声明的版本/系统环境完成真实安装 → 加载 → 示例任务验证，并验证冲突或失败恢复。其他主流工具继续纳入注册表并公布适配进度；八个工具的一次测试不代表所有版本/系统已通过。K1–K3 的目录和指导完成不能表示多工具一键安装全目标完成。

客户端支持能力的未知或过期状态必须可见。版本升级后受影响组合进入待复测，不自动继承旧版本的成功结论。

## 5. 精选规则：热度与质量分开

“只选评分最高最好用”调整为：**先满足必要条件，再选在具体比赛任务与环境中表现好的条目**。安装量、GitHub Star、第三方星级可帮助发现候选，各自保留来源、日期与样本；不能直接合成真实能力分数。skills.sh 排名使用安装数据，并非本站实际任务的效果评价。[官方目录说明](https://www.skills.sh/docs)

### 5.1 可进入安装包的必要条件

- 来源身份与目录明确，能定位到固定版本；有明确允许所需使用/分发的许可依据。
- SKILL.md 与配套文件完整，依赖、调用工具、网络与文件操作可解释；无无法解释的执行行为。
- 至少一个目标环境完成文件安装与示例任务验证；对应结果有日期和证据。
- 不要求把用户密钥写进技能文件、公开仓库或普通日志。

条件未满足时可进入“候选说明/外链”区，不能成为已验证一键安装包的内容。高热度不能抵消上述缺项。

### 5.2 编辑推荐与评价依据

首版采用“推荐理由＋验证记录”，不急于做统一排行榜。记录具体输入、预期交付物、实际结果、是否需要人工修正、失败恢复、学习成本与运行成本。
如果后续采用数值评分，必须先定义并版本化量规，按相同任务、模型、客户端与环境比较，公布测试次数和失败情况。建议维度为任务适配、结果正确性、可操作性、成本与维护；权重是待校准方案，不冒充科学分数。
样本不足显示“证据不足”，不能称“全网最好”。同一个 skill 可以适合 React UI，却不适合游戏引擎或影视制作；总分不能掩盖场景不匹配。

## 6. 每个 skill 如何讲清楚

详情采用固定结构，中文解释由本站编辑，不复制整份第三方教程：

| 字段 | 用户应能理解的内容 |
| --- | --- |
| 一句话用途 | 帮你完成哪个任务，如检查演示页面，而非泛称“提升效率” |
| 适合与限制 | 适合的技术栈/角色/赛道；不适合的任务与已知限制 |
| 前置条件 | AI 工具与版本、运行时、API 账号、网络、所需输入、费用依据 |
| 三步开始 | 安装或手动使用 → 示例请求 → 检查交付物 |
| 输入与输出示例 | 使用清楚的练习材料，说明输出仍需哪些检查 |
| 权限与变更 | 是否读取项目、写文件、运行脚本、访问网络；可选择的范围 |
| 来源与许可 | 作者、原仓库、skill 路径、commit、许可与必要署名 |
| 验证证据 | 哪个工具/版本/系统验证了什么、何时验证、失败情况 |
| 遇到问题 | 依赖缺失、加载失败、调用失败的处理与替代方案 |

教程优先让用户用自己的工具完成一个小练习，不强迫新人为了套餐切换熟悉的开发环境。初次配置和练习时间需要计入 M05 计划。

## 7. 赛道技能包

套餐先作为**版本化技能组合**，不默认等于付费商品。每包建议三至五个必要技能，可选技能单独列出；这是控制学习成本的建议，不是固定数量验收。
以下是能力组合草案，不代表已有对应名称的开源技能已被精选或实测：

| 赛道 | 最小交付目标 | 必要能力组合候选 | 关键核查 |
| --- | --- | --- | --- |
| 游戏 | 可玩的短流程＋演示说明 | 玩法与范围收敛、所选引擎/栈的原型开发、试玩检查、作品说明 | 引擎版本、素材许可、输入/设备、构建与演示条件 |
| 影视 | 完整短片或明确规则允许的样片＋制作说明 | 脚本/分镜、镜头一致性检查、制作/剪辑流程说明、交付清单 | 生成工具/API、费用、输出格式、素材/音乐使用条件；skill 不自动提供视频生成能力 |
| AI Agent | 可演示的核心任务＋评估样例 | 工作流/工具设计、所选框架接入、评估与异常处理、README/演示 | 模型与框架版本、API 成本、权限、真实工具调用与失败恢复 |

通用测试、文档等能力可复用，但不能默认安装所有通用技能。遵守赛事规则：禁止 AI、预制作品或某类外部素材时，相关条目提示不适用；规则不明确则提示核实，不能由套餐判断比赛允许使用。

`TrackBundleVersion` 保存适用赛道、工具适配范围、预期产物、固定 SkillVersion 引用、必需/可选项、依赖顺序、成本说明与审核证据。同一技能在多个包中只维护一份版本。项目引用包版本，包更新后提示差异，不自动升级已有项目。
套餐另有 `BundleCompatibility`：在同一个声明环境验证全部必需项、共同依赖、安装/加载顺序和最小产物。不同技能分别在不同环境成功，不能合并为整包已验证；可选项未通过时显式说明，不影响已明确剔除它的必要组合。

## 8. 许可与内容边界

开源仍有版权和许可条件；公开 GitHub 仓库也不自动授予任意复制、修改或分发权限。无明确许可时保留来源外链和自写介绍，不能打包成本站下载内容。[GitHub 官方许可说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

分别检查仓库根许可、skill 目录例外、引用代码、依赖和素材，保留适用 LICENSE/NOTICE 与作者信息。本站推荐不保证参赛使用、商业使用或云服务免费；限制和未知部分可见。
后续提供付费服务时，应另行定义收费的是编辑、测试、支持或安装服务，并核对分发条件，不因“套餐”一词推定用户授权购买或本项目已经决定收费。

## 9. 一键安装：真实行为与阶段

### A. 首个可交付网站版本

选工具和系统 → 查看适配套餐与缺项 → 查看所需依赖与安装范围 → 查看经过验证的命令或下载方案 → 完成示例任务。
按钮明确写“复制安装命令”“下载安装清单”“查看教程”。复制后仅显示“已复制”，下载后仅显示“清单已下载”；没有本机证据不显示安装成功。
未经命令验证的组合仅提供教程与待适配状态。默认推荐项目范围；用户范围单独选择。缺少 Node/Git 等前置依赖时解释步骤，不声称一条命令自动解决所有环境问题。

### B. 真正的本机一键安装

使用经过审查的本地 Helper/CLI 或已连接、具备对应能力的客户端。普通网站按钮本身不能提供任意本机程序执行能力。Helper 的首次获取、启动与配对需有清楚教程；未连接时保留 A 路径。

1. 网站生成 `InstallationPlan`，展示目标工具、范围、包版本、内容、依赖、费用与需要的操作。
2. 用户在本机选择并确认项目目录；安装计划只含结构化参数、受控适配器 ID 与固定来源，不接受任意 shell 文本。
3. Helper 检查工具/系统/运行时、目标路径和同名技能。已有内容默认保留，冲突提供跳过或有备份的替换选项。
4. 暂存获取文件，核验来源版本与哈希、限制下载体积、检查文件路径与符号链接；校验通过后再写入目标。
5. 按技能返回安装回执。文件写入、客户端加载、示例运行分别验证，部分失败单独显示并可重试。
6. 恢复与移除只处理本次记录的变更；用户后续修改先比较，不能直接删除整个已有目录。

安装 skill 不代表安装所有软件、授权所有外部账号或自动执行其脚本。依赖安装、首次运行与获得新权限是独立动作。Helper 与网站使用短期配对、来源校验和操作计划授权，不开放任意网页调用的本地命令执行入口；本机密钥不回传网站。
真正写入前重新校验计划有效期、清单哈希与最新发布/撤回状态；撤回版本使尚未执行的计划失效，下载到暂存也不能绕过。无法取得有效状态时停止新的受控安装并保留已有环境；网站不能把用户在外部自行执行的旧命令声称为已阻止执行。

### 版本与可重放

本站 manifest 至少锁定：源仓库、完整 commit SHA、skill 子路径、内容哈希、安装适配器/CLI 版本和清单版本。不能把分支名、浮动 latest 或第三方包 URL 当固定版本保证。锁定方式必须经过真实安装测试。
CLI 来源语法与安装行为需按采用的发行版核对，不把 `owner/repo@skill-name` 的 skill 名误当软件版本。使用第三方 Packs 时核查其更新和访问规则；无法满足版本固定要求则只作来源入口，不作为固定项目依赖。

## 10. 数据、接口与模块职责

| 实体 | 主要内容 | 所有者 |
| --- | --- | --- |
| Skill / SkillVersion | 名称、用途、作者、来源、固定文件版本、依赖、许可、教程、发布状态 | M10 |
| AgentAdapter / SkillCompatibility / BundleCompatibility | 工具注册表、适配规则版本、单项/整包环境、支持级别与证据 | M10；公共安装执行由主会话审查 |
| SkillEvaluation | 固定任务与环境、量规版本、结果、样本、费用、验证者 | M10 保存；M08 审核发布依据 |
| TrackBundle / TrackBundleVersion | 赛道、产物、固定技能项、必需/可选、审核与版本 | M10 |
| InstallationPlan / InstallationReceipt | 本人选择、manifestHash、短期计划、每项结果、来源与恢复引用 | M10；Helper 执行本机操作 |
| ReviewRecord | 指向 skill/bundle 的确切版本、审核依据、发布/撤回决定 | M08；通过 M10 发布 Port 操作 |
| ProjectSkillBundleRef | 项目选择的包与版本、用途；不包含本机密钥或绝对路径 | M02 资料容器，通过新增明确接口接入 |
| Task.skillRefs | 合法 skillVersionId 或 bundleVersionId 与使用目的 | M05；不同于现有 Resource 引用 |

M09 保持工具/灵感/组件链接模型，提供技能库导航入口，不将安装状态塞入现有 Resource。M10 独立定义内容和安装语义；M08 共用审核运营流程；M06 继续独占 GitHub 写入，不因安装包而扩大仓库授权。
当前九个模块代码正在并行开发：本次新增规划不要求它们修改现有 Resource.type、既有接口或交付事实。新增契约由主会话单独集成，未登记接入前只是设计草案。

| 页面/接口建议 | 责任 |
| --- | --- |
| `/skills`、`/skills/:id` | 工具/用途筛选、教程、许可与兼容证据；公开阅读 |
| `/kits`、`/kits/:id` | 赛道包、工具选择、版本与内容；公开阅读 |
| `/app/skill-installations/:id` | 本人安装计划与回执，不公开本机路径 |
| `GET /api/v1/skills`、`GET /api/v1/skill-bundles` | 只返回已发布条目及真实支持级别 |
| `POST /api/v1/me/skill-installation-plans` | 会话确定 userId；验证工具、版本与可安装项，产生短期计划 |
| `POST /api/v1/me/skill-installation-receipts` | 验证配对客户端与计划；用户手动反馈另标来源，不能伪造受验证回执 |
| M10 PublicationPort | M08 审核后按精确内容版本发布/撤回，拒绝过期审核 |
| M10 ReviewedSkillLookupPort | M05 查询已审核条目、校验固定引用；没有资源时计划仍可生成 |

安装计划授权绑定用户、工具、版本、范围、manifestHash 与有效期；重复执行用 operationId 幂等。本机绝对路径只在本地保存，服务器使用不泄露路径的标识。Helper 报告文件核验不等同平台独立验证所有本机行为，页面注明证据来源。

## 11. 状态与异常

内容发布、许可核验、兼容测试、文件安装、客户端加载和示例任务结果是独立字段，不用单一绿色“认证可用”取代。

| 情况 | 处理 |
| --- | --- |
| 已复制命令，尚无回执 | 提示在自己的工具中执行；安装状态为未知 |
| CLI 声明支持但本站未实测 | 显示待验证，不进入对应环境的实测推荐 |
| 许可未知或不允许打包 | 显示外链说明，阻止加入安装包 |
| 套餐只部分兼容所选工具 | 展示缺项，明确能否达到该包的最小目标；不静默替换 |
| 本机有同名技能 | 不覆盖，列冲突与保留/备份替换选择 |
| 网络/下载中断 | 保留原有内容与计划；按条目重试，不假装全部失败后回滚成功 |
| 文件安装成功但客户端未加载 | 独立显示加载待验证或失败，给出工具对应处理 |
| 新版本或有害内容被撤回 | 停止新的安装，保留历史引用并通知对应用户；不悄悄删除其本机文件 |
| 临近截止或依赖复杂 | 推荐保留熟悉工具与手动路径，不强迫重新配置环境 |

## 12. 开发拆解与验收

| 阶段 | 任务 | 可观察交付 |
| --- | --- | --- |
| K0 可行性 | 工具注册表与命令/加载验证，候选许可，真实练习任务 | 按环境的兼容证据；不能以总工具数量代替 |
| K1 内容基础 | SkillVersion、教程、筛选、审核发布、少量条目 | 新人能解释用途和开始步骤；来源与未知可见 |
| K2 赛道包 | 三种赛道能力清单、固定版本项、工具筛选、冲突/缺项提示 | 同一包切换工具后准确变化；少量技能有完整示例 |
| K3 安装指导 | 验证命令/清单、项目范围选择、教程和手动反馈 | 复制与实际安装状态分开；安装失败仍有手动路径 |
| K4 本机桥接 | 配对、路径预检、下载校验、备份、每项回执与恢复 | 一个真实工具环境跑通；其余适配按同一验收扩展 |
| K5 主流覆盖 | 首轮八工具逐项适配、整包验证、运维与过期处理 | 每工具至少一个声明环境真实安装/加载/示例通过；标为可用的整包必需项共同通过；其他组合有明确状态 |
| K6 项目沉淀 | M02/M05/M07 的选择、学习工时、实际使用经验 | 可复用固定版本与经验，复制项目不自动装技能 |

现有总体规划的人日估算不包含 M10；不把多工具安装桥接无成本塞入原排期。先以 K0 实测估算后续适配与持续维护工作，再安排具体日期。若 K4 不成熟，K1–K3 仍可独立交付并明确限制。

验收重点：错工具不能得到误导命令；未许可条目不能分发；撤回/旧审核不能发布，未执行安装计划在撤回后失效；篡改清单、错误哈希和越界路径被拒绝；同名技能与用户修改得到保留；部分失败/重复执行可恢复；复制命令不显示安装成功；首轮各工具和所声明套餐的实测环境能完成相应样例。权限、版本、路径、冲突和状态做必要自动化测试，教程/排版人工核验。

试用记录：找选项耗时、成功完成示例的比例、安装/加载失败原因、维护耗时、真实任务是否采用与人工修正量。比较时记录参赛者经验、工具与任务差异，不能将小样本相关性宣传为保证效率提升。
