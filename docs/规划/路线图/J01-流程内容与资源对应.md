## 实施

1. 按总体规划定义 JourneyGuide / JourneyPhase / JourneyNode / JourneyResource。首版只有公开准备指南，不加入账号、projectId、进度、status 或 checked 字段。
2. 导出 `getJourneyGuide(): JourneyGuide`，提供树根、三阶段、注意事项、具体行动与对应资源。对象不引用 private 项目或真实运行凭据。
3. 赛前以找比赛开始，讲清主办方核对、报名、最小作品、个人备赛出行、环境、空间、职责与排期。赛中连 Demo、并行 UI/素材、测试、PPT/讲稿、视频与正式提交。赛后连复盘、成果保留与经验复用。
4. 每个行动给具体成果/操作和 actionLabel/href；每个资源子枝一句使用时机/用途。无空间的团队功能先到 `/app`，不制造 ID，不宣称已经确认赛道、已经报名或已经提交。
5. 只链接现有本站入口：events/app/participation/app-account/resources/inspiration/skills/github/roadshow/ppt/library 的确实存在文章。不新增外部网站精选或许可结论。`/inspiration` 的 DSH 状态、`/resources` 的审核和原创教程来源要说清。
6. UI 草图和讲稿大纲可提前并行，视频成片需要可演示成果；可选资源不设默认阻塞。
7. Node 测试验证节点与阶段唯一、链接边界、可见三阶段、指南不携带私人完成数据、核心状态/依赖/提交语义。不要为每句中文镜像断言。
8. README 和交付说明记录公共导出、内容依据、测试、未接入部分和 NEEDS_INTERFACE。无需新环境变量或数据库迁移。

## 协作与验收

J02 以 model.ts 为唯一类型来源，允许双方先按总体约定独立实现。主会话负责路由与入口；不越界修改其代码。只需 Node 测试和类型检查，不运行 npm install/build、服务重启、真实验证码/模型/仓库操作。全局类型失败若来自尚未交付文件，只报告来源。

Constitution Check：I/X 公开指南与用途说明；II 来源和规则边界；III/IV 可选分工与并行真实依赖；V 交付事实分离；VI/VII 无私人数据或新增执行权限；VIII 必要内容测试；IX 不增加外部调用。
