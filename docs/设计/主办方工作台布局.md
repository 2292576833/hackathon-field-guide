# 草根黑客松情报局 · 主办方工作台布局规划

日期：2026-10-16 · 版本：**布局规格 v1.0**
上游：[主办方工作台设计](主办方工作台设计.md)（决定"有哪些面板、读什么数据"）、[规划 33](../规划/33-主办方可用性与赛后闭环.md)、[网页视觉设计](网页视觉设计.md)（令牌与品牌语法）
本文决定：**这些面板在屏幕上怎么摆**——画布与栅格、尺寸与间距、断点行为、滚动与粘性、以及每个容器在每个宽度下的确切列数。

> **本文件只做布局，不改代码。** 所有尺寸都从**当前真实实现量出来的值**出发（见第 2 节），不是凭空设定；新增的唯一数值是断点，理由写在第 6 节。
> **一条硬纪律**：一屏之内**只有一个 `.primary`（实心主动作按钮）**。次要动作用 `.secondary`，链接用 `.link`。

## 1. 布局目标

| # | 目标 | 可复核的判据 |
| --- | --- | --- |
| L1 | **首屏可见"唯一下一步"** | 1440×900 与 1280×800 下，状态条（含主动作按钮）**不需要滚动**即可完整看到 |
| L2 | **一屏一件事** | 每个滚动视口内只有**一个** `<h2>` 级主区块标题在视口顶部附近 |
| L3 | **不横向滚动** | 320px 起任意宽度下 `document.scrollWidth === clientWidth` |

| L5 | **状态不随滚动丢失** | 赛事上下文与状态条在长列表滚动时保持可见（粘性），但**不遮挡**被它压住的内容 |
| L6 | **列数随宽度确定** | 比赛卡、指标行、期限行、section 内容在 4 档宽度下的列数**唯一确定**（第 6 节表） |
| L7 | **不新增色值** | 新增 CSS `MUST` 只用 `globals.css` 已有令牌与既有模块的同族色 |

## 2. 实测画布与间距（当前真实值）

### 2.1 宽度链（每一层都会吃掉可用宽度）

| 层 | 规则 | 桌面（≥1200px 视口）实际可用 |
| --- | --- | --- |
| `body` | `background: var(--paper)` | — |
| `.shell`（`src/components/site.module.css` L1） | `max-width: 1200px; margin: 0 auto; padding: 24px 30px 64px` | 1200 − 60 = **1140px** |
| `.container`（`competition-workspace.module.css` L1） | `width: min(1200px, calc(100% - 48px)); margin: 0 auto; padding: 32px 0 64px` | min(1200, 1140−48) = **1092px** |

> **⚠ 实测发现的真实浪费**：工作台被**两层容器**包住，`.container` 又额外扣掉 48px 左右内边距，因此在 1440px 屏幕上内容只有 **1092px**，两侧各留 174px 空白。
> **本规划的处置**：工作台**不新增第三层容器**；`OrganizerSectionPage` 的 `<div className={styles.container}>` **必须去掉**（外层 `.shell` 已经提供 1200px 居中与 30px 内边距）。这样获得的宽度是**布局修正**，不是放大字号，风险低且立刻见效。
> **改动面与前提**：去掉后，`competition-workspace.module.css` 的 `.container` 会只剩工作台列表页在用。若它同时服务其他页面，`MUST` 改为新增一个更窄的页面级容器、**不改动 `.container` 本身**（否则会连带改动别的页面的宽度）。改动前先确认 `.container` 的全部引用点。
> **✅ 已核实（2026-10-16）**：`.container` 在 `competition-workspace.tsx` 共 **8 处**（L75、79、82、89、200、293、330、341），其中只有 **L293 `OrganizerSectionPage`** 属于工作台 section 页；其余 7 处是公开赛事页、评委页、管理页等。`competition-workspace.module.css` 另被 `organizer-action-center.tsx` 导入。**因此结论成立**：section 页 `MUST` 改用**新的页面级窄容器**，`MUST NOT` 直接改 `.container` 的宽度规则。
> **不动 `SiteShell wide/bare`**：`wide` 目前只服务团队空间画布（`project-client.tsx` L57），改它会影响其他页面。

### 2.2 间距与圆角（沿用，不新增）

| 用途 | 现值 | 来源 |
| --- | --- | --- |
| 区块之间的纵向间距 | `gap: 24px` | `.container`（L1） |
| 面板内边距 | `padding: clamp(16px, 3vw, 28px)` | `organizer.module.css` `.panel`（L10） |
| 卡片内边距 | `padding: 22px` | `competition-workspace.module.css` `.card`（L6） |
| 卡片栅格间距 | `gap: 16px` | `.cards`（L6）、`.panel` 内 `gap: 16px` |
| 表单字段间距 | `gap: 16px` | `.form`（L8）、`.surface` 内 `gap: 20px` |
| 圆角 | 面板 18px / 卡片 16px / 控件 10px / 徽标 99px | 各模块现值 |
| 页签横向间距 | `gap: 6px`，每项 `padding: 10px 14px` | `.tabs`（L5） |
| 正文行高 | `1.65`–`1.8` | `.shell` 1.65、`.muted` 1.65、`.rules` 1.8 |

**新增间距一律从此表取值。** 需要新档位时必须在本文件登记，不在组件里就地写魔数。

### 2.3 字号（沿用）

| 层级 | 现值 |
| --- | --- |

## 4. 栅格与容器规则

### 4.1 单栏为主，不用 12 列

工作台**不引入 12 列栅格**。理由是当前实现的全部布局都是"单栏区块 + 区块内自适应卡片"，引入 12 列会同时改动几十个既有组件，收益为零。可用的三种原语已经够用：

| 原语 | 规则 | 用在 |
| --- | --- | --- |
| **单栏堆叠** | `display: grid; gap: 24px`（区块）或 `gap: 16px`（区块内） | 页面主序、面板内 |
| **自适应卡片** | `grid-template-columns: repeat(auto-fit, minmax(min(100%, 290px), 1fr)); gap: 16px` | 比赛卡、指标卡、模板选择 |
| **键值对行** | `grid-template-columns: repeat(auto-fit, minmax(165px, 1fr)); gap: 12px` | 期限行（既有 `.deadlines`） |

### 4.2 窄栏并排（仅一处）

页签是唯一横向排布的组件，用**换行 flex** 而非栅格：`display:flex; flex-wrap:wrap; gap:6px`。**禁止**给页签加横向滚动（`overflow-x:auto`）——横向滚动在小屏上会让右半部分不可发现。

### 4.3 语义结构（利于跳出率与键盘）

```
<main>
  <h1>比赛名</h1>                        ← 每页唯一 h1
  <section aria-label="本场状态">        ← ② 状态条
  <nav aria-label="本场运营工作">        ← ③ 页签
  <section aria-label="报名管理">        ← ④ 内容
    <h2>报名审核</h2>
```

**约束**：`h1` 每页唯一；页面内标题层级不跳级（`h1 → h2 → h3`）；`<nav>` 必须带 `aria-label`，且**同一页只有一个页签 `<nav>`**。

## 5. 组件布局规格

### 5.1 比赛状态卡（`.eventCard`）

| 项 | 规格 |
| --- | --- |
| 栅格 | `repeat(auto-fit, minmax(min(100%, 290px), 1fr))`，`gap: 16px` |
| 内边距 | `22px`（沿用 `.card`） |
| 圆角 / 边界 | `16px` / `1px solid var(--line)` |
| 底色 | `var(--space-component-surface)` |
| 内部行距 | `display:grid; gap:10px` |
| 标题 | 一行省略还是换行？→ **换行**（`overflow-wrap:anywhere`），长比赛名不截断 |
| 徽标行 | `flex-wrap:wrap; gap:6px` |
| 期限行 | 两列键值在同一卡内**纵向排列**（卡宽只有 290–380px，并排会挤成两行且不对齐） |
| 动作行 | 主按钮 `flex:1 1 100%`（占满卡宽）；次链接在下一行左对齐 |
| 触摸 | 整张卡**不可点**（避免与卡内按钮冲突）；只有按钮与链接可点 |

### 5.2 本场状态条（`.nextStep`，由 `OrganizerActionCenter` 改造）

| 布局 | `display:grid; gap:12px`，**不使用两列**（"唯一下一步"需要通栏阅读） |
| 徽标行 | 一行 `flex-wrap:wrap; gap:6px` |
| 标题 | 22px，通栏 |
| 说明 | `.muted`，通栏，`max-width: 68ch`（避免超宽行难读） |
| 动作行 | `flex-wrap:wrap; gap:10px`；手机上各按钮 `flex:1 1 100%` |
| 粘性 | **不粘性** |
| 高度预算 | 桌面 ≈ 150–190px（含 3 行文字 + 1 行动作）；`MUST` 让 L1 的"首屏免滚动"成立 |

### 5.4 期限行（`.deadline`）

| 项 | 规格 |
| --- | --- |
| 位置 | 紧跟上下文条下方，**独立一条**，不进状态条 |

### 5.5 区块页签（`.tabs`）

| 项 | 规格 |
| --- | --- |
| 布局 | `display:flex; flex-wrap:wrap; gap:6px; border-bottom:1px solid var(--line); padding-bottom:12px` |
| 单项 | `min-height:44px; padding:10px 14px; border-radius:10px` |
| 当前项 | `aria-current="page"` + 底色 `var(--action)`、文字白（**唯一允许实心橙底的导航项**） |

## 6. 断点与各宽度列数

### 6.1 断点选型（不新增碎片化）

代码库当前有 **34 个不同的 `max-width` 断点**（620px 出现 20 次、760px 9 次、650px 7 次、640px 6 次）。**本次只准用下面三档**，并在需要时复用既有档位，不允许再造新值：

| 档 | 阈值 | 选用理由 | 既有先例 |
| --- | --- | --- | --- |
| **S 手机** | `≤ 620px` | 库内**最高频**断点（20 处）；`site.module.css` 的手机规则也在 620px | `.paletteFabPanel`、多处模块 |
| **M 窄桌面/平板** | `≤ 760px` | **站点外壳**的官方断点（`globals.css` L75），改动与全站节奏一致 | `globals.css`、9 处 |
| **L 分栏→收拢** | `≤ 1024px` | 仅用于"双列收成单列"这类布局判断；`1023px` 库内已有 3 处先例 | `1023px` ×3 |

**不再新增** 640/650px 档：`.container` 用 650px、`organizer.module.css` 用 640px，本规划**不要求统一**（统一会改动既有页面），但**新写的规则必须从 S/M/L 三档里选**。

### 6.2 各宽度列数（唯一确定，实现照此）

| 区块 | ≥1025px | 761–1024px | 621–760px | ≤620px |
| --- | --- | --- | --- | --- |

| 概览指标卡 | 4 列 | 2 列 | 2 列 | **1 列** |

| 页签 | 一行 | 换行 | 换行 | 换行（字号 14px） |

## 7. 滚动、粘性与锚点

| 项 | 规则 |
| --- | --- |
| 粘性元素 | 仅 ① 上下文条与 ③ 页签。**两者 `MUST` 包在同一个粘性容器内**，避免两个 `top:0` 叠在一起互相覆盖（这是当前实现里"设置页 ①②③ 三处都显示状态"的同类风险） |
| 锚点跳转 | 页面内锚点（如 `#project-goal` 式跳转）`MUST` 用 `scroll-margin-top` 给粘性区留位，跳转后目标标题**不被压住** |
| 长列表 | 报名/工单/评审列表用既有分页游标，**不做无限滚动**（无限滚动会让"我处理到哪了"丢失） |
| 焦点管理 | 表单提交失败后焦点回到第一个错误字段；错误提示**不被粘性区遮挡** |
| `prefers-reduced-motion` | 关闭平滑滚动与过渡（既有 `.container *{scroll-behavior:auto}` 与各模块规则已如此，新增组件必须继承） |

## 8. 状态占位布局（容易漏的一环）

| 状态 | 布局要求 |
| --- | --- |
| **加载中** | 占位高度**接近真实内容高度**，避免加载完成后页面跳动；但**不做数字骨架屏**（不显示假数字） |
| **未读取** | 明确显示"尚未读取"+ 重新读取按钮，**布局保持区块存在**（不留空洞） |
| **读取失败** | 该区块内联错误 + 重试；**其他已读到的区块照常显示**（不整页报错） |
| **空** | 区块内给一句说明 + **一个**下一步动作；不留空白、不显示 `0`（`undefined ≠ 0`） |
| **权限不足** | 说明当前身份能做什么、不能做什么，给可执行替代；**不渲染任何该权限的数据区块** |
| **归档只读** | 全页可见，但所有写控件 `disabled` 并说明原因；**期限与历史仍可见** |
