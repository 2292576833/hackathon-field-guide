# 草根黑客松情报局 · 主办方工作台设计

日期：2026-10-16 · 版本：**设计规格 v1.0**
依据：[规划 33 · 主办方可用性与赛后闭环](../规划/33-主办方可用性与赛后闭环.md)（含分项 [P05](../规划/主办方/P05-复制赛事与配置复用.md)–[P09](../规划/主办方/P09-赛后闭环.md)）、[宪法 v1.21.0](../../.specify/memory/constitution.md) 原则 X / XI / XII、[网页视觉设计](网页视觉设计.md) 与 [配色方案](配色方案.md)。

> **本文件只做设计，不改代码。** 所有面板都标注"数据来源"，且**只用已有接口或规划 33 已登记的接口**——不发明新端点、不新增状态、不做评分或预测。
> **本文件管"有哪些面板、读什么数据"**；面板在屏幕上怎么摆（画布、栅格、断点、粘性、确切列数）见 [主办方工作台布局](主办方工作台布局.md)。
> **设计的第一原则**：主办方打开工作台，应该**一屏之内知道"现在该动哪一件"并直接动手**，不需要逐个页面找、不需要自己算。

---

## 1. 设计目标

| # | 目标 | 判断方式（可复核） |
| --- | --- | --- |
| G1 | **一屏给出唯一下一步**，且按钮直达该动作 | 任意状态下，"现在该做什么"只出现**一条**建议与**一个**主动作 |
| G2 | **不再一页页找**：需要动手的事在所在页面就能动手 | 抽查每个面板，操作不跳出当前赛事上下文 |
| G3 | **同一个事实只说一次** | 状态徽标、规则版本、期限在全站各只出现一处权威位置 |
| G4 | **跨比赛可见**：不用点进每一场才知道哪场该管 | 工作台首页按机构列出可管理比赛及其当前阶段 |
| G5 | **复用期配置**：办第二届不必从零重填 | 创建向导内有"复制上一场"，产出**草稿**而非已发布规则 |
| G6 | **数字可比对**：面板上的数字与来源模块一致 | 每个数字标注统计范围与数据时间；`undefined`（未读取）≠ `0` |
| G7 | **不制造焦虑**：不出百分比、进度条、完成度、倒计时压迫 | 全文搜索无"完成度 / 进度 % / 成功率 / 影响力" |

## 3. 信息架构

### 3.1 两层结构（对齐选手侧"主页主路 + 空间细步"）

```
第 1 层  赛事工作台  /organizers/workspace          ← "我有哪些比赛、今天先动哪一件"
             │  点某一场
             ▼
第 2 层  本场运营     /organizers/workspace/[eventId]/…
             │
             ├─ 本场概览（新增落地页 /organizers/workspace/[eventId]，承载 P06/P07 与"唯一下一步"）
             ├─ registration  报名管理
             ├─ teams         队伍管理
             ├─ communication 通知与答疑
             ├─ schedule      行程管理
             ├─ services      现场服务
             ├─ judging       收件与评审
             └─ settings      比赛设置（原 /organizers/workspace?event=… 的配置部分）
```

**关键决定**：`/organizers/workspace` **不再同时承担"配置表单"**。当前把"选比赛 / 配规则 / 发布 / 处理待办"挤在一页，是 F1/F2 的根因。拆成"选（工作台）→ 用（本场运营）→ 改（比赛设置）"三段。

### 3.2 一级导航的纪律（宪法 X）

- **仍然只有一处主办方入口**：`/organizers/workspace`。section 页签**只在本场运营内出现**（现状 `IdentityFrame` 已如此，保留）。
- **不新增第三条路径**：本场概览与 section 页是同一层的兄弟，不是新层级。
- 未入驻用户 `MUST` 仍走 `/organizers` 的入驻申请，工作台不重复提供入口。

## 4. 第 1 层：赛事工作台 `/organizers/workspace`

### 4.1 页面结构（自上而下）

| 区块 | 内容 | 数据来源 | 状态 |
| --- | --- | --- | --- |
| **A 身份条** | 机构名 + 我的角色（组织管理员 / 工作人员） | `/organizer/organizations`、`/me/competition-identities` | 已有 |
| **B 未入驻/暂停态** | 未通过时只显示申请状态与依据；**不显示任何待办数字** | 同上 | 已有，收敛表达 |
| **C 我的比赛** | 按机构分组，每场一张**状态卡**（见 4.2） | `/me/competition-identities` + 每场 readiness | 已有数据，重排 |
| **D 唯一下一步**（有选中比赛时） | 复用 `OrganizerActionCenter` 的判定，但只保留"状态 + 一条建议 + 一个主动作" | readiness、registration-counts | 重构 |
| **E 高级设置入口** | 机构设置、发信邮箱、工作人员与授权、认领说明、归档比赛 | 既有 | **收进折叠区**，不再铺在首屏 |
| **F 创建比赛** | 一个按钮 → 进入创建向导（内含"复制上一场"） | `/organizer/templates` | 已有，加 P05 |

### 4.2 比赛状态卡（C 区块核心，解决 F5）

每张卡显示**事实**，不显示完成度：

| 行 | 内容 | 来源 |
| --- | --- | --- |
| 标题行 | 比赛名 · 机构名 | identity |
| 状态徽标 | `草稿（选手看不到）` / `已发布（选手可见）` / `比赛已结束` / `已归档` | `event.status` |
| 规则版本 | `正式规则 v{n}`；未发布时**不显示**该徽标 | `publishedRevision` |
| 机构暂停 | 仅当机构非 approved 时显示 `机构暂停运营` | `organization.status` |
| 期限行 | `报名截止 {时间}` / `作品截止 {时间}`；**无值则不显示该段** | `event.registrationClosesAt` / `submissionClosesAt` |
| 待补提示 | `还有 {n} 项信息需要你们确认`（仅 `missing + conflicting` 计数） | readiness |
| 动作行 | `进入本场运营`（主）· `比赛设置`（次）· `看选手看到的样子`（仅已发布） | — |

**排序**：`机构暂停 → 草稿有缺项 → 已发布 → 已结束 → 已归档`；同组内按 `报名截止` 升序（无值排最后），再按标题。

**明确禁止**：卡片上不出现报名人数、评审进度、完成百分比。跨比赛比较数字会诱导排名与焦虑，且违背 G7。

### 4.3 空态与失败态

| 情形 | 页面表现 |
| --- | --- |
| 尚未入驻 | 只显示申请状态、审核说明与"填写入驻申请"；**不显示比赛区** |
| 已入驻、无比赛 | "这个机构还没有比赛。" + 一个"创建第一场"主动作；工作人员显示"创建比赛请联系组织管理员" |
| 读取失败 | 明确说明哪一块没读到、保留可用的其他块、给"重新读取"；**不显示 0 或占位数字** |
| 权限不足 | 说明当前身份能处理什么、不能处理什么，给出可执行替代（联系组织管理员） |

## 5. 第 2 层：本场运营

### 5.1 统一结构（每个 section 页同构）

四个区，自上而下，**顺序固定**：

```
┌─ ① 赛事上下文条 ─────────────────────────────┐
│ 机构名 · 比赛名 · 当前身份 · 比赛时区          │
│ 期限（只有一个时：作品截止）                    │
│ 右侧：切换比赛 · 我的比赛 · 比赛设置 · 看选手视图 │
├─ ② 本场状态条 ───────────────────────────────┤
│ 状态徽标 · 正式规则 v{n} · [机构暂停]          │
│ 唯一一句话：下一步做什么（不写"完成度"）        │
│ 唯一个主动作按钮                                │
├─ ③ 本区块页签（身份 + 模块双过滤）             │
│ 报名管理 · 队伍管理 · 通知与答疑 · 行程 · 现场服务 · 收件与评审 │
├─ ④ 本区块内容 ───────────────────────────────┤
│ 本区块自己的操作区与折叠面板                    │
└──────────────────────────────────────────────┘
```

**② 就是改造后的 `OrganizerActionCenter`**：它只负责"当前这场、现在该动哪一件"，**发布门槛清单移出**（见 6 节）。

### 5.2 新增落地页：本场概览 `/organizers/workspace/[eventId]`

进入某场比赛的默认页，承载跨 section 的"全貌"，避免每个 section 都自说自话。

**路径说明**：该路径当前**为空**（`src/app/organizers/workspace/[eventId]/` 下只有 `communication/`、`judging/`、`registration/`、`schedule/`、`services/`、`teams/` 六个子目录，**没有** `page.tsx`），因此新增概览页**不占用任何既有路径、不需要改动既有 section 路由**。

| 区块 | 内容 | 来源 | 对应规划 |
| --- | --- | --- | --- |
| **概览指标行** | 报名（待审/已通过）· 队伍数 · 已收件数 · 本轮评审进度 | `registration-counts`、`teams`、`workspace()` | 33 第 3 期 |
| **数据看板下钻** | 报名 / 队伍 / 收件 / 评审 / 后勤 五块的筛选视图 | 复用既有读取 | **P07**（待实施） |
| **下一步与门槛** | 组合 `OrganizerActionCenter` + 发布门槛清单 | readiness | 已有，重排 |
| **最近变化** | 已发布版本的 `changeSummary` 与时间 | `publication-changes` | 已有 |
| **快速入口** | 只列**身份可处理且模块已开启**的 section | capabilities + modules | 已有逻辑 |

**未实施项的处理**：P07 未落地前，本区只显示**已有指标**（报名计数、期限、状态），`MUST NOT` 用占位数字或骨架屏假装已有看板。

### 5.3 六个 section 页的操作区

| Section | 首屏主要动作（唯一） | 折叠区（按需展开） |
| --- | --- | --- |
| registration | 处理待审报名 | 入选通知模板编辑、报名表配置、导出、**复制上一场**（入口见 6.2） |
| teams | 查看与锁定正式名单 | 建议分组、重开锁定、名额说明 |
| communication | 发布公告 | 公告版本与已读、求助工单处理、公开 FAQ 整理 |
| schedule | 编辑行程草稿 | CSV 导入预览与确认、发布、版本历史 |
| services | 住宿分配与餐券发放 | 餐券核销、破冰分组、导入预览 |
| judging | 指派评委与推进本轮 | 收件材料、**评审进度**、汇总与公布、校准、自检、公平包、相似线索、申诉、导出、审计 |

**每个 section 的组内顺序统一为**：① 现在要做的 → ② 进行中的记录列表 → ③ 折叠的高级操作与历史。

## 6. 组件设计

### 6.1 `OrganizerActionCenter` 瘦身（解决 F1/F3/F4）

**现状**：4 个职责挤在一起——状态徽标、唯一下一步、发布门槛清单、身份可处理说明；同一组件挂在设置页与所有 section 页。

**改造后**：

| 现状职责 | 改造后去向 |
| --- | --- |
| 状态徽标 | **保留在本组件**，成为全站该赛事状态的**唯一权威位置** |
| 唯一下一步 + 主动作 | **保留在本组件** |
| 发布门槛清单 | **移到"比赛设置"页**（它属于"改配置"，不属于"日常运营"） |
| 你的身份可以处理 … | **删除**（页签已经按身份过滤，重复表达；宪法 X 要求同义信息只一套） |
| 挂载位置 | **只在 `② 本场状态条` 出现一次**；设置页不再重复挂载 |

**保留的判定优先级**（顺序不变，避免行为漂移）：

1. 机构暂停 → 先处理机构状态
2. 草稿且有缺项 → 去补赛事信息
3. 草稿且信息齐 → 预览并发布
4. 已发布且有待审报名 → 去处理报名
5. 已发布 → 照看正在进行的事项
6. 已结束/已归档 → 查看设置

### 6.2 创建向导内的"复制上一场"（P05，解决 F6）

| 项 | 设计 |
| --- | --- |
| 位置 | 创建向导"选一个起点"模板选择区**下方**，作为第三个选项（模板 / 复制 / 空白） |
| 交互 | 选来源比赛（限**本机构**）→ 显示将要复制的项与**不复制的项**（时间、答卷、队伍、通知已读、评审分数）→ 明确按钮"以它为起点创建草稿" |
| 产出 | 新**草稿**，名称默认 `<原名>（副本）`，可当场改 |
| 不做的表达 | 界面上 `MUST NOT` 出现"一键复制并发布"；发布仍走既有预览 + 变更说明 |

### 6.3 评审进度视图（P06，解决 F7）

| 项 | 设计 |
| --- | --- |
| 位置 | `judging` 页，与 `calibration` / `integrity` / `fairness` / `duplicates` 折叠面板**并列**，不替换、不合并 |
| 作品列 | `已提交 {n} / 本轮最少 {m}`，还差时给 `还差 {k} 位` 文字徽标 |
| 评委列 | `已交 {n} / 应评 {m}`；`recused`（已回避）、`revoked`（已撤销）单独列出并标注原因，**不计入分母** |
| 轮次汇总 | 尚未收齐的作品清单（按缺口数降序，同数按标识稳定排序） |
| 数据 | **只用 `workspace()` 已返回的集合**，不新增读路径 |
| 明确禁止 | 百分比、进度条、完成度、评委排名、"最慢评委" |

### 6.4 已公布结果导出（P06）

| 项 | 设计 |
| --- | --- |
| 位置 | `judging` 页既有"审计与导出"区 |
| 两个按钮 | `导出分数明细（内部对账）` = 既有 `exportScores`；`导出已公布结果（可对外留档）` = 新增 |
| 区别说明 | 两按钮下**各一句**说明用途与是否含评委账号；`MUST` 让主办方不会拿错 |

| 对外件**不含** | 评委账号或真名、联系人、答卷、求助、住宿、申诉正文 |
| 需复核时 | `needs_review` 只输出状态与版本，**不输出分数与名次** |

### 6.5 选手侧资源汇总的接入点（P08）

不属于主办方工作台，但**由本设计的赛事页结构承接**：

- 位置：`/competitions/[eventId]` 既有页面内的只读汇总区。

- 主办方工作台**不出现**该区块，避免两侧职责混淆。

### 6.6 赛后闭环的接入（P09）

- 主办方侧：本场概览的"赛后"区只列**已公布**成果与"下一届可复用"（每项指回既有记录）。

## 9. 视觉与交互规则

### 9.1 令牌（沿用，不新增字面色值）

| 用途 | 令牌 | 说明 |
| --- | --- | --- |
| 页面底 / 卡片面 | `--paper` / `--space-component-surface`（暖白 `#FFFDF8`） | 与既有工作台一致 |
| 正文 / 次级 | `--ink` / `--muted` | — |
| 主动作按钮 | `--action` / `--action-hover` | 白字主按钮只用 action |
| 强调装饰 | `--brand` | 不用于普通大小白字 |
| 边界 | `--line`（装饰）/ `--control-line`（需辨认的交互边界） | 表单必须用 control-line |
| 待确认 / 时间风险 | `--warning` / `--warning-bg` | 待补字段、缺项提示 |
| 失败 / 明确问题 | `--danger` / `--danger-bg` | 读取失败、冲突 |
| 已确认 | `--success` / `--success-bg` | 必须配文字，不单靠颜色 |

### 9.2 红色分级（宪法 X 硬约束）

**只有真阻塞可用红色**：① 机构暂停导致无法运营；② 读取失败需要重试；③ 有明确冲突需人裁决（`conflicting`）。

其余一律中性标记：待审报名、待补字段（用 `--warning`）、尚未发布、评审未收齐。

### 9.3 禁止的视觉表达

- ❌ 进度条、环形进度、完成度百分比、打勾清单
- ❌ 倒计时压迫式大数字
- ❌ 排行榜、名次徽章（对外部/内部人员都不做）
- ❌ 数字骨架屏（未读到就明确说"未读取"，不装样子）

### 9.4 排版与密度

- 参赛流程透明铺陈的页面**不套外层大容器**；工作台组件按既有暖白底与 1px 边界。
- 每个面板一个 `<h2>` 级标题，不用层层嵌套标题堆砌。
- 折叠只用于**高级与历史**；**期限、权限、费用、错误、未保存输入、正式回执 `MUST NOT` 被折叠隐藏**。

### 9.5 键盘、手机与减少动效

- 所有交互元素 `min-height: 44px`；聚焦环沿用既有 `outline: 3px solid` + offset。
- 页签在窄屏换行，不横向滚动；主要按钮在手机上**独立可完成**。
- `prefers-reduced-motion: reduce` 时关闭过渡（既有 CSS 已这么做，新增组件必须继承）。

## 12. 验收口径

| # | 检查 | 通过标准 |

| 1 | 唯一下一步 | 任意状态下，"现在该做什么"只有**一条**建议与**一个**主动作 |
