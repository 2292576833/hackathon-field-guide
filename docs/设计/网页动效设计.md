# 草根黑客松情报局 · 网页动效设计

日期：2026-10-08 · 动效规格草案 v0.1  
关联：[网页视觉设计](网页视觉设计.md)、[总体规划](../规划/00-总体规划.md)、[协作约定](../规划/10-数据与接口协作约定.md)、[宪法 v1.2.0](../../.specify/memory/constitution.md)。

本文规定动效的用途、触发、时间、状态与降级方式，供后续设计和前端实现使用；当前尚未实现这些动画。

## 1. 动效方向

延续暖白＋橙红“情报编辑部”视觉，采用**轻展开、短位移、清楚反馈**的动效。
首页的感觉像资料被整理到桌面，项目工作台的感觉像任务状态被清楚更新。

动效主要回答三个问题：我点到了吗？哪些内容发生变化？现在还在处理还是已经完成？
品牌表达可以有一点趣味，关键操作不能等待动画结束才能继续。
不通过旋转数字、烟花或全屏庆祝，把测评得分、计划草案或仓库保存夸大成比赛成功。

### 风格词

- 轻：位移通常 2–8 px，不晃动整个页面。
- 快：普通反馈约 120–240 ms；进入不拖延，退出更短。
- 稳：内容、按钮和阅读位置保持稳定。
- 有依据：状态动画由真实事件触发，不按预设时间制造“完成”。

## 2. 通用规则

1. 每个动效必须有一个信息或操作目的；没有目的就保持静态。
2. 每个区域通常只有一个正在运动的焦点，禁止任务、倒计时、按钮与背景同时闪动。
3. 返回已看过页面、切换项目、轮询更新时，不重复播放首页式入场。
4. 保持稳定的列表 key 与任务 ID，不把每次刷新都当成全新卡片。
5. 鼠标 hover 只是补充；手机、键盘和触摸不依赖 hover 才能看懂信息。
6. 成功、失败、未知和等待必须有文字，不能仅靠颜色或动画判断。
7. 取消和关闭只表达实际支持的动作；远端写入已经发出时，不暗示已撤销。
8. 系统选择减少动效时采用静态状态；账号设置可提供“关闭非必要动效”。

## 3. 动效令牌

以下数值是本项目建议值，需在真实页面上调校，不是第三方设计网站的强制规范。

| Token | 建议值 | 使用场景 |
| --- | --- | --- |
| `--motion-instant` | 0 ms | 焦点、减少动效、必须立即生效的状态 |
| `--motion-fast` | 120 ms | 按钮颜色、边框、轻提示退出 |
| `--motion-feedback` | 160 ms | 收藏、标签与局部状态反馈 |
| `--motion-panel` | 200 ms | 菜单/对话框进入、内容切换 |
| `--motion-enter` | 240 ms | 首页辅助板、抽屉、轻量区块进入 |
| `--motion-exit` | 140 ms | 对话框/抽屉退出 |
| `--motion-stagger` | 40–60 ms | 少量新卡片依次进入；只用于前几项 |
| `--motion-shift-sm` | 2 px | 卡片 hover，桌面适用 |
| `--motion-shift-md` | 6–8 px | 小面板进入、可选辅助内容 |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 进入和位移，快速落稳 |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 常规状态切换 |
| `--ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 退出 |

不使用夸张弹簧、越界回弹和 360° 旋转作为主要交互语法。
未知时长的后台操作没有“动画总时长”；200 ms 面板出现后，保持真实等待状态，直到收到实际结果。

## 4. 首页与公开内容

### 4.1 首屏进入：一次轻整理

标题、导航和主要按钮先可见、可用；动画不挡住关键文字，不要求用户等待完整序列。

| 阶段 | 动效 | 时长/延迟 | 触发条件 |
| --- | --- | --- | --- |
| 首屏出现 | 标识、标题、主动作保持可见 | 0 ms | 页面首次可显示 |
| 品牌强调 | 标题旁橙红短线由左向右展开，预留尺寸 | 220 ms / 0 | 非减少动效、首次进入 |
| 副说明 | 可选 4 px 上移至原位，文字始终可读 | 180 ms / 40 | 同上 |
| 清单示意板 | 6 px 上移＋轻淡入 | 240 ms / 100 | 同上 |
| 清单编号 | 前三行依次显现 | 160 ms / 40 间隔 | 仅静态流程示意；不是已完成任务 |

整个辅助序列建议在约 450 ms 内结束。手机可以只保留短线和示意板进入。
没有 JavaScript 或图片加载失败，标题和操作仍直接可见；不能默认 opacity:0 后依赖脚本救回内容。

### 4.2 滚动区块

栏目标题保持可见；资源/赛事卡片首次进入视区时可轻淡入，上移最多 6 px，180–220 ms。
最多前四张卡片错开进入，超过部分直接展示；总延迟上限约 180 ms。
不把页面滚动替换成动画时间线，不锁定滚轮，不自动横向滚动资源墙。

返回列表、筛选和分页不重复播放整个栏目。减少动效模式全部直接显示。

### 4.3 卡片 hover

桌面鼠标进入：边框稍加深＋卡片上移 2 px，160 ms；离开恢复，120 ms。
卡片内箭头最多平移 3 px；不要让文字、截止时间和按钮同时跳动。
手机只保留按下与选中状态；键盘 focus 显示立即可见的焦点环，不用位移动画代替焦点。

## 5. 导航、登录与组件

| 场景 | 默认动效 | 减少动效/注意事项 |
| --- | --- | --- |
| 主按钮 hover | 背景和边框 120 ms | 保留状态变化；不放大整块按钮 |
| 按下 | 立即改变颜色 | 点击立即处理，无人为延迟 |
| 键盘焦点 | 立即显示焦点环 | 不淡入，不闪烁 |
| Tab 切换 | 选中条短移动/背景切换 160 ms；内容可直接替换 | 静态选中态，正确焦点和语义 |
| 菜单 | 4 px 进入＋淡入 160–200 ms | 直接打开；不靠动画结束才聚焦 |
| 对话框 | 遮罩淡入，面板 6 px 进入，200 ms | 直接显示；焦点进入、关闭后恢复 |
| 手机筛选抽屉 | 底部最多 12–16 px 进入，220 ms | 直接展示；高度稳定，不弹跳 |
| 帮助展开 | 首版直接展开，或高度变化短于 200 ms | 内容可达，不能被裁切隐藏 |
| 收藏 | 等服务器确认后图标实心/文字“已收藏”，160 ms | 直接改状态；失败保留备注 |
| 成功轻提示 | 4 px 进入＋淡入 160 ms | 静态；重要成功仍在页面有记录 |
| 表单错误 | 边框与错误文本出现，不摇晃输入框 | 保留输入；错误和恢复动作可见 |

登录验证码流程：点击后立刻显示真实发送中状态；发送成功才显示“已发送”。
重发倒计时只用数字文字，不做数字翻页和持续脉冲；过期时明确给出重发操作。
登录完成后返回原页面；动画不是身份验证的依据。

## 6. AI 长任务：让等待可理解

适用：赛事分析、评分、分工建议、计划生成与复盘草稿。

### 6.1 状态与反馈

| 真实状态 | 页面反馈 | 动效 |
| --- | --- | --- |
| 本地发起/等待请求 | “正在发起…”；防重复点击 | 按钮文字更新，尺寸不变 |
| queued | “任务已排队，可离开后继续查看” | 状态图标静态；不假设已经开始推理 |
| running | 显示后台实际提供的步骤或“正在生成草案” | 一个小旋转标记可选，约 1 s 一周；减少动效用静态图标 |
| succeeded | “草案已生成，等待校验/确认”或已校验的实际结果 | 状态短切换 160 ms，展示结果入口 |
| failed | 错误类别、草稿仍在、可适用的重试/手动路径 | 停止所有加载动效，错误留在页面 |
| cancelled | “已停止本次生成”，以服务器实际状态为准 | 静态状态；不暗示撤回已发生的外部动作 |
| 超时/状态不明 | “暂未获得结果，正在查询状态” | 区别于正常生成；不自动报成功或创建重复任务 |

模块特有的 validating/review_ready/ready 表示不同校验步骤，应使用各自真实含义。
例如评分已生成但 schema 无效，不显示“测评已完成”；采集完成不显示“已发布”。

### 6.2 不显示假的进度

有可测工作量才能显示确定进度：例如“已上传 3/5 个文件”或实际上传字节。
上传完成只是传输完成，不等于 GitHub commit 成功。
模型无可测总量时，不显示自动从 0 走到 99 的进度条，也不把动画步骤数当完成百分比。
可以显示经过时间与最后更新，但不伪造预计剩余时间。

页面读取超过约 150 ms 才考虑显示占位，避免极短请求闪一下；结果一到立即可用，不设“动画至少播放两秒”。
骨架采用静态浅底占位，尺寸与真实内容相近，不做扫光；减少视觉干扰并稳定布局。

### 6.3 完成与焦点

任务完成后提供简短站内提示与“查看结果”，不自动跳页，不抢走用户正在编辑的焦点。
离开页面再回来，按已保存 jobId 查询状态，不能再次发起同一生成。
流式文本若展示，只作生成过程预览；结构化校验通过前不能成为生效分工/计划。
不把逐字打字效果施加到已经生成的长答案，用户应能立即阅读完整结果。

## 7. 提问、测评与分工

### 提问切换

保存上一题后，下一题内容可轻淡入 160–180 ms，位移最多 4 px；不做整屏左右翻牌。
若保存失败，停留当前题并保留输入，不能用翻页动画遮住失败。
显示真实题数时使用“第 3/6 题”；动态追问尚未确定总量时写“补充问题”，不造固定完成百分比。
上一题可返回，题目焦点与读屏提示由实际导航控制。

### 测评结果

分项条一次展示实际值；可选择 160 ms 轻展开，必须同时有静态数字、得分含义和量规版本。
不做 0→100 跳数、不做战力升级、排行榜登顶和大范围雷达扩张。
证据不足保持“证据不足”，不能为了动画完整填满条形图。

### 分工建议

先显示草案标签与推荐理由，再显示任务行。成员未完成测评不让其头像消失或摇晃。
负责人修改后，仅该行出现一次浅橙标记，约 160 ms 切换、停留约 1 s 后恢复普通背景；差异文字保留。
确认分工由项目管理员执行。成功反馈只写“分工已确认”，不等同于任务时间可行。

## 8. 任务、时间计划与重规划

### 8.1 工作台进入

导航、截止时间、生效任务直接显示。数据加载期间保留已知内容，后台刷新不让整页闪空。
“下一步”面板最多轻淡入一次，160 ms；用户查看旧项目时不重复入场。
倒计时正常使用文字，不做持续闪烁；临近截止也采用稳定风险提示和动作建议。

### 8.2 更新任务进度

用户选择“进行中/阻塞/待验收/完成”→立即显示保存中→服务器确认→更新状态标签。
保存失败恢复可编辑状态，保留输入并说明未同步。
任务完成用状态文字和一个小勾，不喷彩带、不整屏变绿。
首版不在正在点击时自动把卡片移到另一个区域；可保持当前行，下一次主动切换筛选才整理列表。

### 8.3 重规划差异

```text
旧计划继续可读
     ↓ 发起调整
真实生成/校验状态（不是新计划已生效）
     ↓ 草案可查看
差异摘要：删减、改负责人、改期限、仍未解决的缺口
     ↓ 项目管理员确认，校验预期版本
生效版本更新＋审计记录
     ↓
局部反馈“新计划已应用”；可行性另外显示
```

差异出现 160–200 ms 轻淡入，新增/修改/移除都有文字标记，不能只靠绿红背景。
桌面可以并排旧/新；手机上下对照。保留任务 ID、滚动位置和正在编辑内容。
应用成功只更新受影响区域，避免整张时间线滑出再滑入。
版本冲突立即显示，保留编辑；不能在动画结束后才告诉用户应用失败。

### 8.4 拖动与排程

首版推荐列表＋表单修改，不需要先做复杂拖动。
后续若增加拖动，拖动期间只显示合法落点和当前卡片，释放后等待规则校验；失败回到原位置并说明原因。
键盘/触摸用户都有“调整时间/修改负责人”菜单或表单替代。
布局移动动画最多 160 ms，减少动效直接定位；不使用拖动物理弹簧制造越界落点。

## 9. GitHub 保存与赛事交付

### 9.1 保存流程

预览阶段：目标仓库、分支与文件清单稳定显示，删除/修改标记有文字。
点击“保存一个版本”后立即进入真实处理状态；按钮宽度固定，防重复提交。
有实际阶段才显示“上传文件/创建版本/核对结果”，没有阶段接口就只显示“正在保存”。

| 结果 | 反馈 |
| --- | --- |
| 已核实保存成功 | 160–200 ms 切换为小勾＋“版本已保存”；显示 commit/分支入口 |
| 结果未知 | “正在核对保存结果”；没有成功勾，避免鼓励重复提交 |
| 权限失效 | 停止加载，保留草稿，显示重新授权入口 |
| 版本冲突/不支持文件 | 行内说明、保留文件与下载/原生处理路径 |
| 部分操作成功 | 逐项显示已发生的真实事实，不把整个流程动画成全部完成 |

关闭面板、离开页面和停止等待不等于撤销远端写入。
GitHub 操作已发出后，不提供含糊的“取消并还原”动效；重新进入可查询相同 operationId。
若支持停止未开始操作，则仅在服务端确认取消后显示取消成功。

### 9.2 三种交付状态分别反馈

仓库版本、运行验证、赛事提交分别绑定对应记录。
commit 成功只更新仓库那一行；运行检查和赛事提交不能一起亮绿。
“用户标记已提交”与“平台确认”采用不同文字，不因勾选自报就播放官方提交成功庆祝。
提交临近截止，页面主要动作是查看材料与官方提交入口，动效不能遮盖待确认项。

## 10. 工具与灵感库

筛选更新保留搜索框和已选条件；列表使用短淡入或直接替换，不把全部卡片飞出屏幕。
实际结果数直接显示，数字不从零累加。无结果和请求失败是不同状态。
收藏等待成功后切换实心图标和文字；失败恢复未收藏并保留备注，不让心形跳动假装成功。

“加入项目资料”对话框以 200 ms 显示；选择项目后呈现将共享的内容。
实际写入成功后提示“已加入某项目”；个人收藏不因为打开对话框就自动公开。
外站访问失败/下架只更新对应条目，不重新排列整个资源库制造“内容消失”错觉。
返回资源列表保留筛选和滚动位置，不重复首屏装饰序列。

### 10.1 技能筛选、套餐与安装

切换 AI 工具/系统保留筛选与滚动位置；更新兼容结果用短淡入或直接切换。验证中的标签显示对应状态，不先染绿再等请求。选择套餐不是安装动作，不触发庆祝或安装进度。
“复制安装命令”在剪贴板实际写入后显示短提示“已复制”；失败给可选中文命令文本。提示不能变成“已安装”。打开教程不播放完成动效。
安装预览沿用 200 ms 对话框进入，焦点落标题或第一可操作项；关闭回到触发按钮。检查到冲突时直接展开受影响项并提供处理，不摇晃或自动跳过。
实际本地安装按每项真实事件更新检查/获取/校验/写入状态。没有可计算总进度时用阶段文字；即使文件下载到 100%，仍不能表示安装、加载或样例验证全部完成。
部分成功只对已确认条目显示完成图标；失败项保留错误、重试与恢复动作。文件核验后可用 120–180 ms 图标切换，客户端加载与示例仍独立显示。回执延迟显示等待/未知，不通过计时器造成功状态。
减少动效模式用静态状态文本与图标。恢复/移除结果同样需要实际证据，动画结束不产生业务状态。

## 11. 移动端与减少动效

### 减少动效模式

检测系统 `prefers-reduced-motion: reduce`，取消位移、旋转、错开入场、数字翻动、布局动画和连续扫光。
所有内容直接可读；等待用静态图标＋状态文字；成功/错误用文字与图标直接切换。
可以提供用户“关闭非必要动效”的站内偏好，不能用站内设置覆盖系统减少动效请求。
[MDN 官方参考](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)

WCAG 2.2 的交互动画可关闭条款 2.3.3 为 AAA。本项目主动采用可关闭非必要动效，同时整体仍按视觉规格中的 AA 目标验收，不能把两者级别混写。
[W3C 2.3.3 说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

### 其他可访问性

- 异步状态可用节制的 live region 播报，不逐 token 和每秒倒计时重复打断读屏。
- 对话框显示后进入正确焦点，关闭后恢复触发按钮；焦点不依赖 animationend。
- 自动出现的装饰不承载唯一信息；关键错误留在页面，不随短 toast 消失。
- 没有 hover 的设备提供所有信息与操作；拖动有菜单/表单替代。
- 不使用闪光、快速高对比脉冲、视差和大幅缩放。
- 浏览器后台或元素不可见时停止装饰循环；页面返回直接恢复真实状态。

手机默认少一档动效：保留按下、面板和状态切换，取消卡片 lift、首页错开序列与列表布局运动。
减少动效不是去掉反馈，文字、焦点与错误恢复照常工作。

## 12. 前端实现建议

### 12.1 实现范围

普通 hover、淡入、颜色与短位移优先 CSS；复杂动画库不是首版必需依赖。
若以后做多元素布局过渡，再评估一个统一方案；不同时引入多套动画库。
把业务状态与动画状态分开：服务器确认决定结果，动画仅呈现结果。

优先对 opacity/transform 做短动画，避免逐帧改变布局属性或大范围阴影/模糊；实际性能需测量，不能因选了 transform 就承诺流畅。
不要给所有元素永久设置 will-change。[web.dev 动画性能指南](https://web.dev/articles/animations-guide)

### 12.2 CSS 起点示例

以下用于说明令牌与降级，尚未作为项目代码运行；组件状态、焦点与数据流程另行实现。

```css
:root {
  --motion-fast: 120ms;
  --motion-feedback: 160ms;
  --motion-panel: 200ms;
  --motion-enter: 240ms;
  --ease-out: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-standard: cubic-bezier(0.2, 0, 0, 1);
}

/* 默认可见：动画没有执行，内容也能阅读。 */
.motion-enter {
  opacity: 1;
  animation: gentle-enter var(--motion-enter) var(--ease-out);
}

@keyframes gentle-enter {
  from { opacity: 0; transform: translateY(6px); }
  to   { opacity: 1; transform: translateY(0); }
}

/* 只对合适的输入设备采用 hover 位移。 */
@media (hover: hover) and (pointer: fine) {
  .motion-card {
    transition: transform var(--motion-feedback) var(--ease-standard);
  }
  .motion-card:hover { transform: translateY(-2px); }
}

/* 这组类用于非必要动效，不应用于全部页面元素。 */
@media (prefers-reduced-motion: reduce) {
  .motion-enter, .motion-card, .motion-spinner {
    animation: none;
    transition: none;
    transform: none;
  }
}

/* 站内关闭动效与系统减少动效都生效，不互相覆盖。 */
[data-motion="off"] .motion-enter,
[data-motion="off"] .motion-card,
[data-motion="off"] .motion-spinner {
  animation: none;
  transition: none;
  transform: none;
}
```

关键 H1/截止/主操作不套淡入类。加载图标需有独立状态文字，不能因关闭旋转变成毫无反馈。
组件显示/隐藏、取消和成功逻辑不以动画回调作为唯一触发；即使动画被禁用也完成正确状态转换。

## 13. 实施优先级

| 优先级 | 动效 | 理由 |
| --- | --- | --- |
| P0 | 按钮/表单反馈、真实长任务状态、失败/冲突、对话框焦点、减少动效 | 核心操作必须清楚可用 |
| P1 | 收藏、任务状态、计划差异、版本保存局部反馈、抽屉 | 减少对变化的理解成本 |
| P2 | 首页短线、辅助清单、少量卡片进入 | 品牌表达，核心功能稳定后再做 |
| 后置 | 复杂拖动布局、多元素转场、互动装饰 | 有真实使用需求与性能验证再考虑 |

实现顺序：先静态页面与状态→P0→P1→P2。不能靠增加动效掩盖失败路径和数据状态尚未实现。

## 14. 验收与设计交接

每个动效交接表记录：motionId、页面/组件、触发事件、真实前后状态、时长、曲线、重复条件、减少动效表现和异常表现。

| 检查情景 | 通过条件 |
| --- | --- |
| 快速点击、重复请求 | 即时反馈，不重复写入，不等动画才锁定关键操作 |
| 生成失败/结果未知 | 加载及时停止或显示核对，不能自动进入成功 |
| 未完成题目/保存失败 | 输入保留，不自动翻页 |
| 计划尚未确认 | 旧计划可读，新草案不表现为已应用 |
| 计划应用冲突 | 编辑和差异保留，错误可见 |
| GitHub 返回未知 | 不亮绿、不盲目重写，可恢复查询 |
| 用户自报提交 | 来源标签清楚，不伪装官方确认 |
| 键盘与手机 | 操作可达，焦点正确，hover/拖动不是唯一入口 |
| 系统减少动效/站内关闭 | 所有非必要位移与循环停止，状态和反馈仍完整 |
| 返回页面/刷新 | 不重复无关入场，恢复真实 job/operation 状态 |
| 低性能设备/慢网络 | 内容和按钮可用，动画不造成可见卡顿或阅读位置跳动 |
| 动画失败/脚本未运行 | 关键内容直接可读，不出现永久透明内容 |

性能检查使用实际设备与浏览器录制观察，重点看长任务页面、任务列表和手机抽屉；静态设计规格不能作为“已经通过性能测试”的证据。
动效修改引入业务状态风险时检查对应行为；纯时长/曲线调整通常采用视觉检查，不为可逆样式制造重复实现的测试。
