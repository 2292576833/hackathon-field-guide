## 1. 设计定位

像一本可以操作的参赛手册：公开页面有编辑部的鲜明排版，登录后的项目页有清楚的下一步与真实状态。
品牌表达“有人把复杂参赛流程整理清楚”；使用体验让第一次参赛的人敢于开始，也能持续更新任务。

三个关键词：清楚、踏实、有活力。首页可以大胆，正文和工作台保持易读。
面向新人不等于把界面做成儿童游戏；避免用夸张战力分、闪烁警报和倒计时制造焦虑。

## 2. Awwwards 参考怎样落到本项目

本次查阅了 [Awwwards 官网](https://www.awwwards.com/) 的搜索、分类、案例、作者与 Collections 等信息结构。
参考重点是“如何发现与组织灵感”，不是把某个获奖站的布局当作唯一标准。
本规格没有把未访问到的具体案例视觉写成已观察事实，也没有取得案例图片与代码的使用授权。

| 可查阅的参考结构 | 本项目转译 | 设计判断 |
| --- | --- | --- |
| Inspiration 搜索与类别入口 | 工具/灵感按用途、阶段与栈筛选 | 搜索写“你现在想完成什么”，减少泛标签 |
| 案例卡片附名称与作者信息 | 资源卡片附用途、门槛、来源与核验时间 | 先帮助选择，弱化无依据热度 |
| Collections | 个人收藏与项目资料集合 | 收藏能接到任务与复盘，不成为闲逛终点 |
| 网站/UI/交互等不同入口 | 整站灵感、AI 设计辅助、UI 组件分别组织 | 看参考与获取组件代码是不同动作 |

暖白、橙红、编辑式大字、编号和细分隔线，是针对本项目的原创设计建议；并非声称 Awwwards 本身采用这套配色。
可在后续设计评审中从官网挑二至三个具体案例，记录“只参考字体层级/卡片节奏”等目的，再核对素材使用边界。

## 3. 品牌与视觉语法

### 3.1 标识

文字标识优先：**草根黑客松情报局**。空间受限时使用“黑客松情报局”，不只显示难懂的英文缩写。
标识旁可以用一个橙红方块和短横线构成“资料标签”图形；首版不依赖复杂插画与吉祥物。
英文小标可用 `HACKATHON FIELD GUIDE`，只作辅助，不能替代中文主要信息。

### 3.2 建议品牌文案

- 首页标题：**从第一次参赛，到第一次交付。**
- 副标题：看懂比赛、找到工具、分好任务，把想法一步步做出来。
- 主动作：浏览赛事情报。
- 次动作：创建参赛项目。
- 资源库标题：**少搜一点，多做一点。**
- 工作台标题：**接下来，先完成这一件。**

不使用“保证获奖”“100% 能力识别”“零门槛自动交付”等文案，不展示虚构参赛人数与成功率。

### 3.3 页面视觉规则

用大字、编号、窄标签、细线与留白形成品牌。每个区块有自己的信息重点，避免所有内容都装成相同的大圆角卡片。
公共区块允许 01/02/03 栏目编号；工作台只保留有助于导航的编号，不能给任务编号造成额外负担。
图片仅用于有来源与许可的设计参考；赛事和工具默认用文字封面、类别图标或经许可的素材。

## 4. 设计令牌

### 4.1 颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--paper` | `#F6F3EB` | 全站暖白背景 |
| `--surface` | `#FFFFFF` | 表单、项目任务与关键资料表面 |
| `--ink` | `#21201C` | 标题、正文、重要数字 |
| `--muted` | `#666257` | 次级说明与元数据 |
| `--brand` | `#EF4D2E` | 品牌图形、大字强调、非正文装饰 |
| `--action` | `#B8351E` | 白字主按钮、普通大小强调文字与链接 |
| `--action-hover` | `#9C2A17` | 主按钮悬停/按下 |
| `--tint` | `#FBE9E2` | AI 建议/资源提示的浅底 |
| `--line` | `#D9D4C8` | 装饰分隔线、非交互容器边界 |
| `--control-line` | `#7D776C` | 表单等需辨认的交互边界 |
| `--success` / `--success-bg` | `#2C6647` / `#ECF3EB` | 已确认/成功，必须配文字或图标 |
| `--warning` / `--warning-bg` | `#845311` / `#FFF1D6` | 待确认、时间风险、费用未知 |
| `--danger` / `--danger-bg` | `#A52F30` / `#FBE8E5` | 操作失败/明确问题 |

主按钮采用 action，不能直接给 brand 橙配普通大小白字。
用标准相对亮度公式计算的主要对比度：

| 前景 / 背景 | 计算值 | 使用规则 |
| --- | --- | --- |
| ink / paper | 14.70:1 | 正文可用 |
| muted / paper | 5.49:1 | 次级文字可用 |
| 白字 / action | 5.89:1 | 普通按钮文字可用 |
| action / paper | 5.31:1 | 普通大小链接可用 |
| brand / paper | 3.28:1 | 只用于满足大字条件的文字或非正文图形 |
| 白字 / brand | 3.64:1 | 不作为普通大小按钮文字方案 |
| success / success-bg | 6.00:1 | 状态文字可用 |
| warning / warning-bg | 5.83:1 | 状态文字可用 |
| danger / danger-bg | 5.83:1 | 状态文字可用 |

正文对比度以 4.5:1 为目标，大字/必要非文字控件按对应标准检查。色值计算不等于整站已通过可访问性验收，实际透明度、背景与焦点还需检查。[WCAG 2.2 官方要求](https://www.w3.org/WAI/WCAG22/quickref/)

### 4.2 字体与排版

首版优先系统中文字体，不依赖跨域加载：`"PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。
日期、编号与少量代码使用 `ui-monospace, "Cascadia Mono", Consolas, monospace`，不能把整段中文变成等宽字体。
后续采用自托管字体时，核对许可、按语言与字重裁剪，并验证回退布局。

| 层级 | 桌面字号/行高 | 移动字号/行高 | 用途 |
| --- | --- | --- | --- |
| 首页展示标题 | 64–80 / 1.12 | 36–44 / 1.18 | 首屏一至两句 |
| 页面标题 H1 | 36–44 / 1.25 | 28–32 / 1.3 | 赛事/资源/项目标题 |
| 区块标题 H2 | 24–28 / 1.35 | 22–24 / 1.4 | 栏目与重要分组 |
| 卡片标题 | 18–20 / 1.4 | 18 / 1.4 | 名称与任务 |
| 正文 | 16 / 1.65 | 16 / 1.65 | 阅读、表单帮助 |
| 操作与元数据 | 14 / 1.5 | 14 / 1.5 | 标签、按钮、核验时间 |
| 辅助编号 | 12–13 / 1.5 | 12–13 / 1.5 | 非关键栏目编号 |

关键截止时间、错误说明、费用与许可状态不得缩成 12 px 小字。
正文段落控制宽度约 40–48 个中文字符；复杂条款使用列表和表格，避免一行横跨整屏。

### 4.3 间距、圆角与阴影

- 间距基准：4/8/12/16/24/32/48/64/96 px。
- 公开区块上下留白：桌面 64–96，手机 40–56；工作台区块间距 24–32。
- 圆角：标签 4–6、按钮/输入 8、普通卡片 12、重点面板 16；只在头像使用圆形。
- 主要靠细线和表面明度区分内容。阴影用于悬浮菜单/对话框，卡片 hover 可有极轻阴影；不使用满页重阴影。
- 重点动作每个区域通常一个；次要动作使用描边或文字链接。

## 5. 栅格与响应式

### 公共页面

桌面参考宽 1440，内容最大 1280，边距至少 32，12 栏，栏间距 24。
首屏左右约 7:5；赛事和资源列表根据可读宽度为三栏或两栏，卡片最小约 280 px。
宽屏不无限拉长段落和卡片。

### 登录工作台

桌面侧栏建议 232 px，顶部项目栏约 64–72 px，主内容内边距 24–32。
概览用“主要工作区域＋侧边提醒”两栏；任务页允许全宽表格或按人列表。
数据密度提高，但字号不为塞更多列而降低。

### 断点建议

| 宽度 | 布局 |
| --- | --- |
| < 640 | 单栏；导航菜单；筛选抽屉；任务卡片；页面留边 16–20 |
| 640–1023 | 公共区两栏；工作台侧栏改可收起导航；任务详情抽屉 |
| ≥ 1024 | 公共区三栏；固定工作台侧栏；概览两栏 |

时间线在手机转为按日期/负责人列表，不强制横向拖动大甘特图。
筛选手机用明确“应用/清除”；桌面可即时更新并保留 URL 查询状态。
关键操作区不能遮住内容、错误和键盘焦点；固定导航为正文留出空间。

## 6. 页面规格

### 6.1 首页：品牌入口与两种开始方式

首屏内容优先于装饰：品牌、主张、简短说明、浏览赛事/创建项目、资源入口。
右侧是一张“参赛准备清单”的编辑式示意板，用步骤而非虚构数据展示产品。

```text
┌ 标识 ─ 赛事情报 ─ 工具与灵感 ─ 参赛指南 ─ 我的工作台/登录 ┐
│  第一次也能开始 / FIELD GUIDE                              │
│  从第一次参赛，           ┌ 参赛准备清单 · 流程示意 ┐       │
│  到第一次交付。           │ 01 看懂资格与必交材料   │       │
│  看懂比赛，分好任务……     │ 02 确定负责人和时间     │       │
│  [浏览赛事情报] [创建项目] │ 03 保存版本并核对提交   │       │
│  找灵感？查看精选工具 →   └─────────────────────────┘       │
├ 01 本期赛事情报 ───────────────────────────── 查看全部 → ┤
│  有来源的赛事卡片 / 截止时间 / 适合条件 / 需确认项          │
├ 02 工具与灵感 ─ 设计参考 · AI设计 · UI组件 · 实用工具 ────┤
│  “要做什么”卡片＋少量资源，不以大截图墙压倒主要入口         │
├ 03 从报名到交付 ─ 四项核心功能的可执行说明 ───────────────┤
└ 页脚：项目说明 / 纠错入口 / 数据与使用说明                 ┘
```

首版没有真实数据时显示流程示意或空状态，不使用“已有 10,000 人”之类填充。
赛事卡片、截止和报名状态来自 M03；示例作品必须标“演示数据”。
“参赛指南”首版仅链接少量静态流程帮助，不另建文章社区/CMS；内容未准备好时暂不显示入口。

### 6.2 赛事列表与详情：让人看懂来源

列表上方：搜索、比赛阶段、截止、线上/线下、已核验字段；未知信息保留未知。
卡片顺序：赛事名→主办来源→重要截止（时区）→资格/必交物摘要→待确认项→查看规则。
不在卡片最显眼处放一个没有定义的“靠谱分”。

详情桌面约 8:4 两栏：左为条款和分析，右为截止/必交清单/加入项目。
三个内容标签使用清楚的文字：“来源事实”“AI 建议”“待确认”，分别使用中性、浅橙、浅黄。
条款有原始链接、核验时间与版本；来源冲突显示两条依据和需要确认的字段。
“加入我的项目”若未登录，登录后返回当前赛事；若已有项目则提供明确选择。

### 6.3 登录：小而可信

左为简短品牌与参赛流程，右为最大 420 px 的表单；手机只保留必要表单与标识。
登录方式以 M01 最终实现为准；若采用邮箱验证码，只出现邮箱、获取验证、验证码、继续。
字段有 label、输入帮助、内联错误，按钮忙碌时有文字“正在验证”。
清楚写明“这是本站登录，连接 GitHub 在项目交付页完成”。不要把 GitHub 大按钮设计成唯一入口而误导非技术成员。
验证码过期、邮件未到、登录限流、返回原页面都有状态；不把错误藏在短暂 toast 里。

### 6.4 项目概览：把下一步放在最前

```text
┌ 项目切换 / 项目名 ───────── 最后更新 ─ 成员 ─ 设置 ┐
│ 导航    │ 当前阶段 · 赛事截止：完整时间与时区        │
│ 概览    │ 接下来：确认三项必交材料 [查看要求]      │
│ 赛事要求├──────────────────────┬───────────────────┤
│ 分工    │ 当前任务 / 阻塞       │ 必交清单          │
│ 计划    │ 负责人、交付物、期限  │ 规则待确认        │
│ 交付    │ [更新进度]            │ 截止/提交缓冲     │
│ 资料    ├──────────────────────┼───────────────────┤
│ 复盘    │ 当前计划与调整理由    │ 相关资源（可选）  │
│         │ 最近保存/变更记录     │ 查看项目资料 →    │
└─────────┴──────────────────────┴───────────────────┘
```

“下一步”由缺失项与项目状态决定，不永远显示“生成 AI 计划”。
截止信息显示输入来源；数据未更新时显示最后更新时间，不把计划估计当真实进度。
总进度若使用，定义为任务完成项或已验收项比例；不用复杂仪表盘装饰四个空数字。

### 6.5 提问与分工：回答容易，结果可讨论

提问每屏一题/一个小任务，有“为什么问这个”、预计作答量、跳过或稍后、已保存状态。
自评与试做结果分开；动态追问明确是补充，不造成无止境问卷。
结果页先显示可承担任务、证据与限制，再显示本次得分及评分版本。
建议用横向条与文字分项，不用雷达图制造未经校准的科学感。

分工表：任务/交付物、负责人、协助人、推荐理由、缺口、期限；允许编辑。
未测评成员标“证据不足，可先安排短试做”，不灰掉整个团队的开始按钮。
“确认分工”显示将改变的内容；当前用户不是项目管理员时提供查看/建议入口。
原始回答不显示在团队公共面板；共享范围有清楚的本人控制。

### 6.6 任务与时间：风险也要能行动

输入区先展示确认过的截止、成员可用时间、最小交付目标；缺项可手动补充。
输出区有可行性文字、必需/可选任务、负责人和依赖、集成/测试/提交缓冲。
可行性状态独立于“计划已应用”。不可行时，重点动作是“缩减可选范围/调整可用时间”，不是一个巨大红色失败页。

任务详情包含验收条件、资源参考、预计区间、状态、阻塞说明和进度更新。
重规划采用并排或上下差异：“移除哪些可选项、谁的时间变了、哪些必需项仍无法完成”。
应用按钮必须有版本检查与明确反馈，冲突时保留用户修改。
拖动排程如果做，必须提供表单修改时间的替代；首版可先用列表和表格。

### 6.7 GitHub 与交付：三行真实状态

页面按步骤：连接账号/授权仓库→选择仓库→添加普通支持文件→查看变更→保存一个版本→核对交付。
主按钮可写“保存一个版本”，其下显示目标仓库与独立分支；点击前提供文件新增/修改/删除的清单。
疑似密钥/不支持文件逐项说明，保留可下载草稿。网络结果未知显示“正在核对结果”，不直接提示再次保存。

交付状态独立展示：

1. **仓库版本**：已保存到指定 commit / 未保存 / 正在核对。
2. **运行验证**：未验证 / 用户报告通过 / 附有验证记录。
3. **赛事提交**：未提交 / 用户标记已提交 / 平台确认（仅真实支持时）。

颜色与文字共同表达；一个绿色 commit 不让三行同时变绿。
复杂冲突转为保留文件＋清楚的 GitHub 原生处理路径；不在新人表单上堆 token、tree API 等实现术语。

### 6.8 工具与灵感库：编辑精选，按任务选

首屏采用与首页一致的大字，但高度较低，第一屏能看到搜索/类型与部分列表。
四个入口：设计灵感｜AI 设计辅助｜UI 与视觉资源｜参赛实用工具。
卡片使用受控类别色块与简洁图标；预览图片仅在有来源和许可时采用。无需从第三方批量抓截图才能做出好看页面。

```text
┌ 工具与灵感                                     我的收藏 ┐
│ 少搜一点，多做一点。                                    │
│ [你现在想完成什么？例如：做一个报名表单          搜索]   │
│ 设计灵感 | AI设计 | UI与视觉 | 实用工具                   │
│ 阶段 ▾  技术栈 ▾  费用 ▾  门槛 ▾       清除筛选         │
├────────────────────┬──────────────────┬────────────────┤
│ 类型 / 名称         │ 类型 / 名称       │ 类型 / 名称     │
│ 帮你完成什么        │ 用途说明          │ 用途说明        │
│ 栈 · 门槛 · 费用状态 │ 栈 · 门槛         │ 栈 · 门槛       │
│ [看详情]  收藏       │ [看详情] 收藏     │ [看详情] 收藏   │
└────────────────────┴──────────────────┴────────────────┘
```

详情先写“它适合帮你做什么”，再给官方访问、最短开始步骤、费用/许可来源、核验时间与项目收藏。
AI 与组件分别说明“草稿需检查”和“代码需验证”。不要用“本站认证安全”标签暗示完整安全审查。
“加入项目资料”打开明确项目选择，个人收藏不会自动公开。
没有真实点击统计时按编辑顺序/名称/最近核验排序，不出现虚构“热门榜”。

### 6.9 复盘与后台

复盘按目标/实际完成/卡点/工具与解决方式/下次改变整理，支持引用任务和交付证据。
“复制为新项目”清楚显示要复制的参考，不复制旧授权、旧截止与提交成功状态。

后台沿用暖白与字体，但主要用高密度表格、审核状态、字段证据、前后差异。
发布/下架有明确理由，采集成功与已发布分开。个人隐私不因后台界面存在而全部展示。

### 6.10 技能库与赛道包：先选工具，再开始任务

沿用暖白、炭黑、橙红与编辑栏目语法。新增公开“技能与赛道包”入口，工具与灵感页亦可进入；不在项目工作台增加抢占必交任务的巨大推广位。关联 [M10 规划](../规划/模块/10-技能库与赛道技能包.md)。

```text
┌ 技能与赛道包                                      使用指南 ┐
│ 为这场比赛，准备合适的 AI 技能。                           │
│ 你正在用：[Codex ▾]    系统：[Windows ▾]                    │
│ 通用 | 游戏 | 影视 | AI Agent      [你想完成什么？ 搜索]   │
├─────────────────────┬─────────────────────────────────────┤
│ 用途/技术栈/条件筛选 │ 赛道包名称 · 固定版本               │
│ □ 已有对应环境实测  │ 帮你交付什么；必要技能与可选技能     │
│                     │ 依赖 · 费用依据 · 兼容/待验证        │
│                     │ [查看套餐和教程]                     │
└─────────────────────┴─────────────────────────────────────┘
```

桌面工具选择固定在筛选区，移动端工具与系统选择放列表之前，筛选收进可展开面板。工具图标只作识别辅助，名称必显；没有可使用图标时用文本标签，不擅自抓取品牌资产。
技能卡优先显示用途与产物，再显示对应工具的验证状态、门槛与来源。评分样本不足显示“证据不足”；第三方热度另列出处与日期，不画虚构五星或“最佳”徽章。

套餐详情先呈现最小交付目标，再列固定技能项、必需/可选、依赖与教程。切换 AI 工具后逐项更新适配结果，缺项需可见；“部分适配”不能使用全包成功的绿勾。
安装预览是可阅读页面或对话框：工具、系统、范围、内容、依赖、许可、已知冲突与操作说明。用户不必理解哈希等内部字段才能作出选择，版本与详细证据可展开查看。

第一层按钮用“复制安装命令”“查看教程”，复制只显示已复制。连接到具备能力的本地端后才显示“安装到所选项目”，首次获取/连接本地端另有明确引导。配对、未连接、检查中、冲突、部分失败、安装文件已核验、加载待验证是不同状态；成功区允许按技能展开证据与下一步样例，不把所有步骤一起变绿。
项目资料仅保存包版本、用途与公开说明；不展示或共享成员本机绝对路径。临近截止显示简短的配置时间与手动替代说明，避免推荐占用关键交付空间。

## 7. 基础组件清单

| 组件 | 必须覆盖的状态 | 特别要求 |
| --- | --- | --- |
| 按钮 | 默认、hover、focus、busy、disabled | 主按钮 action 色；忙碌文字说明；禁用原因可见 |
| 输入/选择 | 空、填写、错误、只读、失效 | 明确 label；错误关联字段；不只用 placeholder |
| 赛事卡片 | 正常、未知字段、已结束、来源过期 | 完整截止时区与来源状态 |
| 资源卡片 | 已发布、费用未知、收藏中、下架 | 用途优先；收藏状态真实 |
| 任务卡片 | 待开始、进行中、阻塞、待验收、完成 | 负责人/交付物/期限清楚，颜色不是唯一信息 |
| 状态标签 | 事实、建议、未知、用户自报 | 标签含文字；不要合并不同事实 |
| 来源块 | 链接、核验时间、版本、冲突 | 键盘可用，长 URL 不撑坏布局 |
| 确认对话框 | 差异、提交中、冲突、失败 | 焦点管理；恢复操作；后台不丢草稿 |
| 长任务面板 | 排队、执行、成功、失败、取消 | 只显示已知进度，未测量不造百分比 |
| 版本差异 | 新增、修改、移除、过期 | 文字与标记共同表达；移动端顺序阅读 |
| 空状态 | 未设置、无结果、无权限、加载失败 | 各有不同下一步，不复用一句“暂无数据” |
| 轻提示 | 成功、错误、撤销 | 错误重要时页内保留，不能只靠 toast |

组件基础候选：一套可定制的体系，例如 [shadcn/ui](https://ui.shadcn.com/docs) 的开放组件代码方式；底层交互候选 [Radix](https://www.radix-ui.com/primitives/docs/overview/introduction)。
这是架构候选，不表示已安装，也不意味着现成组件会自动让整站可访问。若开发者更熟悉另一套体系，可以统一主题后使用；避免同时引入多套基础表单与弹窗系统。

## 8. 动效与操作反馈

详细规格见 [网页动效设计](网页动效设计.md)，按页面列出触发事件、时长、真实状态和降级规则。

首版动画服务于位置变化和结果反馈：按钮 120–160 ms，菜单/抽屉 160–220 ms，卡片轻微进入 180–240 ms。
首页可以有一次轻微错位/编号显现；工作台不做滚动劫持、自定义光标、持续噪点、全屏 WebGL 或自动播放大视频。
这些并非 Awwwards 必需条件，也不适合在参赛倒计时期间增加操作负担。

`prefers-reduced-motion` 下去掉非必要位移与连续动画。加载使用稳定占位与真实状态；没有实际进度信息时用“正在生成”，不显示假 83%。
hover 不承载唯一信息，手机和键盘同样可以查看说明。

## 9. 可访问性与内容规则

- 首屏有跳到主要内容；语义标题层级连续，按钮/链接语义正确。
- 键盘焦点清楚：建议 action 色 2 px 环＋2 px 间隔，不能被 sticky 区域遮住。
- 目标 WCAG 2.2 AA；正文 4.5:1、大字 3:1，必要非文字控件 3:1；具体例外以标准为准。
- 产品点按区域建议 ≥44×44 px，较 WCAG 2.2 AA 的 24×24 px 基础要求更宽裕；不混淆两者。[WCAG 官方速查](https://www.w3.org/WAI/WCAG22/quickref/)
- 200% 文本放大与窄屏重排检查；表格有标题与合理移动替代。
- 颜色、图标、百分比不能单独表达状态；错误有文字、位置和恢复动作。
- 表单保留输入，支持粘贴/密码管理器适用能力；不设计无必要的记忆挑战。
- 日期显示“2026-10-10 18:00（UTC+8）”这类明确格式；示例注明示例，不能被当真实赛事截止。
- 空白页解释真实原因：尚未创建/筛选无结果/加载失败/无权限是四种状态。
- 中文文案说用户动作：确认要求、更新进度、保存版本、记录提交。实现术语放在需要时展开的帮助中。

## 10. 前端交接与验收

### 设计交付物

1. 全站颜色、字体、间距、圆角和组件状态令牌。
2. 首页、赛事详情、登录、项目概览、提问/分工、任务计划、GitHub 交付、资源库/详情的桌面与手机布局。
3. 原始事实/AI 建议/未知、用户自报/已验证的标签规范。
4. 空状态、失效、冲突、长任务、失去权限与保留草稿的设计。
5. 真实数据、演示数据、不可用功能的边界说明；预览不能暗示后端已实现。

### 实施顺序

先做基础令牌与登录/项目壳，再做项目概览、赛事、任务和交付；资源页面复用相同组件。
首页最后根据已实现的路径调整展示，避免宣传尚不存在的能力。
优先把页面用真实长中文与缺失数据填满，再增加装饰。

### 验收清单

| 检查 | 通过条件 |
| --- | --- |
| 信息重点 | 新用户能指出下一步、截止、必交物与负责人 |
| 状态诚实 | 保存/运行/提交互不代替；费用/来源未知可见 |
| 桌面/手机 | 1440、1024、768、390 和 320 px 下关键流程无被遮挡动作；表格按需要有合理替代 |
| 中文与数值 | 长赛事名、多人、长任务、零数据、倒计时过期可正常排版 |
| 键盘与放大 | 焦点、对话框、错误提示、200% 放大与重排可用 |
| 对比与状态 | 实际使用颜色达到目标；hover/focus/error 不依赖颜色单独传达 |
| 减少动效 | 非必要动画可关闭，加载状态依然能理解 |
| 外部资源 | 链接说明与核验时间可见，收藏/共享权限清楚 |
| 性能 | 不因大图片、字体或装饰阻塞任务使用，按总体规划测量 |

本文件是视觉设计规格，尚不是已实现页面或已通过验收的网站。
