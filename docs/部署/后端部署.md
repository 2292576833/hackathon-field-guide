# 后端部署与运行

本指南对应当前仓库的后端：Next.js 网站、PostgreSQL、常驻后台 worker、固定版本 DeepSeek Harness。正式生产仍应使用 connected 模式；本机 SakuraFrp HTTPS 试用使用 local PGlite，也支持接入 Resend 或 SMTP 向用户邮箱发送验证码。缺少所选发信凭据时公网登录不可用，开发邮箱仅供本机回环调试。

2026-10-10本机已实际应用迁移032–041并重建启动，完整记录见[全规划补齐验收](../协作/验收报告-全规划补齐-2026-10-10.md)。最终041备份实际复制恢复、重开及全库约束检查通过；这不代表远程PostgreSQL或云主机已部署。GitHub真实验收按用户要求暂缓。

## 1. 服务与数据边界

| 服务 | 职责 | 持久化/凭据 |
| --- | --- | --- |
| `postgres` | 账号、项目、规则证据、任务、审核、执行记录、灵感卡片/版本、技能清单 | `postgres-data` 命名卷；数据库密码 |
| `migrate` | 发布时运行一次版本化数据库迁移 | 与网站同一数据库；完成后退出 |
| `web` | 页面、登录、API、管理员审核、AI 请求入口 | 应用服务端凭据；只通过反向代理开放 HTTPS |
| `worker` | AI 队列、已配置来源采集、赛事发现与独立灵感官网分析 | 同一 Postgres；常驻运行，不依赖用户保持网页打开 |
| DSH 调用子进程 | 单次、有时限、无工具的 JSON 分析 | 每次生成独立 HOME/工作目录；只收到 DeepSeek key 与必要运行环境 |

正式配置使用 `APP_MODE=connected`。该模式下网站实例不会自动执行数据库迁移；发布流程明确先运行 `migrate`。开发用 PGlite 的 `.runtime/postgres-data` 不适合由独立网站和 worker 进程同时打开。

`npm run dev/start` 使用 `scripts/serve.mjs` 给服务进程设置 `FIELD_GUIDE_SERVE=1`；`src/instrumentation.ts` 在 Node 服务启动时初始化应用与单例后台任务，独立于浏览器访问。构建不设置此标志，不连接实际数据库或启动付费任务。连接部署也可在网站进程自动运行任务；已有独立 worker 时设置 `FIELD_GUIDE_EMBEDDED_WORKERS=0`，避免重复启动任务组。Docker 运行阶段设置服务标志，Compose 的 web 禁用嵌入任务并使用既有 worker 服务。

新增四项维护与既有AI/来源/赛事/灵感共用任务组及数据库：`planning-notifications`每30秒消费提醒，`github-maintenance`与`retention-maintenance`每300秒清理已过期临时内容，`resource-links`每60秒检查有界周期资格、同站至少24小时。链接核对仅允许实际审核版本中的精确公开入口，HEAD失败不自动撤回资源。维护等待期间定期保留心跳，不将等待写成新一轮完成；周期启动失败保留失败状态。

账号导出及复盘编辑草稿属于本人私有数据。保留维护只清过期导出正文和开发邮件，GitHub维护清过期草稿正文/state；不可变采集回执、来源证据、项目快照、历史、正式交付与未知付费请求保留。当前没有独立临时采集正文表，`/admin`维护状态明确显示无可清样本。管理员审计、来源可观测性、资源检查与保留状态GET只读，不能通过刷新启动网络核对、派送或模型。

嵌入任务收到 SIGINT/SIGTERM 时先撤销运行中的任务，HTTP 排空和进程退出仍由 Next 处理；强制终止和外部结果未知时保留持久标记与估算，不自动重发。`npm run build` 自动执行 NFT 后处理：Turbopack instrumentation 的追踪不受普通路由排除完整覆盖，构建后移除 `.runtime`、环境文件和凭据的引用，并验证构建目录没有私有副本。发现副本则构建失败、保留现场，不修改源凭据。单独验证用 `npm run build:verify`。

DSH 位于后端 `/app/.runtime/dsh-runtime/node_modules/@deepseek-ai/dsh`，不是参赛者需要自行安装的插件。`src/modules/operations/deepseek-harness.ts` 为每次调用启动独立 Node 子进程，使用全新配置，禁用工具及外部插件，传入有限公开文本。子进程环境不继承 `DATABASE_URL`、GitHub 授权、Resend key、Brave key、`NODE_OPTIONS` 或用户原有 DSH 配置；DeepSeek key 以 `DEEPSEEK_API_KEY` 单独传入。超时/取消会终止这次进程。这个进程隔离用于控制输入、配置和凭据，不能等同于虚拟机级隔离。

技能目录与中文教程由 `src/modules/skills/catalog-lock.ts`、`seed.ts` 等代码在运行时写入数据库；Docker 会保留这些源文件，以及独立桥接下载器的源码。技能原始文件按固定 commit 与 SHA256 从上游获取，下载和写入发生在参赛者明确授权的本机项目目录。服务器不会替用户安装本机技能。桥接下载入口为 `/api/v1/skill-bridge/download`，文件落盘、客户端发现技能、任务效果分别记录。

## 2. 运行前准备

网站所有自由聊天由 `src/server/dsh-chat.ts` 固定组合 DSH，无论 `AI_PROVIDER` 如何选择。必须配置下面的 DSH 安装/账号或 API-key 路径、模型与费率；仅填写通用 `AI_*` 不会启用聊天。`GET /api/v1/navigator/intro` 返回 `chat.provider=dsh` 与配置状态，配置状态不能证明实际凭据或联网正常。聊天错误不会降级到通用 HTTP 或静态回答，首页与项目页共用 `/api/v1/navigator/messages`。

需要 Node.js 24+、npm、Docker Engine 和 Docker Compose v2；服务器或其反向代理需要可用 HTTPS 域名。Docker 镜像构建需要访问 npm 官方 registry；实际后台服务需要按启用能力访问模型、邮件、搜索、GitHub 和白名单来源。

仓库新增的安装脚本可直接运行；`package.json` 应包含：

```json
{
  "dsh:install": "node --experimental-strip-types scripts/install-dsh.mts",
  "worker": "node --env-file-if-exists=.env.local --experimental-strip-types scripts/backend-worker.mts"
}
```

`db:migrate`、`admin:grant` 使用仓库现有脚本。Compose 从 `.env.production` 加载服务端变量；此文件被 `.gitignore` 和 `.dockerignore` 排除。不要把任何私钥放入 `NEXT_PUBLIC_*`、前端包、Docker build args 或镜像层。

以下命令用于你实际准备部署的机器；本次交付没有执行这些部署命令。

## 3. 填写 `.env.production`

先在仓库根复制 `.env.example` 为 `.env.production`，再将正式变量改为已核实的值。下面是关键字段结构；空值必须填完整，不能直接运行。

```dotenv
APP_MODE=connected
AUTH_ORIGIN=https://你的实际域名
AUTH_CODE_PEPPER=
AUTH_EMAIL_FROM=
RESEND_API_KEY=
AUTH_GLOBAL_SEND_LIMIT=200
AUTH_GLOBAL_VERIFICATION_LIMIT=500

POSTGRES_DB=fieldguide
POSTGRES_USER=fieldguide
POSTGRES_PASSWORD=
# 用户/密码需 URL 编码；Compose 内部主机名固定为 postgres。
DATABASE_URL=postgresql://fieldguide:URL编码后的密码@postgres:5432/fieldguide
WEB_HOST_PORT=3000

# 固定版本 DSH 在镜像中已经安装，下面配置真实 DeepSeek 调用。
DSH_API_KEY=
DSH_MODEL=
DSH_BASE_URL=https://api.deepseek.com/anthropic
DSH_RUNTIME_PACKAGE_DIRECTORY=/app/.runtime/dsh-runtime/node_modules/@deepseek-ai/dsh
DSH_INPUT_MICRO_USD_PER_MILLION=
DSH_OUTPUT_MICRO_USD_PER_MILLION=
DSH_TIMEOUT_MS=90000
DSH_MAX_OUTPUT_TOKENS=8192
DSH_DAILY_NAVIGATOR_CALL_LIMIT=40
DSH_DAILY_NAVIGATOR_BUDGET_MICRO_USD=
DSH_DAILY_SOURCE_CALL_LIMIT=20
DSH_DAILY_SOURCE_BUDGET_MICRO_USD=2000000

# Brave 是独立的网页搜索服务，有独立账号、密钥和费用。
BRAVE_SEARCH_API_KEY=
BRAVE_SEARCH_COST_MICRO_USD_PER_CALL=
DISCOVERY_MINIMUM_INTERVAL_MS=300000
DISCOVERY_RECRAWL_AFTER_MS=300000
DISCOVERY_MAX_PAGES_PER_CYCLE=3
DISCOVERY_RESULTS_PER_QUERY=10
DISCOVERY_DAILY_SEARCH_CALL_LIMIT=144
DISCOVERY_DAILY_MODEL_CALL_LIMIT=360
DISCOVERY_DAILY_BUDGET_MICRO_USD=1000000
DISCOVERY_QUERIES_JSON=["hackathon official open registration","黑客松 比赛 报名 官网"]

# 灵感与赛事分开记账；启用前填写有效 DSH 模型和费率。
INSPIRATION_ENABLED=true
INSPIRATION_MINIMUM_INTERVAL_MS=60000
INSPIRATION_RECRAWL_AFTER_MS=86400000
INSPIRATION_DAILY_MODEL_CALL_LIMIT=24
INSPIRATION_DAILY_BUDGET_MICRO_USD=100000
```

`AUTH_ORIGIN` 必须是完整 HTTPS origin，不能带路径、结尾斜线或多个域名。`AUTH_CODE_PEPPER` 至少 32 字节；可以在自己的终端用 Node `crypto.randomBytes(48).toString('base64url')` 生成后存入该文件。Resend 发件人使用已验证域名，SMTP 发件地址使用认证邮箱；配置见 [QQ邮箱验证码配置](QQ邮箱验证码配置.md)。正式模式不会用开发邮箱预览假装发送成功。生产登录的全站邮件/验证码额度需要根据真实访问量调整，目前默认不是每个用户独享的额度。

通过 SakuraFrp 让手机访问时，可在 `APP_MODE=local` 下显式设置 `AUTH_ORIGIN=https://你的SakuraFrp域名` 与 `AUTH_ALLOW_PUBLIC_LOCAL_ORIGIN=true`。服务使用 Secure 会话 Cookie，并严格校验固定 Origin。接入真实邮件无需先迁移数据库：可配置下述 Resend 或 SMTP，再重启网站。local 和 connected 均支持实际发送；未配置且 Origin 不是回环地址时返回服务未配置错误，不生成公开开发邮箱验证码。正式生产仍应使用 connected 与独立 PostgreSQL。

### 3.1 为当前网站启用真实验证码邮件

这是网站管理员的一次性配置，注册和登录的用户只需填写自己的收件邮箱。

1. 在 [Resend Domains](https://resend.com/domains) 添加自己能管理 DNS 的发信域名，按页面提示添加记录，等待显示 Verified。发信域名与 SakuraFrp 网站地址可以不同。
2. 在 [Resend API Keys](https://resend.com/api-keys) 创建具有发送权限的密钥，保存在部署主机 `.env.local`，不放入前端或聊天。
3. 配置以下两项并重启网站：

```dotenv
RESEND_API_KEY=你的Resend密钥
AUTH_EMAIL_FROM="黑客松情报局 <login@你的已验证域名>"
```

配置后发送接口使用用户填写的邮箱作为 `to`，登录和注册共用验证流程。供应商受理不等于已进入收件箱，应实际检查收件箱和垃圾邮件完成投递验收。Resend 默认 `onboarding@resend.dev` 只用于向 Resend 账号本人邮箱测试，不能用于所有参赛者。[发信域名验证](https://resend.com/docs/dashboard/domains/introduction)、[测试域名限制](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain)。

`DSH_MODEL` 应填写账号实际可调用的模型 ID。DeepSeek key 不是 Brave 搜索 key，也不是 GitHub App key。启用发现前必须完整配置 DSH；未配置 Brave 时，容器可选择下方官方来源方式，本机已核查的 Desktop/account 路径可使用原生搜索，均不能宣称全平台完整覆盖。来源分析还有独立的每日调用/费用上限，默认每个来源 20 次、2 USD；灵感默认独立上限为 24 次模型、0.10 USD / UTC 日，与个人导航、全站发现分别计入。结果未知的付费请求不能靠自动重试突破预算。

费用单位全部明确为 **USD 微美元**，`1 USD = 1,000,000 micro USD`。输入/输出费率字段分别表示每一百万 token 的微美元费用；例如实际报价为 `1 USD / 1M tokens` 时应填 `1000000`，该数字只是换算示例。Brave 字段表示每次搜索的微美元费用；上面赛事预算 `1000000` 表示 `1 USD`，灵感预算 `100000` 表示 `0.10 USD`。应以自己的实际计费方案填费率，不要用 `0` 代替未知价格。DSH 返回的实际 token 用量与这些费率用于费用估算，预算预留不会等同于供应商最终账单。[DeepSeek 定价说明](https://api-docs.deepseek.com/quick_start/pricing)、[Brave Search API 官方入口](https://brave.com/search/api/)。

设置 `AI_PROVIDER=dsh` 后，项目 AI 工作流（规则建议、测评、分工、时间规划、复盘）与导航、来源分析共用真实 DSH；无需另一份 `AI_API_KEY`。项目任务复用 DSH 的输入/输出限制、USD 预算费率及每日项目调用上限，每次模型调用仍单独记账。`AI_PROVIDER=http` 则使用 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 和 `AI_*` 预算。配置了有效的 AI 和/或 DSH 服务才能启动有处理能力的 `worker`；否则它会明确退出并报告未配置。

本机现已使用 `D:\dddsss` 中 Desktop 自带的 **0.2.0-rc.2**，配置 `DSH_DESKTOP_DIRECTORY=D:\dddsss`、`AI_PROVIDER=dsh`、`DSH_MODEL=deepseek-flash`。账号授权从本机 DSH 默认 `.credentials.yaml` 读取（可用 `DSH_DESKTOP_CREDENTIALS_FILE` 指定），每次仅由隔离子进程读取官方 DeepSeek grant，临时文件只保留这个 grant 并在进程退出后清理；不读取个人会话、浏览器凭据、技能或插件。不会把 token 写入 `.env.local`、API 响应或日志，不修改个人 DSH 授权。账号退出或过期时，服务会提示检查 DSH 登录。Windows 常驻服务需要能访问这份安装和授权，并维护登录状态；Linux 或容器部署使用官方 API key 运行时，不能直接引用 Windows 安装目录。Desktop 升级后版本检查会拒绝未经兼容验收的新版本。

当前本机按 2026-10-08 核查的 Flash 峰值未命中输入 `0.30 USD/1M`、输出 `1.20 USD/1M` 作保守预算估算，因此输入字段为 `300000`、输出字段为 `1200000`；缓存、低峰或账号套餐的实际账单可能更低。实际 token 有模型测量，金额仍是预算估算，不宣称等同于账号扣费。此前小规模真实 SDK 校验已返回有效 JSON（118 输入/5 输出 token）。Desktop 账号模式限定官方推理端点，供应商内部及外围自动重试均关闭。本机赛事现用 DSH 原生搜索；固定官方列表和独立 Brave 仍可按下文配置，灵感只读取固定官网范围。[DeepSeek 官方模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)、[官方 Desktop CLI 说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md)。

GitHub 功能需同时配置 `GITHUB_APP_ID`、`GITHUB_APP_SLUG`、`GITHUB_APP_CLIENT_ID`、`GITHUB_APP_CLIENT_SECRET`、`GITHUB_TOKEN_ENCRYPTION_KEY`。最后一个字段必须是 32 字节随机密钥的 base64；`GITHUB_TOKEN_ENCRYPTION_KEY_ID` 用于密钥版本，轮换时保留旧 key 到 `GITHUB_TOKEN_ENCRYPTION_PREVIOUS_KEYS`，否则旧授权需要重新连接。GitHub App 的用户授权回调应为 `AUTH_ORIGIN + /api/v1/github/authorization/callback`，安装 setup URL 为 `AUTH_ORIGIN + /api/v1/github/installation/callback`。需要启用过期用户 token，并针对真实使用的仓库授予内容与 PR 权限；新建个人仓库的权限必须按 M06 已核实的实际端点要求设置。只配置网址或填写 PAT 不能代替 GitHub App 授权。

## 4. DSH 固定版本安装与核验

### 不使用搜索密钥的官方来源采集

设置 `DISCOVERY_PROVIDER=official_sources` 与 `DISCOVERY_SOURCE_IDS_JSON=["ethglobal","lablab"]`，检查限定官网的近期赛事卡片，提取单场详情链接，再交给真实 DSH 分析。此模式不需要 Brave key 或 Brave 搜索单价；模型调用和费用限额继续执行。后台中的“来源检查”是官网列表检查次数，搜索 API 单价为零，不代表模型分析免费。

支持的来源由服务端 catalogue 固定；未知 ID、重复 ID、私人地址或任意外链不能进入配置。抓取仍检查公开 DNS、TLS、robots、重定向、页面大小与超时，不绕过访问验证。目录格式或近期标记变化时停止该来源并留下安全错误代码，不能把整张列表当成一场比赛。官方方式仅覆盖指定官网，并不提供全网搜索。

使用 `DISCOVERY_PROVIDER=brave` 可切回独立搜索服务；保留原有 Brave key、单价与查询配置。两种方式共享持续发现状态和每日预算，不通过切换入口重置已保存的调用记录。

历史本机使用 `SOURCE_HTTP_PROXY=http://127.0.0.1:22321`。2026-10-11实测此端口已无监听，导致来源获取失败；经原受限网络适配器验证 awwwards 和 hackertrip 的 robots 可直连，已删除本机失效代理选择并正常重启。当前采用原有受限直连，未改网站域名、系统DNS、TLS或robots限制；ETHGlobal robots 仍被响应校验拒绝，不能推定所有来源可读取。

可选代理仍只支持显式可信 loopback HTTP CONNECT 地址，无账号、密码或路径，不读取系统或其他环境代理。父进程验证全部 DNS 答案、固定公开 IP CONNECT，并校验 TLS 域名。配置代理后若不可用，抓取失败，不自动回退到不受限制的获取方式；配置仅用于公开页面与 robots，不传给 DSH 子进程。

官方列表有多场历史活动，ETHGlobal 当前 HTML 约 1.86 MB，列表读取单独限定为 2 MB；详情仍使用 `DISCOVERY_MAX_PAGE_BYTES` 的独立限制。公开比赛页只展示分析结果、未知项和官网跳转，采集配置、额度与暂停留在管理员后台。

两种 DSH 运行方式均在写入授权或 API key 前隔离新建临时目录：Windows 设置并验证当前服务账号独占、可继承的 NTFS ACL；Unix 使用 0700。不能建立私有目录时返回 `DSH_SESSION_PRIVACY_UNAVAILABLE`，不启动模型并按未发送处理。临时目录保护不修改原始 Desktop 凭据。构建 tracing 排除 `.runtime` 与 `.env*`，部署仍应使用自己的环境配置。

后端固定为官方 `@deepseek-ai/dsh@0.2.1-alpha.1`，不使用 `latest`/`alpha` 浮动 tag。[官方仓库](https://github.com/deepseek-ai/deepseek-harness)、[官方 npm 包](https://www.npmjs.com/package/@deepseek-ai/dsh)。2026-10-08 核查官方 npm registry 的 tarball integrity 为：

```text
sha512-DJ8pwG/XqzwDrYQTgJXuIga6ku153Z4vJI/B3MzNtudVCkDaOf4O2pUQh1ToroLHPPe4mxhhFeNJ7ttNculqMw==
```

`scripts/install-dsh.mts` 会在项目 `.runtime` 下新建临时目录，以清洁环境调用官方 npm CLI，关闭 lifecycle scripts、audit 和 fund 请求。它先 `npm pack` 并独立计算 tarball SHA512，再生成只含精确顶层版本的 lock，检查官方 registry 来源和固定 integrity，最后执行 `npm ci --ignore-scripts`。安装完成后保留 `package-lock.json`、`runtime-receipt.json` 和真实包文件；失败仅清理自己创建的临时目录，不修改现有运行目录。[npm ci 与 ignore-scripts 行为](https://docs.npmjs.com/cli/v11/commands/npm-ci/)。

```sh
npm run dsh:install
npm run dsh:install -- --check
```

默认目录为 `.runtime/dsh-runtime`。既有目录仅核验、不覆盖；不完整目录或未固定的旧 lock 会被拒绝。需要切换安装时，可新建 `.runtime/dsh-runtime-new` 并相应修改服务端配置：

```sh
npm run dsh:install -- --directory .runtime/dsh-runtime-new
```

安装器只允许当前项目 `.runtime` 下名为 `dsh-runtime` 或 `dsh-runtime-名称` 的直接子目录，不安装到用户全局 DSH/Agent 目录。`--check` 不下载、不安装，检查 lock 和真实 CLI 身份；它不是一次真实模型调用。安装器不会读取 `.env.local` 或导入应用密钥。构建如需出站代理，可给构建环境提供标准 npm HTTP(S) 代理设置；不要把代理密码或 `.npmrc` 写入镜像。

顶层 DSH tarball 是固定的；传递依赖由构建时生成的 lock 固定并保存在镜像中。重新生成 lock 时可能解析出不同的传递版本，因此应发布并复用已验证的镜像 tag/digest，同时归档该镜像里的 runtime lock。当前基础镜像的 Node 24、Postgres 17 标签也会接收同主版本更新；要完全复用某次构建，应在自己的镜像仓库记录 digest。

## 5. 首次启动

在部署机的仓库根执行。`config --quiet` 只校验格式，不打印含密钥的合成配置。

```sh
docker compose --env-file .env.production config --quiet
docker compose --env-file .env.production build
docker compose --env-file .env.production up -d
docker compose --env-file .env.production ps -a
docker compose --env-file .env.production logs --tail=80 migrate worker
```

预期是 Postgres 健康，`migrate` 成功退出，`web` 健康，`worker` 持续运行。Compose 通过 `service_healthy` 和 `service_completed_successfully` 控制先后顺序；迁移失败时应用不会进入正常启动。[Compose 启动顺序文档](https://docs.docker.com/compose/how-tos/startup-order/)。

容器网站显式监听 `0.0.0.0:3000`，宿主只映射 `127.0.0.1:WEB_HOST_PORT`。配置宿主反向代理，将正式域名的 HTTPS 请求转发到该端口，保留正确 `Host`，设置实际 `X-Forwarded-Proto`；根据需要配置请求体和超时上限。仓库没有替你申请证书或安装反向代理。[Next.js 自托管说明](https://nextjs.org/docs/app/guides/self-hosting)。若反向代理运行在另一个容器，需让它加入同一个 Compose 网络并访问 `web:3000`，不能把代理容器自己的 `127.0.0.1` 当成网站。

先通过正式邮件完成一次登录，再在服务器将该已验证邮箱授权为管理员：

```sh
docker compose --env-file .env.production run --rm --no-deps migrate npm run admin:grant -- 已验证的管理员邮箱 admin
```

该命令操作当前数据库并记录角色审计，不会创建一个绕过邮箱验证的账号。管理员可进入 `/admin`；未授予角色的账号不会获得管理权限。

## 6. 持续采集与上线核验

“持续发现”表示常驻 worker 按频率、查询、预算与来源策略轮询，不保证覆盖全网、永不中断或全部赛事完整。搜索索引、可访问页面、robots、登录、预算、网络和比赛更新都会影响覆盖。发现卡片保持未核验；用户使用前仍需到主办方公告核对规则和期限，M08 正式候选发布沿用人工审核。

本机现用 `DISCOVERY_PROVIDER=dsh_native`，直接调用 `D:\dddsss` Desktop DSH `0.2.0-rc.2` 内置官方原生搜索。使用已有 DeepSeek 账号授权，另设 `DSH_SEARCH_MODEL=deepseek-v4-flash`、`DSH_SEARCH_MAX_OUTPUT_TOKENS=2048`、`DSH_SEARCH_MAX_USES=1`、搜索输入/输出费率 `300000`/`1200000` microUSD/百万 token。这是 peak Flash 的保守估算，缓存输入一并按未命中计算，最终收费以账户账单为准。[官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。原生搜索目前仅在已核实 Windows Desktop/account 路径启用，API-key 和容器路径没有宣称支持此新入口。

网站停止且 3000 端口关闭后，可运行 `npm run db:migrate`，再用 `npm run discovery:once -- --activate-native` 明确首次启用原生搜索。该操作有唯一激活审计，只推进首次日程，不清空预算、暂停状态或未知请求；重复执行激活标识不再次推进周期。自动循环不使用此激活参数。PGlite 不能在网站和独立脚本中同时打开；正常本机循环仍复用网站的数据库实例，远程部署用常驻 `npm run worker` 与真实 PostgreSQL。

服务启动即自动调度，每轮一个公开社交赛事搜索词，最短间隔 5 分钟，每轮最多分析三页；日搜索上限 144、搜索与分析合计模型上限 360，日费用上限仍为 1 USD。付费搜索预发送标记跨重启/跨日保留，未知结果不自动重放。有效结果无 usage 按完整预留收费。引用摘录卡片显示“搜索引用 · 未读取全文”；没有真实引用时不能拿搜索生成回答代替依据。微信小程序内部内容没有接入。

赛事详情按最短 5 分钟重抓，正文哈希未变不再次分析。新的报名/参赛建议结构版本可重分析旧成功结果，但不能清除未知请求 hold。144 次搜索在每轮一个查询词时至多约 144 轮；每日费用预留、长轮次和访问限制也可能进一步减少，不能把 5 分钟最短间隔承诺为全天每 5 分钟一轮。

报名入口必须由本次可见 HTML 或真实引用文本中的明确链接提取并附证据，再由 DSH 选择；缺少候选时显示查看原文。`consider/caution/insufficient_info` 仅为条件性参赛建议，不保证访问者技能或资格，不给匹配百分比。旧卡片没有新字段时保留原分析并提示信息不完整，不能假装已经重分析。

### 灵感官网的独立运行策略

`/inspiration` 独立呈现视觉参考、网页案例、组件代码和动效官网；`/resources` 保留 M09 审核工具/资料及个人收藏、项目共享。固定 21 个已核查官网仅是候选身份，生产正文必须来自实际官网获取后完成的 DSH 分析。未分析卡片显示真实名称、官网链接和等待状态，不能显示 seed 的手写推荐。没有使用许可依据时，说明应保留未知部分，不把链接当作素材、字体或代码使用授权。

先应用 `020_inspiration_catalog.sql`：本地在网站进程启动时复用 PGlite 自动迁移，连接模式按既有 `migrate` 顺序执行。灵感卡片和不可变版本保存在数据库；`inspiration-catalog` 使用独立调度、预算和未知模型结果标记。`INSPIRATION_ENABLED=true` 必须有有效 DSH 模型/费率；后台在同一任务组每 10 秒检查，最短每分钟处理一个到期官网，同站默认 24 小时后重抓。内容与提示版本未变时不重复付费模型，请求未知时保留 hold。当前本机独立上限是 24 次模型和 0.10 USD / UTC 日，预留不足时会提前停止，不能承诺 21 站一天全部分析。

官网读取遵守固定来源范围、公开网络、robots、TLS、重定向、体积与超时限制，仅访问公开且允许读取的内容。DSH 只生成 `description/useWhen/usageNote` 与准确原文摘录，不能改站点身份或官网链接；服务器写入实际分析时间和本次取得内容的官网地址。robots 禁止、来源失效、抓取或校验失败时不生成假正文，已保存说明仍可读取。

比赛页可见时每 3 秒读取 `/api/v1/event-discoveries/live` 元数据，版本变化后读取卡片；灵感页可见时每 10 秒读取 `/api/v1/inspiration` 快照。隐藏页面停止请求，读取有有界超时，断线保留已有内容；这些 GET 均只读取已保存数据，不启动采集或收费任务。

管理员分别使用 `/api/v1/admin/discovery/status` 与 `/api/v1/admin/inspiration/status` 检查账本。灵感暂停入口为 `POST /api/v1/admin/inspiration/paused`，提交 `{expectedRevision,paused}`；每次复核当前管理员权限，处理版本冲突并记录审计。赛事与灵感暂停和额度独立，不通过修改页面、切换供应商或重启清零已有记录。

用管理员登录后检查 `/api/v1/admin/workers`，确认 `ai`/`source`/`discovery`/`inspiration` 中实际启用的 worker 有近期心跳；`stale`、`failed` 和 `errorCode` 是处理信号，不是正常成功状态。缺少所选入口所需配置时相应能力保持未配置状态；网站展示 `configured=true` 仅表示配置齐全，不能证明凭据有效或供应商调用成功。

可视化入口为 `/admin/services`，运营工作台中有“后端服务控制台”入口。控制台以只读 SQL 快照展示服务配置、实际启用 worker 的心跳与陈旧状态、模块等待任务及中央执行记录、来源任务、卡片与审核数量、今日调用和费用。本次灵感调度与独立预算的可视化组合仍待最终验收。手动刷新和可选自动刷新都只读取本站状态，不主动测试供应商或派发付费任务。快照只返回安全元数据，不返回模型输入、原始日志、账号资料、密钥或租约凭据。

配置完整与实际可达分别记录；数据库完成本次查询才显示可达，其余供应商连接保持未验证。模块等待与中央执行可能描述同一任务，不能将两组数字相加作为独立任务数。今日 AI 合计跨项目、个人和来源范围，不能除以某个项目的限额计算占用率；每范围政策单独展示。费用保留已知部分、预留及未知用量，不能把不完整金额当最终供应商账单。金额单位为微美元，配额按 UTC 日期计入，时间展示为北京时间。管理员权限在每次快照读取的事务中重新校验，撤权后无法继续读取。

以下是交付前需要在你真实环境完成的核验，测试时使用自己的测试账号、仓库和低成本样例：

1. 正式邮箱收到验证码，错误/重复验证码不能登录，退出后会话失效。
2. 新建项目、邀请和加入队伍；非成员不能读取或修改该项目。

5. 所选 DSH 原生/官方列表/Brave 入口实际返回来源；完成一个低配额发现周期，核对证据、报名链接、条件性参赛建议及预算。未提供报名候选、全文不可得或旧卡片缺字段时状态诚实，达到限额后不继续收费。
6. 配置来源后完成一次入队→抓取→分析→审核→发布，人工核对时区、原文和当前版本。
7. GitHub App 实际授权回调、安装范围、仓库发现、预览确认保存；一次提交后远端文件与 commit SHA 相符，撤销授权后无法继续保存。
8. 下载技能桥接，在隔离测试项目写入并撤销一项固定版本技能；不要把文件写入成功当成客户端加载或任务验证成功。
9. 停止和重启 worker 后检查队列与心跳，确认不自动重复已发送但结果未知的付费请求。
10. 在低配额下实际读取一个 robots 允许的固定灵感官网并完成 DSH 分析，核对实际时间、官网依据和服务器固定身份。其它候选保持等待，页面刷新只读；暂停/恢复复核权限与 revision，24 小时重抓和内容复用、预算不足、抓取失败与未知结果持久阻断分别验证。

自动测试与模拟 HTTP/PGlite 不替代真实外部验证。此前本机账号模式的 DSH 搜索、分析、导航和部分来源已有真实记录；本次报名、参赛建议及灵感官网的最终集成与真实样例验收尚待主会话补充。正式邮件、GitHub、远程数据库、容器与其它客户端仍未通过真实验收，不能把既有本机通过扩展为整组通过。

## 7. 发布更新、备份与恢复

发布前备份 Postgres 和当前镜像 tag/digest；不得重写已经应用的迁移文件。可以先停止应用，保持数据库，再构建新镜像、单次执行迁移，最后启动两个服务：

```sh
docker compose --env-file .env.production stop web worker
docker compose --env-file .env.production build
docker compose --env-file .env.production run --rm --no-deps migrate
docker compose --env-file .env.production up -d web worker
```

迁移按文件内容 hash 检查已应用版本；重复执行已应用迁移只会核对并跳过，不会每次重建数据。迁移失败应先解决错误，再启动应用。代码回退不保证已升级数据库能兼容，应根据具体迁移评估；不要仅回退镜像就宣称已恢复。

Postgres 命名卷承载正式数据；正常 `docker compose down` 保留卷，带 `-v` 会删除数据，不能用来处理运行故障。备份可使用 `pg_dump -Fc`；在容器内写到临时文件，再 `docker compose cp` 导出到受保护的备份目录，可以避免不同 shell 的二进制重定向差异。定期把备份恢复到独立测试数据库，验证账号、项目、审核证据与提交记录可读。恢复命令应显式指向该测试数据库。

`AUTH_CODE_PEPPER`、数据库密码和 GitHub 加密 keyring 必须单独备份并控制访问；缺失 keyring 会使数据库中的旧授权密文无法解密。运行日志不应收集完整提示、供应商原始错误、HTTP Authorization 或验证码；目前 worker 输出安全状态码，排障也应保留这一边界。

### 主办方自己的发信邮箱

通过认证的机构管理员在“主办方 → 赛事工作台 → 发信邮箱：使用主办方自己的账号”设置。选择 QQ/163/126/Gmail，输入完整发信地址与该邮箱SMTP授权码（Gmail应用专用密码），明确确认后验证保存。服务器只验证TLS连接和认证，不发送测试信；每机构60秒一次、UTC日最多10次。失败保留旧设置，页面清除授权码，读最新设置不会重新认证。

同一机构的赛事通知优先使用其当前已验证账号；未配置或明确停用时回到已配置的网站发信服务。网站也未配置时只发布站内通知。平台登录/注册验证码仍使用平台邮箱，与选择哪场比赛无关。发送前复核机构状态和配置版本，accepted只表示邮件服务接受，未知结果持久暂停重试。等待邮箱配置的队列项延后调度，不阻塞其他机构。

邮箱地址与授权码一起AES-GCM加密，接口只返回脱敏邮箱和版本。加密key从稳定`AUTH_CODE_PEPPER`派生独立用途：connected部署必须保留原值；local部署同时备份`.runtime/local-secrets.json`和数据库。不要重新生成key来解决解密错误，不把凭据放浏览器、日志、DSH提示、公开导出或部署包。目标服务器须能连到上述官方SMTP主机465端口；任意自定义SMTP地址与Outlook OAuth暂未适配。

| 现象 | 处理 |
| --- | --- |
| `migrate` 失败、web 没启动 | 检查数据库地址/权限与迁移错误，保留已有卷和迁移历史 |
| web API 503 | 查看配置是否完整、Postgres 是否可连接；页面服务在线不代表后端可用 |
| worker 不断退出 | 确认 `DATABASE_URL` 为真正 Postgres，且至少启用通用 AI 或 DSH；检查 runtime 路径 |
| `DSH_INSTALL_*` 安装失败 | 官方 registry/代理可达性、Node/npm 版本、tarball integrity 或旧目录状态；不取消校验来绕过 |
| `DSH_VERSION_MISMATCH` / `DSH_START_FAILED` | 检查容器是否使用当前镜像、runtime path、目录权限和临时会话目录空间 |
| 来源结果长时间不更新 | 查看 worker 心跳、发现暂停、来源状态、限额/费用预留、访问失败；不要无上限提高配额 |
| 灵感官网一直显示等待 | 查看独立灵感启用/暂停、心跳、0.10 USD 预算及预留、robots/获取错误；成功后 24 小时重抓，已知获取失败最短五分钟重试，未知模型请求 hold 不自动重发；候选名称存在不代表已分析 |
| GitHub 提示重新授权 | 检查 App 回调、当前账号/安装、token 过期与旧 keyring；按提示重新连接 |

已核对源码配置、生成文件、隔离测试与官方 tarball 校验；当前环境没有 Docker CLI，镜像构建和真实容器启动尚需在目标环境验收。真实部署是否成功，应以实际启动、健康、业务样例和外部调用结果为准。
