# 网站服务启动方式与故障记录（2026-10-11）

## 1. 事故：进程空转、端口占用但不响应

**现象**：`http://127.0.0.1:3000` 连接被拒，但 3000 端口仍有监听；隧道持续报
`连接映射目标 [tcp(auto-https)://127.0.0.1:3000] 失败`。

**实测证据**：

| 项目 | 值 |
| --- | --- |
| `next start` PID 7492 | CPU 累计 **21372 秒**，WorkingSet 516 MB |
| 该进程连接 | 仅 1 条 `Listen`，**0 条 Established** |
| 停止前最后日志时间 | 17:44:43，之后再无任何输出 |
| 父进程 | 已消失（与启动 wrapper 脱钩） |

**根因（高置信）**：上次用 `npm.cmd run start 2>&1 | Tee-Object -FilePath ...` 把网站挂在
**会话的后台管道**上启动。当管道读取端停止消费（会话暂停/管道缓冲占满）后，子进程写 stdout
阻塞，事件循环被毒住：**进程活着、端口占着、但不接受任何连接**，同时空转烧 CPU。

**修复**：改用 [scripts/serve-service.ps1](../../scripts/serve-service.ps1) 以脱离会话的方式启动，
输出重定向到日志文件而不是管道。修复后实测 30 秒真实时间内 CPU 仅消耗 0.38 秒、日志增长 0 字节。

## 2. 日常操作

```powershell
# 启动（已在运行且健康时会拒绝重复启动）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\serve-service.ps1 start

# 查看状态（会真实建立 TCP 连接，能发现"端口在听但不响应"的假活）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\serve-service.ps1 status

# 停止
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\serve-service.ps1 stop

# 重启
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\serve-service.ps1 restart
```

- 日志目录：`.runtime/logs/site-<时间戳>.out.log` 与 `.err.log`
- PID 文件：`.runtime/serve.pid`；锁文件：`.runtime/serve.lock`
- 脚本刻意只用 ASCII，避免 Windows PowerShell 5.1 以 GBK 解析无 BOM 的 UTF-8 脚本导致语法错误。

## 3. 重启顺序（重要）

frpc 会在隧道启动时探测本地服务，探测失败会把隧道的"自动 HTTPS"**永久置为禁用且不自动恢复**。
因此涉及网站重启时，顺序必须是：

1. 先停隧道（或接受隧道需要重启一次）
2. 停网站 → 改配置 → 启网站，并确认 `status` 显示 `AcceptingTCP : True`
3. 再启隧道，使其探测时网站已在线

若顺序错了导致公网打不开，执行 `restart` 隧道（停止 `frpc.exe`，SakuraFrpService 会在约 5 秒后重新拉起）。

## 4. 仍然存在、未解决的问题

- `SOURCE_HTTP_PROXY` 指向 `http://127.0.0.1:22321`，该端口当前没有监听，
  导致采集类后台每轮 `FETCH_UNAVAILABLE`（不产生模型调用，无费用）。
  恢复代理或改配置前，公开页面只显示已有快照，不会产生新卡片。
- 公网证书仍是 `CN=SakuraFrp Automatic TLS` 自签证书（有效期至 2027-10-08，**未过期**），
  浏览器/手机会提示不受信任。根治方式见「HTTPS 隧道 + nyat.app 子域」方案。
