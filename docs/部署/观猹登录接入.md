# 观猹登录接入与启用边界

2026-10-12：代码、隔离账号关联测试、页面和068迁移已完成；本机已保存用户提供的服务器端凭据。`GUANCHA_LOGIN_ENABLED=false`，当前仍使用原邮箱验证码登录，不能把源码交付当作真实第三方登录成功。

## 已核对的官方协议

官网 watcha.cn 的登录组件链接至[观猹认证接入文档](https://agentuniverse.feishu.cn/wiki/EMYHwT3sIiUYaDkL1ZvcPntGnpb)和[申请接入说明](https://agentuniverse.feishu.cn/docx/McKCdI70Gols8hxiBVYcMfhCnNc)。已读取公开正文，细节见 `src/modules/guancha-login/protocol-notes.md`。

- 授权：`https://watcha.cn/oauth/authorize`。
- 兑换：`https://watcha.cn/oauth/api/token`，服务器端表单POST。
- 用户资料：`https://watcha.cn/oauth/api/userinfo`，按官方示例使用私有access_token查询参数；原生HTTPS，无日志、缓存、重定向或自动重试。
- 只申请`read`，授权码配合S256 PKCE，以固定issuer与稳定user_id识别用户，不按昵称或未经验证的第三方邮箱合并本站账号。

## 网站流程

启用后，登录/注册页出现“使用观猹登录”。已有绑定时进入原本站账号；首次使用先验证本站邮箱，再显示账号供用户明确确认关联。原队伍、文档、任务与角色沿用既有账号权限。短期pending不是本站登录会话。

来源、随机state、浏览器Cookie、期限、配置版本和回调都校验；异常或取消不能重放原兑换。授权与pending凭据只保存在HttpOnly/Secure/SameSite=Lax Cookie。关联结果响应丢失时可只读核对同浏览器、同账号已完成的绑定，不盲目重写。

## 本机配置与尚未通过的项目

`.env.local`使用`GUANCHA_CLIENT_ID`、`GUANCHA_CLIENT_SECRET`、`GUANCHA_REDIRECT_URI`、`GUANCHA_LOGIN_ENABLED`，严禁NEXT_PUBLIC前缀或在文档中记录密钥。

当前`AUTH_ORIGIN`为`https://frp-off.com:44353`，精确回调必须是：

```text
https://frp-off.com:44353/api/v1/auth/guancha/callback
```

用户提供的`https://frp-off.com:44353/events`是网站地址，不代表上述callback已经在观猹后台登记。当前未能核对应用后台的精确回调；frp-off公网入口严格TLS仍为自签证书错误。现有hib域名证书本身可信，但普通DNS路径异常，且不是当前应用origin。用户要求保留域名、只修穿透；本轮没有改域名、DNS、证书或AUTH_ORIGIN。

只有精确callback登记和当前公共origin的严格HTTPS均验证后，才设置`GUANCHA_LOGIN_ENABLED=true`并正常重启，实际验证已有账号、首次邮箱关联、拒绝授权、手机Cookie回跳和会话撤销。不得通过忽略TLS、自造用户邮箱、猜回调或直接把开关改为true来冒充验收。

验证码仍沿用网站邮件服务。观猹测试使用受控provider替身，未向任何第三方发送真实令牌或本机用户数据。
