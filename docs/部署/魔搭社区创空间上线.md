状态：**方案已定，尚未构建、尚未推送、尚未验证**。本文只记录已核实的外部约束与本站适配点，不代表已经上线成功。

## 路线选择（先读这段）

拿到一个「可用于演示」的链接有两条路，成本差很多：

| | 路线 A：Static 演示空间 | 路线 B：Docker 真实应用 |
| --- | --- | --- |
| 产出 | 静态产品演示页，可公开分享 | 完整应用（登录、AI、数据库） |
| 拿到链接 | 拖一个文件夹，几分钟 | 建空间 + git push + 平台构建 |
| 前置条件 | **只需魔搭账号** | 阿里云绑定 + 实名认证 + `MODELSCOPE_API_TOKEN` |
| 需要本机 shell | **不需要** | 需要（构建与推送） |
| 能否登录 / 用 AI | 不能 | 能 |

演示页已生成在 `modelscope-demo/index.html`：单文件、内联样式与内联 SVG、零二进制资源，内容取自项目内真实产物（DSH 原生搜索运行回执、参赛路线图 15 个行动节点、21 个已核查灵感官网、8 项技能与 3 个赛道包），并明确标注自己是静态演示。

**路线 A 的上传步骤**（全程在魔搭网页完成，不需要 shell、token 或实名认证）：

1. 在「空间文件」这一步，把 `modelscope-demo` **这个文件夹**整个拖进去。不要拖项目根目录（原因见第 7 节）。
2. 第 2 步「部署设置」里 SDK 类型选 **Static**。要求创空间仓库根目录直接出现 `index.html`——`modelscope-demo/` 里只有这一个文件，正好满足。
3. 第 3 步确认并部署，等状态变成「运行中」，链接形如 `https://modelscope.cn/studios/{owner}/{repo_name}`。
4. 验收：用**未登录窗口**打开，确认样式正常、21 个灵感官网链接可点、窄屏不横向溢出。确认后再把空间改为公开。

注意：Static 创空间**不执行构建**，所以这里放的是写好的纯静态文件；不要附带源码或 `node_modules`。演示页是产品形态展示，站内路径以文字呈现、不做成链接，避免整页 404。

以下第 1 节起是路线 B（真实应用）的方案与约束。

## 1. 目标与结论

目标：把本站上线到魔搭社区创空间，取得公开链接 `https://modelscope.cn/studios/{owner}/{repo_name}`。

结论：

- 魔搭创空间支持四种 SDK 类型：`static`、`gradio`、`streamlit`、`docker`。
- 本站是**全栈应用**（邮箱验证码登录、数据库、服务端 AI、常驻采集/维护任务），**不能用 `static`**。`static` 只上传已构建的纯静态文件，不执行 `npm run build`，也没有服务端。把本站做成 static 只能得到另一个"展示页"，不是本站。
- 因此走 **`docker` 类型**：由创空间基于仓库根 `Dockerfile` 构建镜像并运行。

## 3. 本站适配设计

### 3.1 单容器、单进程

创空间一个仓库只跑一个容器，仓库自带的 `compose.yaml`（`postgres` + `migrate` + `web` + `worker` 四个服务）**不适用**。

采用 `APP_MODE=local`：

- 数据库用嵌入式 PGlite，不额外起 PostgreSQL。
- 常驻任务由网站进程内嵌启动（`FIELD_GUIDE_SERVE=1`）。这与既有约定一致：PGlite 不能被网站和独立 worker 两个进程同时打开，所以**必须**用嵌入式任务，不能另起 `npm run worker`。
- `FIELD_GUIDE_EMBEDDED_WORKERS` 保持默认启用。

代价：local 模式不是正式生产形态，多连接并发与独立 worker 不在验证范围内；`connected` 模式要等有外部 PostgreSQL 时再用。

### 3.2 数据持久化

`src/server/config.ts` 把本地数据库与本地密钥**硬编码**在 `process.cwd()/.runtime` 下：

- PGlite 数据目录：`.runtime/postgres-data`（第 227 行）
- 本地密钥 `local-secrets.json`（第 86–88 行）

处理方式已在 `scripts/container-entrypoint.sh` 与根 `Dockerfile` 落地（**尚未构建验证**）：

- 只把 `postgres-data` 符号链接到 `/mnt/workspace/state/postgres-data`；先建好目标目录再建链接，避免出现悬空符号链接。
- 镜像内的 DSH 运行时留在 `/app/.runtime/dsh-runtime` **不移动**，因此 `DSH_RUNTIME_PACKAGE_DIRECTORY` 与 Compose 完全一致，不需要改配置。
- 根 `Dockerfile` 增加 `chown node:node .runtime`（运行用户要能建这个链接）、`EXPOSE` 增加 7860、`CMD` 改为读取 `${PORT:-3000}`，**同一份镜像同时服务 Compose（3000）与创空间（7860）**，避免两份构建逻辑漂移。
- 检测到 `/mnt/workspace` 不存在时（Compose、普通 `docker run`）入口脚本直接放行，不改文件也不打告警，既有部署行为不变；存在但不可写时明确告警"重启后数据全部丢失"，不静默假装已持久化。

**`AUTH_CODE_PEPPER` 必须作为创空间环境变量提供。** 这是一个实际陷阱：`config.ts` 用 `"wx"`（`O_CREAT|O_EXCL`）写 `local-secrets.json`，目的正是防止两个进程生成不同的 pepper。因此入口脚本既不能预建该文件（空文件会让 `JSON.parse` 抛错），也不能用悬空符号链接指向持久目录（链接自身已存在 → `O_EXCL` 返回 `EEXIST`，随后重读又因 `ENOENT` 失败）。显式提供环境变量后该文件不会被创建，问题自然消失。

### 3.3 站点地址与登录

```dotenv
APP_MODE=local
AUTH_ORIGIN=https://modelscope.cn
AUTH_ALLOW_PUBLIC_LOCAL_ORIGIN=true
```

- local 模式默认只允许回环 origin，公网必须显式打开 `AUTH_ALLOW_PUBLIC_LOCAL_ORIGIN`，且 `AUTH_ORIGIN` 必须是 HTTPS。
- 站点地址带路径 `/studios/{owner}/{repo_name}`，但 `AUTH_ORIGIN` 只接受**完整 origin**（不能带路径），所以填 `https://modelscope.cn`。
- 会话 Cookie 为 `Path=/; HttpOnly; SameSite=Lax; Secure`（`src/server/guancha-http.ts`、`application.test.ts`），Lax 在顶级导航下可用。

### 3.4 邮件是公开登录的硬前提

未配置 `RESEND_API_KEY` 或 SMTP 时，非回环 origin 会返回"服务未配置"，**不生成验证码，公网登录与注册不可用**。上线要能注册就必须配一项（变量名见第 5 节，值只在创空间的环境变量里配置）。

### 3.5 DSH 只能走 API key

容器是 Linux，**不能**引用 Windows Desktop 的 `D:\dddsss`。镜像里已按官方固定版本 `@deepseek-ai/dsh@0.2.1-alpha.1` 安装运行时，上线使用：

```dotenv
DSH_API_KEY=
DSH_MODEL=
DSH_INPUT_MICRO_USD_PER_MILLION=
DSH_OUTPUT_MICRO_USD_PER_MILLION=
```

诚实边界：`dsh_native` 原生搜索只在已核实的 Windows Desktop/account 路径启用，**API-key 与容器路径没有宣称支持**。所以上线后本站的自由聊天（固定 DSH）与项目 AI 可用，但**自动赛事发现不能沿用原生搜索**，只能改用固定官方来源（`DISCOVERY_PROVIDER=official_sources`）或已配置的 Brave。不得把"容器能启动"说成"自动采集正常"。

### 3.6 最大未验证风险：带路径的反向代理

魔搭把创空间挂在 `https://modelscope.cn/studios/{owner}/{repo_name}` 之下，而 Next.js 的资源与路由是**根绝对路径**（`/_next/static/...`、`/inspiration`、`/journey`）。若平台不剥离该路径前缀，页面会 404 或静态资源丢失。

处理预案与代价评估：

- 方案 A：平台剥离前缀 → 无需改动。
- 方案 B：需要 `next.config.ts` 的 `basePath: "/studios/{owner}/{repo_name}"`。`basePath` 在**构建期固定**，所以 `owner`/`repo_name` 必须先定下来；Next 的 `<Link>` 与静态资源会自动加前缀，但**客户端直接写的根绝对 `fetch` 不会**。
- 本站这类调用只有 4 处，改造成本可控：
  - `src/components/account-self-service.tsx`
  - `src/components/participant-profile.tsx`
  - `src/components/workflow.tsx`
  - `src/modules/planning/PlanningNotificationsPanel.tsx`

**在没有真实部署前不能断定平台采取哪种行为**，因此这一项必须由第一次真实部署的日志与浏览器控制台来判定，不能预先宣称已经适配。

## 4. 上线步骤

### 4.1 你需要先做的（我无法代办）

1. 注册/登录魔搭社区，取得 Access Token：<https://modelscope.cn/my/myaccesstoken>。
2. 完成**阿里云账号绑定 + 实名认证**（`docker` 类型构建的前提）。
3. 定下：`owner`（账号或组织名）、`repo_name`（建议小写字母/数字/连字符）、显示名称、简介、**公开还是私有**（建议先私有，验收后再公开）。

### 4.2 我可以执行的（需要本机 shell 可用）

```sh
# 1. 本地构建并自测：不需要额外组装，直接用仓库根 Dockerfile（创空间也认这个文件）
docker build -t hackathon-field-guide-modelscope .
docker run --rm -p 7860:7860 \
  -e APP_MODE=local -e PORT=7860 \
  -e AUTH_ORIGIN=https://modelscope.cn -e AUTH_ALLOW_PUBLIC_LOCAL_ORIGIN=true \
  -e AUTH_CODE_PEPPER=<32 字节以上的随机值> \
  -v <本地持久化目录>:/mnt/workspace \
  hackathon-field-guide-modelscope
# 2. 打开 http://127.0.0.1:7860 自测，并重启容器确认数据仍在
# 3. 关联创空间远程并推送 master（禁止 force push）
# 4. 触发部署并查看 build / run 日志
```

创建与部署也可以直接走 HTTP API（MCP 未配置时）：

```sh
curl -s -X GET "https://modelscope.cn/openapi/v1/users/me" -H "Authorization: Bearer ${MODELSCOPE_API_TOKEN}"
curl -s -X POST "https://modelscope.cn/openapi/v1/studios" \
  -H "Authorization: Bearer ${MODELSCOPE_API_TOKEN}" -H "Content-Type: application/json" \
  -d '{"owner":"<owner>","repo_name":"<repo>","sdk_type":"docker","display_name":"黑客松情报局","description":"...","private":true}'
curl -s -X POST "https://modelscope.cn/openapi/v1/studios/<owner>/<repo>/deploy" -H "Authorization: Bearer ${MODELSCOPE_API_TOKEN}"
curl -s -X GET  "https://modelscope.cn/openapi/v1/studios/<owner>/<repo>/logs/build" -H "Authorization: Bearer ${MODELSCOPE_API_TOKEN}"
```

### 4.3 验收清单（按第 6 节既有约定，不能省略）

1. 公开链接在未登录窗口可打开，CSS/JS/图片无 404（判定第 3.6 节风险）。
2. 站点地址与 `AUTH_ORIGIN` 的实际 Origin 一致，登录 POST 不被 `AUTH_ORIGIN_INVALID` 拒绝。
3. 真实邮箱收到验证码并完成一次登录。
4. 重启创空间后，账号、项目、审核证据仍在（证明 `/mnt/workspace` 持久化生效）。
5. 一次真实 DSH 分析返回 JSON 与用量；错误 key 不显示为成功。
6. 明确记录：自动赛事发现用的是固定官方来源还是未启用；不把容器启动当成采集正常。
7. 创空间为私有则改公开后，再用未登录窗口复核一次。

必需：


`DSH_RUNTIME_PACKAGE_DIRECTORY` 不需要设置：镜像里已经是 `/app/.runtime/dsh-runtime/node_modules/@deepseek-ai/dsh`，与 Compose 一致。

公开登录必需（二选一）：

```text

# 或 SMTP 相关变量
```

按需：

```text
DISCOVERY_PROVIDER=official_sources
DISCOVERY_SOURCE_IDS_JSON=["ethglobal","lablab"]
BRAVE_SEARCH_API_KEY
```

## 6. 已知阻塞

1. **本机 shell 完全不可用**：`pwsh` 任何命令都在沙箱初始化阶段失败（`SetNamedSecurityInfoW failed (Win32 5): grantWrite(F:\黑客松情报局)`）。因此 `npm run build`、`docker build`、`git push`、以及上面的 `curl` 都无法执行。一次性权限修复被拒绝，方案尚未诊断。
2. **缺 `MODELSCOPE_API_TOKEN`** 与 owner/repo 名称、公开/私有选择。
3. **缺阿里云绑定 + 实名认证**（Docker 类型前提）。
4. **缺真实邮件凭据**，否则公网登录不可用。
5. **缺 DSH API key**，否则聊天与项目 AI 不可用；自动赛事发现在容器路径未宣称支持。
6. 第 3.6 节的路径前缀行为必须由第一次真实部署判定。

## 7. 禁止事项：不要把项目目录整体拖拽上传

创建创空间的第一步「空间文件」支持拖拽文件或**整个项目文件夹**，界面文案是「支持 .py .json .html 等文件」——那是给 Gradio / Streamlit / Static 路线用的。**本站不能走这条路，更不能把项目根目录整体拖进去。**

`.dockerignore` 只约束 Docker 构建上下文，**不约束网页拖拽上传**。当前本机项目根目录下至少包含以下不可外传的内容：

| 路径 | 内容 |
| --- | --- |
| `.env.local` | 本机正式环境变量与凭据 |
| `.runtime/local-secrets.json` | `AUTH_CODE_PEPPER`；机构邮箱授权码的加密 key 由它派生 |
| `.runtime/ecs-hk/export-clone-*/postgres-data/` | 一份完整的真实数据库副本（账号、项目、审核证据） |
| `.runtime/ecs-hk/export-clone-*/.env.local`、`.runtime/backups/*/.env.local` | 多份环境变量副本 |
| `.runtime/ecs-hk-authorize-deployment.sh` | 云主机 SSH 授权配置 |
| `node_modules/`、`.next/` | 数千个无需上传的文件，拖拽上传会失败或极慢 |

正确做法是用 **Git 推送到创空间仓库**（平台只拉取仓库内容，并按 `.dockerignore` 构建镜像），且推送前复核远端确实没有 `.env*` 与 `.runtime`。若已误传，应立即删除创空间中的对应文件，并轮换 `AUTH_CODE_PEPPER` 覆盖到的凭据（该 pepper 同时派生机构邮箱加密 key，轮换前须先解密再用新 pepper 重加密，步骤见[后端部署](后端部署.md)）。
