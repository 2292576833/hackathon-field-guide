02

参赛路线图：从找比赛到留下经验

本站原创指南，三个阶段的 15 个行动节点。点击不代表完成，主办方要求永远优先——路线图只负责让你知道下一步该做什么、以及需要哪份资料。

before赛前：选比赛，定目标，做好准备

从适合的比赛开始，把规则、最小作品、人员和可用时间说清楚，再安排能交付的任务。

找比赛，核对规则与报名

核对资格、费用、时间与必交材料；保存分析或创建空间都不等于已报名。

→ 去找比赛并查看原文
定一个最小能演示的作品

写清一个使用者、一个问题和一条核心流程，把必需功能与可选功能分开。

→ 创建或打开团队空间
安排个人备赛与出行

补充经验、城市和可投入时间；个人计划是待核对草案，分享前由本人选择内容。

→ 打开个人参赛准备
试通开发环境与版本保存

用小练习确认项目能启动、能保存与恢复版本，并准备网络或设备故障时的替代演示。

→ 学习 GitHub 与版本保存
邀请队友，填时间，选择职责

按所需人数创建邀请链接或本地二维码；AI 建议不自动成为正式分工。

→ 进入空间安排成员与分工
排任务、交接条件与提交缓冲

确认负责人、成果、验收条件、预计用时与前置交接，给集成和提交留缓冲。

→ 进入空间确认任务与时间
during赛中：做出作品，检查协作，展示提交

先做通核心流程，再持续集成和检查；展示材料围绕实际成果制作，按主办方要求完成正式提交。

做通一个核心 Demo

先完成能从头演示的最小流程，给每次交接附成果与启动方法。

→ 进入空间推进核心任务
准备 UI、素材与视觉参考

先画草图，再整理配色与素材；不把漂亮截图当作可运行作品。

→ 按当前界面任务找灵感
集成、测试，记录实际运行结果

从头跑一次，检查登录、网络、空数据和主要失败路径；版本保存成功不能替代运行通过。

→ 进入空间检查作品运行
写讲稿、做 PPT，练习路演

用问题、使用者、实际成果和演示流程组织讲稿，按比赛时长练习。

→ 准备讲稿与路演练习
按要求准备演示视频

先核对是否要求视频及格式、时长；成片必须基于可演示成果录制。

→ 查看录制与演示工具
保存代码，向主办方正式提交

核对仓库、分支和差异并保存版本，再按主办方原文进入正式提交入口。

→ 进入空间核对保存与提交记录
after赛后：复盘，保留成果，用于下一次

把这次的协作、技术和时间经验整理成可核对记录，保留成果，再挑选适合下次参赛的部分。

复盘合作、技术与时间问题

对照实际任务和交付记录，写清做对了什么、卡在哪里、下次怎么改。

→ 进入本次空间写复盘
保存成果，按需归档空间

整理仓库版本、演示说明与提交凭证，检查链接能否继续访问。

→ 打开空间整理成果与历史
挑选经验和资源，准备下一次

从已确认经验里挑选复用项，但旧分工、截止与授权不自动适用。

→ 选择下一次参赛空间
路线图自带的核对提醒
  • 资格、人数、费用、报名状态、官方赛道、评分重点与 AI 使用规则，都要回到主办方原文核对。
  • 报名截止、开赛时间和作品提交截止要分别记录并保留时区——作品提交截止不能代替报名截止。
  • 赛前已有的代码、素材和预做作品是否可用，按比赛规则确认。
  • 设计参考不等于获得图片、品牌或代码许可，使用素材前另行核对来源与署名。

技能库按四个赛道（通用 / 游戏 / 影视 / AI Agent）组织。每个技能固定上游 commit 与校验和，每个技能包说明适用条件、产出物和已知限制——「复制安装命令」和「客户端真的加载了」是两件分别记录的事。

技能包怎么用

先核对前置条件与许可，预览并确认清单，只授权项目目录进行文件安装，再到客户端里检查技能是否真的加载，最后用一个示例任务验证产物。

不做什么

不替用户安装本机技能，不自动补装依赖，不覆盖同名文件，不把「文件写入成功」当成「客户端加载成功」或「任务验证通过」。

05

团队空间：一个参赛项目一个共享空间

不看板、不打卡。空间里放着这场比赛的目标、资料、任务交接、代码保存与正式提交记录，以及赛后的复盘。

成员与分工

邀请链接或本地二维码加入，按人数限额；每人填写可用时间并自选职责，AI 可给建议但由管理员确认正式分工。

任务与交接

每个任务写明负责人、成果、验收条件、预计用时和前置交接。成员报告完成后仍需实际检查，进度在空间里更新。

三类记录分开

代码版本保存、实际运行检查、向主办方正式提交是三件事，分别留下记录与凭证；没有回执时注明是本人自报。

隐私边界

原始测评、个人准备与出行资料默认仅本人可见，个人 AI 也继承本人导航记忆；是否共享由本人选择，邀请队友不会自动共享。

赛后复盘

对照实际任务与交付记录写复盘，确认哪些经验值得复用；复盘不会生成第二份「运行成功」或「提交成功」状态。

归档即只读

项目归档后业务内容只读，历史保留，不删除既有交付凭证。

06

技术实现

模块化单体：Next.js App Router + React + TypeScript + PostgreSQL，采集与分析 worker 独立运行。十个业务模块通过注入的 Port 协作，不互相读写私有存储。

前端与运行时

Next.js App Router · React · TypeScript · Node 24

数据

PostgreSQL 17 · 68 个版本化迁移 · 已应用迁移不可重写

模型调用

官方 @deepseek-ai/dsh@0.2.1-alpha.1（固定版本，不用浮动 tag）

子进程隔离

每次分析启动独立无工具子进程，不继承数据库、邮件、搜索、GitHub 密钥；用完即终止。

费用与预算账本

搜索、分析与灵感分开记账，按 UTC 日设上限；付费请求结果未知时保守结算并禁止自动重发。

抓取边界

只访问公开页面，校验 DNS、TLS、robots、重定向、体积与超时；目录格式变化就停下留安全错误码，不把整张列表当成一场比赛。

这套做法换来了什么

纪律具体做法
不虚构卡片始终是未核验线索；模型只能从实际可见 HTML 里选择完整候选链接，不能构造链接。
不降级自由聊天固定走 DSH，禁止退化成通用 HTTP 或静态回复；配置缺失就明确报错。
不重复收费结果未知的付费请求写入持久 hold，重启或跨日都不重放；只有管理员新建 run 才授权新尝试。
可核对比赛页展示分析结果、折叠依据和原文跳转；管理员后台单独放采集配置、额度与暂停。
